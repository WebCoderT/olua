SELF-HOST · 自建服务器

自己部署一份

一台机器 + Docker，跑起属于你自己的服务器

架构一览

仓库自带 Docker Compose 编排，五个服务全部容器化：

服务职责对外端口
admin管理端（React + nginx）：管理页面 + 官网 + 游戏站三域名分流 + /api 同源反代80
server游戏服务端（NestJS + SQLite）：账号 / 角色 / 战斗权威 / 管理接口仅内网
server-realtime实时进程：多人同屏位置 / 动作 / 击杀广播（与 server 同镜像不同入口）仅内网
game游戏客户端静态托管（Cocos Web 构建产物 + /game-resources 素材）8080
website官网静态站（nginx 只读挂载）仅内网（经 admin 分流）
设计约束：数据落在具名卷 olua-data 的 SQLite（WAL 模式，双进程共享）； 服务端与实时进程都不映射宿主机端口，所有流量从 :80 按 server_name 分流进入。

环境要求

  • 一台 Linux 主机（2C4G 起步，磁盘 ≥ 10GB——游戏资源约 2.5GB）；
  • Docker 20+ 与 Docker Compose v2；
  • 本机装有 Git、SSH 客户端（部署脚本从本机推送代码与产物）；
  • （可选）一个域名，A 记录指到服务器 IP；没有域名也能用 IP 直接访问。

快速开始

1. 拉代码

git clone https://github.com/WebCoderT/olua.git
cd olua

2. 拉取游戏资源包（约 2.5GB，仓库不含素材）

# 查看已发布的资源版本
gh release list --repo WebCoderT/olua

# 下载并解压到 client/assets/resources（也可手动从 GitHub Releases 页面下载）
make resources-download VERSION=<版本号>

3. 填写部署配置

cp deploy.env.example deploy.env
vim deploy.env

关键配置项：

变量说明
DEPLOY_HOST / DEPLOY_USER / DEPLOY_KEY服务器 IP、SSH 用户与私钥路径（权限须 600）
DEPLOY_DIR服务器上的部署目录（如 /opt/olua）
JWT_SECRET登录令牌签名密钥，务必改成随机长串
ADMIN_REGISTER_CODE管理端账号注册邀请码
OLUA_SITE_DOMAINS官网站域名（多个用空格分隔，如 "example.com www.example.com"）
OLUA_ADMIN_DOMAIN管理端域名（如 admin.example.com）
OLUA_GAME_DOMAIN游戏域名（如 game.example.com）
ADMIN_PORT / GAME_PORT管理端与游戏站对外端口（默认 80 / 8080）
域名全走环境变量：nginx 配置是 envsubst 模板，域名只在 deploy.env 出现—— 换域名 / 分环境 = 改配置文件重发一次，不改代码、不重建镜像。没有域名时 IP 访问会落入管理端（default_server 兜底）。

4. 一键部署

bash .workbuddy/skills/olua-deploy/scripts/deploy.sh            # 全量：传代码 + 生成 .env + 重建镜像 + 健康检查
bash .workbuddy/skills/olua-deploy/scripts/deploy.sh --no-build # 只换代码，不重建镜像（改静态文件用）
bash .workbuddy/skills/olua-deploy/scripts/deploy.sh --game     # 同步 Cocos 客户端构建产物
bash .workbuddy/skills/olua-deploy/scripts/deploy.sh --resources # 同步游戏素材包（image/audio manifest 等）
bash .workbuddy/skills/olua-deploy/scripts/deploy.sh --verify   # 只做验收检查

5. 打包并上传客户端（可选，本地开发机执行）

游戏客户端用 Cocos Creator 打开 client/ 构建 Web 桌面包（Cocos 只能 GUI 构建）， 产物在 client/build/web-desktop-001/，然后：

bash .workbuddy/skills/olua-deploy/scripts/deploy.sh --game

发布新资源版本（开发者）

make resources-manifest VERSION=2026-11-04-1   # 生成清单（先入库提交）
make resources-pack RES_VERSION=2026-11-04-1   # 打分卷包
make resources-upload RES_VERSION=2026-11-04-1 # 传 GitHub Release

VERSION= 与 RES_VERSION= 两种写法等价。同步约定：先清单入库，后上传资源， 其他机器 git pull 后按清单下载即可逐字节校验。

本地开发

cd server && npm install && npm run start:dev   # 服务端 :3100
cd admin && npm install && npm run dev           # 管理端 Vite 开发服务
# 客户端：Cocos Creator 打开 client/，预览时自动连 localhost:3100

客户端按访问地址自动判断环境：本机 / 局域网直连 localhost:3100， 公网 IP 与域名走同源 /api 反代——一份构建产物，本地与线上通用。

部署常见问题

报错先对号入座

启动后所有配置表为空 / 商城没有商品
出厂配置快照 server/data/config-sync.sql 必须打进镜像。确认没有修改 server/.dockerignore 里对它的放行规则，且 compose 两个服务都设了 CONFIG_SNAPSHOT_PATH=/app/config-sync.sql。
管理端构建报 TS2307（找不到 server 模块）
管理端要引用服务端的枚举常量，构建上下文必须是仓库根而不是 admin/（compose 里 context: . + dockerfile: admin/Dockerfile），根目录 .dockerignore 负责挡大目录。
用 IP 访问 :80 打不开 / 404
nginx 的 _ 不是通配符：未匹配的域名会落到 :80 上第一个 server 块。管理端块已标 default_server 兜底，若你改过模板请保留这行。
管理端图片选择器报 404：/game-resources/image-manifest.json
素材包没上服务器。执行 deploy.sh --resources 把 client/assets/resources（含 image / audio manifest，约 2.5GB）同步上去。
能登录但实时通道连不上
实时通道走 /api/realtime 的 WebSocket 升级，反代必须透传 Upgrade / Connection 头（仓库自带模板已配好，改动前看 map $http_upgrade 那段）。同时确认 server-realtime 容器在跑。
部署脚本验收报 502
多半是容器还没就绪。新版本脚本已内置健康检查轮询；若手动验收，等 docker compose ps 全部 healthy 后再打接口。
上线前要备份数据吗？
强烈建议。数据在具名卷 olua_olua-data 的 SQLite（注意数据多在 -wal 文件里，备份要连同 -wal 一起拷）。发布前可先 docker exec 进容器执行 PRAGMA wal_checkpoint(TRUNCATE)。

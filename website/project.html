OVERVIEW · 项目概览

这是什么

一个跑得起来的、免费开源的 2D 即时战斗项目

olua 是一个 完整开源（MIT） 的 2D 即时战斗游戏项目：客户端、服务端、运营后台一个不少， 数值、地图、掉落、特效都能在后台改。它免费，也允许商用 —— 任何人都可以拉下来，在自己的机器或服务器上跑起来，和朋友一起玩。

它是

  • 一个三端跑通的学习型项目
  • 一套可以参考的全栈 TypeScript 工程
  • 一个「AI 写代码、人验收」的实践样本
  • 一个能自己部署、自己改数值的玩具

它不是

  • 可以直接开服运营的商业产品
  • 开箱即用、免配置的发行版
  • 追求高并发与横向扩展的架构
  • 带客服与 SLA 的服务
说清楚这件事很重要。项目里的每个设计取舍（单库、双进程、不做分布式）都是按「一个人、一台机器、几个朋友」来的； 拿它去扛大服会很快撞墙，那不是 bug，是前提不同。

THREE ENDS

三个端，职责不重叠

客户端玩、服务端算、管理端改

客户端

玩家看到的全部

登录、选角、战斗、背包、商城、社交、小地图。Cocos 工程，用 Creator 打开 client/ 目录即可运行。

只负责输入与表现：数值等快照、结果等服务端，本地不判定任何战斗结果。

Cocos Creator 3.8.7
TypeScript · Box2D
186 个 TS 文件 / 4.65 万行

服务端

唯一的权威数据源

账号、角色、地图、怪物、战斗结算、掉落、邮件、排行榜。两个进程共用一个 SQLite 文件，Swagger 从这里生成契约。

客户端与管理端的接口文件都由它产出，不手写。

NestJS 12
node:sqlite · JWT · Swagger
23 模块 / 4.95 万行

管理端

运营改数据的地方

账号角色、地图与刷怪区、NPC 与碰撞盒、掉落表、装备体系与外观、特效、公告邮件、权限与操作日志。

页面 50 个，改完落库即生效，不用重启服务端。

React 19 + Vite
Tailwind CSS v4
50 页面 / 4.11 万行

STACK

技术栈与运行要求

没有原生的坑，没有外部中间件

客户端
Cocos Creator 3.8.7 + TypeScript + Box2D。改客户端才需要编辑器，只跑服务端不需要。
服务端
NestJS 12 + node:sqlite（Node 22 内置）+ JWT + Swagger。没有原生模块，npm install 不会卡在编译。
管理端
React 19 + TypeScript + Vite + Tailwind CSS v4。构建产物是纯静态文件。
存储
SQLite 单库，WAL 模式。备份就是拷文件，迁移就是拷文件。
部署
Docker Compose 四服务：admin:80（入口）/ game:8080 / server:3100 / realtime:3101。
Node 版本
≥ 22.5。低于这个版本没有 node:sqlite，服务端起不来。
素材
client/assets/resources/ 体积大，不入库。通过 make resources-download 从 Release 拉取并校验 sha1。
Cocos Creator 3.8.7 TypeScript NestJS 12 node:sqlite React 19 Vite Tailwind v4 JWT Swagger Docker Compose nginx

REPOSITORY

仓库长什么样

三端平级，各自有 README 与 FAQ

olua/ ├── client/ # Cocos Creator 工程（打开这个目录） │ ├── assets/ │ │ ├── configs/ # 全部可调项：数值 / 布局 / 配色 / 时长 / 路径 │ │ ├── ui/ # 界面、控制器、组件、网络层 │ │ ├── skills/ # 技能表现 │ │ ├── entities/ # 角色、怪物实体 │ │ └── resources/ # 素材（不入库，走 Release） │ ├── README.md · FAQ.md │ └── types/engine/ # Cocos 类型声明（vendoring，CI 免编辑器） │ ├── server/ # NestJS，唯一权威 │ ├── src/ │ │ ├── modules/ # 23 个业务模块 │ │ ├── database/ # 建表 / 快照 / 仓储 │ │ └── main.ts · main.realtime.ts # 两个进程入口 │ ├── test/ # 29 套 e2e │ ├── data/config-sync.sql # 出厂快照（空库自举） │ └── openapi.json # 契约源，提交进仓库 │ ├── admin/ # React 运营后台 │ └── src/pages/ # 50 个页面 │ ├── tools/ # 跨端脚本：契约生成 + 15 项审计 ├── website/ # 本项目官网（纯静态） ├── docs/ # 部署说明 ├── Makefile # 三端常用动作收在一处 ├── docker-compose.yml └── resources.manifest.json # 素材清单（sha1 + 大小）
两条全局约定：客户端一切可调的都在 assets/configs； 接口文件全部由服务端生成。前者保证「调手感不用改逻辑」，后者保证「改字段不会忘了一边」。

AUDIENCE

适合谁，不适合谁

适合

  • 想读一个完整 TS 全栈项目的学生 / 转行者
  • 想了解「AI 参与真实项目」是什么样的人
  • 想在自己服务器上架一个和朋友玩的游戏的人
  • 需要一个 2D 游戏服务端骨架的开发者

不适合

  • 想直接开服拉人、要商业化运营的
  • 要求开箱即用、有人答疑的
  • 需要高并发 / 分布式 / 多区服的
  • 指望素材可以商用的（素材版权需自行确认）

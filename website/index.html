核心特色

一切可调皆配置，代码只做「怎么跑」

装备 15 品质变体

前缀 5 档（普通→超神）× 后缀 3 档（人 / 天 / 神级），每件基础装备展开 15 个变体，属性逐项缩放，名称分段按品质着色。

品质边框与详情背景

背包与身上装备按前后缀组合播放发光边框动画（84 张图集），悬停详情弹窗切换同组合的品质背景动画（41 套帧序列），特殊装备可自定义。

掉落系统与光柱

每只怪独立掉落表，逐条配置权重 / 概率 / 数量区间；掉落物同心环散落互不重叠，装备落地即播品质光柱（普通→超神 5 档，第 6 套留给特殊装备）。

商城

全部装备自动上架，门面式弹窗 + 卡片网格分页浏览（一行 3 张、每页 6 件），购买先扣款再入包，余额不足 / 背包满都不会改数据。

背包全套操作

一键整理（合并 + 重排 + 铺满）、拖动换格（移动 / 合并 / 交换）、一键回收为绑定元宝、拖出弹窗松手整格销毁——不可撤销的操作全部两步确认。

战斗与技能

技能触发统一入口：冷却 / 耗蓝 / 距离校验、伤害飘字、击退、突进位移（十步一杀瞬移）；状态 Buff 挂身循环特效 + 图标倒计时。

怪物 AI

区域刷怪、待机游走、主动追击、受伤激怒、普攻结算；死亡倒地动画播完才移除，点击选中显示信息面板与光圈。

三条成长线

战魂 37 阶 / 称号 34 阶 / 军衔 100 阶，三条同构成长线都消耗绑定元宝、都计入战力与地图进入条件；称号与军衔解锁后常显在头顶信息栏。

全服公告与邮件触达

公告带生效时间窗，管理端发布后客户端登录弹窗 + 公告板即时可见（已读记录单独存放，不污染角色存档）；邮件走模板配置 + 投递队列 + 指数退避重试，未启用时整体禁用而不是静默失败。

运营后台与双层权限

角色运营台支持六维筛选、批量删除与装备 / 技能 / 背包的结构化编辑；装备 / 药品 / 物品 / 怪物 NPC / 商城定价 / 时装 / 掉落表 / 成长曲线 / 军衔全量可调，另有区服管理页（开区 / 合并区）。25 个权限点 × 3 种管理员角色双层守卫，写操作自动留痕、敏感字段打码。

服务端权威与区服模型

地图与怪物全部由服务端控制：刷怪区表驱动播种、怪物数值读库即时生效、伤害 / 掉落 / 经验服务端结算；账号归属区服，多开区 / 合并区一个事务搬账号重排世界，代际号让两个进程的世界内存即时失效。

WebSocket 实时通道

一次性票据换连接、握手拒连与其余接口同形；应用层心跳与存活探测、一账号一条连接（顶号踢下线）、断线指数退避重连；世界内广播伤害与怪物状态，跨区攻击直接拒绝。

地图与小地图

Tiled 对象组导入服务端：NPC 点位、刷怪区、复活点由服务端播种下发；小地图按视野等比缩放随角色平移，预览弹窗左键寻路、右键传送，未达标地图自动拦截。

自动战斗

快速攻击与自动挂机开关，基于 A* 寻路绕障碍走位，卡住自动换目标；大地图与小地图同步绘制寻路路线指示。

三端架构

客户端只是其中一端；玩法之外还有服务端与运营后台

客户端 · Cocos Creator

TypeScript + Cocos UI / 2D，跑在浏览器里的 Cocos Web 产物。玩法、渲染与交互都在这端；数值、文案、布局、配色、资源路径一律收敛进 configs/，代码只做「怎么跑」。

服务端 · NestJS

162 个 REST 接口 / 134 条路径 / 241 个模型，Swagger 文档是唯一契约源；JWT 双受众鉴权（玩家 / 管理员）+ 每次请求回查库，25 个权限点的双层守卫，角色数据走修订号乐观锁与冲突自愈；旁边还有一条 WebSocket 实时进程，双进程共享同一份 SQLite。

管理后台 · React

角色运营、账号封禁、公告发布、邮件发信与投递记录、操作日志查询，装备 / 药品 / 物品 / 怪物 NPC / 商城定价 / 时装 / 掉落表 / 成长曲线 / 军衔全量配置管理，以及区服管理（开区 / 合并区）；界面按权限点渲染，服务端仍是唯一权威 —— 前端改不出一份越权数据。

工程化与约定

不只是一个玩法 demo，更是一套可维护的工程范式

配置驱动

数值、文案、布局、配色、资源路径全部收敛在 configs/，代码只做「怎么跑」；审计脚本自动扫出散落在逻辑里的可配置项与未登记文案。

58 套单测 + 12 套审计

单测覆盖背包整理 / 拖动 / 回收 / 丢弃、装备边框、详情背景、掉落名、光柱、商城、称号、成长曲线、文案、角色帧素材守卫等纯函数，全部可在 Node 里直接跑；审计脚本盯的则是单测抓不到的「静默失效」——配置外泄、地址硬编码、生成物漂移、两端口径不一致、服务端模块边界被绕过、文档里的数字过期。

接口契约代码生成

以服务端 Swagger 文档为唯一契约源，生成客户端与管理端的路径表 / 接口方法 / 实体类型。三端签名对不上会直接编译报错，而不是线上出现一个 undefined；生成物不许手改，有审计逐字节盯着。

2446 条服务端 e2e

二十四套 e2e 脚本真起服务、真连库，覆盖权限越权、令牌受众隔离、封禁闭环、公告触达、邮件投递、备份恢复，以及服务端权威化的硬核链路：战斗结算 / 掉落经验 / 商城购买 / 用药收权、世界按区隔离、开区合并事务与代际失效、实时通道踢下线；每套脚本断言自己的条数，少一条就当场失败。

输入与交互打磨

双通道输入（触摸 / 鼠标）、按压归属、拖动手势、全屏模态独占输入、自定义指针……每个交互细节都有对应审计脚本钉住。

屏幕适配

NO_BORDER 铺满窗口不留黑边，常驻 HUD 贴边重排；选角舞台等比缩放，任意窗口宽高比下元素都不会跑出屏幕。

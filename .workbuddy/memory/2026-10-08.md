## 弹窗层级：点哪个哪个浮到其它弹窗之上

- 需求：同屏开多个弹窗时，点任意一个即把它显示到其它弹窗之上。
- **做法（两个入口 + 一处登记）**：`LayerManager.addDialogToUILayer(node)`（登记进 `dialogNodes` + 挂 UI 层）与 `LayerManager.raiseDialog(node)`（置顶）。置顶目标 = **已登记弹窗里最上层的那个所在兄弟序号**，所以只在弹窗之间排序：飘字提示、悬停物品详情这类「弹窗之后创建」的临时层仍盖在弹窗之上；未登记节点（HUD）与已销毁弹窗自动跳过。
- **绑定**：`GameUiHelper.bindDialogRaiseOnPress(node)` 挂两条通道 —— `TOUCH_START` 冒泡 + `MOUSE_DOWN`（**绝不注册 MOUSE_MOVE**，会吞指针移动）；`createDialogBg` 里已统一调用（9 个走 createDialog 的弹窗自动获得），MallDialog 自有底图、ConfirmDialog 全屏框各补一次。逐文件断言弹窗挂载点全走 `addDialogToUILayer`（10 个文件 / 11 处）。
- **引擎事实（核实过源码）**：`node-event-processor` 的派发是 捕获 → AT_TARGET → 冒泡；`propagationStopped` 只拦**祖先**（`if (!event.propagationStopped) …冒泡循环`），**同节点的其它监听照常执行** —— 所以挂在弹窗根（与 Draggable 同节点）的置顶监听不会被 Draggable 的 stopTouchBubble 顶掉。另：全局 `input.on(TOUCH_START/MOUSE_DOWN)` 在「有节点命中并独占」时不会派发（`_emitEvent` 遇到 dispatcher 返回 false 即 break），所以**不能**用全局监听做置顶。
- **缺口与补法**：手势区域把触摸收住（`propagationStopped`）后事件到不了弹窗根 —— 项目里只有 `BagGridView.setupTouchOwnership` 与 `ConfirmDialog` 这么做；前者在 BagDialog 里补挂 `bindDialogRaiseOnPress(this.bagGrid)`，靠 `raiseDialog` 的「沿祖先找最近已登记弹窗」（`findDialog`）定位到背包弹窗。鼠标通道不受影响（MOUSE_DOWN 照旧冒泡到弹窗根）。
- **不被卷进来**：HUD（bottomBar/roleInfoBar/smallMap/monsterInfoPanel）、飘字、悬停详情、悬停提示、死亡遮罩、升级特效仍走 `addToUILayer`（死亡遮罩因此保持盖在弹窗之上）。

## 服务端（NestJS）+ 管理端（React）+ 客户端接入服务端

- **需求（原文要点）**：按当前游戏流程建服务端，只做登录/注册/角色操作接口；客户端调这些接口；管理端也要登录注册并能对「每个账号对应的角色」操作；接口文档用 Swagger 抛出；客户端与管理端**不许硬编码任何地址**；请求必须**二次封装、统一调度**；服务端 NestJS、管理端 React + Tailwind CSS。
- **三端骨架**：`server/`（NestJS 12 + `node:sqlite` + `@nestjs/jwt` + `@nestjs/swagger`）、`admin/`（Vite + React 19 + Tailwind v4）、客户端新增 `assets/configs/network.ts` 与 `assets/ui/utils/net/`（7 个文件）。三者各自独立工程，不进根 `package.json`。
- **零原生依赖持久化**：用 Node 22 内置 `node:sqlite` 的 `DatabaseSync`（`prepare/run/get/all/exec` + `lastInsertRowid/changes` 均可用），**不引 better-sqlite3**（避免原生模块编译）。WAL + `PRAGMA foreign_keys = ON`，删账号靠 `ON DELETE CASCADE` 级联删角色；`:memory:` 供 e2e 用。启动脚本带 `node --disable-warning=ExperimentalWarning`。
- **统一响应包裹**：成功与失败形状恒为 `{ code, message, data, timestamp, path? }` —— 成功走 `TransformInterceptor`，失败走 `AllExceptionsFilter`；业务码分段（1xxxx 账号 / 2xxxx 角色 / 3xxxx 管理端 / 4xxxx 通用，0=成功）。客户端与管理端的请求层都按同一个包裹解包，业务层见不到 code/message。
- **两套 JWT 受众隔离**：`TokenService.sign(subject, audience)` 写进 `aud`，`verify(token, audience)` 按接口要求的受众校验 → 玩家令牌调管理端接口 401。`AuthGuard` 每次请求**回查库**（封禁/删除立即生效，不必等令牌过期）。口令用 Node 内置 `scryptSync`+随机盐+`timingSafeEqual`（格式 `scrypt$salt$hash`），不引 bcrypt。
- **Nest 三个必踩点**：① 全局 `ValidationPipe({ whitelist: true })` 会**剥掉没有 class-validator 装饰器的字段** —— query DTO 只写 `page?: number` 会被静默丢掉（e2e 的「分页/关键字检索」两条就是这么挂的），必须补 `@IsOptional/@IsInt/@Min/@Max`；② `@Post` 默认 201，登录/选中角色这类「读性质」的 POST 要显式 `@HttpCode(HttpStatus.OK)`；③ Swagger 画统一包裹要用 `allOf: [$ref ApiEnvelopeDto, { properties: { data: $ref Model } }]`，被 `$ref` 的模型必须登记进 `extraModels`，否则文档缺 schema。
- **角色数据是「不透明文档」**（关键设计）：`roles.data` 存客户端 `entities/Role` 的 JSON 快照。服务端**不复制**游戏配置（复制必然漂移：改客户端配置忘了改服务端就会出现「客户端合法、服务端说非法」），只校验结构 + 归属 + 数量上限 + 重名；索引字段（id/name/occupation/sex/level）另落独立列，列表查询不解析 JSON。
- **踩坑（e2e 首轮 4 条失败）**：`AdminService.patchRole` 把 `row.data`（数据库里的 **JSON 字符串**）直接交给 `parseRoleData` → 字符串不是对象 → 报 `20003 角色数据格式不正确`。修法：`role-data.util.ts` 拆成 `decodeStoredRoleData`（读路径容错，坏数据当空对象）与 `parseStoredRoleData`（**编辑路径解析失败直接报错**）—— 绝不能用空对象兜底去写，那会把玩家背包/装备清空。修完 e2e **129 条全绿**。
- **管理端请求层**：`src/api/config.ts`（地址唯一来源，读 `import.meta.env.VITE_API_BASE_URL`）→ `http.ts`（拦截器链 + AbortController 超时 + 包裹解包 + 错误归一 + 401 跳登录 + `silent`）→ `auth.api/accounts.api/roles.api` → barrel。新增 `POST /admin/roles/:id/select`（管理端也能切在线角色 —— 用户要求「能对每个账号对应的角色进行操作」，一开始写成「管理端不代玩家选角」的占位提示是错的）。页面 7 个，`RoleDetailPage.buildPatch` **只提交改动过的字段**。构建 `✓ 45 modules transformed`，295 KB（gzip 92 KB）。
- **客户端请求层刻意选 `XMLHttpRequest` 而不是 `fetch`**：Cocos 在 Web 与原生两端都保证有 XHR，fetch 在部分原生环境不存在。注入令牌做成**默认请求拦截器**（业务层不许自己拼 `Authorization`）。

## Swagger 分组（公共 / 客户端 / 管理端）+ 管理端权限管理

- **需求（原文）**：「swagger做分组，区分管理端，客户端，公共接口，并且需要做权限管理」。
- **分组**：`server/src/common/constants/swagger-tags.ts` 三组声明（`addTag` 的声明顺序 = 文档展示顺序：公共 → 客户端 → 管理端）；`common/decorators/api-doc.decorator.ts` 提供 `ApiPublicDoc / ApiPlayerDoc / ApiAdminDoc` 组合装饰器，一次同时给出「分组 + 令牌锁（security）+ 所需权限点」。控制器**不写类级 `@ApiTags`**（一个类里常同时有公共接口与需登录接口，类级 tag 会把方法钉死），分组按方法标。
- **重坑 1：`autoTagControllers`**。`@nestjs/swagger` 默认（true）在没有类级 tag 时**自动拿控制器类名当分组** → 文档里每个接口除了自己的分组还多挂 `Health` / `Auth` / `AdminRoles` 之类的类名分组，e2e 的「恰好一个分组」断言直接报 27 个异常。**`@ApiTags()` 空标签清不掉**（空数组同样走 auto 分支，看 `explorers/api-use-tags.explorer.js` 的 `isEmpty` 判断）。正解：`createDocument(app, cfg, { autoTagControllers: false })`。
- **重坑 2：装饰器只写文档没真校验**。`ApiAdminDoc({ permissions })` 最初只 `ApiExtension("x-olua-permissions", ...)` 写文档，**没有调用 `RequirePermissions`** → 守卫读不到元数据 → **所有权限全部放行**（e2e 一次抓出 9 条：只读观察员封号返回 200）。修法：`ApiAdminDoc` 内部同时 `RequirePermissions(...permissions)`，文档与运行时元数据同源，不可能漂移。
- **两层权限模型**（都在守卫里，业务代码不许写角色判断）：① **受众** audience = player/admin 令牌（`AuthGuard`，回查库，封禁/降权下次请求即生效）；② **权限点**（`PermissionGuard`，注册在 AuthGuard **之后**，直接用 `request.user.role`，不再查库）。唯一来源 `common/constants/permission.ts`：10 个权限点、3 个角色（`super_admin` 全部 / `admin` 除 `admin:manage` / `viewer` 三个读）、`ROLE_PERMISSIONS` 映射 + `rolesWithPermission` 给文档反查「哪些角色拥有」。
- **admins 表加 `role` 列**：`ensureColumn()` 用 `PRAGMA table_info` 判断后 `ALTER TABLE ADD COLUMN`（SQLite 带 NOT NULL 必须给默认值，默认值取 `AdminRole.ADMIN` 保持单一来源）。**存量库兜底 `ensureSuperAdmin()`**：补列后所有人都是 admin → 一个超管都没有 → 后台再也管不了管理员；因此「有管理员却没有超管」时把最早创建的那位提为超管（实测真实库 `gm001` 被自动提升，日志有记录）。首个注册的管理员 = 超管，其余 = 普通管理员。
- **保护规则（30007）**：允许改自己（超管可轮值），但**最后一个启用中的超级管理员**不能降级 / 停用 / 删除。判定收敛成一句：改完之后他不再「启用中的超管」而外面又没人接得上 → 拒绝。
- **业务码新增**：30006 权限不足（message 直接写出缺哪个权限的中文名）、30007 保护性拒绝、30008 角色不合法。
- **新增管理端接口**：`GET /admin/admins`（`admin:read`）、`PATCH|DELETE /admin/admins/:id`（`admin:manage`）；`AdminDto` 现在带 `role / roleLabel / permissions`，管理端据此显隐。
- **管理端前端按权限渲染**：`api/types.PERMISSION`（与服务端一一对应）+ `store/session.hasPermission`（读 localStorage 的会话，脏数据兜底空数组 = 最小权限）；`Layout` 导航项带 permission 过滤、顶部显示角色徽章；账号 / 角色各页的写按钮 `disabled={!can...}`；新增 `pages/AdminsPage.tsx`（角色下拉直接改、启停、删除，自己没有 admin:manage 时只读）；`App.tsx` 加 `RequirePermission` 外壳（硬闯地址栏给提示而不是白屏）。构建 47 modules / 303 KB（gzip 93 KB）。
- **验证**：服务端 e2e **187 条**（新增 58 条：文档三组与每接口权限标注、只读观察员四处越权、降权即时生效、超管保护、管理员列表与筛选）；Swagger 深验 27 接口 = 公共 5 / 客户端 8 / 管理端 14，0 未分组、0 悬空 $ref、13 个接口带权限点；管理端 build 通过；25 套单测 + 3 套审计全绿；`audit-api-hardcode` 通过；客户端 tsc 干净；19 个关键文件 22 秒哈希一致。

## 给「所有影响属性的部分」加每秒血量回复并应用

- **需求（原文）**：「给所有的防御装备，等级，称号，元神等所有对属性有影响的部分，添加每秒血量回复量，并且进行应用」。（「元神」= 项目里的「战魂」`soulOfWar`）
- **口径（先定后写）**：新属性 `hpRecover`（点/秒）定为 `BattleAttributes` 的一员、与 `maxHp` 同级。于是「凡是加属性的地方」天然都要处理它；**强度唯一入口** `configs/growth.attributeRange.hpRecoverRate = 0.01`（每秒回最大生命的 1%），等级裸回血 = `round(maxHp × 该值)` —— 与既有 `mpRate`（maxMp = maxHp × 0.5）同一套派生方式。装备 / 战魂 / 称号 / 军衔各自乘自己那套折扣（部位权重 × setPowerRate、rate × factor），因此与最大生命**同涨同落**，调快慢只改一个数。
- **五处来源（`GameHelper.combatCalc` 唯一出口）**：①等级 `getRoleLevelAttributes` ②**防御装备**（`equipmentSlotShare` 新增 `recover` 列：衣服 40 / 头盔 20 / 腰带 20 / 鞋子 20，合计 100；武器与首饰为 0，`equipmentStats` 里 `share.recover > 0` 才算）③战魂 `scaleAttributes` ④称号 ⑤军衔（`getEquivalentAttributes` 的 mix 里也补了 `hpRecover` —— 军衔按分数等效等级插值，漏了就会在分段边界算错）。`scaleEquipmentAttributes`（前后缀变体）同步乘 `hpRecover`（超神·神级 = 普通·人级 × 4.2）。
- **真的应用起来**：新增 `ui/utils/battle/HpHelper`（与 `MpHelper` 同构，静态工具类 —— 角色在存储层是 JSON 普通对象不能挂方法）。`Game.update` 的每秒块改为 `MpHelper.recover` + `HpHelper.recover`，**`if (mpChanged || hpChanged)` 才 `updateOnlineRole` + `updateRoleData`**（血蓝共用一次落盘，不额外挤占 `roleSyncDelay` 1500ms 的同步防抖窗口）。不足 1 点累加进 `hpRecoverAccumulator`（低回血速度不被取整丢掉）、封顶不超过最大生命。
- **三条边界**：①**死亡不回复**（`hp <= 0` 直接 return false，否则回血会把角色从死亡流程里「拉起来」）②**不计入战斗力**（`configs/battle.ts` 权重表改为 `Map<CombatCalcAttribute, number>`，`CombatCalcAttribute = Exclude<keyof BattleAttributes, "hpRecover">` —— 回血不改变输出与承伤上限，算进去会抬高所有地图 `combat` 门槛）③**怪物不回血**（`monsterStats` 恒 0，`MonsterBaseStats` 的 `Pick` 带上它对齐口径）。
- **平衡取舍（有实测）**：装备回血**故意不做「保底 1 点」**（`maxHp`/攻防有 `Math.max(1,…)` 保底，回血不能有）—— 1 级穿满四件防具白拿 4 点/秒，而同级怪输出约 7 点/秒，前期直接无敌。数值探针：1 级 1/秒、60 级裸 987/秒（抵掉同级怪输出 26.5%，裸血生存 26s → 36s）、穿满防位 1975/秒、满养成 4531/秒（裸 987 + 防具 1975 + 战魂 666 + 称号 385 + 军衔 518）vs 同级普通怪 3731/秒 —— 「能稳住挂机但不该高出一个数量级」，已写进单测与 `growth.ts` 注释。

## 修复「怪物死亡后选中光圈残留」（19:36）
- 现象：怪物死亡后怪物信息面板正常消失，但脚下选中光圈永久留在原地（不跟随、不消失，重进游戏才恢复）。
- 根因（两处叠加，缺一不可）：
  1. **引擎 `isValid(value, strictMode?)` 的 `strictMode` 没有默认值**（`cocos/core/data/object.ts`）→ `isValid(node)` 只判 `Destroyed`、**不判 `ToDestroy`**，而 `Node.destroy()` 是「当帧标 ToDestroy + active=false、帧末才真销毁」→ **怪物死亡当帧 `isValid(怪物节点)` 仍为 true**。面板 `update()` 有数据判据（`getMonsterData` 为 null 就销毁）所以正常消失；光圈只判 `isValid(节点)` → 比面板多活一帧。
  2. `RoleUIManager.selectMonster` 用「`monsterInfo` 在 ⇒ 光圈也在」的耦合前提做创建分支：面板已死、光圈仍活的那一帧里，AutoBattle（`Game.update` 里 `AutoBattle.tick` 跑在 `roleDisplay.update()` 之前）选了新目标 → 走「重建两个」分支 → **新光圈直接覆盖 `monsterSelect` 引用**，旧光圈节点失去引用后再不被 update、也永不被 destroy → 冻在尸体位置。
- 修法（3 处）：
  - `RoleUIManager.selectMonster` 重写：面板与光圈**各自独立**维护（存活则 `select(target)` 复用；失效/缺失则先 `destroyXxx()` 再 `factory(target)`），杜绝覆盖引用产生孤儿节点。
  - `MonsterSelectIndicator.update()` 补数据判据（`MonsterManager.getMonsterData` + `hp > 0`），与 `MonsterInfoPanel.update()` 完全一致 → 光圈与面板同帧销毁。
  - `RoleDisplay.update()` 抽出私有 `isTargetGone(target)`（`!isValid` 或 数据消失/血量归零），死亡当帧即清选中。
- 验证：tsc 0 错；磁盘复检 3 处改动在位。沉淀 skill **`cocos-view-lifecycle`**（isValid 严格模式表格、症状→成因链路、视图独立复用/重建模板、排查清单），MEMORY.md 工程风险节补该引擎事实。
- 遗留：已有存档/正在运行的会话里已经孤儿化的光圈需重进游戏才会清掉（改的是生成逻辑，不会回收旧残留）。

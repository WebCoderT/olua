## #1166 技能释放行为配置化（feat/1166-skill-behavior，等第二遍 e2e 后合并）

用户要求「技能的释放动画、伤害、是否位移等都通过管理端管理」。实测现状：动作 / 伤害系数 / 击退拉人
**早已**在管理端可管（#367 起全暴露）；真正的缺口是**释放行为按 id 硬编码**（roleSkillHandlers）与
**施法者自身突进无配置字段**（skill_1008）、「施法动作」是自由文本。AskUserQuestion 三项全按推荐拍板：
行为类型配置化 + 自身突进配置化 + 动作改下拉枚举。

### 关键改动
- **服务端**：`skills` 加 `behavior` 列（attack/status/dash，默认 attack，建表语句放 updated_at 后与 ALTER 列序一致）；
  启动迁移条件回填（`WHERE behavior='attack' AND (category='2' OR id='1008')`，防覆盖运营显式改过）；
  DTO/仓储/SkillDto 全链；`assertSkillBehavior` 独立联动校验（status⇔category2、dash⇔targetType0）——
  **只改 behavior 的 PATCH 只跑联动**，否则 1008「分类主动但倍率空」的历史行会被倍率校验拦死（e2e 实测踩到）；
  `needsMonsterTarget` 加 behavior!=="dash" 兜底；怪物 AI `buildCastPlan` 拒 dash（AI 无瞬移语义，不挡会按伤害技能掷）。
- **客户端**：`configs/skill.ts` 改按 behavior 分发（behaviorHandlers + 未知值回退 attack）；
  warrior.ts 三实现改名 skillAttack/skillStatus/skillDash（文件名保留 warrior.ts——换名要动 Cocos .meta）；
  SkillData/SkillSeedLike 加 behavior；RoleSkillId 只剩 id 段语义，新增角色技能不再改客户端。
- **管理端**：编辑/新建弹窗加「释放行为」下拉（切 status 带出分类2、切 dash 带出区域0，反向不自动改）；
  「施法动作」改下拉（SKILL_ACTION_OPTIONS，键=客户端 ACTION 枚举，die 不进下拉）；列表加「行为」列。
- **数据**：dev 库手动 ALTER+回填（**没动 :3100 用户侧服务**——运行中的服务端内存缓存要等它自己重启才带 behavior）；
  config-export 重导 + **版本归 0**（照例）。

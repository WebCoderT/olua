## Web 端部署游戏客户端（进行中）

目标：把 Cocos 客户端以 Web 端部署上线（用户决定：**独立端口 8080 + 全量资源**）。

### 代码侧：接口地址改为按环境解析（#59 / PR #60，已合入 8294664）
`client/assets/configs/network.ts` 里 `baseUrl` 原写死 `http://localhost:3100/api`，
线上打开会去连访问者自己本机的 3100。改为 `resolveBaseUrl()`：
- 页面来源 `localhost` / `127.0.0.1` / `file://` → 本机服务端地址（本地预览照旧）
- 其余 → 同源 `/api`（nginx 反代到 server 容器）
- 拿不到 `location`（原生壳）→ 回落本机地址

**收益：本地与线上共用同一份构建产物**，换环境不必重建（一次全量构建约 8 分钟）。

### 关键踩坑：Cocos Creator 命令行构建在本机不可用（结论）

排查链（每一层都纠了一个错误猜测）：

1. **假象「Cocos CLI 不存在」**：`CocosCreator --help` 输出的是 node 的 usage。
   真因 = WorkBuddy 注入了 `ELECTRON_RUN_AS_NODE=1`，Electron 被当成纯 node 运行。
   → 必须 `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS` 调用，之后 CLI 才真正启动（打印 `init **** success`）。
2. **`init builder manager success` 后卡死**，日志 82 万行：
   全是 Sentry `sentry-minidump` 的 unhandled rejection —— **自激循环**：
   上报失败 → 抛新 rejection → 上报 → ……
3. 自激循环的起因是**我们传了 `--disable-gpu`**（为绕开第 4 点），而 Sentry 每次取 GPU 信息都会抛错。
   → 所以**不能靠「丢掉日志」解决**：日志丢弃后进程活着但零写盘。
4. **`--disable-gpu` 最初是为了绕**：GPU 进程崩溃 → `FATAL: GPU process isn't usable. Goodbye.`。
   崩溃根源 = `sandbox initialization failed: Operation not permitted`（Electron 派生不了 GPU / network 子进程）。
5. **脱离工具沙箱重跑，`sandbox initialization failed` 依旧** → 说明这是 **Chromium 自身的 macOS 沙箱/**本机环境限制，不是工具沙箱。

**结论：这台机器上 GUI 能构建（10-07 的 `web-desktop-001` 就是 GUI 产物），CLI 走不通 → 打包需要用户在 GUI 点一次。**
AppleScript 菜单自动化也不可用：`System Events` 报权限违例 (-10004)。

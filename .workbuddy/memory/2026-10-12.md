### 关键踩坑：Cocos Creator 命令行构建在本机不可用（结论）

排查链（每一层都纠了一个错误猜测）：

1. **假象「Cocos CLI 不存在」**：`CocosCreator --help` 输出的是 node 的 usage。
   真因 = WorkBuddy 注入了 `ELECTRON_RUN_AS_NODE=1`，Electron 被当成纯 node 运行。
   → 必须 `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS` 调用，之后 CLI 才真正启动（打印 `init **** success`）。
2. **`init builder manager success` 后卡死**，日志 82 万行：
   全是 Sentry `sentry-minidump` 的 unhandled rejection —— **自激循环**：
   上报失败 → 抛新 rejection → 上报 → ……
3. 自激循环的起因是**我们传了 `--disable-gpu`**（为绕开第 4 点），而 Sentry 每次取 GPU 信息都会抛错。
   → 所以**不能靠「丢掉日志」解决**：日志丢弃后进程活着但零写盘。
4. **`--disable-gpu` 最初是为了绕**：GPU 进程崩溃 → `FATAL: GPU process isn't usable. Goodbye.`。
   崩溃根源 = `sandbox initialization failed: Operation not permitted`（Electron 派生不了 GPU / network 子进程）。
5. **脱离工具沙箱重跑，`sandbox initialization failed` 依旧** → 说明这是 **Chromium 自身的 macOS 沙箱/**本机环境限制，不是工具沙箱。

**结论：这台机器上 GUI 能构建（10-07 的 `web-desktop-001` 就是 GUI 产物），CLI 走不通 → 打包需要用户在 GUI 点一次。**
AppleScript 菜单自动化也不可用：`System Events` 报权限违例 (-10004)。

### 唯一拦路问题：Web 端根路径 `/` 404（#64 / PR #66，已合入 99d81be）
- 现象：公网 `GET /` → **404**，`GET /index.html` → 200，`/api/health` → 200
- 真因：`location / { try_files $uri =404; }` 只把 `$uri` 当**文件**命中；请求 `/` 时 `$uri` 是
  根**目录**，匹配不上就落 `=404`，index 模块没机会接手。当初「刻意不做 SPA 回落」是对的，但漏了目录分支
- 修法：`try_files $uri $uri/ =404;` —— 多出的 `$uri/` 把目录请求交回 `index index.html`；
  **不是** SPA 回落，缺失文件仍如实 404（实测 `/assets/nope.json` → 404）
- 闸：`tools/audit-deploy.cjs` 第 8 条「带 index 的静态站 try_files 必须含 `$uri/`」。
  故障注入（改回 `$uri =404`）确认 FAIL，还原 PASS；两份 nginx 都覆盖（admin 是 SPA 语义）
- **只换 nginx 配置的上线方式**：不必整份重发 —— `scp deploy/nginx-game.conf` 到
  `$DEPLOY_DIR/deploy/`，再 `docker exec olua-game-1 nginx -t && nginx -s reload`（bind mount 直通）

## #22 数据库自动定时备份（已合入，PR #73 / f0347e2）

目标：服务进程自己按 `BACKUP_INTERVAL_HOURS` 拉起同一份备份脚本，且把「最近一次成没成」露在系统信息页。
**不是**另写一份 VACUUM INTO——复用 `scripts/backup.cjs`（与 `make db-backup` 同一份），避免两套保留/校验口径漂移。

### 结构
- `BackupService`（`modules/system`）：封装子进程调用 + 记账（`lastOk/lastError/lastAttemptAt/lastSuccessAt/体积/耗时/份数`）。
  失败必然留痕 + 打 error 日志（「静默失败的备份 = 没有备份」）。
- `BackupSchedulerService`：周期触发（`unref` 不挡退出）；启动先跑一次；到点判定是纯函数
  `isBackupDue`，重启后从磁盘备份推断上次时间（不反复重备）。
- `SystemInfoDto.backup` 新字段；管理端系统信息页加「自动备份」卡片。
- 保留策略两道闸：`BACKUP_KEEP_COUNT`(默认7) / `BACKUP_RETENTION_DAYS`(默认30)，清理永远在「已有一份新备份」之后。

### 部署相关
- `server/Dockerfile` 运行镜像 `COPY scripts ./scripts`（否则容器里自动备份每次都失败，本机验不出）。
- `tools/audit-deploy.cjs` 加一条：运行镜像必须带备份脚本（故障注入：删 `COPY scripts` → FAIL，还原 → PASS）。

### 真 bug（顺手修）

### e2e 竞态（真问题，不是偶发）

## #20 玩家邮箱字段（已合入，PR #74 / 20bbcb4）

目标：`accounts` 加邮箱列（存量库 `ensureColumn`），后台可补录；管理端详情看/补；邮件页选账号自动带出。

### 关键决策
- **邮箱是个人信息，单列权限点 `account:email`**（ADMIN/SUPER 持有，VIEWER 不持有）——照「重置密码单列」的先例。
  没并进 `account:read`：只读观察员能看账号 ≠ 该看到一串玩家联系方式。**补录与查看共用同一道闸**（能改就能看）。
- **可见性用「字段不返回」实现**，不是脱敏：`AccountDto.from(row, includeEmail)` 默认 false，玩家侧登录/注册永远不填；
  观察员拿到的 JSON 里**根本没有 email 键**（响应形状本身说明「无权看」），比返回 null 更强的隐私信号。
- **唯一性**：`idx_accounts_email ON accounts(LOWER(email)) WHERE email IS NOT NULL`（部分唯一索引，未填写不限、大小写不敏感）。
  写路径双保险：service 先 `findByEmail(email, excludeId)` 预查给明确业务码 `ACCOUNT_EMAIL_EXISTS(10007)`，索引兜底防并发。
- **清空语义**：传空串 = 清空。所以 DTO **不能**加 `@IsEmail`（会把空串判成格式错误），格式校验放业务层 `isEmail` 只在非空时验。
- **发信兜底复用 `MAIL_ADDRESS_MISSING(50005)`**（该码语义本就是「既没传 to，账号上也没邮箱」）：`SendMailDto.to` 改可选，
  没填则取关联账号邮箱；注意邮件页的账号搜索走 `accountsApi.list`，无 `account:email` 的运营看不到邮箱 → 提示文案说
  「未获取到该账号的邮箱，请手动填写」（不能说「未填写」，那对无权限者是假话），服务端兜底不受影响。

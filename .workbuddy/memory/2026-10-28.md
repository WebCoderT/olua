## 修 cameraPriority 空指针（#443，PR #444，squash d103c7f）

**症状**：进游戏后鼠标一动就刷 `Cannot read properties of null (reading 'cameraPriority')`，每个指针事件刷一次，整个游戏输入全废（点按钮、按住走路、选中目标全不响应）。

**根因**：`ui/components/hud/QuestTracker.ts`（#396 任务追踪栏）是 `Node` 子类、自己就是按钮，但节点是代码拼的 HUD，从没走过 `UiHelper.createNode` → **自始至终没有 `UITransform`**。构造里先 `blockClickThrough(this)`（防呆发现没 UITransform，静默跳过 + 一条 warn），紧接着 `this.on(TOUCH_END)` 照旧注册 → 节点进了引擎指针监听列表 → `_sortPointerEventProcessorList` 读 `trans!.cameraPriority`（非空断言）→ 每帧崩。

**三条值得记的**：

1. **`dispatchEventTouch` 也调这段排序**（不只是鼠标事件）。所以「只注册 TOUCH_*」一样炸，而 `ensureMouseHitTestable` 只装在 `trackUiPress` / `bindMousePress` / `blockClickThrough` 三个**鼠标**入口上，管不到裸写的 `this.on(TOUCH_*)`。
2. **守卫静默跳过 = 把证据吞掉**：`blockClickThrough(this)` 那行让审计第 1 段判成「已登记」，修复前审计是 **PASS**。这类「防呆把红变成绿」比红本身危险 —— 判据不能问「有没有调防呆」，要问「它需要的前提在不在」。
3. **顺序也是 bug**：`blockClickThrough` 在 UITransform 之前 → 鼠标通道根本没登记 → PC 上点追踪栏穿透到世界，角色顺带走一步（比崩更难发现）。

**改法**：构造先 `addComponent(UITransform)`（命中区 = `layout.width` × `layout.rowHeight * layout.maxRows`，锚点 (0.5,1) 罩住最多三行）再 `blockClickThrough(this)`；空态 `this.active = false`（命中区常驻，留着活动会让点左侧空白也开面板）。

**防回归**：`tools/audit-ui-click-through.cjs` 加第 6 段 —— `class Xxx extends Node` 且在自己身上注册 `TOUCH_*/MOUSE_*` 的文件必须有 `addComponent(UITransform)`；UITransform 由助手施加的四个（applyAutoFightButtonStyle / applyBottomNavBarButtonStyle / applyShortcutKeyStyle / applyFlexColStyle）进白名单，并核对助手还在、文件里确实补过 UITransform 或 Sprite（Sprite 自带 `@requireComponent`）。第 5 段再加一条顺序接线（QuestTracker 里 UITransform 必须在 blockClickThrough 之前）。`test-quest.cjs` 补三条断言，`client/FAQ(.en).md` 补这个变体。

**顺带**：补 5 个漏提交的 `.meta`（仓库里 228 个 meta 都入库，缺了编辑器每次重新导入会换 UUID）。

**留下的想法**：给「在自己身上注册指针事件」收一个 `bindTap(node, handler)`（内部先要 UITransform、再登记两通道、顺序不可反），但那是 100+ 处重构，先不做。

## 画面随窗口自适应（#447，PR #448，squash c034e4f）

用户口径：「游戏画面尺寸自动适应窗口尺寸」。查下来**游戏内部早就自适应了**，缺的是最外面那层。

**三层职责（以后问「为什么不跟着窗口变」先按这个分）**：

1. **页面层 —— 画布元素本身多大**：引擎自带的 `templates/web-desktop/index.ejs` 把尺寸写死在内联样式
   （`<div id="GameDiv" cc_exact_fit_screen="false" style="width: <%= previewWidth %>px; …">`），
   还带 5px 黑边 + 阴影 + 页面上下两行文字。**这就是构建出来的页面里那个固定框**。
2. **设计分辨率层 —— 内部坐标怎么映射到像素**：`ScreenLayout.applyScreenPolicy()` → `setDesignResolutionSize(1624, 750, NO_BORDER)`，
   四个场景 `start()` 各调一次（项目设置里是宽高都勾 = SHOW_ALL 留黑边，运行时故意覆盖成铺满 —— 编辑器里 SHOW_ALL 更好摆版面）。
3. **场景布局层 —— 元素摆哪**：`getAnchoredPosition(尺寸, getVisibleSize(), 边, 边距)`；`Game.ts` 注册 `onWindowResize`
   重排四个 HUD + 引导遮罩；登录 / 选角整块舞台走 `getStageScale` 等比 contain。

**引擎 screen-adapter 的两种口径（3.8.7 `pal/screen-adapter/web`）**：

- `exactFitScreen = false` → `_windowType = SubFrame` → 画布尺寸取 **`#GameDiv` 的 `clientWidth/clientHeight`**（CSS 说了算）
- `exactFitScreen = true` → `BrowserWindow` → 直接用 `window.innerWidth/innerHeight`（CSS 都不看）

当前产物是 false，所以只要把 CSS 铺满就能跟着窗口走（`window-resize` → `_updateFrame` → `_resizeFrame()` → `_updateContainer()`）。
两种口径下 `_resizeFrame` 都会重设 canvas 像素，所以 CSS 方案在两种设置下都成立。

**改法**：`client/build-templates/web-desktop/index.ejs` + `style.css`（自定义构建模板 = 构建时把
`build-templates/<平台>/` 下的同名文件 `copySync` 覆盖到产物目录，其它模板文件仍用引擎默认）。
`html` / `body` / `#GameDiv` / `#Cocos3dGameContainer` / `#GameCanvas` 全 100%，`overflow: hidden`
（滚动条会让 clientWidth 比窗口小，`getVisibleSize` 的口径就对不上），保留 `--safe-*` 变量（引擎 `safeAreaEdge` 要读）。

**为什么不换 `web-mobile`**：它天生铺满，但模板给 canvas 挂了 `oncontextmenu="event.preventDefault()"` ——
右键寻路 / 传送会被吃掉。覆盖桌面模板比换平台便宜。

**限制**：模板只在**构建时**生效（GUI 打包），预览器用的是它自己的页面 + 按「全屏预览」开关设 `exactFitScreen`，
所以在编辑器里拖预览窗口不一定能验出来 —— 验证要看构建产物。

**防回归**：`client/tools/test-scene-stage.cjs` 加 F 组 7 条（模板存在 / `#GameDiv` 不写死宽高 / `cocosTemplate`
注入还在 / canvas 不挂 oncontextmenu / 三层 100% / 无滚动条 / 安全区变量在）。`client/FAQ(.en).md` 新增「屏幕适配」一节。

## 登录/选角的飘字看不见（#451，PR #452，squash a391017）

用户报：注册时报「该账号已被注册」，**控制台能看到、界面一个字都没有**。

**根因不是「没提示」，是「提示看不见」两层的第二层**：

1. 第一层（上一轮修过）：飘字挂 `LayerManager.UILayer`，而那个容器只有游戏场景 `initLayer` 才建 ——
   登录/选角挂到了一个不在场景树里的静态节点上，什么都不渲染。修法：`mountFloatingTip` 按
   「容器是否在场景里」判断，非游戏场景改挂场景根。
2. 第二层（这次）：**挂载点对了不等于位置对了**。飘字坐标以**屏幕中心为原点**设计
   （`configs/layout/hud.tipsLayout`：起点 `(0,0)`、上浮到 `(0, risePositionY)`），游戏内成立是因为
   `UILayer` 被 `LayerManager.move` 搬到角色位置（= 屏幕中心）。挂在**场景根**时局部 `(0,0)` 是**世界原点**，
   而登录/选角的 UI 相机是 `Canvas` 的子节点、世界位置在 `Canvas` 中心（1624×750 → 约 `(812, 375)`）——
   飘字正好压在**屏幕左下角顶点**上，300×20 / 字号 12 的 Label 大半个在屏外。

**改法**：非游戏场景挂**场景里的 `Canvas` 节点**（`scene.children.find((c) => !!c.getComponent(Canvas)) ?? scene`）。
Canvas 原点即屏幕中心，且 `alignCanvasWithScreen` 随窗口重设自身位置与尺寸（窗口缩放后仍居中，不用自己跟 resize）。
顺带 `tip.layer = host.layer`：新建节点恒为 `DEFAULT`，之前能看见只是碰巧相机 visibility 里带着它。

**排查手法（以后复用）**：看不清渲染位置时直接读 `.scene` 文件 —— `cc.Camera._visibility` 拆位判断图层
（登录/选角 = 1108344832 = `DEFAULT | UI_2D | UI_3D`），再看 `Camera` 节点的 `_parent` 是不是 `Canvas`，
就能算出「局部 (0,0) 落在屏幕哪个角」。

**判据**：`test-client-net.cjs` / `test-dialog-top.cjs` 改成断言挂 `Canvas` + 图层跟随，并加一条
**反向断言**（不许退回直接挂场景根）；`make ci` 全绿、`make audit` 11 项全绿、`make client-test` 45/5 基线不变。

**注意**：模板级/渲染级改动都要**重新构建**才生效（和 #447 一样），编辑器预览器里验不出来。

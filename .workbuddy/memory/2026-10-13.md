## 排查「本地 Cocos 预览登录失败」（进行中）

现象：`[net] 请求失败：network code=-1 status=0` → 按 `HttpClient` 的映射，`kind=network` **只**来自
`xhr.onerror`（`ontimeout` 是 `Timeout`，解析失败算 `Http`），即**一个字节响应都没收到**。

**已逐项排除（全部实测）**
- 服务端健康：3100 上的进程父进程是 `npm run dev`（用户自己的），打开的正是正式库 `server/data/olua.db`；
  用真实账号 POST `/api/auth/login` 返回 `10003 账号或密码错误` → 账号存在、库正确。

- 连通性：127.0.0.1 / ::1 / localhost / 局域网 IP 全部 200；`/etc/hosts` 里 localhost 同时映射 v4 与 v6。
- CORS：`CORS_ORIGINS=*` → `enableCors({origin: true})` 全反射，实际请求与 OPTIONS 预检都正确放行。
- 代理：macOS 系统代理 / PAC **关闭**，shell profile 无代理导出。

2. **看进程是谁起的**：`ps -p <pid> -o pid,ppid,etime,command` 看 PPID —— 本例 PPID 是 `npm run dev`，

3. **不用 devtools 取客户端内部状态**：诊断塞进 `ApiError` 的 `serverMessage` —— `describe()` 优先

## 备份 e2e 的两条 flake（#86 PR #87、#88 PR #89，均已合入）

PR #85 的 CI 连红两次，都跟它自身（只改 `docs/resume.md`）无关，是被 `test/backup.cjs` 的两条
**本机恒绿 / CI 偶红**断言拦下的。两条根因不同，都值得记住：

1. **#86 取整**：断言要求 `lastSuccessAt === lastAttemptAt`。但前者会被 `syncFromDisk()` 用
   **备份文件名里的时间戳（按秒取整）**覆盖，后者是 `runOnce()` 入口的毫秒值 → 跨秒时差几百毫秒。
   模拟算出：脚本耗时 δ 时，一整秒里只有 δ/1000 的起点会不等，最大差值 = δ（δ=6ms 时正是 CI 报的 6ms）。
   改成窗口断言（5 秒）。
2. **#88 半截状态（更深）**：轮询等的是「`lastFile` 变了」，但 `lastFile`/`lastSuccessAt` 每次读快照
   都会被 `syncFromDisk()` **按磁盘重写**，而本轮记账要等 `await callScript()` 之后才写
   （`backup.service.ts:145` → `:146-148`）→ 轮询落在 await 缝里会读到「文件已新、记账还旧」的自相矛盾快照。
   **改法等的是 `lastAttemptAt` 往前走**：它与 `lastSuccessAt`/`lastFile` 在 :146-148 **同一个同步块里
   连着写**（中间没有 await），等到它变就一定整体写完了，快照必然自洽。
   断言也随之改成比**单调性**（比上一轮晚 + 不早于本轮尝试），不再依赖差值大小 —— 压窗口只是把 flake 换地方。

**教训（可复用）**：
- **修补 e2e flake 时别只看现象**：第一版（窗口断言）修掉了「差几毫秒」，第二次 CI 又红出「差一个间隔」，
  逼出了真正的根因（观测方式错了）。修完要追问「还有没有别的缝」。
- **算差值上界时别漏项**：我一开始算成 `drift ∈ [0, δ)`，卡了半天；实际半截状态下
  `lastSuccessAt = floor((上一轮尝试 + 10800 + δ)/1000)*1000`，向下取整会减掉 0~999ms，
  所以 `drift ∈ [9801, 10800+δ)` —— 实测的 10251 正好落在里面，这才对上模型。
- **`waitFor`（`test/backup.cjs:218`）超时是静默返回最后一次结果、不抛错** → 超时会变成下游一条
  莫名其妙的断言失败。所以「时刻在往后走」这类断言要留着，它不是被等待条件保证的废话，它接住了超时。
- **取证据优于推理**：加临时日志把两份状态（`first` / `second`）整个 JSON 打出来跑一次，
  真实值一眼就能否决/印证猜测。本机那份：`attempt === success`、`second.attempt − first.attempt = 10804ms`。

## #93 derived 出口（PR #97）

- **只挂详情不挂列表**：新建 `AdminRoleDetailDto extends AdminRoleDto`，只有 detail/patch/select 用它。
  列表页**压根不展示战斗力**（实测：管理端列是 角色名/账号/职业/性别/等级/状态/修订/更新时间，

- **`mismatch` 语义要写在代码里**：它表示**口径不一致，不等于作弊**（升级与重算之间存档、配置漂移、
  存档留着旧装备 id 都会命中）。所以**只记不拦**、不纠正存档。
- **`mismatch` 重算不出来时恒 false，另配 `comparable`** ——「没比成」与「一致」是两回事，
  不能都塞进 false 里让调用方猜。（同 `role-attributes` 里「静默给 0 会被读成算过了、结果就是 0」。）
- **比对用 1e-6 容差**而非严格相等：`combat` 含乘法，两端求和顺序不同时严格相等会把「口径其实一致」
  误报成不一致；篡改动辄改几个数量级，容差完全兜得住。
- **e2e 的锚**：拿服务端刚算出的 `combat`/`maxHp` **原样上报** → `mismatch` 必须 false。
  没有这条，其他「不一致」的断言可能只是服务端自己算错了。

## #107 一次被工具骗了的「实测」（已关闭，非 bug）

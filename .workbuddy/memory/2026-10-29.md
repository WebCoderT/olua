## 顺带挖出的真 bug：babel loose 展开 Map/Set 迭代器（#471，同 PR）

**现象**：私聊选人页永远多一行空名字的幽灵行，节点名 `chat_pick_row_undefined`。
**根因不在几何**：`[...map.values()]` 被 babel loose 转成 `[].concat(map.values())`，concat **不展开非数组** →
返回值是 `[MapIterator]`，调用方拿到的每条都不是数据。**tsc 全绿、源码读起来也对，只有产物里才错。**

六处同写法全中（都是清理/取表路径，静默失效）：

| 位置 | 后果 |
| --- | --- |
| `ChatStore.privatePeers()` | 幽灵行（本症状） |
| `OtherPlayerManager` 全量帧重建 / `reset()` | `remove(迭代器)` 一个都没删 → 换图残留幽灵玩家 |
| `MonsterManager.cleanupStatusEffects()` | 循环体一次都不执行 → 状态特效永不过期 |
| `QuestNpcMarks.reset()` | 任务 NPC 标记清不掉 |
| `configs/quest.allQuests()` | 任务「可接」列表整块坏 |

**守卫**：`tools/audit-iterator-spread.cjs`（`make audit` 循环自动带上 → 12 项）：
A 展开 `.keys()/.values()/.entries()` 硬错误；B 展开 `new Map()/new Set()` 硬错误；
C 展开**裸字段**（静态看不出数组还是 Map）必须登记 `tools/iterator-spread-allowlist.json` 并写原因。
**教训**：判据要落在「写法」上，别落在「这次跑起来对不对」上 —— 这类错只有产物才暴露。

- **几何断言要用真实配置算**，不抄常量：`prepare()` 沙箱把 `configs/layout/*.ts` 编出来，断言直接读 `roleAttributeListLayout` /
  `chatDialogLayout` —— 改配置改错了先在单测红，而不是等真机截图。
- **新审计/新单测会牵动文档数字**：审计 11→12、单测 50→51、回归守卫 62→63，`audit-doc-numbers` 直接给出行号；

## 行内文字越界（#477，PR #478）

**症状**：任务弹窗「可接」页两行只有底板、看不到任务名；队伍/排行榜行同构。
**根因**：`UiHelper.createLabel` 是 `CLAMP` + 左对齐 → 文字从**文本框左缘**起排，而布局里给的是**中心 x**。
行 552 宽（半窗 276）时 `nameX=−180 / 宽 360` 的左缘是 −360，跑出行外 84px，被 ScrollView 遮罩裁掉。
**为什么一路漏网**：tsc 不报、数据 e2e 不报（节点和文字都在、dump 得到）、文字重叠审计也不报（被裁的压根没渲染）——
只有「拿配置算 bbox」能拦。守点 = `client/tools/test-dialog-row-bounds.cjs`（五处行：名字/次行/正文在行内、名字与正文不重叠、
文字不与动作按钮相交、遮罩比行宽；全部用真实配置算）。

四处行统一「bbox 左缘 = 行左缘 + 16」：任务 −180→−80 / 队伍成员按钮 196→184、252→244 且名 −180→−100 / 邀请行 −180→−100 / 排行榜 −186→−112。

**真机截图还抓出同源两处**：
- 聊天消息行 `nameX −130→−118`、正文 `textX 45→60 / 宽 280→236`（名字 −178..−58 与正文 −58..178 衔接）；
- **聊天输入条**：`createInputBox` 把字号写死 24，26 高的窄框里 24 号字形顶出上下边、贴到窗体金边，且没有底板 →
  看起来像「飘在窗底的一行大字」。给 `createInputBox` 加可选 `fontSize`（默认 24、其余调用点不变），聊天用 13 + 补底板（颜色/圆角进配置）。
  **教训**：组件默认值只对一种尺寸成立时（这里 24 号只配登录页 40 高的条），窄容器必须显式参数化，别指望调用方记得改。

## 第三轮：真机验证循环（#491 → #499，四条修复 + 一条新发现）

### #491 商城卡片没有价格 + 组队空态自相矛盾（PR #492，82e74ed）

- **商城卡片只画名称 / 品质 / 等级，没有价格** —— 玩家不知道买的是什么价、也判断不出值不值。
  加 `mall_card_price_<id>`（金色、右对齐），文案 `mall_price: "{value} 绑元"`：
  **光秃数字会被读成数量**（「1」到底是 1 个还是 1 元）。`reserve` 50 是算出来的
  （4 位数字 22 + 空格 5 + 2 个全角「绑元」20 = 47，留 3 余量），品质行要让出这块宽度
  并 `SHRINK` 防压价格。踩坑：用 perl 批量改正则时把 `\{`、`\(` 的转义剥掉了 → 断言失配，
  改用 Edit 重写；BSD `sed -i ''` 在本环境一直失效。
- **组队面板没队伍时**：副标题「（队伍成员会显示在这里）」+ 顶部「你还没有队伍」= 两句互相打脸。
  新增 `noPartyEmpty`，`memberEmpty` 的语义收窄成「在队里但只有自己」。
- 守点：`test-mall`（价格接线 + 由 layout **现算**的几何自洽）、`test-social`
  （三句空态文案两两不同、`!snapshot` 分支不得渲染 `memberEmpty`）。

### #493 进图早于实时连接 → 玩家「不在世界里」（PR #494，0a1ec2f）

真 bug，从「聊天发不出去」倒查出来的：

- **现象**：聊天点发送，不报错也不回显（WS 抓帧看到服务端回「还没进入世界，无法发言」）；
  同时没有互见、怪物在本地刷。
- **根因**：`RealtimeClient.start()` 是异步的（取票 + 握手），建图流程先跑完 →
  `MonsterAreaSpawner.spawnAll` 里「只有 active 才登记图 id」→ `lastJoin` 永远为空 →
  服务端 presence 里根本没有这个人。三个症状是同一个根。
- **修法**：`spawnAll` **无条件** `sendWorldJoin`（内部先记 `lastJoin` 再发；未连接是 no-op），
  本地刷怪仍看 `active`；`welcome` 分支无条件 `resendWorldJoin()`（没有 lastJoin 是无操作）。
- 守点：`test-realtime` M 段（未连接时登记不建连 → 首连 welcome 必须补发同一条 worldJoin
  且 `reconnected === false`）+ 故障注入（改回 `if (reconnected)` 立刻 2 红）。
- **教训**：「异步初始化」与「同步建图」的竞态，症状会伪装成完全无关的三处功能同时坏。

### #495 服务端拒绝玩家看不见（PR #496，d020734）

- 服务端所有拒绝都是 `{type:"error", data:{code,message}}`（`party.service.fail()` /
  `chat.service.reject()`），而 `RealtimeClient.onFrame` 处理了 settle / world / monster-ai /
  players / picked / chat / quest / party / partyInvite / expGain —— **唯独没有 error**。
  于是聊天限频、组队失败、参数不合法全部静默：点完按钮什么都不发生，只能反复点。
- 修：`RealtimeClient` 加 `error` 分支 → `CombatChannel.dispatchServerError`
  （形状校验：没有 `message` 只打日志、不弹空提示；没接线时 `console.warn` 而非静默）→
  组合根 `createTipText(error.message)` + `teardown` 摘回调。
- 真机验证用**聊天限频**触发（单账号 10s 窗口 5 条，第 6 条被拒）：前 5 条正常回显、
  第 6 条飘「发言太频繁，稍后再试」且精确匹配。**踩坑**：本想用超长消息触发，
  结果 EditBox 有前置长度限制（130 字只收下 20 字）→ 发送成功、根本没走到服务端。
  测服务端拒绝要用**客户端拦不住的口子**。
- 顺带修：私聊**会话页**空态复用选人页文案（「先点选人挑一个对象」，而对象已经挑好了）。
- 守点：`test-realtime` N 段（error 帧 → 回调收到 `{code,message}`；坏形状不弹；连接状态不变）、
  `test-chat`（会话页空态独立、两句互不相同、不含「选人」）。

### #497 组队邀请不校验等级（PR #499，765e8fd）

- 客户端入口锁 10 级（`bottomNav.ts` 的 `group.openLevel`，低等级点入口只提示
  「组队功能需要在10级后开放」），而服务端 `invite()` 的校验链是
  `self → exists → 拉黑 → 在线 → 已在队 → 重复邀请` —— **一行等级判断都没有**。
  改包就能邀请 1 级号，对方收到邀请后打不开面板，邀请永久悬空。
- 修：`PARTY_MIN_LEVEL`（默认 10，`PARTY_MIN_LEVEL` env 可覆盖，脏值回落 ——
  门槛读错不该让「所有人都不能组队」）；`invite()` 两侧都卡
  （发起人「需要 10 级才能组队」/ 目标「对方还没到 10 级（当前 N 级），暂时不能组队」，同码 50144）；
  新增 `RolesService.levelOf(roleId)`（只读 `roles.level` 索引列，不解析存档 JSON）。
  位置放在「在线」之后（不在线先报不在线，更中性也更常见）、「已在队」之前。
- **防漂移**：`audit-shared-data` 新增一段比 `PARTY_MIN_LEVEL_DEFAULT` = 客户端组队入口
  `openLevel`，并要求 `configuration.ts` 的默认值引用常量而不是再写一份字面量。
  （这是「同一个数两端各写一份」的第三种破法，前两种是角色上限和实时关闭码。）
- **e2e 79 → 87**：主进程 `PARTY_MIN_LEVEL=1` 保住原有语义（party 套全是 1 级角色，
  经验分成那组要「1 级打 1 级怪」才凑得出等级差 0 的干净数值），门槛本身**另起一台默认配置的
  独立进程**验（第十一组 5 条：低等级发起被拒 / 被拒的邀请不送达 / 邀请低等级目标被拒 /
  够级的照常组队）；第十组补门槛脏值 3 条。`startServer(dbPath, extraEnv)` 支持逐项覆盖。
- 真机：A（10 级）在邀请页点「邀请」B（3 级）→ 屏幕出现「对方还没到 10 级（当前 3 级），
  暂时不能组队」，B 侧 0 条邀请。

### #498 乐观 UI 撤回（✓ PR #502）

## 装备/武器位置对齐：内观与外观改按帧内容 bbox 算（#505 / PR #506，d3a75a8）

**用户诉求**：「把所有背包内的装备和所有的武器，位置全部对齐，包含内观和外观」。

**根因（两条，别只修第二条）**：

1. **位置是手写的绝对坐标**。`configs/equipments.ts` 每把武器一组 `inPosition` + 8 向 `outPositions`，
   而素材画布与裁剪留白各件不同：武器外观画布 245×234 ~ 570×608、身体外观 142×112 ~ 480×480、
   武器内观 212×375 ~ 420×420、身体内观 100×100 ~ 400×400；更狠的是**衣服本体内容尺寸 77×86 ~ 252×206
   （差 3 倍），而且这 12 件全在掉落表里** —— 同一组数字只对作者当初那具身体成立，换衣服必飘。
   20 把武器 = 20 组互不相干的手调数字，这本身就该是危险信号。
2. **片段里混进 2×2 占位空帧**。`isSolidFrame` 旧判据「边长 > 1」只挡 1×1；普查 8513 个空帧后
   发现武器还有 **184 个 2×2**（衣服全是 1×1），它们被切进动画片段 → **武器每轮循环消失一半时间**。
   内观路径 `playLoopAtlasWithDuration` 更彻底：**完全不过滤空帧**（衣服内观图集有 1×1 空帧）。

**方案（算法唯一来源 `configs/equipAlign.ts`，纯函数）**：
握持点 = 身体内容 bbox 横向 `0.52 × 半宽`、纵向 `0.52 × 高`（角色右手；朝左下等方向换边）；
外观把**武器内容中心**放到握持点；内观再缩放到身体内容高度的 `1.15` 倍。
几何字段（`inPosition` / `outPositions`）**退化为逐件微调，默认 0** —— 20 把武器全部归零。

**三个必须记住的实现细节**：

- **内容中心 ≠ 节点中心**：`SpriteFrame.rect` 是裁剪后的图块、`SpriteFrame.offset` 是裁剪偏移
  （TexturePacker 的 `spriteOffset` 与引擎 `offset` **同号同值、y 向上**，真机实测确认），
  所以「把 X 摆到 Y」一律走 `GameUiHelper.spriteContentBox()`，用节点框会随留白漂移。
- **衣服节点可能带缩放**：`cloth_1` 的 `inScaleX/Y = 1.3`，身体 bbox 必须乘节点缩放
  （内观缩放期望值因此从 0.624 变成 0.812）—— 少乘这一下，武器偏一半。
- **「素材就绪」回调里帧还读不到**：帧要下一帧才落到 Sprite 上，回调里 `spriteFrame` 常为 null
  或还是占位空帧 → 按 `EQUIP_ALIGN.alignRetryDelayMs / alignRetryTimes`（50ms × 20）重试；
  占位帧判据与切片侧同口径（面积）。

**判据要按面积，不能按边长**（这条是通用的）：占位空帧实际尺寸是 1×1 与 2×2，
按边长 `> 1` 漏掉 2×2、按边长 `> 2` 又会误伤 **2×174** 这种薄武器帧；
`BLANK_FRAME_MAX_AREA = 4`（`configs/animation.ts`）两头都成立。特效里的 3×3/4×4 是真实小图（42 个）不受影响。

**验证管线（省时间的关键）**：离线用 PIL + plistlib 按裁剪语义合成「身体 + 武器」PNG，
先与真机截图比对确认合成器语义正确，再批量出 20 武器 × 8 方向拼版图看错位分布 ——
比重建客户端快两个数量级。最后才上真机：`equip-align-check.cjs` 逐用例改存档（API PUT）→ 重登 →
读 `cloth` / `weapon` 节点的 `frame.rect/offset` 断言「武器内容中心 = 握持点」±6px（容动画帧间裁剪差）。
**8 组用例**（`cloth_1` / `cloth_10` / `cloth_14` / `cloth_26` × 短剑 / 长剑 / 长柄）场景与内观全过、控制台 0 报错。

**坑**：

- `checkAligned` 的期望值也要乘衣服缩放 —— 判据与被测代码**各错一半**时照样全绿（这次差点又踩）。
- 用例 id 写错（`cloth_5` 不存在，带 1.3 缩放的是 `cloth_1`）时，客户端安静回落到默认身体、
  内观连 `cloth_in_show` 节点都不建 —— 读不到节点就该怀疑「这件装备到底存不存在」。
- `GameUiHelper.ts` 是 **CRLF** 文件：Edit 工具会整文件改成 LF，产生 5355 行假 diff，
  提交前必须 `perl -pi -e 's/\r?\n/\r\n/'` 还原并复查 `git diff --numstat`。
- `client/tools/align-equipment.py`（早版静态计算器）与 `tools/dump-equipment-geometry.cjs`
  （一次性几何导出）都没入库，用完即删 —— 静态重算只对参考身体成立，正是被否决的方案。

**数字**：单测 55 → **56**（新增 `test-equip-align`）、回归守卫 67 → **68**；接口/表/仓储/e2e 均不变（纯客户端）。

## 装备对齐几何「保存即生效」（#513 / PR #514，2cd796a）

用户要的是：工作台里把衣服 / 武器 / 裸模位置拖好，**点保存就落库，客户端重新加载就能看到效果**，
不再走「导出 JSON → 项目根跑脚本写回源码 → 重打 3.1G 包」。

**核心矛盾**：客户端几何的唯一来源是打包进包的 `configs/*.ts`，而快照纪律白纸黑字写着
「资源路径 / 几何 / AI 参数一律不覆写」。要「保存即生效」必须开一条通路。

**解法**：单开一个接口 `GET /game-config/equip-align`（33 行），**不塞进快照** ——
快照那条注释是资产（资源路径确实不能被运营改坏），塞进去它立刻变成谎话；
同时在 `apply-snapshot.ts` 里开**唯一一处显式例外**，打破面严格限制在
「外观缩放 + 8 方向位置 + `outManual`」，资源路径一个都不动（守点：单测断言 `target.out = ` 不存在）。

**存储**：新表 `equip_aligns`（43 → 44 张），`id / out_scale / out_positions / out_manual / updated_by / updated_at`。
三条口径：
1. **没有行 = 用客户端配置值** → 「重置」就是删行（幂等，不存默认值副本）；
2. **只校验 id 形态**（`cloth:*` / `weapon:*` / `role:1|2`），不查存在性 —— 装备清单在客户端配置里，
   服务端硬编会漂移，也会把「新增一件衣服」变成发布依赖；
3. **不做内观几何**（`inScale` / `inPosition`）：页面根本不调它们，内观是运行时现算，
   不做「存了没人读」的字段（先做进 DTO 又全砍掉，这是这一刀唯一一次返工）。

**三个坑（都写进 MEMORY 了）**：
- **覆写前必须还原出厂值**：进游戏可以重进，不还原的话「管理端把某件重置了」在重进后仍显示上次位置 ——
  删行与「从没调过」必须长得一模一样。为此记 `alignBaselines`（引用 → 出厂值，`outPositions` 深拷贝）。
- **几何要每次进图都拉**：快照十几张表只拉一次没问题，但几何的验收动作是「退回选角再进图」（场景重载，
  JS 上下文不重来）。原来 `if (loaded) return` 会短路掉，症状是「保存没生效」。33 行的小接口不值得省。
  顺带发现原注释写着「重进即见新值」而代码刚好相反 —— 自相矛盾的注释会被下一个人当成事实。
- **变体共享的是数组引用**：`buildEquipmentMap` 用 `{ ...base }` 展开 15 个变体，`outScale` / `outManual`
  是各自的原语，但 `outPositions` 共享同一个数组 → 按基础件命中全部变体必须**逐个对象赋值**
  （原地写数组才会自动传开，那样就没有回落基线可用了）。

**页面三份真相**：`localStorage 草稿` > `服务端已保存` > `catalog.json 出厂值`。
少了中间层，第二次进页面会把上次调好的位置当成没调过显示。保存成功后用服务端回包覆盖本地几何
（2 位小数往返一次，避免「刚存完又显示未保存」）。

**顺带修既有缺陷**：审计查询的目标类型枚举停在 5 种（`equipment` / `title` / `guild` 筛不出来）→
从 `@AuditTarget` 的 `AUDIT_TARGET_TYPES` 派生，查询侧与写入侧共用一份（e2e 第一轮就是这条红的）。

**守点**：`e2e-equip-align.cjs` 67 条（空表 / 保存即下发 / 幂等 / 边界 / 权限与审计 / 文档契约）+
`test-equip-align-apply.cjs` 27 条（15 变体命中 / 资源路径不动 / 裸模按性别 / 删行回出厂 / 坏行只丢自己 /
幂等 / 接线源码断言）。门禁：`make ci` 全绿（23 套 e2e）、client-check 0 错、client-test 52/5（老基线）、
`make audit` 13 项全过。数字连坐：158 接口 / 131 路径 / 237 模型 / 44 表 / 36 仓储 / e2e 2338（23 套）/
单测 57 / 守卫 70。

**没验的部分**：真机视觉（要起 `make server-dev` + `admin npm run dev` + Cocos 预览；用户当时把两个
后台服务停了并要求不要重启）。功能路径已由 e2e（保存 → 玩家侧拿到同一份）与单测（拿到 → 覆写到全部变体）覆盖。

## 聊天窗改常驻左下角（#469 → PR #472，761bfc8）

用户口径：*「其他网游都是放在屏幕左下角，并且切换频道等功能都是在聊天窗口里进行的」* —— 原来的 600×560 居中大弹窗
是「打开一个面板」，不是「一直看得到的那块」。

- **布局**：440×280，`dock: bottom-left`（margin 24/205）。位置**算过邻居**：摇杆顶到 `y=-185`、任务追踪栏三行到 `y=124`，
  本窗占 `-170~110`，两头都不叠 —— 停靠位置不能只写"左下角"，必须量邻居。
- **壳体**：新增 `GameUiHelper.createChatBox()`（半透明深底 + 金色细边 + 整体 `blockClickThrough`），
  刻意不用 `createDialog`：常驻窗不要 ornate 大框/标题栏/拖拽。
- **自动开两条路**：进游戏（引导不在进行中）→ 开；引导本次会话**走完/跳过**的瞬间 → 补开（`GuideStore.onChange`，
  离场必须退订，否则回调指向已销毁的 bottomBar）。`open(auto=true)` **只开不关且不推进引导** ——
  「别一个人玩」那步得玩家自己点开，程序代开不算学会。
- **缩放**：`ChatDialog.refreshDock()` + 组合根 `onWindowResize` 里调，关着时是 no-op。
- **私聊选人行**：原来沿用消息行的窄列（名字 120 宽、左距行缘 4px），`createLabel` 是 CLAMP + 左对齐 → 长名字被裁；
  改 `pickRow`（名字列 220、按钮挪行尾），几何进配置、颜色复用 `row`。

## 顺带挖出的真 bug：babel loose 展开 Map/Set 迭代器（#471，同 PR）

**现象**：私聊选人页永远多一行空名字的幽灵行，节点名 `chat_pick_row_undefined`。
**根因不在几何**：`[...map.values()]` 被 babel loose 转成 `[].concat(map.values())`，concat **不展开非数组** →
返回值是 `[MapIterator]`，调用方拿到的每条都不是数据。**tsc 全绿、源码读起来也对，只有产物里才错。**

六处同写法全中（都是清理/取表路径，静默失效）：

| 位置 | 后果 |
| --- | --- |
| `ChatStore.privatePeers()` | 幽灵行（本症状） |
| `OtherPlayerManager` 全量帧重建 / `reset()` | `remove(迭代器)` 一个都没删 → 换图残留幽灵玩家 |
| `MonsterManager.cleanupStatusEffects()` | 循环体一次都不执行 → 状态特效永不过期 |
| `QuestNpcMarks.reset()` | 任务 NPC 标记清不掉 |
| `configs/quest.allQuests()` | 任务「可接」列表整块坏 |

**守卫**：`tools/audit-iterator-spread.cjs`（`make audit` 循环自动带上 → 12 项）：
A 展开 `.keys()/.values()/.entries()` 硬错误；B 展开 `new Map()/new Set()` 硬错误；
C 展开**裸字段**（静态看不出数组还是 Map）必须登记 `tools/iterator-spread-allowlist.json` 并写原因。
**教训**：判据要落在「写法」上，别落在「这次跑起来对不对」上 —— 这类错只有产物才暴露。

## 方法沉淀

- **UI 排版问题的判据做成"量"的**：`ui-audit.cjs`（在场文本两两比对）+ `ui-audit-dialogs.cjs`（按弹窗字段 open → 文本快照 diff
  → 报重叠百分比）。本次 80%/30% 两对就是它给的，比肉眼靠谱；**空分节标题也会被它抓出来**（正是 80% 那对）。
- **几何断言要用真实配置算**，不抄常量：`prepare()` 沙箱把 `configs/layout/*.ts` 编出来，断言直接读 `roleAttributeListLayout` /
  `chatDialogLayout` —— 改配置改错了先在单测红，而不是等真机截图。
- **新审计/新单测会牵动文档数字**：审计 11→12、单测 50→51、回归守卫 62→63，`audit-doc-numbers` 直接给出行号；
  中英双语要同步（`audit-docs-en` 会抓 "中文多 1 次 / 英文多 1 次"）—— 顺带发现 `FAQ.en` 里「37 test suites」这种**过期数字**。
- **Cocos CLI 构建的沙箱坑**：`--enable-unsafe-swiftshader` 之类不管用，必须 `--no-sandbox` **且**脱沙箱执行，
  否则 7 秒 SIGTRAP（exit 133）而产物时间戳不动 —— 判断构建成功看 `client/build/web-desktop/index.html` 的 mtime，不看 exit code（本次成功的几次 exit 都是 36）。

## 行内文字越界（#477，PR #478）

**症状**：任务弹窗「可接」页两行只有底板、看不到任务名；队伍/排行榜行同构。
**根因**：`UiHelper.createLabel` 是 `CLAMP` + 左对齐 → 文字从**文本框左缘**起排，而布局里给的是**中心 x**。
行 552 宽（半窗 276）时 `nameX=−180 / 宽 360` 的左缘是 −360，跑出行外 84px，被 ScrollView 遮罩裁掉。
**为什么一路漏网**：tsc 不报、数据 e2e 不报（节点和文字都在、dump 得到）、文字重叠审计也不报（被裁的压根没渲染）——
只有「拿配置算 bbox」能拦。守点 = `client/tools/test-dialog-row-bounds.cjs`（五处行：名字/次行/正文在行内、名字与正文不重叠、
文字不与动作按钮相交、遮罩比行宽；全部用真实配置算）。

四处行统一「bbox 左缘 = 行左缘 + 16」：任务 −180→−80 / 队伍成员按钮 196→184、252→244 且名 −180→−100 / 邀请行 −180→−100 / 排行榜 −186→−112。

**真机截图还抓出同源两处**：
- 聊天消息行 `nameX −130→−118`、正文 `textX 45→60 / 宽 280→236`（名字 −178..−58 与正文 −58..178 衔接）；
- **聊天输入条**：`createInputBox` 把字号写死 24，26 高的窄框里 24 号字形顶出上下边、贴到窗体金边，且没有底板 →
  看起来像「飘在窗底的一行大字」。给 `createInputBox` 加可选 `fontSize`（默认 24、其余调用点不变），聊天用 13 + 补底板（颜色/圆角进配置）。
  **教训**：组件默认值只对一种尺寸成立时（这里 24 号只配登录页 40 高的条），窄容器必须显式参数化，别指望调用方记得改。

## 第二轮 UI 修复（继续「直到系统完善」的验证循环）

四个真缺陷，都是**真机截图**看出来的（单测/审计/数据 e2e 全绿也不代表画面对）：

### #481 技能说明被单行截断
`createSkillItem` 里说明是 `createLabel(…, Size(205,15))` —— `createLabel` 默认**单行 CLAMP**，
205 宽 × 10 号字一行只 ~20 字，而 `skill-data.ts` 里说明 40~72 字：后半句直接不画，也没有省略号。
改成按宽度换行（`enableWrapText` + 行高 14）+ 行高按估算行数自适应，上限 4 行；
行内数字全进 `skillListDialogLayout.row`；行数用纯函数 `TextLayout.wrappedLineCount`
（中文 1 字宽 / ASCII 0.55 字宽，**宁可多算半行留白、不能少算切字**）。
**顺带**：行高从固定 50 变成 40~82 后，行内水平 Layout 会把图标垂直居中 → 图标浮在行中间、
看着像属于上一条；改成手动摆放（图标与说明列都贴行顶）。Layout 的 `alignVertical` 是布尔、不给顶对齐。

### #483 成就名称/描述被行左缘裁掉 + **通用扫描守卫**
`achievementDialogLayout.row`：行 480（半宽 240），`namePosition.x = −150` / 宽 280 → bbox 左缘 −290，
越界 50px，真机上只剩名称最后一个字。改 x = −84（bbox −224..56）。
守点不再逐弹窗手写：`client/tools/test-layout-row-bbox.cjs` 遍历 `configs/layout/*.ts` +
`configs/{achievement,quest,mail,social}.ts` 全部导出，凡「有 size（宽 ≥ 100）的对象里带
`xxxX/xxxSize` 或 `xxxPosition/xxxSize`」的行内文字一律算 bbox —— 扫 14 个模块，除成就外全干净
（反证 #477 修到位）。**扫描器第一版把 require 异常吞了 → 「扫了 0 个模块」也全绿**；
现在加载失败直接判红（假绿比漏检更危险）。

### #485 三个入口点了没反应
`BottomBar` 的 handlers 表没有 `friend`/`horse`/`config`（原注释还写着「未补则点击无反应，不会报错」）。
数据加 `comingSoon: boolean`，fallback 改成飘字「{功能}功能正在开发中」，与「等级不够」的
`feature_locked_tip` 严格分开（混用会让玩家以为练级能解锁一个不存在的功能）。
守点 `test-bottom-nav.cjs`：`comingSoon` 必填 + 集合等于登记名单，新增入口要么接回调、要么改登记。

### #486 底部导航节点重名（这条差点被误判）
节点名按**图标路径**取（`bottom_nav_${icon}`），而「聊天」与「好友」共用 `friend` 图（#468 待接入）
→ 两个 `bottom_nav_bottom-nav-bar_friend`。排查 #485 时 `find(...)[0]` 拿到的是聊天按钮，
点下去开聊天窗，一度误读成「好友的等级门槛失效」。改按 `config.key` 命名（key 是身份、图标是外观）。
**教训**：按名字取节点前先数一遍同名节点有几个；`find(...)[0]` 在重名场景下是最安静的错。
守点：`test-bottom-nav.cjs` C 段断言按 key 命名两两不同（按图标撞名的现状只打印、不判红 ——
等 #468 接入后就不撞，写成断言会因「状况变好」假红）。

## #670 怪物 AI 全部上服务端（多端画面一致）

用户原话：「处理 #670，现在要求怪物 AI 全部在服务端，下发至客户端，必须保持多用户画面一致」。
issue 原标题只是「怪物对着尸体放技能」，被扩成「AI 全服务端化 + 一致性」。

**#670 本体根因**：`RolesService.applyMonsterHit` 在 `previous <= 0`（玩家已倒下）或不在线时 `return null`，
而 `MonsterAiService.attack()` 只把它当「这一下落空」→ `runtime.target` 不清、`positions` 里那条 hp>0
的缓存不删 → 下一拍又把尸体选成目标。更糟的是 `castSkill()` 无论命中与否都 `pendingCasts.push(cast)`。
**修法 = 认结算结果，不是读血量**：`forgetTarget(accountId)` 删位置记录 + 清掉所有怪身上指向该账号的
`target`；`castSkill()` 改成先结算再落账（拿不到 hit → 不记冷却、不进硬直、不发 casts，返回 false）。

**多端一致的三个缺口**：① world 快照 `x/y` 是出生点，而 `monster-ai` 增量帧「有变化才发」→ 站着不动的
怪永远不会被纠正；② 血量只在 `hits` 里（只发给出手者本人）；③ 客户端 `serverAuthority=false` 时仍跑本地 AI。
修法：`withLiveMonsterPositions()` 覆盖 world 帧坐标（`worldJoin` 应答 + `broadcastWorld` 两处）；
`monster-ai` 帧带必填 `hp/maxHp`、`hurt` 也算「有变化」；客户端本地 AI 全删。

**击退搬服务端**：原计划「删掉客户端 push，不做击退」，发现 `skills.push_distance` 有数据（1001 烈火剑法 = 120px），
改成 `applyPush(instanceId, fromAccountId, distance)`：方向 = 施法者 → 怪，时长取
`runtime_params.monster_ai.pushDuration`（新字段，出厂 200），`stepMonster` 里击退优先于施法硬直。
**不需要新协议帧**，落点走普通位置广播。客户端 `stepServer` 步长加追赶
（`max(moveSpeed, distance / 0.2s)`），否则 120px 击退要拖一秒多才补齐。

**踩坑**：
- `skillOf()` 返回的是 `applySkillOverrides` 归一化后的**驼峰**对象，我第一版写 `Number(skill.push_distance)`
  拿到 `undefined` → 击退静默失效。要 `SkillSource` 补 `push_distance` 列 + 映射成 `pushDistance`。
- `applyPush` 里 `pushEndAt = now + ai.pushDuration`，但当时 `MonsterAiParams` 还没这个字段 → `NaN` → 永不生效。
- e2e 量击退距离必须在**停稳后**量（连续两拍位移 < 0.5px）：广播 100ms 一拍、击退 200ms，急着量只量到半路。
- `pickPointInArea(cx, cy, 0, 0)` = 恒定落中心点，e2e 用它把怪钉死，位置断言才可复现。

**测试**：新增 `server/test/e2e-monster-ai.cjs`（17 条，四段：别人打的伤害可见 / 击退 119.4px / C 晚进图坐标与 A
一致 / 尸体期 hits 0 条 + casts 0 次），套数 **38 → 39**（README + 站点三页同步）。
`make client-test` 有两套红：`test-skill-decouple`（期望值里写着 `push: {distance:120}`）与
`test-skill-snapshot`（断言 `after.push?.distance === 60`），按「击退已不在客户端」改写成**反向守卫**
（`push === undefined`）后 60/60 全绿。

**改到的文件**：服务端 `monster-ai.service.ts`（核心）/ `realtime.service.ts`（world 帧覆盖）/
`realtime.protocol.ts` / `world.service.ts`（注释）/ `combat-settlement.service.ts`（击退 + 注释）/
`runtime-config-cache.ts`（pushDistance）/ `config-sync.sql`（pushDuration 出厂值）/ `package.json`；
客户端 `MonsterAI.ts`（465 → 220 行）+ `MonsterManager` / `Game` / `SkillManager` / `types/{skill,monster}` /
`game-config.ts`（删 `monsterAI` 常量块）；工具 `audit-world-authority.cjs`（`BEHAVIOR_FIELDS` 反向守卫）、
`test-changed.cjs`。

**纪律收获**：显示效果（帧率/位置/尺寸）不写断言这条，在「击退」上反过来也成立 —— 击退**距离**是数值口径
（可断言、必须断言），击退**过程**是演出（不写）。e2e 只量落点，不量中间帧。

**收尾**：三个提交（服务端 / 客户端 / 文档+记忆）→ PR #744 → CI 五 job 全绿（静态 24s + 四个 e2e 分片各 ~1.5min）

偶发，判红前先看是不是「端口 / 超时」而不是断言失败。


## #745 地图监控精细日志：数值来自结算，过程来自 AI（issue #745）

用户原话：「管理端地图监控中，需要看到详细信息，精确到怪物血量减少多少，怪物开始追击，结束追击，
需要特别精细的日志，并且携带具体时间」。原来文字流只有 `kill` / `respawn`，看到的是**结论**而不是**过程**。

**两类口径，不能混着写**（这是整块的设计核心）：
- **数值来自结算**（`CombatSettlementService.settleNew`）→ `damage` 事件。快照差分只说得清「掉了血」，
  说不出「谁打的、用什么技能、这一下多少、推开多远」。`hpBefore = hpAfter + amount`（世界层只回扣完之后
  的血量，前值反推）—— 页面上「65 → 56（-9）」三个数**永远自洽**；
- **过程来自 AI**（`MonsterAiService` 新增 `onLog` 回调）→ `chase`（start/end + 成因 + 那一刻距离）、
  `cast`（技能名 + 被打者血量前后）、`hit`（普攻）。
- **为什么是回调不是注入**：`MapMonitorService` 构造时已依赖 `MonsterAiService`（采样要读 `livePositionOf`），
  AI 反过来注入它就是循环依赖。与 `onBroadcast` 同一手法：宿主 bootstrap 赋值、shutdown 置 `null`；
  回调体内 `try/catch` 只 warn —— 监控写失败绝不能影响战斗。
- **名字自己缓存**（`Map<accountId, name>`）：`presence.identityOf()` 只在人在场时给名字，而「目标离线」
  恰恰是那个人已离开在场表的那一刻 —— 不缓存的话最需要看清的那条日志恰好没有名字。
- **「目标丢了」四种成因分开**：目标离线 / 目标倒下 / 目标换图 / 位置上报超时。`forgetTarget`（出手结算
  不出来）与 `onMonsterKilled`（怪被打死）都要补一条 `chase.end`，否则留下没有结局的追击。
- **保留条数上调**：`mapMonitorEventKeep` 300 → 2000、`trimEvery` 25 → 100（细到每一下伤害后条数消耗快
  一个数量级，300 条只够十几秒）；`keep()` 里的兜底值也同步成 2000。
- **DTO**：六种 `kind` 共用一张宽表，新增 14 个字段，**不适用的给默认值（空串/0/false）而不是缺字段** ——
  客户端按 kind 分支渲染，缺字段会让「有没有这一栏」也变成契约的一部分。

**管理端**（`admin/src/components/map/MapMonitor.tsx`）：
- 时间到**毫秒** + 与上一条的间隔（一秒内连发四条时「+0ms / +3ms」比四个相同时间戳有用）；
- 六类分色、各有详情行：伤害显示 `65 → 56 / 120（47%）` + 血条 + 推开距离 + 「这一下打死了」；
  追击显示「开始/结束追击 谁 · 成因 · 距离px」；怪物出手显示「玩家血量」走玫红条（与怪掉血的琥珀区分）；
- **类型筛选 chips 带条数**（关掉的一律半透明，不用 line-through —— 中文压一条横线读不清）；
- **点地图上的怪只看它的日志**（再点取消）：聚焦的怪加白色虚线外圈、其余退到 `opacity 0.3`；
  换图/换区/reset 时清掉聚焦（实例 id 只在图内唯一，留着会「筛出来永远 0 条」）；
- 底栏与流头显示「显示 N / 共 M 条」，筛选放**上层**算（两处各自过滤会出现「底栏说 12、流里 8」）；
- 筛选只改显示不改游标：仍混着拉 60 条/次，页面留 300 条 —— 这是**显示**上限，不是服务端保留上限。

**e2e 两坑**：
- 想稳定看到 `chase`，必须把玩家**站到怪身上**（`target.x, target.y - 20`）+ `setInterval` 每 800ms
  重复上报（超 3s 不报会被判「目标离线」，那就只能看到 end 的离线成因）；
- 裁剪断言不能写「同时存在两条 kill」：新增的 damage/chase 也占行，`KEEP=3` 时第一轮早被裁掉。
  改成「存在比第一轮那条更新的 kill」+ respawn 按 `id` 比较。

**验证**：`server npm run build` 0 错；`e2e-map-monitor` **129 条通过**（新增「二·五」段 + 文档契约 2 条）；
`npm run gen:api`（209 接口 / 6 文件）；`admin npm run build`；`make audit` 15/15；`make client-check` 0 错；
`make test-changed` 46 步全绿。

**改到的文件**：服务端 `common/map-monitor.ts`（两侧共用事件契约 + `MAP_MONITOR_EVENT_KINDS` 白名单）/
`realtime/monster-ai.service.ts`（`onLog` + 身份四件套 + 成因）/ `realtime/map-monitor.service.ts`（`recordDamage`
+ `recordAi` + 名字缓存）/ `realtime/combat-settlement.service.ts`（`hitSpot` 总是算 + `pushDistance` 提出分支）/
`map/dto/map-monitor.dto.ts` / `map/map.service.ts`（14 字段先赋默认再按 kind 填）/ `config/configuration.ts` +
`.env.example`；管理端 `components/map/MapMonitor.tsx`（471 → 824 行，拆出 EventHead/EventDetail/KindChip/HpBar）；
生成物 `openapi.json` + `admin/src/api/models.ts` + `client/assets/ui/utils/net/ApiModels.ts`；
测试 `test/e2e-map-monitor.cjs`（686 → ~800 行）。

**收尾**：三个提交（服务端+生成物 / 管理端 / 文档+记忆）→ PR #746 → CI 五 job 全绿（静态 35s + 四个 e2e 分片

## #747 清理弹窗九宫化后的死配置与无用零件函数（PR #748 / `85254b79`）

  600×500 推的，九宫化后头行恒定 42px，这个数已经没有意义 —— 这就是用户说的「计算有问题」）。

## 修复「怪物死亡看不到死亡动画」（16:45）
- 根因：不是死亡流程问题，是**怪物动画映射表与素材包真实布局不符**。`configs/animation.ts` 的 monsterAnimation 按「11 动作 × 8 方向 × 10 帧 = 880 帧连续切割」，但 220 个怪物包实测只有 224 帧（怪物 27 缺 walk 段仅 176 帧）：真实布局 = stand(0 起，4帧/向，向隔10) / walk(80，6帧/向，隔10) / run(160，6帧/向，隔10) / injured(240，2帧/向，隔2) / **die(260-339，10帧/向，隔10)**。stand/walk/run 之前能正常显示纯属 stride-10 巧合（窗口内空帧被过滤）；die 映射到 800-879 → 切片为空 → `MonsterAI.die` 返回 false 走立即移除兜底。附带发现：attack_near 映射窗口(320-399)撞进 die 段，之前攻击动作播的其实是别的方向的死亡帧。
- 修法：`configs/animation.ts` 怪物映射改为按实测规格表 `monsterActionSpecs`（action/start/frames/spacing，帧号公式 start + 方向下标×spacing + 帧内下标）生成，attack/test/a1 等素材里不存在的动作不进表（playAction 自动回退待机）。逐包模拟校验：220 包 × 5 动作 × 8 方向缺帧总数 48 = 怪物 27 的 walk 段，其余全命中。
- 附带修复：击退受伤动作（injured 240-255）此前映射落空回退待机，现在能正常播放。
- 方法论沉淀：**素材帧布局排查 = 列目录帧号找连续段 + 抽帧看图认动作**；跨包一致性用脚本全量验证。

## 21:10 修复「窗口尺寸变化后头像/地图区域显示不全」
- 现象：改窗口尺寸后左上角色信息栏（头像区）与右上小地图（地图区）被切掉，底部栏正常。
- **根因**：上一轮用 `view.getVisibleSize()` 当可见区，而 NO_BORDER 下它**恒返回设计分辨率 1624×750**——引擎 `NoBorder.apply` 是把「视口」放大到超出画布、让画布裁掉溢出部分，`_visibleRect` 被反算回设计尺寸。于是窄窗口时贴左/贴右两块被排到屏幕外（脚本核算：1024×768 越界 293/310px、1920×1080 越界 126/143px，底部居中不受影响 → 与现象完全吻合）。
- 修：`ScreenLayout.getVisibleSize()` 改为 `screen.windowSize / view.getScaleX|Y`（与引擎相机 `orthoHeight = windowSize.height / getScaleY() / 2` 同口径，NO_BORDER 下 scaleX≡scaleY 故自洽），极端空值退回 `view.getVisibleSize()`。
- 附带修：`Canvas._onResizeCamera`（由 canvas-resize 触发，先于业务监听）会把相机世界坐标拽回 Canvas 节点位置，而相机/UI 层只在主角移动时由 `LayerManager.move` 对齐 → 尺寸变化后视野/UI 会错位；`Game.start` 的 onWindowResize 回调里先补 `LayerManager.move(roleDisplay.getWorldPosition())` 再重排三区域。
- 校核：脚本按引擎口径模拟 7 种窗口，三区域全部在屏内（底部栏纵向溢出属设计如此）；tsc 两轮 0 错（unused 仅 Login.ts 既有 2 处）。

## 23:55 修状态图标条「首图标位置飘出背景框」
- 现象：释放状态（如护体神盾）后，头像下方的状态图标出现在信息栏背景框左侧外的空白处。
- 根因：`StatusIconBar.row` 是宽 220 的横向 Layout 容器，Cocos HORIZONTAL Layout **从容器左边界起排**（paddingLeft=0）→ 首图标中心 = -110+12 = -98（row 本地），换算到信息栏 -198，超出背景框（跨 ±150）。
- 修法：① row 尺寸改为单图标大小（`layout.iconSize`）→ 左边界起排后首图标中心正好落在容器原点；② `statusBar.position.x` 从 -100 对齐到头像中心 -109.5。多图标向右自然排开（Layout 不裁剪溢出）。
- 教训：**横向 Layout 容器宽度 ≠ 内容实际起点**——左对齐起排的容器，首元素永远贴左边界；要「首个元素对齐某锚点」就把容器宽度做成单元素尺寸、锚点对齐该处。

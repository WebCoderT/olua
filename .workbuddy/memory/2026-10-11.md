## issue 打扫：#23 .DS_Store 卫生（PR #52，已 squash 合入 f7e73d6，#23 CLOSED）

最简的 open issue，纯机械改动：
- `.gitignore` 加 `.DS_Store` + `._*`
- 实际被跟踪的 `.DS_Store` 有 **5 个**（issue 原文写 2 个、已过时），用 `git rm --cached` 退出版本库；本地文件本意保留

### 关键 gotcha（值得记）
`git rm --cached` 在分支上确实只删索引、留本地文件；但**合入 master（squash 合并）后，工作树的这 5 个文件也被删了**——因为合入提交是「文件不在树中」，git 把工作树对齐过去。`.DS_Store` 是 Finder 元数据、下次开文件夹自动重建，且已 gitignore，故 `git status` 仍干净，无实质损失。若将来要「保留本地文件」为真硬指标，得在分支上 `git rm --cached` 后**不要合并删除提交**，或合并后 `git checkout <old> -- <file>` 还原再 commit 一个「不跟踪」——但那样会重新引入删除。结论：本 issue 目标（干净 + 不进库）已达成，不留本地副本是可接受的。

## issue #24 决策 + 落地：CI 覆盖客户端走路径 B（PR #53，squash 合入 704657e，#24 CLOSED）

#24 是「CI 是否覆盖客户端」三路决策题（A 维持现状 / B 只上类型检查 / C 素材托管+全量）。用户选 B。

### 落地做法
- 根因：Cocos 编辑器生成的 `client/temp/declarations/{cc,cc.custom-macro,jsb,cc.env}.d.ts` 里 shim 的 `/// <reference path>` 指向**本机 Cocos 绝对路径**，且 client/temp 在 .gitignore、CI 没 Cocos。
- 解决：`client/tools/gen-declarations.cjs` 把声明 vendoring 进 `client/types/engine/`，改写绝对路径为相对（cc-engine.d.ts / jsb-engine.d.ts = 真实引擎声明，cc.d.ts 3.4MB 自包含无绝对路径泄漏）；`tsconfig.check.json` 的 types 改指 `../types/engine/*`。
- CI 的 tsc：`client/package.json` 加 `devDependencies typescript@5.8.2`（与 Cocos 自带同版本）；`install-ci` 加 `cd client && npm ci`；`make ci` 加 `client-check`；`ci.yml` 传 `TSC=node_modules/.bin/tsc`（注意 client-check 会先 `cd client`，所以 TSC 必须绝对或相对 client 的路径，不能写 `client/node_modules/...` 会被叠成 `client/client/...`）。
- 根 FAQ.md / FAQ.en.md 加「为什么 CI 不覆盖客户端」一节（路径 B 决策 + 三条路理由）。
- 本地验证：`make client-check TSC=<npm tsc>` 与 Cocos 基线同 `0 错`；`make audit` 8 全 PASS；CI 58s 绿。

### 审计抓出的两个真问题（重要，对未来双语文档编辑复用）
1. **万展开是字符串追加 bug，不是算术**：`tools/audit-docs-en.cjs` 把 `16.8万` 展开成 `16.80000`（给 "16.8" 字符串追 4 个 0），而非 16.8×10000=`168000`。所以中文若写「16.8万」，英文写「168,000」会两边对不上（报「16.80000 中文多 1 / 168000 英文多 1」）。**绕法：中文也直接写数字 `168000`，不写「万」**。
2. **数字 parity 看 ASCII 数字 multiset，不看汉字数字/单词**：中文「10 套」贡献数字 `10`；若英文写成单词 "Ten" 就少一个 `10` → FAIL。中文「五套」是汉字数字（不计），英文就得写 "five" 而不是 "5"（否则英文多出一个数字 `5`）。结论：**中英文同一概念要用同一种数字表达形式**（都写阿拉伯数字，或都写单词/汉字），否则必 mismatch。

### 结论
路径 B 已闭环：客户端类型检查进 CI、单测本地专属。升级 Cocos 后 `make client-gen-declarations` 重生成声明即可。

### 本轮踩的坑（复用价值高）
1. **`git archive HEAD` 导出的是「已提交」状态** —— 我改的 compose 没提交，第一次发布的还是旧 `:8080`。→ **发布前必须先提交并合入 master**，再归档。（这也是仓库纪律想要的：线上跑的一定能在提交历史里追到。）
2. **scp 顺序**：`server/.env` 必须在**解压之后**传，否则 `server/` 目录还不存在 → `dest open ... No such file`。
3. **`pkill -f "git clone"` 会杀掉自己**（模式匹配到自身命令行，ssh 会话直接断、无输出）→ 写成 `pkill -f "git clon[e]"`。
4. **zsh 不做变量分词**：`SSH="ssh -i ... -o ..."` 再 `$SSH host` 会把整串当命令名；`$OPTS` 同理会把整串当一个参数（报 `keyword stricthostkeychecking extra arguments`）。→ ssh/scp 选项**内联写**，或用 `${=VAR}`。
5. **BSD sed `sed -i ''` 在本环境把脚本当文件名**（替换静默不生效，还把密钥回显到输出）→ 密钥替换改用 Python `re.sub`；密钥一旦在输出里露过面就**重新生成**。
6. 40M scp / docker build 都会超前台 120s → 一律 `run_in_background`。
7. 判断 docker 存活用 `systemctl status docker` / `pgrep dockerd`，别用 `docker info`（受 socket 权限干扰，会误报「没启动」）。

  摆位 `x = (col − (columns−1)/2) × (cardWidth + gapX)`，`y = −(row×pitch + pitch/2)`，pitch = 100+6 = 106

  `firstRow/lastRow`（pitch + virtualBuffer）→ `first = firstRow×columns`，`last = min(len−1, (lastRow+1)×columns−1)`。
- 卡片图标仍 `MOUSE_ENTER` 悬停详情 + `trackUiPress(icon)`；购买链路不变。

## 清理 `resources/role` 下的「空帧」（同日稍后）

**现象**：Cocos 客户端刷屏报错（导入阶段）。

**根因（实证）**：`resources/role/1`、`role/2` 里共 368 个文件扩展名是 `.png`，本体却是 **1×1 的 32 位 BMP**
（文件头 `42 4d` = `BM`，70 字节；真帧 ~2.9KB）。Cocos 按 `.png` 解码必然失败 → 每个文件的 `.meta` 都是
`"imported": false` / `"files": []` / `"subMetas": {}`（**没有任何子资源**）→ 每次扫描刷屏。
这是继「大写扩展名」之后的第二类素材导入坑：**扩展名与真实格式不符**。

**处理**：全部移除（368 个 `.png` + 368 个 `.png.meta`）。因 `resources/role/` **未被 git 追踪**
（`git ls-files` = 0，删除不可逆），先备份到 `.workbuddy/backup/role-empty-frames-20261007065939/`。
新增清理脚本 `tools/clean-role-empty-frames.cjs`（默认预演只列清单；`--apply` 备份 + 删除；幂等，可当日常体检）。

**核对**：清理后每个目录 **416 帧**（全为合法 PNG），缺失的 184 个帧号**精确等于**扫描到的空帧帧号，
无新增/误删；无孤立 `.meta`；20s 复检目录条目数与哈希不变（无编辑器回写）。
（预演 368 个、执行时只剩 343 个 —— 期间有外部进程动过这批文件，但最终状态与「删净 184×2」完全一致。）

**为什么删掉零影响**：`role/1` 走 `AnimationHelper.prepare(dir, "role")` → `buildClips(roleAnimationMap)`，
切割按**显式帧号映射**（`fillAnimationMap` 从 0 起填，0~599）且已有「空图过滤」（`getRect().width > 1`）；
而这些占位帧因导入失败**本就不在 SpriteFrame 列表里**，故角色动作清理前后完全一致。

**顺带查清的两件事**：
- `roleAnimationMap` 需要 0~599（600 帧），但 role/1 只有 416 帧有效 —— 各动作**每方向 8 帧里后 4 帧原本就是空的**
  （STAND / WALK / RUN / ATTACK_NEAR / ATTACK_SKILL_1 / ATTACK_FAR 各空一半；A1 空 40/64、DIE 空 32/64；
  TEST1 / TEST3 / INJURED 无空帧）。即这些动作的片段实际只有 4 帧（过滤后自动降级）。**属素材现状，非本次造成**；
  要让动作完整需重新导出补帧。
- `role/2`（帧号 600~1199，空帧分布与 role/1 完全对称）在代码里**没有任何引用**
  （`grep "role/2"` 无命中；`ROLE_DEFAULT_CLOTH_OUT = "role/1"`）。要接线需另配动画表（帧号偏移 600）。

**全库体检**：`find … -size -1k` 得 8304 个小图片文件，逐个验文件头 —— 全部合法 PNG/JPEG，无同类问题。

**留了两件工具**：
- `tools/clean-role-empty-frames.cjs`（默认预演只列清单、`--apply` 备份+删除；幂等）
- `tools/test-role-frames.cjs`（**新增守卫单测**，与 `test-equipment-appearance` 同类：钉住「每个帧文件都是合法 PNG / 帧号无重复 / 无孤立 meta / 各目录帧数 416 / roleAnimationMap 的 88 组动作×方向全部能切出帧」，并打印每动作每方向有效帧数）。
  注意取动作名不能简单 `split("_").slice(0,-1)`：方向值自带下划线（`right_up`/`left_down`），要按方向后缀**从长到短**匹配去掉。

**验证**：15 套单测全部通过（本次未改 ts 代码）。

## 默认外观按性别区分（男 role/1、女 role/2）+ 目录帧号基准

- `PreloadManager.ts`：`getEquipment(...)?.out || getRoleDefaultCloth(role.sex).out`。
- 单测：`test-role-frames.cjs` 扩到**两套素材各自按帧号基准归一**都断言 88 组可切（+基准登记检查）；**新增 `tools/test-role-default-cloth.cjs`**（43 项：分表/回落/字段口径/素材对齐/接线/旧常量清除/同口径）。

## 光柱系统（装备落在地上时的品质光效）

**需求**：`effect/light` 下 6 个动画，装备掉在地上时在图标上播；按 5 档区分，最后一个预留手动配。

**先澄清（用户原话是「5 个后缀」，与代码不符）**：`EQUIPMENT_SUFFIX` 只有 **3 个**（人级/天级/神级），`EQUIPMENT_PREFIX` 恰好 **5 个**（普通→超神）——6 = 5 + 1 预留，口径对得上 → 用户确认**按前缀 5 档**，并确认**光柱画在图标下层**。

**素材实测**：`effect/light/{1..6}`，帧号各自独立连续（02881/02900/02920/02940/02960/02980 起，14/15/15/15/15/15 帧），400×400 画布。
→ **不需要帧号基准**：整包循环播放（`playLoopDir`），不做动作区间切割。
→ **meta 是 auto-trim 真裁剪 + 非 0 offset**（trimX/trimY/offsetX/offsetY 全非 0、width<rawWidth）→ 与**详情背景同类**，**trim 必须保持缺省 false**（`createSprite` 默认就是 false，什么都不用改）；改成 true 会帧间抖动。与边框（未裁剪 + offset≠0 → trim=true）相反，别再搞混。

- 新增 `types/light.ts`、`configs/light.ts`（`lightSerials=[1..6]` → `lightResources`/`lights`；`prefixLightData` 5 条 → `prefixLights`；`customEquipmentLightData` 空表（预留 6 号）+ `customEquipmentLights`；`getEquipmentLightKey`（自定义 id → 基础件 key → 前缀表；未登记自定义 key 打 warn 回退）、`getAssignedLights`）、`configs/layout/lights.ts`（`equipmentLightLayout`：namePrefix/size 80×80/frameRate 10）；hudLayout barrel 登记。
- `GameUiHelper.createDropItem`：**先 `applyEquipmentLight` 再 `addChild(icon)`** → 光柱是掉落物第一个子节点、画在图标**下层**；新增 `applyEquipmentLight`（仅装备；`playLoopDir`）、`createEquipmentLight`（空精灵 + Animation，位置取 `dropItemLayout.iconOffsetY` 与图标同中心）。

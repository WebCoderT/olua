## #760 管理端商城显示部位与前后缀（PR #761 / `01fcb384`）

**需求**：上架弹窗里的装备要显示「分类（部位）」和「前后缀」。

**根因**：同一基础件 15 个变体**名称完全一样**（`equipment_variants.label` 是基础名，前后缀在数据里只是 `prefix` / `suffix` 序号，客户端按序号拼），所以 `id / 名称 / Lv` 三列分不清品质与阶级 —— 运营只能从 `_p3s2` 猜。

**做法**：
- 服务端 `MallGoodItemDto` 补 `prefix` / `suffix` 两个**只读序号**；中文名不复制第二份（权威仍是 `equipment_meta.prefix_labels / suffix_labels`），管理端进页面 `equipmentMetaApi.get()` 取一次，越界回落「前缀 N」。
- `CatalogEntry` 加两字段：`catalogEntries()` 从 `variants.listAll()` 取，`requireCatalogEntry()` 走 `variants.findById()`（校验口径仍用 `equipmentLevelOf` 的 runtime cache，别换）。
- 管理端：弹窗行加「部位 + 前缀 + 后缀」三徽章，商品列表在「部位」后插「品质（前缀 / 后缀）」列。
- 快照段 `MallGoodEntryDto` **不动** —— 客户端只认 id / 售价 / 购买等级。

**坑 / 纪律**：
- `client/tools/test-client-net.cjs` 里 `DEV_BASE_URL` 断言**锁死了 localhost:3100 字面量**，本机改局域网 IP 就红 —— 改成锁形状（两个常量各一处 + `baseUrl` 只由 `DEV_MODE` 三元）。这就是「测试锁数值不锁格式」的又一例。
- `gh issue close` **没有 `--comment-file`**（只有 `--comment`），用 `--comment "$(cat file)"`。
- #758 之前其实**没关成功**（`closedAt: null`），本次一并关掉。
- 工作区常年挂 4 处本机调试改动（`admin/.env.development`、`admin/vite.config.ts`、`server/src/main.ts` 的 `0.0.0.0`、`client/assets/configs/network.ts` 的局域网 IP），提交时逐个 add，别 `-A`。
- 门禁前要 `git stash push -- <那三处>`，否则 `audit-api-hardcode` 会在 `main.ts` 的 `0.0.0.0` 上红。

门禁：`make test-changed` 13 步全绿；`e2e-game-config` 992 通过 0 失败；`test-mall` PASS；CI 五 job 全绿。

**收尾（PR #762 / `3f46876d`）**：旧服务端（还没重启）会让 `variant.prefix` 是 `undefined`，徽章显示「前缀 undefined」—— 改成序号缺失时显示「—」，越界仍照实显示「前缀 4」（那是真的数据不一致）。

## #763 商城开卖药品 + 上架弹窗按分类/等级筛（PR #764 / `ea1924a3`）

**需求**：上架弹窗要能选「物品自己的分类（武器 / 衣服 / 药品…）+ 等级」；用户在选项里明确选了「装备 + 药品」，所以是**功能扩展**不是纯筛选。

**做法**：
- 新接口 `GET admin/mall/catalog` 是上架弹窗的唯一数据源：装备变体 + 药品拼成 `MallCatalogItemDto`，筛键只有 `category`（部位 key / `drug` / 空）、`level`、`keyword`；回包带 `levels`（**当前分类下**出现过的等级，不受关键字影响）与 `listed`（已上架则前端置灰，点了必撞 409）。
- `MallGoodItemDto` 补 `kind` / `icon`：以前管理端用 `equipmentIcon(id)` 猜图标，药品拿空图；现在图标由服务端给（装备取基础件 icon、药品取 `drugs.icon`）。
- **`putGoodIntoBag` 必须支持堆叠**（先找同 id 未满格，上限 `drugs.max_stack`，再找空格）——原来只找空格，卖药品会让买两瓶占两格。
- 客户端：`configs/items.getSellableGoods()`（装备在前、药品在后，**不混排**）→ `MallDialog` 类型放宽 `Goods` + `isEquipment` 分支（药品单段名 + 「药品」小字）；`buyMallGood` 删掉「非装备一律拒绝」的本地预检（品类归服务端目录）。
- 管理端弹窗：分类下拉（全部 / 药品 / 13 部位）+ 等级下拉 + 候选分页（每页 8）+ 行内「已上架」标记。

**坑**：
- 商城目录的「分类」有两层语义，别混：**商城陈列分类**（`mall_categories`，运营自建）vs **物品自己的分类**（部位 key / `drug`）。接口里后者叫 `category`，前者叫 `categoryId`。
- `MallGoodItemDto` 加字段不影响客户端（快照段 `MallGoodEntryDto` 没动），但**管理端图标**必须换成 `item.icon`，否则药品空图。
- 客户端的药品堆叠结果以服务端返回的 `bag` 为准（`role.bag = data.bag`），本地不自己算格子。

门禁：`e2e-game-config` 1010 通过 0 失败；`test-mall` PASS；`make test-changed` 93 步全绿；`make client-check` 0 错；CI 五 job 全绿。

## #765 商城分类可管理 + 商品可选分类并按等级/名称检索（PR #766 / `6d6a1f4c`）

**真 bug（客户端一个分类都看不到）**：`MallDialog.build()` 里 `buildTabs(dialog)` 排在
`this.categories = getMallCategories()` **之前** —— 页签按空数组建，建出来 0 个节点。
`build()` 里的顺序是「先取数据、再建依赖数据的节点」，这类错只有看顺序才抓得住，
所以 `test-mall` 加了一条执行顺序断言（取 `private build()` 到 `private nameOf(` 之间的片段，比对两处 `indexOf`）。

**管理端改版（用户口径：分类单独管理，与物品自身分类无关）**：
- 分类管理收进「管理分类」弹窗：新建 + 行内改名 / 改排序 / 删除；页面上只留一个分类筛选下拉。
  行内草稿放 `Record<id, {label, sortOrder}>`，**每次 loadCategories 后用 `draftsOf()` 重建**（草稿不跨请求残留）。
  排序值 >= `AUTO_SORT`(9e8) 视为「排到最后」，输入框显示空。
- 商品检索 = 商城分类 + 物品等级 + 名称/id；`GET admin/mall/goods` 回 `levels`。
  **`levels` 只按分类收敛，不跟着关键字/等级收** —— 跟着收就只剩当前选中的那一档。
- 上架弹窗尾部加「挂到商城分类」（缺省 = 当前筛选值），上完把筛选切到该分类，
  否则刚上架的商品立刻被筛掉、看着像没成功。
- 编辑弹窗（原「改售价/等级」）加「商城分类」：`PATCH admin/mall/goods/:id` 接受可选
  `categoryId`（先 `requireCategory` → 404 50025，否则留下指向不存在分类的孤儿行，客户端页签里看不见）。

**坑**：
- `listGoods` 从「按 catalog entry 过滤再 map」改成「先 map 成 DTO 再过滤」：孤儿行 `kind` 为空，
  拿它去比 `kind`/`slot` 会被误杀，写成 `if (item.kind) {...}` 才保住「孤儿行照实列出」的老口径。
- 等级筛的 e2e 别断言 `total === 1`：出厂 `mall_goods` 里那行 `cloth_1`（基础件 id）是**孤儿行、level 0**，
  按 0 筛会命中两行。断言改成「回包每行都是这个等级」。

门禁：`make test-changed` 69 步全绿；`e2e-game-config` 1022 通过 0 失败；`test-mall` PASS；三端类型检查 0 错；CI 五 job 全绿。

## 调研：「把游戏服务器拆成网关 / 怪物服务器 / 战斗服务器」（结构性事实）

用户提出要拆服务器。调研后发现**这件事的前提目前不存在**，四条硬事实：

1. **服务端不跑游戏世界**。六张表 = `accounts` / `roles` / `admins` / `audit_logs` / `announcements` / `mail_queue` —— 没有任何 world / map / monster / session 表。服务端职责只有「账号 + 角色存档 + 运营（公告/邮件/审计）」。
2. **这是单人游戏**。客户端 grep `otherRole|remoteRole|OtherPlayer|同步.*移动` **零命中** —— 同屏没有第二个玩家。怪物 AI、战斗结算、掉落全部在客户端本地，总计仅 **893 行**（MonsterManager 213 / DropManager 161 / StatusManager 151 / SkillManager 145 / Role 129 / EffectManager 74）。
3. **两端都没有实时通道**。服务端依赖只有 `@nestjs/platform-express`（无 `ws` / `socket.io` / `@nestjs/websockets`），客户端 `net/` 只有 `HttpClient`（REST）。客户端唯一的网络写操作是 `RoleSync`（**1.5 秒防抖刷存档**，乐观锁 revision），不是实时同步。
4. **数据库是单文件 SQLite**（`node:sqlite` 的 `DatabaseSync`，**没设 WAL / busy_timeout**），docker-compose 是单容器 + 具名卷 `olua-data`。多进程同写一份 db 文件要处理锁竞争。

### 结论：三条路线的性质天差地别
- **A 只拆进程拓扑**：能拆的只有三块 HTTP CRUD（账号 / 存档 / 运营）。拆完「怪物服务器里没怪物、战斗服务器里没战斗」，还多一跳网络 + SQLite 写锁。**收益 ≈ 0。**
- **B 服务端权威化**（才是这些名字的本义）：要先建 WS 会话 + tick 循环 + 世界状态存储，再把 MonsterManager / SkillManager / 伤害结算改写成服务端权威、客户端降级为表现层 → **重写游戏核心**，且与记忆里「多人实时同图：用户要求先不做」正面冲突。
- **C 先在单体里划边界**（推荐）：不动进程拓扑，按 gateway / world / combat / 存档 / 运营 划分逻辑分区与内部合约（内层不许跨区摸库）。将来真拆是「把目录挪出去」而非重写。

### 判断
像 MMO 那样的「怪物服 / 战斗服」拆法，前提是 **server-authoritative**（服务端持有战斗权威）。这个前提在 olua 不存在 —— 所以用户的目标到底是「真做多人游戏服务端」还是「要一个分布式形状」，决定了完全不同的工作量（后者可以用 C 满足，前者必须是 B）。**这个分叉点必须先问，不能替他选。**

### 关键技术结论（可复用）
- **客户端纯配置可以在 Node 里编译并加载**。用 `server/node_modules/.bin/tsc` 单独建一个 tsconfig（`rootDir = client/assets`、`strict:false`、`noEmitOnError:false`），把目标配置列进 `files`。

- **哪些 import 会被擦除**：纯**类型**用途的 cc import 会被 TypeScript 擦掉；**运行时真的构造了**（`new Color(...)` / `new Vec2(...)`）就不会。所以 `equipments.ts` 需要垫片、`level.ts` 不需要。
- **最小 cc 垫片**：`Color` / `Vec2` / `Size` 三个空壳类即可，伪装成 `out/node_modules/cc/` 包让 `require("cc")` 命中。已验证 `equipments`、`monster` 都能加载。
- **客户端这侧的 tsconfig 陷阱**：本机 grep 的 `\|` 在 BSD 下**不是或运算**（`-e` 或 Grep 工具才行）—— 这条又踩了一次，表现为「明明有 `new Vec2` 却 grep 出 0 行」。

### CI flake：邮件 e2e 的「重试中时已尝试 1 次」（另开 PR #27 修的）
第一次 CI 就红在 `server-e2e-mail`，但与本机改动无关。根因：**断言钉住了一个轮询观测不到的中间态** —— 退避 `base × 2^(n-1)`，base=30ms 时三次尝试总窗口才 90ms，而轮询间隔有 50ms，观测到的 `attempts` 是 1 还是 2 取决于机器快慢（本机恒绿 / CI 偶红）。
- **修法不是放宽断言，是把窗口拉宽**：base 提到 1000ms（窗口 1000/2000ms，远大于一次 HTTP 往返），严格断言保留；两处终态 `waitFor` 的超时从默认 5s 提到 30s（退避开销现在 3s）
- **怎么在本地证伪**：本机太快复现不了 → 在轮询的 predicate 里注入 300ms 延迟模拟慢机器。新配置 108 绿；旧配置连 `retrying` 都观测不到（与 CI 同源）。**断言数仍是 108，没靠删断言过关**
- 通用教训：**e2e 里凡是「轮询 + 精确值」的断言，先算一下被观测状态能在那儿停多久**；窗口比轮询间隔还窄就是必现 flake

### 踩坑
- **GitHub 锚点算法**：标点去掉后**每个空格各换一个 `-`**（不合并连续空格）→ 「LAN / public」变成 `--`。自己写检查脚本时若按 `\s+` 合并，会把正确链接全判成死锚点。
- **检查脚本要验会被证伪**：故障注入做了三次，前两次因为用了文件里不存在的替换串而**变成空操作**（看起来像被测通过）。注入后务必断言「替换确实发生」（比较 before/after），否则等于没验。
- 检查不仅要 countable，还要**打印上下文**（哪个数字、在哪个句子里），否则只知道有差异不知道修哪。

### 中文-numeral 归一（可复用到 client/server，那两端 ①②③ 更多）
- 中文用 `① ②` 列举、英文自然写成 `(1) (2)` → 被数字 multiset 检查判成差异。修法是**归一后再比**：`[①-⑳] → 1-20`、`[０-９] → 0-9`，并剔除**行首**有序列表序号（`^\s*\d+\.\s+`）—— 排版不是事实。改文档去凑计数是错的。

### 本轮最值钱的教训：检查脚本会静默失效
改归一化时，一次 Edit 把填充计数数组的两行循环**连带替换掉了** → `zRes/eRes` 恒空 → **数字检查永远通过**（不报错，只是不再检查）。是本轮做完故障注入才发现：注入 17→7 却报全绿。

→ **任何改动检查逻辑之后，必须重做一次故障注入**；只相信「刚才绿过」。
→ 守卫要能自证：加一条**空结果即 FAIL**（提取为空、比对数太小都判 FAIL，并写明「别信它的结果」）。
→ 脚本崩（ReferenceError）反而比静默放行好 —— 至少看得见。

## client 端英文文档（#41 / PR #49，最大一份：FAQ 354 行 + README 168 行）

### 检查脚本再加一层：数量单位归一（直接来自翻译实践）
- `N 万 → N0000`、`N 亿 → N00000000`、去掉千分位逗号。**中文写「4 万」，英文自然写 "about 40,000"**，不归一就是假差异
- 关键收益：**这条能抓数量级事故** —— 把「4 万」译成 4,000 只差一个数量级，肉眼扫不出来，现在 FAIL 并打印上下文。所以这不是「放宽检查」，而是**让检查认识单位**
- 注意中文里是「4 万」**带空格**，正则必须写 `/(\d)\s*万/`

### 翻译时最容易丢数字的三类
1. **「非 0」译成 "non-zero"** → 数字凭空少一个（本刀三处：退出码、两处 offset）
2. **「二维」译成 "2D"** → 凭空多一个 2
3. **中文数量单位**（4 万）→ 见上
统一对策：英文里坚持写 `non-\`0\`` 这类保留数字的写法，别图顺口。

### 链接翻转的正则坑
上一刀的翻转正则要求括号紧跟文件名（`\(client\/FAQ\.md\)`），**漏了带 `../` 前缀的写法**（`admin/FAQ.en.md` 里那条 `../client/FAQ.md` 没翻到）。正确写法要允许前缀：`/\((\.\.\/)+client\/FAQ\.md\)/`。改完要**复扫一遍全文**，而不是只看有几处「已翻转」。

### 故障注入纪律已稳定生效
本刀改了归一逻辑后立刻重做三项注入（`40,000→4,000` / 改章节标题 / `25 套→24 套`），全部 FAIL、还原后哈希回原值。另外记一个自己的坑：`cp 备份 && node -e '...'` 这种串在 shell 里，若引号有语法错，**整条都没执行，备份也没建成** → 注入写到一半失败会留下脏文件。注入脚本最好落成文件再跑。

## 成长线升级收权 #248/#249/#250（PR #301 已合并，master = 6aceca2）
- **一个接口覆盖三线**：POST /api/roles/{id}/growth-upgrade（role.growthUpgrade）body {kind: title|soul|rank, targetLevel, revision?}。下一阶**以库内成长链为准**：titles/souls 走 upgrade_order（titles.listUpgrade 已按渠道过滤 upgrade；souls 全量持序）、ranks 天然按阶（level+1）。服务端算出下一阶后校验 targetLevel 一致（防跳级/防并发错位），扣 data.bindGold 后原子推进（revision+1）。
- **业务码分段**：20008 GROWTH_TARGET_INVALID（含满阶）/ 20009 GROWTH_GOLD_NOT_ENOUGH / 20010 GROWTH_CHANNEL_LOCKED（当前阶掉出升级链，称号渠道被切走）；20006/20007 乐观锁与踢下线沿用。**BizException 默认 400**——冲突类必须 BizException.conflict()（e2e 第一轮全 400 的教训）。
- **返回 GrowthUpgradeResultDto**（角色 + consumed/gainedLevel/gainedLabel）：客户端弹提示与重算直接用，免回头查配置。注意 **子类静态 from 签名不能收窄父类**（TS2417）——用 fromRow 命名（AdminRoleDto 先例）。
- **客户端双层提示**：本地预检（configs 的 max/元宝不足 tip）保留为即时 UX；请求非 silent，服务端失败 message 经 HttpClient.failureHandler 自动弹。成功后以返回值刷新 bindGold/阶位/revision，再走既有 combatCalc → updateOnlineRole → updateUi 链路（防抖推回 revision 与服务端一致，幂等）。
- **e2e 前置清理教训**：养成配置专项是**共享 DB 顺序跑**——前面 region 玩过称号渠道（1/2/3 阶已 upgrade、战魂成长列表重排 [2,1,3,...]）且不还原；后面的 region 若对 seed 有前提假设，必须**开头显式清理还原**（PATCH 渠道回 unavailable / upgrade-order 回阶数序），不能假设 seed 状态。断言计数先估后按实测改。
- 边界白名单：REPO_EDGES 补 roles → title/soul/rank 三仓储边（玩家侧升级读配置）。
- 数字：93 接口 / 79 路径 / 145 模型 / 客户端分组 11 / e2e 1465（养成配置 471）。
- **剩余**（epic #293）：商城购买收权（#251 客户端部分）→ 药品用药收权 → 掉落+经验结算权威切换（#254 真正收益点）→ 快照覆写扩展（装备/药品/物品/怪物/NPC/时装/成长曲线）→ 时装穿戴系统。

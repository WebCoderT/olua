## #134 竖屏改造 750×1624（PR #135）

- **改竖屏 = 三处同步**：`project.json.designResolution` + `ScreenLayout.designResolution` + 4 个场景的 Canvas（`_lpos`/`_contentSize`/相机 `_orthoHeight→812`）。运行时策略仍是 NO_BORDER 铺满。
- **竖屏几何事实**：可见宽恒 ≈750（手机宽高比都 ≥ 设计比时宽度绑定），可见高 1000~1624 变 → 常驻 HUD 宽度上限 750；桌面横窗（1024×768 → 可见 750×562）裁的是上下。
- **底部栏实测**：主体 1100 宽两端各溢出 175px（只裁背景装饰）；真正出屏的只有血球/魔法球+两个文字（可见 0~14px）→ 按用户决定整组移除（RoleHpOrb/RoleMpOrb + createHpText/createRoundHpBar + hud.ts 四项 + uiImages 三张注销，素材文件留待用户处理）。
- **移除前先查全引用**：两个组件只在 BottomBar 用；两个工厂只被这两个组件用；三张图只被工厂用 —— 删得干净且 tsc 兜底。
- **选角底部栏横幅（1624×139）**：竖屏缩 0.46 后「开始游戏」按钮只剩 22px 高 → 按钮反向补偿 `1/barScale` 回设计尺寸并居中（补偿后恰好整块盖住牌匾的「开始游戏」槽位，不会露出底下的字）。单测加「补偿后视觉尺寸恒=设计尺寸 + 完整落在底栏矩形内」两条断言。
- **4 个超宽弹窗**（战魂/称号/军衔 880、商城 850）：`GameUiHelper.fitDialogToVisible` 等比缩小兜底（只缩根节点；Draggable 用 getUIDelta 改 position，与自身 scale 无关，拖动不受影响；横屏下系数恒 1 行为不变）。放 helper 而不是 addDialogToUILayer：确认框带全屏遮罩不能缩。
- **新发现的真问题**：全屏背景原来「拉伸到设计分辨率」，竖屏后 1920×1080 横图会被竖向拉长 ~2.6 倍 → `UiHelper.createFullScreenNode` 改 cover（图到位后 contentSize 换素材原始尺寸 + `max(designW/nativeW, designH/nativeH)` 等比放大；换竖版素材后比例自然趋近 1，代码不用再动）。
- 单测垫片同步三处：test-scene-stage（DESIGN/SCREEN_SHIM/用例 C/WINDOWS 重排成竖屏代表）、test-good-detail-placement、test-joystick；`test-mall`/`test-dialog-top` 不引用分辨率、不用改。
- `make verify` 全绿（含七套 e2e）后提交 `47fc864`，PR #135。


## 项目约定（Cocos Creator 3.8.7 游戏 olua）
- 组件一律 `export default class X extends Node`（RoleDisplay 写法）：构造函数里建 UI，不导出预建单例实例，哪里用哪里 `new`；文件/类名不带 Frame 后缀，且**文件名必须与类名完全一致**。跨组件共享用 RoleUIManager 注册表或构造注入（Game.ts 是组合根）。
- 管理器（core/：GameHelper/LayerManager/MonsterManager/DropManager/RoleUIManager/SceneManager/SkillManager/StorageManager）与 helpers（UiHelper/GameUiHelper/AnimationHelper）全部是静态类：`export default class X` 全 static 成员，直接 `import X from "..."` 后 `X.method()` 使用，不实例化；弹窗为普通 class，实例由 BottomBar/npc 点击处创建。怪物数据与节点统一由 MonsterManager（Map<Node,Monster>）管理，怪物节点一律挂 MonsterLayer；图层位值 Layer：MAP=1<<0、DROP=1<<1、GAME=1<<2、MONSTER=1<<3、EFFECT=1<<4、UI=1<<5。
- cc.Node 子类注意：字段名不能叫 up/right（与 Node 内置属性冲突）；`this` 传给 Node 参数需 `this as Node` 断言（isChildOf 型变）。
- 分层：ui/core（全局管理器）、ui/components（**按职责分子目录**：hud/ 常驻 HUD、panel/ 弹窗内可复用面板块、dialogs/ 弹窗、role/ 角色显示与外观、input/ 键盘鼠标输入采集、map/ 地图与生成器）、ui/controllers（场景 Component 控制器）、ui/helpers（UI 工厂，仅 3 个）、ui/utils（纯工具）、assets/entities（运行时实体，如 Role）、assets/skills（技能行为实现）、configs（纯静态数据，按域一文件）、types（纯类型，按域一文件）。configs 与 types 不互相依赖 UI 层。容器组件只做聚合与转发（如 BottomBar 组合 navBar/expBar/hpOrb/shortcutKeyBar 并对内转发 update），具体渲染交子组件。ui/utils 按功能域分子目录、一律**具名导出纯函数**（不 default 对象、不带 Helper/Util 后缀）：battle/BattleMath、drop/DropRoller、map/MapPointMath、map/TiledObjects、physics/ObstacleCollider、resource/ResourceLoader、input/Pointer（`bindPointerAction`：鼠标环境用 MOUSE_UP 分左右键、触屏环境用 TOUCH_END 回调左键，**二选一**，因为引擎会把鼠标事件无条件模拟成 touch，两者同监听会重复触发）、cursor/CursorPainter（形状栅格化成 CSS cursor）、node/NodeTree（`clearChildren`）。
- helpers 仅 3 个，不要新建更多：UiHelper（Cocos 基础组件封装，只被 GameUiHelper 引用）、GameUiHelper（UI 零件库）、AnimationHelper（帧动画加载/切割/播放）。新 UI 方法按语义归入对应类；类内用 //#region 分块。规则：生成 UI 样式的代码只允许出现在 UiHelper/GameUiHelper 中；**GameUiHelper 只做单个可复用零件（如 createCurrencyItem/createCombatPower/createEquipmentSlot），不做整页视图生成，拼接组装由各组件自己完成**（需要数据刷新的零件返回 {node, xxxLabel} 形式）。物理碰撞体（RigidBody2D/BoxCollider2D）与 LayerManager 图层容器不算 UI 样式。
- 移动 assets 下文件必须连同 .meta 一起移动（保留 UUID，场景引用依赖它）；.meta 被 .gitignore 忽略（风险）。
- 组件化改造（2026-09-30 完成）：原平铺的 11 个 components 文件拆为 24 个语义化文件。hud/：BottomBar（容器）/BottomNavBar/BottomNavButton/RoleInfoBar/RoleExpBar/RoleHpOrb/ShortcutKeyBar/ShortcutKeySlot/MonsterInfoPanel；panel/：EquipmentSlotGroup/RoleAttributeList/RoleInShowView/BagGridView；role/：RoleDisplay/RoleAppearance；input/：ScreenClickInput/RoleKeyboardInput；map/：GameMap/MapObjectSpawner；dialogs/：RoleInfoDialog/BagDialog/SkillListDialog/SkillShortcutSettingDialog/MapTeleportDialog。子组件的 Node 命名与类名同风格（ShortcutKeyBar → "shortcut_key_bar"）。
- 场景/地图切换一律走 SceneManager.loadScene → Loading 过渡场景（一行文字显示百分比）：场景预加载 0~90%，进 Game 前预载当前地图 TiledMapAsset 90~100%，完成后才进入目标场景；地图切换=保存 onMap 后重进 Game 场景（不存在原地换图）。给场景挂脚本组件：手写脚本 .meta uuid，scene JSON 用压缩 uuid（前 5 hex + 27 hex→108bit base64 18 字符）。
- 静态类跨场景持有节点（LayerManager 图层容器）时必须在 initLayer/进场景时重建（旧场景销毁会连带销毁静态节点，否则黑屏；把已销毁容器 addChild 到新场景会在 Node.walk 读 null children 直接崩溃）；重建实现为 private createLayer(scene,name,layer)。该逻辑曾因编辑器回写丢失并复现崩溃——**Cocos Creator 编辑器运行时会周期性把「上一代」内容回写覆盖外部修改，症状是文件里新旧内容混合、tsc 报出行号对不上**（2026-09-30 重构 ui/utils 时再次复现：同一批 Edit 里靠后的修改存活、靠前的被回写覆盖）。改完 assets 下文件必须 sed/Read 核对磁盘实际内容，并**延时几秒再复检一次**，被覆盖的重新施加。相机等由 Game.start 重新注入。全局 input 监听（RoleDisplay 键盘、ScreenClick 鼠标）必须随节点销毁移除（NODE_DESTROYED once / Game.onDestroy），RoleUIManager 的视图引用也要在 Game.onDestroy 里 clearViews() 清空。
- GameMap 自身即地图节点：先 await 地图 TiledMapAsset 加载完成，再 addComponent(TiledMap) 挂到自身（组件挂上即地图已就绪，不会黑屏）；不通过 helper 创建地图子节点（UiHelper.createMap/GameUiHelper.createTiledMap 已删）。loadMap 里 TiledMap 挂载后依次：MapObjectSpawner 生成 npc 对象组（NPC + 复活点）→ CollisionAreaSpawner 生成 collision 对象组的碰撞区 → goToRevivePoint(spawner.getRevivePoint())。**loadMap 里任何一步都不许抛异常**：它是无人 await 的 async 函数，throw 会静默 reject 并中断其后所有生成（2026-09-30 踩过——复活点读不到已删除的 objects 组直接 TypeError，导致 NPC 与碰撞区一起不显示）；复活点缺失只 console.warn。
- 地图对象组约定（Tiled 侧）：点位统一画在 **npc 对象组**，用自定义属性 `type` 区分用途——`type=npc`（配合 `id` 属性指向 configs/npc 的键）生成 NPC，`type=revive` 作为复活点（只记录坐标、不建节点）；`monster` 对象组是矩形刷怪区（id/min/max），`collision` 对象组是矩形碰撞区。旧地图（0.tmx）仍把 NPC/复活点画在 `objects` 组、复活点靠 `name=revive` 标记，代码经 `getTiledObjectsFrom(map, "npc", "objects")` 兼容两代命名。
- **Tiled 对象坐标换算（两次踩坑，最终结论）**：Tiled 原始坐标 = 左上角原点、y 轴向下；地图节点本地坐标 = 中心原点、y 轴向上 → `getMapPointPosition` = `(x - W/2, H/2 - y)`，矩形先取几何中心 `(x+w/2, y+h/2)` 再换算（`getMapRectCenterPosition`），地图像素尺寸走 `getMapPixelSize(map)`。**前提是入参必须为 Tiled 原始坐标**：引擎 `TiledObjectGroup._init` 会把 `object.y` 原地改写成「地图像素高 - y」，`getObjects()`/`getObject()` 给到的已是改写后的值，原始值只留在 `object.offset` 里（同一循环里赋值，二者必然同时存在）→ 因此读对象组一律走 `TiledObjects`（取 `object.offset`，保证原始坐标）。等价写法：直接用运行时 y 则用 `y - H/2`（旧提交 979b2e7 的复活点定位就是这么写的，属于正确实现）。**两套写法不能混用**：只改公式不改取值来源 = 翻两次 → NPC/碰撞区上下镜像（南北围墙互换）。四周都有围墙时镜像肉眼几乎看不出，必须做语义自检（叫「北/上」的对象换算后 y 必须 > 0）或与历史可用公式对齐数值。
- Tiled 对象组读取**唯一入口** `ui/utils/map/TiledObjects.ts`：`getTiledObjects(map, 组名)` 把引擎记录收敛成 `TiledObject`（id/name/**objectClass（Tiled 对象类，从 tmxXmlStr 读出）**/x/y/width/height/properties，**坐标为 Tiled 原始值**：取 `object.offset` 而非被改写过的 `object.y`），**组不存在返回空数组**，调用方不必判空（引擎 `getObjectGroup` 返回 null，旧写法 `.getObject(...)` 会直接 TypeError）；`getTiledObjectsFrom(map, ...组名)` 取第一个非空组做命名兼容。RECT/点类型引擎不会自动建节点，需自己换算坐标建节点；碰撞体一律走 `addObstacleCollider`（Static RigidBody2D + BoxCollider2D，size 取节点 UITransform），节点名称带 Tiled 对象名便于在层级里定位。点位识别不到对象类时 MapObjectSpawner 会 console.warn 打出对象名（避免 Tiled 漏设 Class 时静默不生成）。
- **碰撞范围可视化统一入口 `GameUiHelper.showColliderRange(node, name?, kind?)`**：读节点上 BoxCollider2D 的 size/offset 绘制范围框（Graphics）+ 名称与尺寸（Label），因此显示范围与引擎实际判定永远一致；开关只有 configs/debug.ts 的 `debugConfig.colliderRange` 一个（默认开），全部碰撞体——Tiled 碰撞区（CollisionAreaSpawner）、NPC（MapObjectSpawner）、怪物（MonsterManager.createMonsterNode）、角色（RoleDisplay.addRigid，kind 传 "role" 用绿色区分）——都在挂完碰撞体后调用它；没有碰撞体的节点（掉落物只按距离拾取）自然无框。
- Cocos 调试显示 / 动态加 UI 的三条坑（已踩，见引擎 layout.ts `_checkUsefulObj`）：① 目标节点自身是 Layout 容器时（如 NPC 的 npc_node 是 flexCol），后加的子节点会被 Layout 重排 → 用 `UiHelper.createGroupNode`（不带 UITransform 的纯分组节点；Layout 只排列带 UITransform 的子节点，故不会被重排、内部 Label 照常渲染，LayerManager 图层容器同理）；② 图层**已自动继承**：`LayerManager.setNodeToLayer` 除递归设层外，还会为整棵子树注册 `Node.EventType.CHILD_ADDED` 监听（引擎在 `_setParent` 里 `newParent.emit(CHILD_ADDED, child)`），此后动态新建的子节点（背包刷新、装备槽换装、属性列表重建、怪物面板切目标）会自动对齐父节点图层——**2026-09-30 之前的症状是「挂载后新建的子节点留在 DEFAULT 图层（相机 visibility 不含）→ 界面内容整块消失、必须关掉弹窗重开才显示」（背包/个人信息弹窗刷新全军覆没）**；只有当节点不在任何图层容器子树内（如编辑器场景里手摆的节点）才需手动 `setNodeToLayer(node, parent.layer)` 兜底；③ 重建式刷新**不能用 `node.removeAllChildren()`**：引擎实现只是 `child.parent = null`（只摘除、不销毁），每次刷新都会留下未销毁的残留节点，且依赖 `NODE_DESTROYED` 收尾的逻辑不会触发 → 一律用 `ui/utils/node/NodeTree.clearChildren(node)`（先摘除再 destroy）。Graphics 画在节点自身不受 Layout 影响，且其坐标与 BoxCollider2D 同系：都是「节点本地坐标 × 节点世界矩阵」，矩形即 `rect(offset.x - w/2, offset.y - h/2, w, h)`，两者都不受 UITransform 锚点影响（角色节点 anchor 0.5/0 而碰撞体 offset (0,35)，画的框与真实碰撞仍然重合）。
- 技能系统：触发统一入口 SkillManager.release(skillId)（校验/冷却按角色 speedRate[config.action] 折算/单体目标自动补全/距离校验）；技能实现签名 (context: SkillContext) => void，只依赖上下文不反查全局；上下文由 RoleDisplay.buildSkillContext() 组装、Game.ts 组合根 setContextProvider 注入；动画播放动作取 config.action（playSkillAttack(action, direction)）；受击结算走 MonsterManager.hurt；伤害计算走 BattleHelper.calcSkillDamage。键盘/鼠标类全局事件必须挂 input 单例（节点上监听不到 KEY_DOWN）。
- 选中怪物的唯一入口是鼠标点击（ScreenClickInput 全局 input MOUSE_UP，**只处理左键**，右键留给界面操作，否则右键点背包会顺带拾取掉落/选中怪物 → RoleDisplay.setTarget(node|null) → RoleUIManager.selectMonster 创建/销毁面板）：点击怪物选中、点击其他位置取消；移动/走路/攻击都不影响选中；目标死亡或移除时由 RoleDisplay.update()（Game.update 每帧驱动，内部先 isValid(target) 校验再 updateWorldPosition）自动 setTarget(null)。选中期间 MonsterInfoPanel 面板一直显示。
- 动态面板（怪物信息面板 MonsterInfoPanel）：core 不直接依赖 components——组合根注入创建器 RoleUIManager.setMonsterInfoFactory((target) => {new + addToUILayer})，选中怪物时创建、取消选中/目标失效/场景卸载（Game.onDestroy）时销毁（RoleUIManager.destroyMonsterInfo）；每帧刷新走 RoleUIManager.updateMonsterInfo()（面板 update() 返回 false 即销毁）。Node 子类没有 node 属性（node getter 在 Component 上），存活校验用 isValid(this)，对外暴露 isValidNode()。
- 物品体系：物品大类 GOOD_TYPE（EQUIPMENT/DRUG/MATERIAL/OTHER），装备槽位 EQUIPMENT_TYPE 挂在 Equipment.slot 上；物品一律按 id 引用，统一登记在物品总表 configs/items.ts（registerItems 按 prefix_序号 生成 id，装备前缀 cloth/weapon/ring/necklace/shoes/helmet/belt）；getItem(id) 返回浅拷贝（防运行时 count 污染配置）。新增物品先写 configs/{drug,material,equipments}.ts 再在 items.ts 注册。
- 物品使用与装备穿脱（2026-09-30 定）：**统一入口 `StorageManager.useGood(row, col)`** 按 GOOD_TYPE 分发（装备→`equipFromBag` 穿戴、药品→`useDrug`、其余提示暂未开放），新类型只在这里加一条分支；`equipFromBag` 把脱下的旧装备放回**刚腾出的原格**（格数守恒，换装不丢装备）且入槽存 `{...good}` 副本；`unequipToBag(slot)` 用 `findEmptyBagCell` 找第一个空格、满包只提示不动作；两者都走私有 `applyEquipmentChange` 统一收尾（combatCalc → `role.hp = Math.min(role.hp, role.maxHp)` → 落盘 → updateUi/主角外观/角色信息弹窗槽位+属性列表+内观/背包）。可穿戴校验与提示文案唯一来源 `GameHelper.getEquipmentRejectReason`（等级/性别/职业）。UI 侧规则一律不下沉：BagGridView 只上报 `(row, col, "use"|"equip")`，BagDialog 翻译成上面两个方法；装备槽右键脱下由 RoleInfoDialog 注入 `StorageManager.unequipToBag`。
- 掉落体系：怪物配置 MonsterConfig.drops?: DropSource（string 引用 configs/drop 的具名掉落表，或内联 DropTable；未配置走 defaultDropTable）；结算纯逻辑在 ui/utils/drop/DropRoller.rollDropTable（权重 picks 次 → chance → count 区间 → 同 id 合并）；节点与拾取在 ui/core/DropManager（Map<Node,DropItem>，drop/getClickedDrop/pickup/reset），掉落物挂 Layer.DROP 层（LayerManager 有 DropLayer，相机 visibility 必须含 Layer.DROP）。怪物死亡在 MonsterManager.hurt 的 hp<=0 分支先 drop(monster.drops, target.getWorldPosition()) 再 destroy（取位置须在销毁前）；点击拾取在 ScreenClickInput 中优先于怪物选中判定。
- 角色输入三分：RoleKeyboardInput（只采集按键，暴露 isXxx getter）、RoleAppearance（布衣/武器动画与外显，动画 FINISHED 回调 onAttackFinished）、RoleDisplay（组合体，管动作/方向/位移/攻击锁/选中目标）。新加输入或外观逻辑按此归位，不要再往 RoleDisplay 堆。
- 数据读写坑：StorageManager.findOnlineRole() 每次从 localStorage 反序列化出新对象，同一操作内必须复用同一实例（如 useDrug 里 consumeBagGood 要显式把 role 传进去，否则消耗不落盘）；批量改装备等数据后统一 updateOnlineRole + updateUi + RoleUIManager.refreshBag。
- 怪物 AI 分层（2026-09-30 定）：**MonsterManager 只管数据与生命周期**（生成/spawnByAreas/查询/受击结算/reset，Map<Node,Monster>），**MonsterAI（ui/core/MonsterAI.ts，静态类）管行为与动画**（每帧 tick(monsters, player)，由 Game.update 在主角位移之后调用；replayCurrent(node) 由怪物动画 FINISHED 事件调用）。每只怪的状态存在 MonsterAI 的 `WeakMap<Node, MonsterAIState>`（节点销毁自动回收，怪物数据上不挂字段）。怪物移动走**运动学刚体 + linearVelocity**（`ui/utils/physics/MonsterCollider.addMonsterCollider`，与主角同一套做法；静态体挪不动，别再用 addObstacleCollider 做会动的怪）。怪物配置字段：`moveSpeed`（= 刚体线速度，与 ROLE_WALK_SPEED 同单位）/ `aggressive` / `detectRange`（像素），全局节奏在 configs/monster 的 `monsterAI`。**动画铁律**：AnimationHelper 建出的 clip 都是 WrapMode.Normal（播一次即停），循环靠「FINISHED 里 play(当前动作名)」续播 → AI 只在动作/朝向变化时 crossFade，**绝不能每帧 play**；且怪物帧资源只有 stand/walk/run/test1 八向齐全（attack_near 仅部分方向）→ 切动作前必须 `animate.getState(name)` 守卫并回退 stand。怪物打玩家：`applyHitDamage(role, monster)` + `GameUiHelper.showDamageText` + `StorageManager.updateOnlineRole/updateUi`，只在结算时 `findOnlineRole()`（不要每帧读存档）。
- **谁推动谁（2026-09-30 二次迭代定）**：主角是**动态刚体**、怪是运动学刚体 → Box2D 里运动学体质量无限大，会把动态体主角**顶开**（症状：怪追人时把角色推着滑）。修法：怪物的 BoxCollider2D 一律 **`sensor = true`**（有形状、无碰撞响应 → 谁都不推动谁；形状仍供 BattleMath 读 worldAABB 与调试范围显示），"角色不能穿过怪物"由 `ui/utils/physics/MoveBlocking.ts` 手动补：`resolveBlockedVelocity(node, 速度, 阻挡盒[])`（速度×帧时长预估位移，整体被挡再试单轴滑动；**已重叠的阻挡物放行**，否则怪贴上来会把角色卡死）。角色侧在 `RoleDisplay.updateWorldPosition` 传 `MonsterManager.getBlockingRects()`；怪物只在**待机游走**时避开玩家（追击不套阻挡：attackRange 常小于双方体积之和，一挡大体积怪就永远够不到攻击距离）。**击退是唯一能推动位置的途径**：`MonsterAI.push(node, dir, distance, duration?)`（状态 pushEndAt/pushDirection/pushSpeed，tick 里优先级最高并打断普攻；受伤动作属"一次性动作"，replayCurrent 里要单独回 stand 否则一直续播），技能侧在 SkillConfig 写 `push?: { distance, duration? }` 由 SkillManager 对单体目标统一施加（SkillMonsterProvider.push）。引擎事实：Collider2D 的夹具在 `onEnable → PhysicsSystem2D._callAfterStep(_init)` 才创建，`_init` 一次性读 comp.size/offset/sensor → **addComponent 同帧赋值有效，之后再改必须 `collider.apply()`**（`set size/sensor` 只改组件字段、不碰夹具）。
- 新增 assets 下文件必须同时生成 .meta（复制现有同类型模板，uuidgen 生成新 uuid），否则编辑器会重新分配 uuid。

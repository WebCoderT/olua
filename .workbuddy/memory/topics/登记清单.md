> 从 `memory/MEMORY.md` 迁出（原「改数据的登记清单」节），保持原口径。
> 判据：**PATCH 返回 200、库里没变、结算不动** = 又漏了一处。

## 新增一张表（四处登记 + 一处条件）
- `server/scripts/lib/config-tables.cjs` **两份**清单（`CONFIG_TABLES` / `RUNTIME_TABLES`）。
  ← 现在有守点了：`e2e-guard` 拿系统信息页的 `sqlite_master` 全量清单做**双向**比对（2026-11-15 #438 补），
  漏登记会当场红并指名道姓；但守点只管「归类」，不管「该不该跟 git 走」。
- `tools/gen-api.cjs` 的 `MODULES`。
- `tools/audit-server-boundaries` 的 `REPO_EDGES`。
- `tools/audit-target.decorator`（controller 的 `@ApiAdminDoc` 权限点表）。
- **横切服务**再加 `ALLOWED_EDGES` —— 只在 `make audit` 里，`npm run verify` **不跑**，容易漏。

## 新增一个权限点（四处）
1. `server/src/common/constants/permission.ts`：`Permission` 枚举 + `PERMISSION_LABELS` + 哪些角色默认带它
   （`AdminRole.ADMIN` / `SUPER_ADMIN` 的过滤清单 —— 漏了就是「超管少一个点」）。
2. `admin/src/api/types.ts`：`PERMISSION` 常量 + 中文标签（`RequirePermission` / 导航用）。
3. `docs/03`：权限点**个数** + 代码块里那一行。
4. `server/test/e2e.cjs`：「普通管理员比超管少哪些点」的差集断言串。

## 新增一个审计目标（三处）
`AUDIT_TARGET_TYPES`（`audit-target.decorator.ts`，唯一来源）→ `admin/src/api/types.ts` 的 `AUDIT_TARGET_LABELS`
→ `audit.dto.ts` 里 `targetType` 的 description（枚举文案会漂）。装饰器值必须与常量**逐字一致**（tsc 只认联合类型，
`"game-mail"` vs `"gameMail"` 是编译错，不是运行时错）。

## 新增一个 env 键（四处 + 两处门禁）
`configuration.ts`（含范围收敛）→ `.env.example`（`audit-api-hardcode` 会数）→ `config-snapshot.ts`
（信息页可见，`describeLimit` 写单位）→ `e2e-guard` 的 `EXPECTED_CONFIG_KEYS`（漏了 = 快照白名单红）。
另：进 `tools/config-leak-allowlist.json` 只在这类键会被前端读时才需要。


## 新增一列（三处代码 + 两层契约）
1. `CREATE TABLE` 里的列。
2. `migrate()` 里的 `ensureColumn`。
3. 仓储 `rows.ts` + **写入列清单**（`update()` 的 SET 列 / `INSERT` 列数组）。← 漏这里最隐蔽。
4. DTO 字段 + `from()` 映射。
5. 客户端 `types` / `game-config` 区（只有在进快照时才要）。

## 快照加一段
DTO / `snapshot()` / 客户端 `game-config` 区 0 / `configs-sandbox` 三处 / `audit-snapshot-contract`。

## 新道具表
要让 `sellPriceOf` / `itemLabelOf` / `itemTypeOf` 都认识，否则回收价与解析静默失效。

## `config-sync.sql` 加表
只拼**新增节**的 diff + 手改表头三行；`cp` 库前先 `PRAGMA wal_checkpoint(TRUNCATE)`。

## 改 DTO
连 `description` 都算改契约 → `swagger:emit` + `node tools/gen-api.cjs`；Response DTO 要进 `swagger/models.ts`。

## 改列名（不是加列）
`renameColumnIfExists(table, from, to)` 幂等改名（`PRAGMA table_info` 判存在 + 新名已存在则跳），放 `migrate()`
末尾；**别删列重建**（存量数据如已发奖励金额会丢）。改名后五处一起改：DDL / `rows.ts` / 仓储 SQL / DTO / 测试字面量
（#926 货币命名）。

## 新功能的出厂「行」不是加列
快照只在**空库首启**整份灌一次，新增配置行在存量库里根本不存在（症状：功能静默不生效、无报错）→ 一次性补数据
`seedXxxOnce()` + `config_meta` marker，取值放 `common/constants/*-seed.ts`：`INSERT OR IGNORE` 补行 + **只在出厂
空值 / 0 时才写值**（#826 的 `seedCombatStatusesOnce`、#828 的 `seedSkillPointsOnce`）。

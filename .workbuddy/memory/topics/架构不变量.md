# 架构不变量（按域展开）

> 从 `memory/MEMORY.md` 拆出来的按域细节。MEMORY.md 只留一句话索引，查细节来这儿。

## 通用（服务端权威 / 一份数据一个来源）
- **服务端权威**：`@ApiAdminDoc({permissions})` · `BizException` 默认 400 · 乐观锁 409 + **20006** · 校验失败 **40000** ·
  失败响应 `data` 恒 `null`（带数量给 `details`）· 客户端零决策。乐观锁客户端口径「拉最新 + 丢弃本轮」，**不重推**。
- 方向恒 `apply-snapshot → game-config → types`（`configs/` 不引 UI）；`client-test` 基线红先怀疑本地 `network.ts` 硬编码 IP；
  `db.transaction()` 可重入。**一份数据一个来源**：库表 → 快照段 → `apply*` 整表重建（派生 Map 要重建，客户端零兜底）。
- 部分更新接口加数组字段要区分「显式传」与「存量漂移」，否则扩档旧调用被 400 卡死（#720）。
- 客户端只报格子、数值直读表（#785）；「玩家在哪」= `data.mapAt`；改 bag 收尾必须 `refreshBag()`；
  `Array.from` 替 `[...map.values()]`、不用 `Object.entries`、`Map` 吃不下 `Partial<Record<>>`。
- 资源目录 `client/RESOURCES.md`；改名三处同源：磁盘 + plist → 库 19 个路径列 + `config-sync.sql` → 客户端 configs。
- **纯服务端消费的参数别并进 `RuntimeParamsDto`**（那是客户端快照的形状，加一段动五处）。

## 战斗（#822~#825）
① 状态唯一在 `combat/status-combat.ts` + `role_status`，`category="2"` 在目标校验**之前**分流；
② 物法分离看系数 `baseType`，不另开 `damage_type` 列；③ 目标形态看 `target_type` + `require_target`，区域/群体命中
集合由**服务端**算（夹到 `skills.distance`、最近 8 只）；④ `collectEquipmentBundles` 是装备属性公共入口（只算不改档）。

## 状态层两侧（#826 第三批，见 `olua-server`）
① 角色状态落 `role_status`（跨进程，`ticked_at` 只初始化一次）、怪物状态在 `MonsterRuntime.statuses`（Map，冻结/重生即重建），
两端各一个 `activeStatuses()` 管「刷层/到期/周期/控制」；② 控制判据两处**各自独立**：出手 `cast-guard` 第「一·五」道 →
`rejected: "stunned"`；移动 `presence.movementLocked()` → 只更新 hp + `moving=false`，**仲裁基线不动**；
③ 眩晕与麻痹是同一条 `{stun:1}`，只是时长/图标/来源不同；④ 怪物侧周期伤害**夹到至少留 1 血**（tick 没有 `castId`，
打死就是死账）；⑤ 拉人与击退**互斥（推优先）**，回执给 `applyPull` 返回的**实际**位移；
⑥ 两段连击 = 第一段 × `second_hit_ratio`，不单独掷区间/判暴击。

## 等级差压制（#826 落 / #834 系数配置化）
`sup = max(0, 1 − K × max(0, 目标等级 − 攻击者等级))`，乘在**扣防之前**（先按等级压「能打出多少」再减防）；
`K = growth_scalars.levelGapSuppress`（0~1，出厂 0.05；0 = 关闭、1 = 越 1 级就打不动），缺行/负数回落出厂；
`gap ≤ 0` 短路返回 1（同级与打低级怪既不惩罚也不加成）。回执带 `suppressed`（单体顶层 / 区域 `hits[i]`），
客户端据此飘「等级压制」而不是「伤害 0」。与经验侧 `maxLevelGap` 是两条独立的线。
**命中侧没有**：服务端每发必中，没有 `hitRate` / `dodge`（暂时放置，重开条件见 docs/22 §2.2）。

## 怪物 AI（#853~#858，见 `olua-server` 四之十三补）
位置与血量**唯一副本在 `PlayerPresenceService`**（`markHp` 不刷 `updatedAt`）；`state = idle/chase/return`，
**牵引半径判定放在出手之前**，`endChase` 是脱战唯一收口（清 target + 清 `provoked`）；移动 `slideMove` + `clampToMap`，
击退 `pushPoint`（被挡原地）；**卡住门槛 0.01px 不是 1px**（出厂 `move_speed` 2px/s 每帧 0.1px）；没人看只冻结 10 分钟后回收；
`applyPush` 依赖在场表（超时的人推不动）。

## 背包与装备（#835~#842，见 `olua-server` 四之十六）

存量脏格唯一出路是**穿戴拆散**（空格不够整步失败 20012 不落库）；**单格上限唯一出口 `resolveMaxStack`**
（装备 1 / 四表各读 / 认不出 99），禁止就地写默认值；move/tidy 三层判据（形状 → 绑定守恒 → `findOverstackedCell`）。
**管理端 PATCH 角色三条收口（#836）**：槽位键大小写归一 + 存在性/部位裁决；PATCH 完属性当场重算

（`applyBagCells` 会整体洗白绑定，别退回去）。admin 引 role-inventory/role-authority/combat 三条白名单边已登记，别删。

## 装备穿戴规则（#838，见 `docs/05` 七）

## 任务交互与周期（#862~#865，见 `olua-server` 任务章）

## 成长线两条点数（技能点 #828 / 属性点 #833）

## 刷怪密度（#930）
表单只有「数量」= `max`，`min` 恒 0（老库 `min = max` 一次性抹平，否则下限顶死系数）；目标
`clamp(round(max × 时段系数 × 人数系数), min, max × density_peak)`，人数取**本图观看者**；tick 每秒差量对齐、
每 tick 至多补 2 只、超出裁「死等重生 → 最久没被攻击」的，`lastDamagedAt` 5 秒内不裁；统计用**实例数**不用存活数
（否则打一只变两只）。公式唯一副本 `common/utils/spawn-density.util.ts`（管理端 `targetNow` 与 tick 共用）。
`world_monsters.area_id` 记归属（老档 `findAreaAt` 回填），删区按它清孤儿。代际作废只对「有人看且库里有行」的分域
重载（0 行不重播，否则合区白做），合区后 5 分钟只补不裁。越界区不整区丢弃：先取「区域 ∩ 地图」，整块在图外才退回
原区域取点再 `clampPointToMap`。

## 移动三道校验与寻路（#811）

**参数**：`runtime_params.movement`（单行表第 6 列，`ensureColumn` 补存量库），六个键
`mode / maxSpeed / tolerance / jitterPx / wallCheck / correctIntervalMs`。`MovementGuardService.params()`
**每次现读库** → 改完下一次判定即生效（热切）。**不进客户端快照**（跟 `monster_ai` 同理：纯服务端消费，
给了客户端只会长出第二套逻辑），走独立接口 `GET|PATCH /admin/runtime-params/movement`。

**判据**：`dist > maxSpeed × tolerance × clamp(Δt,0,5s) + jitterPx + credit` → 拒；`crossesWall` 相交 → 拒。
出厂 `maxSpeed 400 / tolerance 1.35 / jitterPx 24`。**服务端没有角色移速属性**（移速只在客户端刚体
`ROLE_WALK_SPEED=2` / `ROLE_RUN_SPEED=4`，按 PTM 32 约 64/128 px/s）→ `maxSpeed` 是全局尺子，别去「抄客户端数字」。

**三档 `mode`**：`off`（连判都不判，回滚用）/ `log`（**出厂**，照判照接受 + 60 秒一行 warn 汇总）/ `enforce`（拒帧 + 回拉）。
**读不到配置时的兜底是 `off`，与出厂 `log` 刻意不同** —— 配坏了不该全服拦人。

**单帧即拒 + 立刻回 `posCorrect`**（推翻 issue 里「连续 3 次才拉回」）：不回帧的话客户端以为自己还在那、继续往那边走，
服务端一直拒 → 越走越远无限不同步。回的是 **`entry.x/y`（上一次被接受的坐标）**，不是「把本帧夹到上限」
（夹出来的点可能在墙里，且让作弊者每帧白赚一段距离贴着上限蹭墙）。节流 `correctIntervalMs`（500ms）。

**合法大位移只有三个出口**，都不靠「连发两帧」：① 换图 —— `join()` 重置基线；② 复活 —— `hp` 从 ≤0 变 >0 那一帧一律接受
（复活走存档进程 HTTP，实时进程不会被告知，判速度必然误杀）；③ 突进技能 —— 一次性 `posCredit`，上界
`CAST_DISPLACEMENT_MAX = 320`，且**只在结算成功之后**给（写在前头等于「报个远点就换一次瞬移，冷却都不用等」）。

**穿墙的宽松侧一律留给误判**：`blockedIn` 用**原始盒**（不外扩 `clearance`）、几何读不到就不判、
**起点在盒里不判**（数据坏了不能把人卡死）。出图即算撞墙。

**两端同一张网格**：`MapGeometryService.buildGrid` 与客户端 `PathGrid.stampRect` 逐行对齐（`clearance` 外扩、
**格子中心**落盒、`originY = -height`、octile 启发、禁切角、起点 4 圈 / 目标 6 圈吸附、`cellSize/2` 视线采样拉直）。
格子口径**复用** `runtime_params.auto_battle.cellSize / clearance`（40 / 20），不另开一套 —— 另开必然出现
「客户端算得到、服务端说不可达」。

**寻路**：`pathFind { mapId, to, seq }` —— **起点不传**，服务端自己从在场表取（客户端说了不算），100ms 防刷。
`path` 帧 `seq` 对不上客户端直接丢。客户端本地 A* **保留作即时预判**（点了立刻有反应），服务端那份负责正确性。
**怪物不给寻路**（仍 `slideMove` + `clampToMap` 直线 + 卡住重选）—— 145 只怪各跑 A* 直接打满单核。

**客户端纠偏**：`posCorrect` → 差 < 64px 记目标按 34%/帧插值、≥ 64px 瞬移，两档都先 `stopRigidBody()`
且**作废当前路点**（否则一边被拉回一边朝旧目标走）；`updateWorldPosition()` 第一行短路，不让本地刚体把权威位置推回去。

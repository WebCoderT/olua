
## #680 音效配置进管理端（PR 待合）

用户要求：「管理端添加音效配置，先加两项 —— 登录场景背景音、登录场景点击登录按钮音；
**先不与客户端对接**，等配置好再对接。音乐位置是 resources/sounds」。
后续补充：「还是只允许英文名，中文名称只是临时放进去，没有想好名字」。

### 做了什么
- 表 `audio_settings`（`audio_key` 主键 + `file_path / volume / loop / enabled` + 追账），
  行由 `AudioSettingService.onModuleInit` 按 `AUDIO_DEFAULTS` 补（`INSERT OR IGNORE`），
  **没有新建 / 删除**（key 由客户端播放入口决定，与 `ui_effects` 同取向）。
- 接口 `GET /admin/audio-settings`（gameConfig:read）+ `PATCH /admin/audio-settings/:id`（write，
  `@AuditTarget("audioSetting")`，新业务码 `50037` AUDIO_KEY_NOT_FOUND）。
- 管理端 `/audio`（`AudioSettingsPage`）：每项一张卡 —— 路径输入 + 「从目录选」+ **试听**
  （按表单当前值播，含音量与循环）+ 音量滑杆 + 循环 + 启用 + 保存 + 追账。
- 出厂值：`login_bgm` = `sounds/login_bg.wav`（音量 60 / 循环）、
  `login_click` = `sounds/click_button.wav`（音量 80 / 不循环）—— 都指向用户 00:30 刚放进
  `sounds/` 的真实文件，装完就有声音。
- 素材清单：`tools/gen-image-manifest.cjs` 现在一并产出 `resources/audio-manifest.json`
  （`{dir:"sounds", files:[带扩展名]}`）；dev 侧 vite 中间件加 `?audio=1`（带扩展名）+ 补音频 MIME。
- `config-sync.sql`：35 张表 / 3395 行（新增 audio_settings 两行）。

### 判据（下次别重新推）
- **路径入库是这个模块与特效管理的根本差别**：特效图集路径是两端约定（换美术要重打包），
  音效文件是运营挑的，所以 `file_path` 进库、带扩展名（客户端对接时去掉扩展名再 `resources.load`）。
- **服务端不检查文件是否存在**（资源包不在服务端，查了会掩盖「本地有、线上没有」）→
  **试听是这条链路唯一的验证手段**，这也是页面的核心交互而不是装饰。
- **文件名只允许英文**（用户定）：`^sounds/[A-Za-z0-9_\-/]+\.[A-Za-z0-9]+$`；空串 = 未配置（合法）。
  资源目录里现存 `木剑砍击音效.wav` 这类临时中文名 —— **选择器要过滤掉不合规文件名**
  （选完才 400 是最差的体验），并在旁边说明「另有 N 个文件名不是英文」。
- 本轮**不下发快照**：e2e 里有一条「`GET /game-config` 没有 audio 段」钉着；对接客户端时
  要一起改那条断言 + 在 `ClientConfigService` 加一段。

### 踩到的坑
- **`audit-api-hardcode` 会判红**：管理端 `fetch('/game-resources/...')` 直接写在页面里不行，
  提示文案里的 `http://localhost:8080` 也算硬编码地址。做法 = 单独 `pages/audioSettings/assets.ts`
  并在审计 `adminAssets` 白名单登记，页面里连 `fetch` 都不出现。
- **不要在页面里手拼试听地址**：`audioUrlOf(resRoot, filePath)` 收口在 assets 里。
- **从「全新库」导出的 config-sync 不能整份覆盖仓库里那份**：列顺序不同（历史 ALTER 加列 vs
  CREATE TABLE 顺序），会造出几千行假 diff。正确做法 = 只把新增表那一节拼进现有文件 + 改表头，
  再用「库副本」`config-import --db` 验证回读（`cp` 之前先 `PRAGMA wal_checkpoint(TRUNCATE)`，
  否则新表还在 -wal 里、副本里没有）。

### 合入结论
- PR #681 五个提交（服务端 / 管理端 / 工具 / 测试 / 文档）CI 全绿（静态 24s，四片 e2e 47s~1m48s），
  squash 成 `50c74d62`，远端分支已删，issue #680 已关。
- **留给用户的决定**：`sounds/` 下 10 个新音频还没进 `resources.manifest.json`（那是打包清单，
  与音效配置的 `audio-manifest.json` 是两份东西）—— 是否随下次发版一起带上，等用户说。
- **下一步（用户配置好之后）**：客户端播放入口 + `ClientConfigService` 加 `audio` 段 + 改
  `e2e-audio-config` 里「快照没有 audio 段」那条断言。

## #683 音效接客户端 + 扩到 11 项 + 分类（同一天下午）

用户要求：「把两个配置接到客户端，并加男生死亡 / 女生死亡 / 物品掉落 / 穿戴装备 / 金钱更新 /
传送成功 / 升级成功 / 战士普通攻击 / 背包物品顺序改变成功；中文名那个就是战士普攻，你重新命名并直接配置；
能全部统一对接就全部对接；对音效分类做 tab；美化页面」。

### 做了什么
- **11 项 / 4 类**（服务端 `AUDIO_KEYS` 按分类成组）：登录与界面（`login_bgm` / `login_click`）、
  战斗与角色（`warrior_attack` / `role_die_man` / `role_die_woman`）、物品与货币（`item_drop` /
  `equip_wear` / `money_change` / `bag_resort`）、成长与传送（`level_up` / `map_teleport`）。
  分类也写在服务端常量（与展示名同一处），**不进库**：库里是「运营改过的值」，分类是「清单本身」。
- **资源改名**：`木剑砍击音效.wav` → `warrior_attack.wav`（`.meta` 一起改，uuid 不变 → prefab 不断链）。
  `audio-manifest.json` 重生成（11 个）。`resources.manifest.json` 仍然 0 条 sounds（本机资源目录不入库）。
- **服务端下发两条路，同形状**（`AudioConfigDto`：key/filePath/volume/loop/enabled，**不带**展示名/分类/追账）：
  快照 `audio` 段（进游戏后）+ **公开接口** `GET /game-config/audio`（登录场景没有令牌，而背景音正是那时要响）。
- **客户端** `ui/core/SoundManager.ts`：常驻节点（`director.addPersistRootNode`）+ 两路 AudioSource
  （循环音 / `playOneShot` 一次音）+ clip 缓存 + 并发加载去重；音量走 `playOneShot` 的 volumeScale
  （`source.volume` 固定 1，否则调一个影响另一个）。11 处挂点全在「服务端确认之后」。
- **管理端**：4 类 tab（带计数）+ 概览四个数字 + 每项一行卡（左信息 / 右文件行 + 试听 + 音量 + 开关 + 保存）。

### 判据（下次别重新推）
- **`file_path` 是唯一允许服务端覆写的资源路径**（`configs/game-config` 开头那条「资源路径一律不覆写」
  的显式例外）：图集 / 帧动画按 id 拼（换美术要重打包），音效文件是运营挑的。
- **客户端没有本地兜底值**：`audioConfigOf(key)` 返回 null 就不播（表里没有 / `enabled=false` / 空路径），
  调用点不各判一遍、也不写 `?? 默认音量`。
- **响在「服务端确认之后」**：`equip_wear` 在 `runBagOp` 成功之后、`map_teleport` 在进入条件通过之后、
  `level_up` 在服务端给的 `leveledUp` 分支里。提前播会把「点了但被拒」演成「成功」。
- **掉落音一次结算只响一次**（按件播会在「一堆怪同时死」时叠成噪音）；金钱音只在三种货币**真的变了**时响
  （`applyServerRoleUpdate` 每几秒来一帧，无条件播会盖掉别的音）。
- **战士普攻按 `config.id === "1000"` 过滤**：`skill_1000` 被 1002~1011 复用（配置换动作与数值），
  烈火剑法 1001 也调它但那是技能音，不是普攻音。
- **`@Public()` 的正当理由只有一类**：玩家还没拿到令牌时就要用的数据（公告 + 音效），
  且里面没有任何玩家数据；有令牌之后别再走它（进游戏读快照，一个值只有一个来源）。

### 踩到的坑
- `Promise.finally` 在客户端编译不过（tsconfig lib 不到 ES2018，**TS2550**）→ 收尾用 `.then()`。
- `StorageManager` 加了 `import SoundManager` → **storage-sandbox 的 `STUB_IMPORTS` 必须同步**
  （否则 7 套存储单测一起挂在「Cannot find module './SoundManager'」）。
- 快照契约加段后 `test-snapshot-contract` 的夹具要补 `audio`，否则第一条断言就抛「缺段」。
- `audit-server-boundaries` 拦了 game-config → audio-setting 的 4 条跨域 import（加白名单边）；
  `audit-config-leak` 拦了 `new Node("sound_manager")`（进 allowlist，引擎侧身份）。
- **`make config-check` 现在红**，但红的是 `drop_tables`（库 5 / 文件 4）—— 用户自己正在改掉落，
  与本轮无关；**别整份 `config-export`**（会把用户手上的改动一起打包）。
- 新建 TS 资源要连 `.meta` 一起提交（uuid 由它承载；缺了 Cocos 下次打开会重发一个，prefab 引用可能漂）。


## #680 音效配置进管理端（PR 待合）

用户要求：「管理端添加音效配置，先加两项 —— 登录场景背景音、登录场景点击登录按钮音；
**先不与客户端对接**，等配置好再对接。音乐位置是 resources/sounds」。
后续补充：「还是只允许英文名，中文名称只是临时放进去，没有想好名字」。

### 做了什么
- 表 `audio_settings`（`audio_key` 主键 + `file_path / volume / loop / enabled` + 追账），
  行由 `AudioSettingService.onModuleInit` 按 `AUDIO_DEFAULTS` 补（`INSERT OR IGNORE`），
  **没有新建 / 删除**（key 由客户端播放入口决定，与 `ui_effects` 同取向）。
- 接口 `GET /admin/audio-settings`（gameConfig:read）+ `PATCH /admin/audio-settings/:id`（write，
  `@AuditTarget("audioSetting")`，新业务码 `50037` AUDIO_KEY_NOT_FOUND）。
- 管理端 `/audio`（`AudioSettingsPage`）：每项一张卡 —— 路径输入 + 「从目录选」+ **试听**
  （按表单当前值播，含音量与循环）+ 音量滑杆 + 循环 + 启用 + 保存 + 追账。
- 出厂值：`login_bgm` = `sounds/login_bg.wav`（音量 60 / 循环）、
  `login_click` = `sounds/click_button.wav`（音量 80 / 不循环）—— 都指向用户 00:30 刚放进
  `sounds/` 的真实文件，装完就有声音。
- 素材清单：`tools/gen-image-manifest.cjs` 现在一并产出 `resources/audio-manifest.json`
  （`{dir:"sounds", files:[带扩展名]}`）；dev 侧 vite 中间件加 `?audio=1`（带扩展名）+ 补音频 MIME。
- `config-sync.sql`：35 张表 / 3395 行（新增 audio_settings 两行）。

### 判据（下次别重新推）
- **路径入库是这个模块与特效管理的根本差别**：特效图集路径是两端约定（换美术要重打包），
  音效文件是运营挑的，所以 `file_path` 进库、带扩展名（客户端对接时去掉扩展名再 `resources.load`）。
- **服务端不检查文件是否存在**（资源包不在服务端，查了会掩盖「本地有、线上没有」）→
  **试听是这条链路唯一的验证手段**，这也是页面的核心交互而不是装饰。
- **文件名只允许英文**（用户定）：`^sounds/[A-Za-z0-9_\-/]+\.[A-Za-z0-9]+$`；空串 = 未配置（合法）。
  资源目录里现存 `木剑砍击音效.wav` 这类临时中文名 —— **选择器要过滤掉不合规文件名**
  （选完才 400 是最差的体验），并在旁边说明「另有 N 个文件名不是英文」。
- 本轮**不下发快照**：e2e 里有一条「`GET /game-config` 没有 audio 段」钉着；对接客户端时
  要一起改那条断言 + 在 `ClientConfigService` 加一段。

### 踩到的坑
- **`audit-api-hardcode` 会判红**：管理端 `fetch('/game-resources/...')` 直接写在页面里不行，
  提示文案里的 `http://localhost:8080` 也算硬编码地址。做法 = 单独 `pages/audioSettings/assets.ts`
  并在审计 `adminAssets` 白名单登记，页面里连 `fetch` 都不出现。
- **不要在页面里手拼试听地址**：`audioUrlOf(resRoot, filePath)` 收口在 assets 里。
- **从「全新库」导出的 config-sync 不能整份覆盖仓库里那份**：列顺序不同（历史 ALTER 加列 vs
  CREATE TABLE 顺序），会造出几千行假 diff。正确做法 = 只把新增表那一节拼进现有文件 + 改表头，
  再用「库副本」`config-import --db` 验证回读（`cp` 之前先 `PRAGMA wal_checkpoint(TRUNCATE)`，
  否则新表还在 -wal 里、副本里没有）。

### 合入结论
- PR #681 五个提交（服务端 / 管理端 / 工具 / 测试 / 文档）CI 全绿（静态 24s，四片 e2e 47s~1m48s），
  squash 成 `50c74d62`，远端分支已删，issue #680 已关。
- **留给用户的决定**：`sounds/` 下 10 个新音频还没进 `resources.manifest.json`（那是打包清单，
  与音效配置的 `audio-manifest.json` 是两份东西）—— 是否随下次发版一起带上，等用户说。
- **下一步（用户配置好之后）**：客户端播放入口 + `ClientConfigService` 加 `audio` 段 + 改
  `e2e-audio-config` 里「快照没有 audio 段」那条断言。

## #683 音效接客户端 + 扩到 11 项 + 分类（同一天下午）

用户要求：「把两个配置接到客户端，并加男生死亡 / 女生死亡 / 物品掉落 / 穿戴装备 / 金钱更新 /
传送成功 / 升级成功 / 战士普通攻击 / 背包物品顺序改变成功；中文名那个就是战士普攻，你重新命名并直接配置；
能全部统一对接就全部对接；对音效分类做 tab；美化页面」。

### 做了什么
- **11 项 / 4 类**（服务端 `AUDIO_KEYS` 按分类成组）：登录与界面（`login_bgm` / `login_click`）、
  战斗与角色（`warrior_attack` / `role_die_man` / `role_die_woman`）、物品与货币（`item_drop` /
  `equip_wear` / `money_change` / `bag_resort`）、成长与传送（`level_up` / `map_teleport`）。
  分类也写在服务端常量（与展示名同一处），**不进库**：库里是「运营改过的值」，分类是「清单本身」。
- **资源改名**：`木剑砍击音效.wav` → `warrior_attack.wav`（`.meta` 一起改，uuid 不变 → prefab 不断链）。
  `audio-manifest.json` 重生成（11 个）。`resources.manifest.json` 仍然 0 条 sounds（本机资源目录不入库）。
- **服务端下发两条路，同形状**（`AudioConfigDto`：key/filePath/volume/loop/enabled，**不带**展示名/分类/追账）：
  快照 `audio` 段（进游戏后）+ **公开接口** `GET /game-config/audio`（登录场景没有令牌，而背景音正是那时要响）。
- **客户端** `ui/core/SoundManager.ts`：常驻节点（`director.addPersistRootNode`）+ 两路 AudioSource
  （循环音 / `playOneShot` 一次音）+ clip 缓存 + 并发加载去重；音量走 `playOneShot` 的 volumeScale
  （`source.volume` 固定 1，否则调一个影响另一个）。11 处挂点全在「服务端确认之后」。
- **管理端**：4 类 tab（带计数）+ 概览四个数字 + 每项一行卡（左信息 / 右文件行 + 试听 + 音量 + 开关 + 保存）。

### 判据（下次别重新推）
- **`file_path` 是唯一允许服务端覆写的资源路径**（`configs/game-config` 开头那条「资源路径一律不覆写」
  的显式例外）：图集 / 帧动画按 id 拼（换美术要重打包），音效文件是运营挑的。
- **客户端没有本地兜底值**：`audioConfigOf(key)` 返回 null 就不播（表里没有 / `enabled=false` / 空路径），
  调用点不各判一遍、也不写 `?? 默认音量`。
- **响在「服务端确认之后」**：`equip_wear` 在 `runBagOp` 成功之后、`map_teleport` 在进入条件通过之后、
  `level_up` 在服务端给的 `leveledUp` 分支里。提前播会把「点了但被拒」演成「成功」。
- **掉落音一次结算只响一次**（按件播会在「一堆怪同时死」时叠成噪音）；金钱音只在三种货币**真的变了**时响
  （`applyServerRoleUpdate` 每几秒来一帧，无条件播会盖掉别的音）。
- **战士普攻按 `config.id === "1000"` 过滤**：`skill_1000` 被 1002~1011 复用（配置换动作与数值），
  烈火剑法 1001 也调它但那是技能音，不是普攻音。
- **`@Public()` 的正当理由只有一类**：玩家还没拿到令牌时就要用的数据（公告 + 音效），
  且里面没有任何玩家数据；有令牌之后别再走它（进游戏读快照，一个值只有一个来源）。

### 踩到的坑
- `Promise.finally` 在客户端编译不过（tsconfig lib 不到 ES2018，**TS2550**）→ 收尾用 `.then()`。
- `StorageManager` 加了 `import SoundManager` → **storage-sandbox 的 `STUB_IMPORTS` 必须同步**
  （否则 7 套存储单测一起挂在「Cannot find module './SoundManager'」）。
- 快照契约加段后 `test-snapshot-contract` 的夹具要补 `audio`，否则第一条断言就抛「缺段」。
- `audit-server-boundaries` 拦了 game-config → audio-setting 的 4 条跨域 import（加白名单边）；
  `audit-config-leak` 拦了 `new Node("sound_manager")`（进 allowlist，引擎侧身份）。
- **`make config-check` 现在红**，但红的是 `drop_tables`（库 5 / 文件 4）—— 用户自己正在改掉落，
  与本轮无关；**别整份 `config-export`**（会把用户手上的改动一起打包）。
- 新建 TS 资源要连 `.meta` 一起提交（uuid 由它承载；缺了 Cocos 下次打开会重发一个，prefab 引用可能漂）。

## #685 音效四处修订（01:38 用户提，四条 + 一条改名授权）

用户试听之后提了四件事，外加一句「你可以根据正确的用途来更改文件的名称，我的命名不是很准确」。

### 改了什么
1. **点击音从「登录按钮」扩到所有按钮**：key `login_click` → **`ui_click`**（展示名「按钮点击音」，
   分类标签「登录与界面」→「界面与交互」）。唯一入口 `SoundManager.bindClick(node)`。
2. **`item_drop` 在捡起时也响**：挂在 `DropManager.applyPickedFrame` 的 ok 分支（发 `pick` 帧只是请求，
   背包满 / 被拒拿不到这一声），带 80ms 节流防自动拾取刷屏。
3. **`bag_resort` 在拖动搬格时也响**：挂在 `moveBagGood` 成功分支（失败分支已把本地排布还原，那里不响）。
4. **`map_teleport` 挪到「角色显示出来之后」**：`changeOnMap` 只 `markTeleportArrival()`（60 秒有效期的标记），
   `Game.start` 在 `roleDisplay.init()` 之后 `consumeTeleportArrival()` 才播。登录 / 选角进图没有标记，不误响。
5. **文件名统一成与 key 同名**（用户授权）：`login_bgm.wav` / `ui_click.wav` / `warrior_attack.wav` /
   `role_die_man.wav` / `role_die_woman.wav` / `item_drop.wav` / `equip_wear.mp3` / `money_change.mp3` /
   `bag_resort.wav` / `level_up.wav` / `map_teleport.mp3`（**连 `.meta` 一起 mv**，uuid 不变）。
   `sounds/move.wav`（用户 01:31 新放，438ms）**没有对应 key，没配** —— 用途待确认（大概率是脚步/搬格音）。

### 判据
- **`Button.EventType.CLICK` 是引擎给的「真点了」信号**：`cocos/ui/button.ts` 的 `_onTouchEnded` 里
  `if (this._pressed) this.node.emit(ButtonEventType.CLICK, this)` —— 不管有没有配 `clickEvents` 都会 emit，
  且 `_interactable` / `_pressed` 都过了才发。这比裸 `TOUCH_END` 准（拖出去松手不会响）。
  同时它末尾把 `event.propagationStopped = true` → **「在根节点监听冒泡」那条路走不通**，别试。
- **`UiHelper.createButton` 是项目的按钮工厂**：`createTexturedButton` / `createMiddleButton` /
  `createBigButton` / `createSmallButtion` / 弹窗关闭按钮全走它 → 在工厂里挂一次 = 覆盖绝大多数按钮。
  剩下手写的贴一行 `SoundManager.bindClick`；**漏了只是不响、不报错**，加新按钮时要看一眼用了哪个创建器。
- **刻意不响的三类**：技能快捷栏（战斗中高频连点会盖住战斗音效）、世界侧对象（NPC / 传送点 / 掉落物）、
  拖拽与摇杆（一次拖拽以 `TOUCH_END` 收尾，绑上去等于松手就响）。
- **节流判定要放在 `await` 之前**：`play` 里先查 `minGapMs` 再 `await ensureConfig()`，
  否则同时进来的两次都能通过（`playOneShot` 会叠）。
- **`ensureConfig` 只试一次**（`configTried`）：点击音是全站高频路径，不设闸门时服务端一挂，
  玩家每点一下按钮就是一次请求。
- **改出厂值要能落地到老库，两件事**（第一版只做了第 2 条，本机 3100 当场暴露）：
  1. **同步出厂行**：`INSERT OR IGNORE` 只在「没有这行」时插入 → 改 `AUDIO_DEFAULTS.filePath` 之后，
     老库还指着 `sounds/login_bg.wav`，资源已经叫 `login_bgm.wav` → **一进游戏全都没声音**，
     而且看不出原因。`rebaseOnPreset` 只动 `updated_at = 0` 的行（运营改过的一个字都不改）。
  2. **清孤儿**：`deleteOrphans(AUDIO_KEYS)`。前提：行只来自 seed，清单外的 key 只可能是我们改名/下线。
  - 实测方式（e2e 覆盖不到：它用新库、onModuleInit 只跑一次）：`cp data/olua.db /tmp/x.db` →
    把几行改回旧值 → `DB_PATH=/tmp/x.db PORT=3199 REALTIME_EMBEDDED=false node dist/main.js` →
    日志「有 9 行出厂值变了」+「清掉 1 行孤儿」，公开接口返回全新路径。
- **本机 3100 不是 watch 模式**：build 完它不会自动重启（判断方式是改完出厂值再 curl，值没变）。
  所以「代码改了本地看不到效果」先想到这个，别怀疑改动没生效。

### 踩到的坑
- `audit-config-leak` 的 `magicCompare`：`Date.now() - x < 60000` 直接比较字面量会红 →
  提成 `TELEPORT_MARK_TTL_MS`（同 `PICKUP_SOUND_MIN_GAP_MS` / `CLICK_MIN_GAP_MS` 的处理）。
- `audit-ui-click-through` 把 `SoundManager.bindClick` 里的 `node.on(TOUCH_END)` 当成点击元素 →
  进 `REVIEWED` 白名单（它不是点击元素，是给已有点击元素补声音的注册点，穿透由调用方负责）。
- `test-mail` 有一条**源码形状断言**：`if (!row.read && !busy) node.on(...)` 被我改成块（多了一行 bindClick）
  就红了 → 断言跟着改成匹配整块（行为没变）。
- e2e 里反斜杠用例的**输入**没跟着改名（`sounds\\login_bg.wav`），只改了断言 → 「规范成正斜杠」那条红。
  批量替换时要连带检查反斜杠写法。
- `grep "a\|b"` 在本机 BSD 恒空（又踩一次）→ 用 `grep -E "a|b"` 或 Grep 工具。

## #685 收尾：移动脚步音 move（PR 见分支 feat/685-move-sound）

用户确认 `sounds/move.wav`（438ms）是**移动脚步音**：左右键点击地面 = 播一次，长按持续移动 = 循环，停下即停。

### 改了什么
- 服务端：`AUDIO_KEYS` 加 `move`（战斗与角色分类）、出厂值 `sounds/move.wav` 音量 65；
  公开接口注释 11→12 行；`config-sync.sql` 重导出（临时实例 PORT=3199 先把 move 行播种进真实库再导出）。
- 客户端：`SoundManager` 加**第三路 AudioSource `loop`**（移动循环专用，永远循环、由调用方起停）
  + `playMove()`（**强制单次**，不走 `play()` —— 运营把这项的「循环」开关打开时 play() 会把它路由到
  背景音那一路，顶掉登录曲且停不下来）+ `startLoop`/`stopLoop`；`Game.tickMoveSound` 每帧判
  `isManualMoving() || isAutoMoving()`（鼠标/键盘/摇杆/挂机走位都是同一种「我在移动」）：
  起步播一声 → 持续超 450ms（脚步音本体长度之后，单击听不到循环接缝）接循环 → 停下即停
  （起步那一声不掐）。`onDestroy` 必须 `stopLoop()`（挂在常驻节点上，不随场景销毁）。
- **列表顺序不再靠 rowid**：`ui_click` 因改名重播种过一次、rowid 落到表尾，「rowid = 登记顺序」
  的假设已经破了（每台机器库里历史不同）→ `listAll()` 显式按 `AUDIO_KEYS` 排序，顺序这种
  「清单自己的属性」以清单为唯一依据；清单外 key 兜底排最后。
- e2e 口径两处放宽（都是**运营数据演进**踩的，不是回归）：
  1. `e2e-audio-config`「出厂行没有追账」不再锁 0 —— 快照跟着库走，用户（gm001）在管理端
     保存过的行带追账进来是 #655 口径；只锁追账字段形状。
  2. `e2e-game-config` 掉落段「seed 全内联」不锁 entries —— 用户把怪 1 指到了新建的具名表
     `elite_1_10`（还在地图管理拖过地图 0 复活点），改成「来源自洽：内联行对 entries、
     指表行 tableId 存在于 drop_tables；按 source 筛的数量按快照现算」。

### 踩到的坑
- **空库自举先灌 config-sync.sql 再跑 onModuleInit**：新加的 key 在 e2e（:memory: 自举）里
  会被排到末尾，等 config-sync.sql 重导出后自举顺序才对 —— 「先播种真实库 → 导出 → 复跑 e2e」
  是固定顺序，跳步会误判成排序 bug。
- 用户新 import 的 `ScreenLayout` 让 `test-dialog-top` 的 layer-sandbox 缺模块、垫片 Node 缺
  `setPosition` → 沙箱补 stub + 最小 setPosition（记坐标不演）。给 LayerManager 这类组件加
  import 时，三个沙箱（configs/storage/layer）都可能要跟。
- `noUnusedLocals` 连模块级常量也管：`MOVE_LOOP_AFTER_MS` 声明在 SoundManager、只被 Game 用
  = TS6133，常量放唯一使用方。

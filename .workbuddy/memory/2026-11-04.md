
## #680 音效配置进管理端（PR 待合）

用户要求：「管理端添加音效配置，先加两项 —— 登录场景背景音、登录场景点击登录按钮音；
**先不与客户端对接**，等配置好再对接。音乐位置是 resources/sounds」。
后续补充：「还是只允许英文名，中文名称只是临时放进去，没有想好名字」。

### 做了什么
- 表 `audio_settings`（`audio_key` 主键 + `file_path / volume / loop / enabled` + 追账），
  行由 `AudioSettingService.onModuleInit` 按 `AUDIO_DEFAULTS` 补（`INSERT OR IGNORE`），
  **没有新建 / 删除**（key 由客户端播放入口决定，与 `ui_effects` 同取向）。
- 接口 `GET /admin/audio-settings`（gameConfig:read）+ `PATCH /admin/audio-settings/:id`（write，
  `@AuditTarget("audioSetting")`，新业务码 `50037` AUDIO_KEY_NOT_FOUND）。
- 管理端 `/audio`（`AudioSettingsPage`）：每项一张卡 —— 路径输入 + 「从目录选」+ **试听**
  （按表单当前值播，含音量与循环）+ 音量滑杆 + 循环 + 启用 + 保存 + 追账。
- 出厂值：`login_bgm` = `sounds/login_bg.wav`（音量 60 / 循环）、
  `login_click` = `sounds/click_button.wav`（音量 80 / 不循环）—— 都指向用户 00:30 刚放进
  `sounds/` 的真实文件，装完就有声音。
- 素材清单：`tools/gen-image-manifest.cjs` 现在一并产出 `resources/audio-manifest.json`
  （`{dir:"sounds", files:[带扩展名]}`）；dev 侧 vite 中间件加 `?audio=1`（带扩展名）+ 补音频 MIME。
- `config-sync.sql`：35 张表 / 3395 行（新增 audio_settings 两行）。

### 判据（下次别重新推）
- **路径入库是这个模块与特效管理的根本差别**：特效图集路径是两端约定（换美术要重打包），
  音效文件是运营挑的，所以 `file_path` 进库、带扩展名（客户端对接时去掉扩展名再 `resources.load`）。
- **服务端不检查文件是否存在**（资源包不在服务端，查了会掩盖「本地有、线上没有」）→
  **试听是这条链路唯一的验证手段**，这也是页面的核心交互而不是装饰。
- **文件名只允许英文**（用户定）：`^sounds/[A-Za-z0-9_\-/]+\.[A-Za-z0-9]+$`；空串 = 未配置（合法）。
  资源目录里现存 `木剑砍击音效.wav` 这类临时中文名 —— **选择器要过滤掉不合规文件名**
  （选完才 400 是最差的体验），并在旁边说明「另有 N 个文件名不是英文」。
- 本轮**不下发快照**：e2e 里有一条「`GET /game-config` 没有 audio 段」钉着；对接客户端时
  要一起改那条断言 + 在 `ClientConfigService` 加一段。

### 踩到的坑
- **`audit-api-hardcode` 会判红**：管理端 `fetch('/game-resources/...')` 直接写在页面里不行，
  提示文案里的 `http://localhost:8080` 也算硬编码地址。做法 = 单独 `pages/audioSettings/assets.ts`
  并在审计 `adminAssets` 白名单登记，页面里连 `fetch` 都不出现。
- **不要在页面里手拼试听地址**：`audioUrlOf(resRoot, filePath)` 收口在 assets 里。
- **从「全新库」导出的 config-sync 不能整份覆盖仓库里那份**：列顺序不同（历史 ALTER 加列 vs
  CREATE TABLE 顺序），会造出几千行假 diff。正确做法 = 只把新增表那一节拼进现有文件 + 改表头，
  再用「库副本」`config-import --db` 验证回读（`cp` 之前先 `PRAGMA wal_checkpoint(TRUNCATE)`，
  否则新表还在 -wal 里、副本里没有）。

## 动画节点销毁后状态残留（#560，fix/560-animation-destroy）

- **现象**：进游戏后控制台每帧一条 `[PreviewInEditor] Cannot read properties of null (reading '_uiProps')`，
  栈 `AnimationState._sampleCurves → TrackEvalStatus.evaluate → Sprite.set spriteFrame → _applySpriteSize`；
  用户复现路径 = **打掉一只怪 → 传送两次地图** 之后开始刷，重启才停。
- **原因**（Cocos 3.8.7 的坑，官方论坛 `forum.cocos.org/t/topic/169283` 有一模一样的栈）：
  带循环片段的节点 `destroy()` 后引擎不保证把 `AnimationState` 从**全局** `AnimationManager` 摘干净 ——
  `Animation.onDestroy → AnimationState.destroy()` 只在「正在播」时才 `removeAnimation`；组件没过 `onLoad`
  连 `onDestroy` 都不走。残留状态每帧往已销毁的 Sprite 写 `spriteFrame`，`self.node` 为 null → 炸 `_uiProps`。
- **改法**（`ui/helpers/AnimationHelper.ts`）：
  ① `useAnimation` 顺手 `guardDestroy(node)`，在 `NODE_DESTROYED`（引擎**先**发事件、**再**销毁子节点与组件）
  上挂一次性钩子 → `stopTree` 递归 `getComponentsInChildren(Animation)` → **逐个 `state.stop()`**
  （`animate.stop()` 只停 cross-fade 权重，状态还留在全局管理器里 —— 这正是论坛里「先 stop 了还照样崩」的原因）；
  ② 播放入口一律先过 `animatable(node)` = `isValid(node, true)`：`destroy()` 同帧内 `isValid(node)` 仍是 true
  （只进了 `ToDestroy` 队列），不拦就会在将死节点上起一个没人停的状态；
  ③ 一次性播放的 `animate.on(FINISHED)` 改 `once(..., node)`，避免监听堆在复用组件上误销毁节点。
- **守点**：`client/tools/test-animation-destroy.cjs`（最小 cc 垫片照抄引擎语义，`Animation.stop()` 故意不动状态，
  判据 = 全局管理器里还剩几个在播的状态）。**已实测不是假绿**：摘掉 `guardDestroy` 立刻红 5 条。
- 顺带修上一刀（#557）留下的两处：
  - `test-equipment-upgrade-hint.cjs` 的静态断言还按 `static equipBetterFromBag` 老签名匹配 → 恒红（`client-test` 不在 CI 里，漏了）；
  - `Makefile` 缺 `server-e2e-bag` 目标（`make test` 声称「全部测试」却不跑背包 e2e），已补目标 + PHONY + test 列表。
- 基线更新：客户端 58 → **59 套**（54 过 / 5 红，红全是素材未入库）；`server/README` 的 25 套 e2e 不变。

## 角色详情改可视化一屏版式（#562，feat/562-admin-role-visual）

- **需求三段**（用户逐轮加的）：① 装备 / 称号等从「id 输入框」改**可视化**、抽全局可复用组件；
  ② 地图与头像也要可视化，且**一屏看完**，背包与技能改独立弹窗；③ 时装与成长阶位**并进装备卡**；
  ④ 卡片**不允许修改** —— 追问后确认口径是「只锁身份 / 货币 / 属性，装备仍可改」。
- **组件层** `admin/src/components/entity/`：`catalog`（唯一数据来源 = `api/gameData`，模块级缓存）→
  `EntityImage`（单图 / 图集首帧 / **空值虚线方块**）→ `EntityCard` → `EntityPickerList`（无壳）+ `EntityPicker`（Modal 壳）
  → 业务 `EquipSlots` / `LevelLadder` / `SkillList` / `BagGrid`。通用壳 `components/Modal.tsx` 新写。
- **只读用纯文本，不用禁用态输入框**：灰输入框像「没权限」，会让人去找解锁开关。左栏「角色」卡断言
  `input/select` 数量 = 0（装备卡仍 19 个可点）。
- **一屏口径**：1440×900 实测 `main.scrollHeight === clientHeight === 829`（左卡 487 / 装备卡 318）。
  三个省高度的杠杆：`Card dense`（只压内边距）、空槽压成一行小按钮、属性窄栏走竖排列表而非表格

- **踩到的坑**：① `EntityPickerList` 根节点漏 `h-full` → 列表按内容长出去压到底部按钮（`overflow-y-auto` 永不触发）；

  ③ 只按 id 字典序排会把「超神的…」堆满第一屏 → `variantRank` + `baseNameOf` 让同款聚在一起；
  ④ `other1/other2` 是合法部位但客户端没配装备 → 给空列表 + `emptyHint`，只有部位表里根本没有的脏键才放开全量。

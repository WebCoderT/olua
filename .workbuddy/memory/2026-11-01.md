## 动画节点销毁后状态残留（#560，fix/560-animation-destroy）

- **现象**：进游戏后控制台每帧一条 `[PreviewInEditor] Cannot read properties of null (reading '_uiProps')`，
  栈 `AnimationState._sampleCurves → TrackEvalStatus.evaluate → Sprite.set spriteFrame → _applySpriteSize`；
  用户复现路径 = **打掉一只怪 → 传送两次地图** 之后开始刷，重启才停。
- **原因**（Cocos 3.8.7 的坑，官方论坛 `forum.cocos.org/t/topic/169283` 有一模一样的栈）：
  带循环片段的节点 `destroy()` 后引擎不保证把 `AnimationState` 从**全局** `AnimationManager` 摘干净 ——
  `Animation.onDestroy → AnimationState.destroy()` 只在「正在播」时才 `removeAnimation`；组件没过 `onLoad`
  连 `onDestroy` 都不走。残留状态每帧往已销毁的 Sprite 写 `spriteFrame`，`self.node` 为 null → 炸 `_uiProps`。
- **改法**（`ui/helpers/AnimationHelper.ts`）：
  ① `useAnimation` 顺手 `guardDestroy(node)`，在 `NODE_DESTROYED`（引擎**先**发事件、**再**销毁子节点与组件）
  上挂一次性钩子 → `stopTree` 递归 `getComponentsInChildren(Animation)` → **逐个 `state.stop()`**
  （`animate.stop()` 只停 cross-fade 权重，状态还留在全局管理器里 —— 这正是论坛里「先 stop 了还照样崩」的原因）；
  ② 播放入口一律先过 `animatable(node)` = `isValid(node, true)`：`destroy()` 同帧内 `isValid(node)` 仍是 true
  （只进了 `ToDestroy` 队列），不拦就会在将死节点上起一个没人停的状态；
  ③ 一次性播放的 `animate.on(FINISHED)` 改 `once(..., node)`，避免监听堆在复用组件上误销毁节点。
- **守点**：`client/tools/test-animation-destroy.cjs`（最小 cc 垫片照抄引擎语义，`Animation.stop()` 故意不动状态，
  判据 = 全局管理器里还剩几个在播的状态）。**已实测不是假绿**：摘掉 `guardDestroy` 立刻红 5 条。
- 顺带修上一刀（#557）留下的两处：
  - `test-equipment-upgrade-hint.cjs` 的静态断言还按 `static equipBetterFromBag` 老签名匹配 → 恒红（`client-test` 不在 CI 里，漏了）；
  - `Makefile` 缺 `server-e2e-bag` 目标（`make test` 声称「全部测试」却不跑背包 e2e），已补目标 + PHONY + test 列表。
- 基线更新：客户端 58 → **59 套**（54 过 / 5 红，红全是素材未入库）；`server/README` 的 25 套 e2e 不变。

## 管理端风格全站统一（#564，feat/564-admin-ui-kit）

- **需求三段**：① 把 #562 角色详情那套视觉规范**固化成技能**（`.workbuddy/skills/olua-admin-ui/SKILL.md`）；
  ② 用技能把管理端**全站 34 个页面**改到同一风格；③ 筛选条件**尽量一行**、**全局紧凑**、能独立成组件的全抽出。
- **用户中途纠正（最重要）**：「我说的是这个，角色名/id 在输入框上面，全部都应该是上下结构」——
  我先前把「筛选一行」理解成 `Field inline`（标签与控件同一行），反而让标签吃掉控件宽度、6 个条件折成两行。
  正确形态：**每个条件块内部上下结构（标签一行、控件一行），若干块横向排成一行**，右侧 `ml-auto` 放查询/重置。
  判据：1440 宽下角色管理页 6 条件 + 查询/重置不折行，`FilterBar` 高度 80px（实测）。
- **新组件层**：`PageHeader`（标题/说明/右侧操作/返回，替代 29 处手抄 h1）、`FilterBar`（一行筛选条）、
  `Modal` 重写四档 `sm/md/lg/xl`（Esc + 遮罩关闭 + 内容区独立滚动 + footer 固定，替代 14 处手写 `fixed inset-0`）、
  `Notice` 四色提示条、`ConfirmDialog` / `EntityPicker` / `BagGrid` 全部改吃 `Modal`。
- **全局紧凑口径**（用户「全局使用紧凑布局」）：`Card` **默认 `dense`**（header `px-3.5 py-2` / body `px-3.5 py-3`，
  `dense={false}` 可退）、`Button px-3 py-1.5`、`Input/Select px-2.5 py-1.5`、`thClass/tdClass px-3 py-2`、`StatCard px-4 py-3`。
- **守点** `tools/audit-admin-ui.cjs`：页面里禁止 ①`fixed inset-0 z-` ②`<h1 className=` ③自造卡片 class ④裸字段标签 `span`；
  负向验证：往 `NpcsPage` 塞两条 → 准确报 2 处 exit 1，恢复回绿。审计数 13 → **14**（README/README.en/olua-server SKILL 同步，
  中英「14」出现次数必须相等，否则 `audit-docs-en` 报「中文多 1 次」）。
- **批量迁移做法**：用 TS 编译器 API 写结构脚本（`ts.createSourceFile` + JSX 祖先判定）而不是正则；
  4 个脚本 /tmp/migrate-*.cjs，全部先 dry run 再 `--apply`。踩到的坑：多行 JSX 缩进被抹平（要写 `reindent`/`dedent`，
  首行不参与公共缩进统计）、批量补 import 产生 `\n, Field } from` 非法语法、`Modal title` 只收 `string` 导致 10 处 TS2322、
  猜的 `onClose` 有 3 处错（`QuestsPage`/`EquipmentsPage` 实际是 `onCancel`）。
- **`Field` 语义最终形态**：默认上下结构 + `width` 定宽（`Input` 自带 `w-full`，宽度只能给外层）；
  `inline` 只留给真没标签位置的弹窗短字段。双层定宽（`div.w-56` 套 `Field.w-56`）会把控件压窄，56 处合并。
- 门禁：`make admin-typecheck` / `make admin-build` / `make audit`(14/14) 全绿；真机 32 路由 `pageerror` 0、横向溢出 0、
  页头字号统一 `18px`，角色详情仍 `scrollHeight === clientHeight === 829`。

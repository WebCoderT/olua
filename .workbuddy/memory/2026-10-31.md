## 在线心跳清算（#547，feat/547-online-heartbeat，worktree /tmp/olua-547）
- 缺口：`accounts.online_role_id` 只在踢/封/删/换角时清，崩溃/断网后残留 → 后台在线数虚高、排行榜/角色列表错。**断线不立刻清标记是对的**（短暂掉线重连不该被 20007 拒存档），缺的是兜底清算。
- 方案：新列 `accounts.online_heartbeat_at`，与标记**一条语句同生同灭**（新 `AccountRepository.setOnlineRole`：select / 首角色自动在线 / kick / 封禁 statusPatch 全走它，不许用 updateById 单独动标记）；实时进程存活探测 sweep 每拍给活连接批量续约（`touchHeartbeats`，只动心跳列**不碰 updated_at**，只续有标记的行）；同拍清算心跳过期（含 NULL）的行（`clearStaleOnline`），宽限 `REALTIME_ONLINE_STALE_MS` 默认 90s=3×心跳、**下限 2×心跳**（防一次网络抖动误杀）、0=关闭；清算只动库，残留连接由踢下线巡检按既有「从有到无」收尾。
- 迁移垫心跳：补列后存量在线标记心跳为 NULL，而 NULL 在清算判据里=过期 → 直接上线会 mass kick；migrate 里垫成启动时刻，给活连接一个宽限窗。
- 客户端零改动（协议层 pong 浏览器自动回，应用层 ping 照旧）。
- e2e-realtime +9 条（50→59；总数 2411→2420 连坐 README 中英×2、FAQ 中英、resume×2、官网×1）。在线心跳组用**第二台服务+文件库**（node:sqlite 第三方读者直接改心跳——`:memory:` 摸不到；WAL 下跨进程读写与 e2e-dual 同款）。

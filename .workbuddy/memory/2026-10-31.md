- **排查结论（这才是真问题）**：管理端改的是**库**，客户端靠快照 + `apply-snapshot` 跟着变；

## 卖价也走运营库（#545，接着 #544 的上移清单往下做）
- **缺口**：`sellGoods` 读生成物 `SELL_PRICES` —— 管理端把兽皮卖价 2 改 77，客户端背包立刻显示 77（快照覆写），服务端仍按 2 付钱。
  玩家只能描述成「价签不对」，我们这边应该读成「这条链路还没接库」。同时 `items` 表的 `maxStack` 也没接（`itemBaseOf` 只回生成物）。
- **修法**：`sellPriceOf(id)` 放进 `runtime-overrides`（#544 那层现成的），三条来源排序：
  装备（含变体）→ 等级基础价 × 前后缀倍率；药品 / 材料 → 各自表 `sell_price`；都没有 → 回落生成物 `SELL_PRICES`；仍无 = `null` = 不可卖（20018）。
- **为什么装备不看 `sell_price` 列**：客户端 `applyEquipmentRows` 的回收价是 `Math.round(equipmentRecyclePrice(row.level) * rate)` —— 按等级曲线**重算**，
  根本不读那列。两端必须同一口径（等级既是穿戴门槛也是定价依据）。所以运营改**等级**就改价，改 `sell_price` 对回收价无效（与客户端行为一致）。
- **曲线不搬公式，搬采样值**：新增导出 `EQUIPMENT_RECYCLE_PRICES`（下标 = 等级-1，60 个数），生成期调客户端自己的 `equipmentRecyclePrice(level)` 采样。
  服务端要是在 TS 里再写一份分段线性插值 = 第二份真相（段边界一改就静默分裂）。等级越界按端点夹紧（宁可给端点价，不要 NaN / 0 = 卖掉没给钱）。
- **材料叠加也接上了**：新增 `applyItemOverrides`（`items` 表）+ `GameConfigService.updateItem` 补 `touchRuntime()`（此前漏了这一处）。
- **验证**：临时脚本「装出厂值 → 568 条价签与生成物逐值相同」0 不一致（跑完即删，但被用户那次 `git add -A` 扫进了 0cb34d3，已在工作区删除）；

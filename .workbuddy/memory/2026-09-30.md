## 2026-09-30 TiledMap collision 对象组动态生成碰撞区（含名称与区域指示线）
- 需求：地图（1.tmx）自带名为 collision 的对象组，把其中所有元素动态生成为游戏内碰撞范围，并显示对象名称与区域指示线。
- **关键坑（本次最大发现）：Tiled 对象坐标 y 轴向下、原点在地图左上角，而 Cocos 地图节点本地坐标以地图中心为原点、y 轴向上，必须翻转 y。** 依据：引擎源码 `cocos/tiledmap/tiled-object-group.ts` 的 `_init` 里对正交地图执行 `object.y = height - object.y`，再按 `object.y - height*0.5` 定位子节点（对象组节点 anchor 固定 0.5/0.5、contentSize = 地图像素尺寸，且它是地图节点的子节点且位置为 (0,0)，故对象组本地坐标 == 地图节点本地坐标）。
- 原 `getMapPointPosition` 写成 `(x - W/2, y - H/2)`，漏了 y 翻转 → NPC/怪物位置上下镜像。已修正为 `(x - W/2, H/2 - y)`。数值自检：边界-北(Tiled y=-36) 换算后 y=+648 压在地图上边缘(y=+640)，边界-南(y=1244) 换算后 y=-634 压在下边缘，西/东分别压左右边缘，四个围墙各自跨在对应边缘上 → 正确；树根 3 个点均在图内。
- 新增 `ui/components/map/CollisionAreaSpawner.ts`：读 `getObjectGroup("collision")`（无该组时直接 return，0.tmx 就没有），逐对象跳过 width/height<=0 的元素，其余生成「节点尺寸=碰撞范围」的节点（`GameUiHelper.createCollisionAreaNode`）→ `addObstacleCollider`（Static RigidBody2D + BoxCollider2D，与 NPC 障碍物同一套）→ `setPosition(getMapRectCenterPosition(...))` → `LayerManager.addToMapLayer`。静态开关 `CollisionAreaSpawner.showDebug`（默认 true，创建时读取）控制是否显示名称/指示线。
- `ui/utils/MapPointMath.ts`：抽出 `getMapPixelSize(map)`（复用于全部换算）、修正 `getMapPointPosition`、新增 `getMapRectCenterPosition(x,y,w,h,map)`（矩形先取几何中心 `x+w/2, y+h/2` 再按点换算）；`getMapPointPositionOnWorld` 改为复用本地坐标 + 地图节点世界坐标。

## 修复：弹窗刷新后内容整块消失（图层未继承）/ 悬停详情残留
- 现象：背包打开时穿脱装备，背包内容整块消失，必须关掉再打开才恢复；个人信息弹窗打开时，换装后槽位/属性/内观都不实时更新，同样要重开。
- 根因一（主因）：引擎 `new Node()` 的 layer 恒为 `Layers.Enum.DEFAULT`（1<<30），**不会随父节点继承**，而相机 visibility 只含自定义的 MAP/DROP/GAME/MONSTER/EFFECT/UI 位 → 挂载之后再动态创建的节点（背包刷新重建图标、装备槽换装、属性列表重建）一律渲染不出来。之前 `addToXxxLayer` 只在挂载那一刻递归设层，之后的新节点全掉进默认层；关闭重开时 `addToUILayer` 又递归设层，所以「重开就好」。
- 修法（`ui/core/LayerManager.ts`）：`setNodeToLayer` 除递归设层外，为整棵子树注册 `Node.EventType.CHILD_ADDED` 监听（引擎在 `Node._setParent` 里 `newParent.emit(CHILD_ADDED, this)`，`node-event-processor.emit → bubblingTarget.emit`，节点销毁时 `eventProcessor.destroy()` 自动清理，无泄漏）；回调里先判 `isValid(node) && node.layer === layer`（父节点已被移出该图层就跳过，防残留监听把子节点刷回旧图层），再 `setNodeToLayer(child, layer)`；`layerWatchers: WeakSet<Node>` 保证同节点只注册一次。`createLayer` 也改走 `setNodeToLayer`，`addToEffectLayer` 由只设自身改为递归（与其他图层一致）。
- 根因二：`Node.removeAllChildren()` 引擎实现只做 `node.parent = null`（**只摘除，不销毁**），所以每次刷新都留下一批未销毁节点，且挂在子节点上的 `NODE_DESTROYED` 收尾（物品悬停详情弹窗）永远不触发 → 右键穿装备时鼠标还停在图标上，图标被摘掉后详情弹窗永久留在屏幕上，还会挡住后续点击。
- 修法：新增 `ui/utils/node/NodeTree.ts` 的 `clearChildren(node)`（先 `removeAllChildren()` 摘除、再对副本 `destroy()`），替换 BagGridView.refresh / EquipmentSlotGroup.updateSlot / GameUiHelper.applyRoleAttributeListStyle 三处 `removeAllChildren`；`createGood` 的悬停详情改为 `closeDetail`（幂等）+ 同时挂 `MOUSE_LEAVE` 与 `NODE_DESTROYED`（引擎 `_onPreDestroyBase` 里 NODE_DESTROYED 在 eventProcessor.destroy 之前 emit，可安全用）。
- 结论沉淀进 MEMORY.md 第 17 条（三条坑）与 `cocos-collider-debug-overlay` skill。tsc：63 引擎噪声 / assets 0 错；改动延时 14s 复检未被编辑器回写。

- 需求：「首次加载会很卡，而且很多东西并没有加载进来，首先需要预加载地图信息，获取到地图信息后，需要预加载地图中包含的所有 npc 和怪物的帧动画，还有当前角色身上穿戴的武器和衣服的帧动画」。

- 修法（三层）：
  1. `ui/helpers/AnimationHelper.ts` 重写为**按目录缓存**：`frameCache`（目录 → 已按帧序号排序的帧序列）+ `frameLoading`（并发同目录只发一次请求）+ `clipCache`（键 `kind|目录|速度倍率` → 动画名 → AnimationClip）。**多个节点共用同一批 clip**（引擎侧 `addClip` 只是引用 + `createState`，AnimationState 每节点独立、`state.initialize(node)` 懒绑定，所以共享安全）。新增 `loadFrames/prepare(dir, kind, speedRate)`；`useManyNameAnimation` 命中缓存时**同步**装好片段并播放（未缓存仍走异步兜底，如运行中换上的新装备）；`play/playOnceWithDir/playLoopWithDir` 也改走帧缓存，且先建动画组件再等帧（回调里的 isValid 守卫保留）。删掉了外露的 `spliceAnimation/createAnimation`（无外部调用），片段创建收敛到私有 `createClip`。目录加载失败也缓存空数组（避免每生成一只怪就重试报错刷屏）。
  2. 新文件 `ui/core/PreloadManager.ts`（静态类）：`preloadGame(mapSrc, role, onProgress)` = 地图信息（`loadResourceAsync<TiledMapAsset>`，tmx 的图集依赖随依赖一起加载）→ 从 **TMX 原文**读对象组推导目录（npc 组按对象类 npc 过滤取 `npcs.get(id).src`；monster 组按 id 取 `monsters.get(id).out + speedRate`）→ 角色穿戴（`equipments.cloth?.out || ROLE_DEFAULT_CLOTH_OUT`、`equipments.weapon?.out`，空串跳过）→ `runTasks` 固定并发池（队列 + N worker）加载，进度 `地图信息` → `帧动画 n/m`；`uniqueTasks` 按 `kind|dir` 去重；结束时 console.log 打一行目录清单便于核对。
  3. 接线：`ui/Loading.ts` 用 `PreloadManager.preloadGame` 取代原来的 `resources.preload(map)`，进度重分为**场景 0~50 / 游戏资源 50~100**，文字带阶段说明（tip）；`ui/Game.ts` 的 `start` 改 `async`，`initLayer` 之后 `await PreloadManager.preloadGame(...)`（Loading 已加载过则命中缓存立即返回；编辑器里单跑 Game 场景时在这里补齐）并加 `isValid(this)` 守卫，新增 `ready` 门闩让 `update` 在预加载完成前直接 return。
- 顺手修的坑：`RoleAppearance` 原来每次刷新都 `getComponent(Animation)?.destroy()` + 重新 `addComponent`（引擎 destroy 到帧末才真正移除组件 → 同帧会短暂存在两个 Animation 互相抢 spriteFrame）→ 改为**复用动画组件**，只在 `out` 真的变了才重载；`AnimationHelper.applyClips` 里加 `if (animate.clips.length) animate.clips = []`（复用组件换一套片段时必须先清，否则新外观缺帧的动作会播成旧外观）；无武器外观（`out === ""`）时不再去 `loadDir("")`，改为隐藏武器节点（原来会留着上一把武器的最后一帧）；`ROLE_DEFAULT_CLOTH_OUT = "role/1"` 提到 configs/role 与预加载共用一份。
- 顺带整理：`TiledObjects.ts` 改为**纯 XML 解析**（新导出 `readTiledObjects(xml, 组名)` / `readTiledObjectsFrom(xml, ...组名)`，`getTiledObjects/getTiledObjectsFrom(map, ...)` 只是取 `tmxXmlStr` 后转发）→ 不需要地图节点也能读对象组（预加载阶段就靠这个），也绕开了"对象类被解析器丢弃"与"object.y 被原地翻转"两个坑；组名/属性名/类名常量集中到 `configs/map.ts` 的 `tiledGroupNames/tiledPropertyNames/tiledObjectClasses`，MapObjectSpawner/MonsterAreaSpawner/CollisionAreaSpawner 与预加载共用（用 python 批量替换，三个文件各自删掉本地常量）。

- 引擎事实（已写进新 skill `cocos-frame-animation-preload`）：① `AnimationClip` 可跨节点共用；② `Animation.clips = []` 的语义（clear crossFade + 移除全部 state）是"换一套片段"的正确姿势，同名 `addClip` 会覆盖但**不会**清理新集合里没有的旧片段；③ 同帧 `destroy()+addComponent()` 会留下两个同类组件，`getComponent` 可能拿到正在销毁的那个；④ `director.runSceneImmediate` 的 `releaseManager._autoRelease` 只 decRef 旧场景依赖列表且 `Scene.autoReleaseAssets` 默认 false（四个 scene JSON 里都确认是 false）→ 动态 loadDir 的帧跨场景仍有效，JS 缓存安全；⑤ `resources.preload/load(mapSrc, TiledMapAsset)` 会连带图集依赖，所以"预加载地图信息"只需这一个调用。

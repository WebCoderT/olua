# 2026-11-02

## #573 地图玩法配置从客户端搬到服务端（feat/573-map-config-authority）

用户原话：「将在客户端对地图添加的配置全部移到管理端进行配置，比如进入等级，进入战斗力等，我说过了，客户端不存储这些东西」。

### 三端边界（这一次是按「资源 / 整理结果」切的）
- **客户端只留资源约定**：`configs/map.ts` 里 `mapData`（11 条的 label/type/level/combat/soulOfWar）整块删除，
  只剩 `mapSrcOf(id) = map/<id>/<id>`（目录约定）、`tiledGroupNames` / `tiledObjectClasses`、以及两个**空容器**
  （`maps: Map<MapId, MapConfig>`、`mapTypeGroups: []`）—— 内容由 `applyMapRows` 在进游戏时填。
- **服务端存「对资源的整理结果」**：新表 `maps`（map_id 主键 / label / type / level / combat / soul_of_war / updated_by / updated_at），
  五个字段与原来的客户端配置逐字一致（玩家看到的东西不变）。
- **管理端可视化改**：`MapsPage` 从只读改成「上半玩法配置可编辑 + 下半观测区只读」。

### 关键决定（和「先想到的做法」相反的三个）
1. **资源路径不入库**。`src` 由两端各按 `map/<id>/<id>` 拼（`mapSrcOf` / `MapService.srcOf`），
   `SaveMapConfigDto` 里根本没有 `src` —— 请求里塞了会被白名单剥掉。理由：存了就会有人改它，而改它只会把客户端指到不存在的图上。
   客户端**不加等待**：资源路径不等配置，所以网络慢只影响名字，不影响进图。
2. **没有「新建 / 删除地图」**。行由 `MapService.onModuleInit` 按资源清单（`MAP_CONTENTS` 的键 = 扫 TMX 目录得到）补出来，
   `INSERT OR IGNORE` 幂等 —— 运营改过的行重启不会被 seed 盖回。没有 TMX 的「地图」在客户端点开就是黑屏，后台不该造得出来。
3. **故意不在 `worldJoin` 拦进图条件**（第一版做了，跑 e2e 就被证伪）。三个事实：
   ① 登录与传送共用同一条 `worldJoin`，登录时进的就是玩家**脚下那张图**；
   ② 运营把某图门槛调高（比如 10 → 50），此刻站在图里的低等级玩家下次登录就被挡住 —— **进游戏即黑屏，且他自己出不来**，
   这个事故不需要玩家做错任何事，只要运营点一次保存；
   ③ `StorageManager.changeOnMap` 已经是所有传送的唯一入口，它读的就是服务端下发的那份配置，所以「改客户端配置进高级图」这条路
   在 #573 之后已经不存在。
   反证：`server/test` 里 **22 处 `joinWorld("1")`**（卧龙城，出厂门槛 10 级）配的是 1 级测试角色 —— 硬拦会把 12 套 e2e 直接打红。
   配套收拾：删掉 `MapEnterBlock` / `enterBlockOf` / `BIZ_CODE 50033~50035` / `realtime → map` 的边界白名单，
   把「为什么不做」写进 `MapService` 顶部（含「真要做需先加一条独立的传送消息」）。

### 落地清单
- 服务端：`maps` 表 + `MapRepository`（seedRow / listAll 按 `CAST(map_id AS INTEGER)` 升序 / getById / update / countAll）+
  `constants/map-config.ts`（`MapType` / `MAP_TYPE_VALUES` / `MAP_TYPE_LABELS` / `MAP_TYPE_GROUPS` / `MAP_ENTER_LIMITS` /
  `MAP_LABEL_MAX_LENGTH` / `MAP_DEFAULTS` 11 条 / `mapDefaultOf`）+ `MapService.list|configs|detail|save` +
  `AdminMapController` 三个 operation（list / detail / save，save 才要 `gameConfig:write`）+ `@AuditTarget("map")`。
- 快照：`GET /game-config` 加 `maps`（7 字段精简行）与 `mapTypes`（顺序即传送弹窗分组）。
- 客户端：`types/map.ts`（`MapId = string`、去掉 `src`、加 `typeLabel`）、`applyMapRows` 整表重建、五个消费点改 `mapSrcOf` / `mapLabelOf`、
  `GameHelper.getMapEnterRejectReason` 判 `> 0` 且「配置还没拉到时不拦」、传送弹窗 `maps.size === 0` 给提示不渲染空弹窗、
  `Game.start` 的 `loadGameConfig()` 改 **await**、文案进 `texts.ts`（`map_config_loading_tip`）。
- 管理端：`api/mapCatalog.ts` 进程内缓存（`Layout` 挂载 `ensureMapCatalog()` / 保存后 `refreshMapCatalog()`）、`gameData.ts` 删掉地图相关转发、
  `MapsPage` 玩法配置 Card（三 Input + 类型 Select + 还原 / 保存 + 「未保存」Badge）。
- 生成物：`gen-shared-data.cjs` 不再产 `MAPS` / `MAP_LABELS`（`audit-shared-data` 的 `REQUIRED_EXPORTS` 同步删），43 张表 / 4831 行 / 1483 KB。

### 门禁与数字
- `make check`（客户端 tsc 0 错 + 管理端 typecheck + 15 审计全 PASS）、`make test-changed BASE=master` 86 步全绿、
  `make ci` 全绿（27 套 e2e，含 `e2e-map` **122 条**）、`make verify` 只剩客户端 5 套已知基线红（素材未入库）。
- 数字：166 接口 / 137 路径 / 256 模型 / 46 表 / 38 仓储 / 管理端 109 接口；e2e **2625 条（26 套）**。
  文档同步：README / README.en / FAQ / FAQ.en 的加数串 `+ 73 + 88` → `+ 73 + 122` 与总数 2591 → 2625（×6 处）、
  `server/README(.en)` 的脚本表与测试表两行、`admin/README(.en)` 页面表与「游戏数据从哪来」段、
  `.workbuddy/skills/{olua-server,olua-admin,olua-client}/SKILL.md`。

  改数字时中英必须同一次改完。
- `client/tools/test-equip-align-apply.cjs` 里那条 `check(/void loadGameConfig\(\)/)` 钉的是「Game 启动会拉配置」，
  改成 `await` 后必须同步改成 `/await loadGameConfig\(\)/`（否则守点自己变红，而它红的原因不是回归）。

### 一个操作坑
`make test-changed` 中途留下两个 `node server/dist/main.js` 进程占着随机端口，下一套 e2e 直接 `EADDRINUSE`。
处理：`lsof -nP -iTCP:<port> -sTCP:LISTEN` 找到 pid → `kill`（`ps` / `pgrep` 在这台机器上被沙箱挡，但 `lsof` 能用）。

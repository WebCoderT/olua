## #573 地图玩法配置从客户端搬到服务端（feat/573-map-config-authority）

用户原话：「将在客户端对地图添加的配置全部移到管理端进行配置，比如进入等级，进入战斗力等，我说过了，客户端不存储这些东西」。

### 三端边界（这一次是按「资源 / 整理结果」切的）
- **客户端只留资源约定**：`configs/map.ts` 里 `mapData`（11 条的 label/type/level/combat/soulOfWar）整块删除，
  只剩 `mapSrcOf(id) = map/<id>/<id>`（目录约定）、`tiledGroupNames` / `tiledObjectClasses`、以及两个**空容器**
  （`maps: Map<MapId, MapConfig>`、`mapTypeGroups: []`）—— 内容由 `applyMapRows` 在进游戏时填。
- **服务端存「对资源的整理结果」**：新表 `maps`（map_id 主键 / label / type / level / combat / soul_of_war / updated_by / updated_at），
  五个字段与原来的客户端配置逐字一致（玩家看到的东西不变）。
- **管理端可视化改**：`MapsPage` 从只读改成「上半玩法配置可编辑 + 下半观测区只读」。

### 关键决定（和「先想到的做法」相反的三个）
1. **资源路径不入库**。`src` 由两端各按 `map/<id>/<id>` 拼（`mapSrcOf` / `MapService.srcOf`），
   `SaveMapConfigDto` 里根本没有 `src` —— 请求里塞了会被白名单剥掉。理由：存了就会有人改它，而改它只会把客户端指到不存在的图上。
   客户端**不加等待**：资源路径不等配置，所以网络慢只影响名字，不影响进图。
2. **没有「新建 / 删除地图」**。行由 `MapService.onModuleInit` 按资源清单（`MAP_CONTENTS` 的键 = 扫 TMX 目录得到）补出来，
   `INSERT OR IGNORE` 幂等 —— 运营改过的行重启不会被 seed 盖回。没有 TMX 的「地图」在客户端点开就是黑屏，后台不该造得出来。
3. **故意不在 `worldJoin` 拦进图条件**（第一版做了，跑 e2e 就被证伪）。三个事实：
   ① 登录与传送共用同一条 `worldJoin`，登录时进的就是玩家**脚下那张图**；
   ② 运营把某图门槛调高（比如 10 → 50），此刻站在图里的低等级玩家下次登录就被挡住 —— **进游戏即黑屏，且他自己出不来**，
   这个事故不需要玩家做错任何事，只要运营点一次保存；
   ③ `StorageManager.changeOnMap` 已经是所有传送的唯一入口，它读的就是服务端下发的那份配置，所以「改客户端配置进高级图」这条路
   在 #573 之后已经不存在。
   反证：`server/test` 里 **22 处 `joinWorld("1")`**（卧龙城，出厂门槛 10 级）配的是 1 级测试角色 —— 硬拦会把 12 套 e2e 直接打红。
   配套收拾：删掉 `MapEnterBlock` / `enterBlockOf` / `BIZ_CODE 50033~50035` / `realtime → map` 的边界白名单，
   把「为什么不做」写进 `MapService` 顶部（含「真要做需先加一条独立的传送消息」）。

## #580 地图页可视化 + 观测区块改弹窗（PR #582）
- **「可视化」的判据不是「画了线」，是「两套坐标对不对得上」**：`groups` 是 Tiled 口径（左上原点、y 向下），
  `spawnAreas` 是世界坐标（y 向上，`cy` 为负）。反算 `x = cx - w/2`、`y = -cy - h/2`，图上**实线（服务端）与虚线（TMX）重合**
  才证明「导入没算错」。验证方式是用 Playwright 探针读 rect 的 x/y/w/h **逐条断言**（新手村三条全等），不是肉眼看。
- **预览图与 TMX 天然等比**（11 张 2048×2048 preview ↔ 8192×8192 TMX，1:4），所以 `<img>` + `viewBox="0 0 w h"`
  能直接叠；但比例按 `detail.width/height` 算，**不写死 8192**，换图才不歪。
- **SVG 三个必踩坑**：`vectorEffect="non-scaling-stroke"`（8192 viewBox 缩到 620px，2px 描边会变 0.03px）；
  点半径与字号按图宽比例算（写死 40 在 8192 图上只有 1 像素）；标签描边 `labelSize/22`（`/8` 糊成光晕）。
- **标签密度策略**：区域宽 / 图宽 ≥ 0.12 才写「#id 怪物名 min~max」，否则只写 `#id`（雪域高原 18 个区域全写会糊成一片）。
- **页面高度预算**：地图 `maxWidth: min(100%, 62vh)`、删掉独立「概览」卡（六个数字并进地图卡 description）才一屏看到
  「配置 + 地图」；密集图另给「放大」弹窗（72vh，`maxWidth="100%"` 在 `max-h-[85vh]` 的 Modal 里会被裁掉）。
- **弹窗要能定位**：`focusArea` / `focusNpc` + `td.bg-indigo-500/10` 高亮；从图上点进来带上 focus，从入口按钮打开先清掉（防残留）。
- `Card.description` 从 `string` 放宽成 `ReactNode`（地图卡要写「口径 + 6 个计数」）。

## #586 刷怪区按地图的边界约定处理（feat/586-monster-map-bounds → PR #587）

## 邮件过期回收（#439，PR #593 → master `5630b1b`）

- **四口径**：①过期只对「已领或无附件」生效（清理 SQL：`claimed_at IS NOT NULL OR attachments = '[]'`），不做自动入包；
  ②`expires_at` 可空 = 永不过期；③谁写 expires_at = 投递方（`send` 加可选 `ttlMs`，BOSS 战报 7 天 `BOSS_MAIL_TTL_MS`，
  运营补发永久）；④清理分批（`MAIL_PURGE_BATCH` 500 / `MAIL_PURGE_INTERVAL_MS` 60s，interval ≤ 0 warn 不启动）。
- **读口即时生效**：过期行在 `listByRole` / `listUnclaimed` SQL 过滤（消失即时），物理删除交给 `GameMailPurgeService` 后台清理。
- **SQLite 陷阱**：`DELETE ... LIMIT` 依赖编译开关不默认可用 → 先 LIMIT SELECT id 再 DELETE IN；
  `Number("3600_000")` = NaN（下划线不合法，setInterval(NaN) 退化成忙轮询）；
  `:memory:` 两个 DatabaseSync 连接不共享 → in-process e2e 要用 tmpdir 文件库才能直调 `app.get(Service).sweep()`。
- 存量库自动补列（`ensureColumn`），老邮件 expires_at = NULL = 永不过期，无迁移动作。
- e2e `e2e-mail-expiry.cjs` 15 条（MAIL_PURGE_BATCH=2 钉跨批行为）；e2e 总数 26 → 28 套，接口 168 / 路径 138 / 模型 264。

## 修复：传送后地图一片黑，动一下才显示
- 根因：引擎 `TiledMap.enableCulling` 默认 true —— 图层按**相机视口**裁剪瓦片，裁剪范围只在 `TiledLayer.updateCulling()` 里算，而它挂在「相机节点/层节点/父节点的 TRANSFORM_CHANGED、SIZE_CHANGED」上**同步**重算；此时相机视图矩阵还没跟上本帧位移（引擎 `onEnable` 自己也把首次裁剪 `scheduleOnce` 延后一帧，注释 "delay 1 frame, since camera's matrix data is dirty"）。于是相机跨屏跳变（小地图右键传送 / 十步一杀 / 进图复活点定位）把可见范围算成跳变前的位置 → 目标区域整片不渲染（黑屏），相机不再变化就一直黑，移动一点才重算恢复。
- 修法：`GameMap.loadMap` 在 `tiledMap.tmxAsset = mapAsset` 之后加 `tiledMap.enableCulling = false`（setter 转发所有 TiledLayer）。引擎注释原本就要求「瓦片地图采用了摄像机就要手动关闭裁剪」。
- 依据：`assembler/simple.ts` 的 `updateRenderData` 分支 `if (comp.enableCulling) {...} else { leftDown={0,0}; rightTop=comp.rightTop }` → **关掉裁剪 = 全量渲染**（不是全不画）；编辑器场景因 `EDITOR_NOT_IN_PREVIEW` 本就强制关裁剪，所以编辑器里看不出问题。
- 开销核算：本工程地图 2 层 64×64 格（128px/格，8192²），全量 8192 quad/帧，屏外被裁剪丢弃，可忽略。
- 校验：tsc 0 错；sleep 20s 复检落盘。README「预览与常见问题」补一条；skill `cocos-tiledmap-objectgroup` 补「坑 3：相机跟随必须关 enableCulling」。

- 修法（把「登记点」同时满足两条约束：能收到事件 = 有 UITransform，写的值唯一 = `event.target`）：
  · `Pointer.trackUiPress(node)` 语义从「UI 根记一次」改为「**每个在鼠标通道上有监听的界面元素各自登记**」，记的仍是 `event.target`；`WeakSet` 去重；监听固定用私有哨兵 `PRESS_TRACKER` 当 target，免得被调用方的 `off`/`targetOff` 摘掉。
  · 为什么「各记各的」这次反而正确：同一个事件里 `event.target` **只有一个值**（`dispatchEvent` 开头赋一次，冒泡期不变），所以面板/滚动区/格子/图标写进去的值完全一样 → 与登记顺序无关。上一版错在记「本节点」，而不是错在「记了多次」。
  · `bindMousePress` / `UiHit.blockClickThrough` 内部都调 `trackUiPress(node)`；`LayerManager.initLayer` 去掉 UI 根的调用（原地留注释说明为什么绝不能挂）。
  · `StatusIconBar` 的状态图标补 `trackUiPress(icon)`：它只注册了 MOUSE_ENTER/LEAVE，而 图标 → 状态条 → 角色信息栏 → UI 根 这条链上**没有任何登记点**，是项目里唯一真实存在的「按下不留痕」缺口（按下它、拖到背包格子上松开会误用物品）。
  · 新增防呆 `ensureMouseHitTestable(node, api)`（三个注册入口第一句）：判 `node.getComponent(UITransform)`，没有就跳过并 `console.warn` 打出是谁在注册 —— **不要用 `_getUITransformComp()`**，它要等组件 `__preload` 后才有值，节点刚建好就绑会被误判成「没有」而静默丢掉全部鼠标事件（比崩溃更难查）。

## 修「拖物品时整个弹窗也跟着拖」（18:22-18:55）
- 反馈：拖动物品时整个弹窗跟着拖。根因 = **触摸冒泡**，不是格子手势：节点 `TOUCH_*` 引擎派发时一律 `event.bubbles = true`（`node-event-processor._handleTouchStart/Move/End`），格子的触摸沿 格子→行容器→网格→**弹窗背景** 冒上去，弹窗背景的 `Draggable` 收到冒泡来的 TOUCH_START 就 `dragging = true`，随后 TOUCH_MOVE 把整个弹窗拖走。
- 修法两侧都做：
  1. **网格容器收住触摸**（`BagGridView.setupTouchOwnership()`，构造时登记）：容器上 `TOUCH_START/MOVE/END/CANCEL` 全部 `event.propagationStopped = true`。登记在容器**一处**即兜住两种按下 —— 按有物品的格子时格子先独占（命中列表更深的节点优先），事件冒泡路过容器被停下；按空格子/网格空白处时没有更深的节点认领，**容器自己独占**。`refresh()` 只重建格子、不动容器监听。
  2. **Draggable 通用兜底**：`onTouchStart` 里 `dragging = false` 复位后判「按下点 `event.target` 自带拖动手势（`hasEventListener(TOUCH_MOVE)`）→ 直接 return 不抢」，且必须判 `event.target !== this.node`（拖拽柄自己也注册了 TOUCH_MOVE，一并拦掉窗口就永远拖不动）。以后往弹窗里加 ScrollView/Slider 不会再踩同一个坑。
- 硬约束：**容器必须先有 UITransform 再登记触摸** —— `pointer-event-dispatcher._sortPointerEventDispatcherList()` 对整张监听列表读 `trans!.cameraPriority`，且 `dispatchEventTouch` 也会触发这次排序（不只鼠标），无 UITransform 的节点注册触摸会让每次指针事件抛空指针。（`applyColumnStyle(this,...)` 里 `addComponent(UITransform)` 已保证，顺序写进断言。）
- 审计脚本：新增的「只停冒泡」登记被点击穿透审计判成「点击元素漏登记」→ 加**严判定** `isStopOnlyHandler()`：回调必须是本文件里「只写了 `event.propagationStopped = true`」的方法（或同样只停冒泡的箭头函数），还干别的事就仍按点击元素要求；输出多一档 `[仅停冒泡]` 并在汇总里说明。**不加白名单**。
- 单测：`test-bag-drag.cjs` 加 10 条（容器四个事件收住、UITransform 在登记之前、只收 touch 通道、Draggable 三条）→ 118 项。

# 2026-11-03

## #626 二十一个快照域并成 `client/assets/configs/game-config.ts`

用户诉求原话：「将管理端获取到的快照信息全部放在一个文件中进行统一管理，方法也尽量放在一起，不然 configs 下有太多文件，
但很多文件内容又只有一点」。拍板方案：21 个域文件 → 1 个（`configs/` 从 47 个 `.ts` 降到 27 个）。

- **合并**：`snapshot-contract` / `title` / `soul` / `rank` / `level` / `battle` / `growth` / `status` / `drug` / `material` /
  `npc` / `quest-data` / `quest` / `skill-data` / `fashionClothes` / `monster` / `monsterRuntime` / `mall` / `map` /
  `effect` / `equipAlign` → `game-config.ts`（约 2100 行，`//#region 0~20 · 标签（原 configs/xxx.ts）`）。
  12 个 `apply*` 从 `apply-snapshot.ts` 搬过来并补回 `export`；`apply-snapshot.ts` 683 → 约 440 行，只剩编排 + 两段几何。
- **依赖成环的解法**：`items` / `equipments` / `skill` 只留算法，`apply-snapshot` 只留编排，方向恒为
  `apply-snapshot → game-config → types`。唯一「读取函数要读七个部位表」的 `getMallGoods` 按语义搬进 `equipments.ts`
  （否则 `game-config → equipments → game-config` 成环）。
- **`import type` 的坑**：`GOOD_TYPE` / `OECCUPATION` / `ACTION` / `SkillType` / `SkillTargetType` / `StatusSource` 是值，
  跟着类型一起 `import type` 会 `TS1361`；得拆成 `import type {...}` + `import {...}` 两行。
- **装配顺序的坑（本次踩到）**：批量搬函数时几个 `apply*` 落到「上一个分区的尾巴」上（`//#endregion` 之前），
  编译没问题、但 `regionOf(source, 15)` 这种按区取源码的守点读不到 —— 用 `/tmp/relocate-regions.cjs`
  按行号区间（不是跨行正则）搬回各自分区。判据：`awk` 打「每行所属 region」逐条核对。
- **工具链改名**：`client/tools/lib/configs-sandbox.cjs`、`tools/lib/client-config-compile.cjs`、
  `client/tools/test-*.cjs`（23 个）、`tools/gen-shared-data.cjs`、`tools/audit-snapshot-contract.cjs`、
  `tools/audit-world-authority.cjs`（加 `regionOf` + `MONSTER_REGION = 15`）。`client/assets` 下 34 个 `.ts` 共 57 处 import。

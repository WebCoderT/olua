## 点击 UI 不影响角色操作（UI 命中检测）
- 需求：角色打怪时点 UI 元素不该打断角色正在进行的操作（原本点界面会走到 `ScreenClickInput` 的 `setTarget(null)`，把当前攻击目标/怪物信息面板清掉，还可能误拾取界面背后的掉落物）。
- 根因（引擎行为，已查 pointer-event-dispatcher / input.ts）：全局 `input.on(MOUSE_UP)` 不会因为点中 UI 就自动屏蔽。`_emitEvent` 按 dispatcher 优先级派发（UI=1 先、GLOBAL=0 后，前者吃掉事件才不派发），而 dispatcher 只遍历**注册过指针事件的节点**；Button 组件只注册 `TOUCH_*`（靠鼠标→touch 模拟），鼠标 MOUSE_UP 不被吞 → 全局监听照常执行。
- 实现：`ui/utils/input/UiHit.ts`（新，纯工具）——`isPointOnUi(root, screenPoint)` 递归遍历 UI 层子树（子节点倒序先判、`activeInHierarchy` 过滤），`markClickThrough(node)` 用 WeakSet 标记点击穿透；`LayerManager.isPointOnUi(screenPoint)` 薄封装（`isPointOnUi(this.UILayer, point)`），调用方传屏幕坐标。
- 接线：`ScreenClickInput.checkClickTarget` 在判完左键后 `if (LayerManager.isPointOnUi(event.getLocation())) return;`；`GameUiHelper.createTip/createErrorTip`（屏幕中间高频飘字，如拾取提示）与 `createUpgradeEffect` 调 `markClickThrough`。
- 坐标坑：`UITransform.hitTest(point)` 要**屏幕坐标**（`event.getLocation()`），而世界命中（`UITransform.isHit`）用的是 **UI 坐标**（`getUILocation()`）——同一个回调里两者并存，不能换用。

## 特效图集黑底修复（加法混合素材转透明）
- 现象：护体神盾状态生效但特效带整块黑色背景。诊断：`effect/**` 的图是 RGBA、但 alpha 二值（只有 0/255），**不透明像素里纯黑（a>250 且 max(R,G,B)<8）占 31%~72%** → 素材本身是加法混合（黑=不发光）设计，转 png 时黑底没抠，不是渲染问题。
- 全量扫了 resources（排除 npc/monster/weapons/clothes/unused）：真黑底只集中在 `effect/` 22 张；`slots/small-map/main-ui/item/skill icon` 等 UI 图里的黑色是描边/按键底色（软边 alpha + 5%~27%），**绝不能动**——两者按「目录 + 纯黑占比」清晰分层。
- 处理：亮度反推 alpha（`(lum/255)^0.8`）+ 反预乘还原 RGB（`255/max(lum,12)`），纯黑→全透明、暗色→半透明高饱和、亮色→不透明，数学上就是加法→普通 alpha 的精确还原。22 张纯黑占比全部归 0，19 张正常图未动。只改 png 像素，.meta/uuid 不动，编辑器自动重导入。
- 备份：`.backup/effect-png-originals/`（27M，rsync 只收 png）；还原按子目录 cp 回去即可。
- 产出对比图 `effect-黑底修复对比.png`（护体神盾 s_2009 两帧前后，彩色斜纹底）。
- 沉淀 skill `cocos-additive-effect-deblack`（含 references/deblack.py 批处理与 compare.py 对比图脚本、判据与禁区）。
- 后续可选：想找回"叠加增亮"的发光感可给特效 Sprite 挂加法混合材质（自定义 .effect，blend ONE/ONE）——不是修黑底的必要条件。

## 鼠标操控角色（左键走路/右键跑动/抬起即停，八方向）
- 需求：按下点没怪 → 按「按下点相对画面的方位」移动，360° 平分八块；抬起停；左键走、右键跑。
- 实现（新组件 `ui/components/input/RolePointerInput.ts` + meta uuid 905a3f94-…）：
  - 构造注入 `host`(角色节点) + `onStateChanged` 回调，只存 `pressed/run/direction`；全局 `input.on(MOUSE_DOWN/MOUSE_UP)`，`host.once(NODE_DESTROYED)` 里 `off`（照抄 RoleKeyboardInput 形态）。
  - MOUSE_DOWN：只认左右键 → `getHitScreenPoint` → `isPointOnUi` 排除界面 → `getClickedMonster` 排除怪物 → 取方位。方位只在按下那刻算一次（按住移动鼠标不改方向）。
  - 方位算法：`camera.screenToWorld(getLocation, new Vec3())`（**必须传 out**，否则引擎会把相机节点位置当返回值写坏）减**角色身体中心**（节点世界坐标 + `BoxCollider2D.offset`；不用 `worldAABB`，它依赖物理步进、首帧可能是空矩形）→ 死区（`configs/role.pointerMove.deadZone=24` 世界单位）→ `getDirectionByVector` 量化八方向 → `getVectorByDirection`（BattleMath 新加的反函数，cos/sin 八分角）当移动向量（量化后再走位，移动与八方向动画严格一致）。
  - RoleDisplay：新增 `pointerInput` 与 `getMoveIntent()`（键盘 > 鼠标 > null）作为唯一汇聚点，`updateAction/updateDirection/updateWorldPosition` 都改读它，删掉键盘那串八方向 if-else（`getDirectionByVector` 等价）；`isMovementKeyDown()` → `isManualMoving()`（键盘或鼠标），AutoBattle.tick 参数同步改名 `manualMoving`。
- 顺手修的坐标系隐患：`ScreenClickInput`（怪物/掉落物命中）与 `CursorInput`（光标悬停）原来用 `getUILocation()` 喂 `hitTest`，而 `hitTest` 内部走 `camera.screenToWorld`，吃的是**屏幕坐标**（`getLocation()`，物理像素；引擎 node-event-processor 与 Button 都是这个口径）。两者只在「画布物理尺寸≈设计分辨率」时相等（例如编辑器内置预览），窗口一大就整体偏移。新增 `utils/input/Pointer.getHitScreenPoint(event)` 统一取点，四处命中检测全部改走它（编辑器预览下数值几乎不变，浏览器/大窗口下才是修复）。
- 已知取舍（已告知用户）：按住期间移动鼠标不改方向（按需求只认按下点）；点 NPC/掉落物也会走过去（只有怪物被排除）；`Input.EventType.MOUSE_LEAVE` 不在 `InputEventMap` 里、`input.on` 类型收不下（`TS2345`），"移出画布即停"没接（引擎 mouseup 挂 window，拖出画布松手仍收得到）。
- tsc assets 0 错；两轮 sleep 复检（20s/22s）全过，meta uuid 全工程唯一。skill `cocos-mouse-button-input` 增「按住鼠标移动角色」整节 + 坐标口径若干补充。

## 鼠标按住期间实时改向（本次需求，**推翻上一条"按住期间不改方向"的取舍**）
- 需求：不只按下那一刻取坐标，按下后鼠标继续移动时角色运动方向也要跟着变。
- 改动 `assets/ui/components/input/RolePointerInput.ts`：全局增听 `Input.EventType.MOUSE_MOVE`（在 `_cocos_input_input__InputEventMap` 里，类型收得下，与 `CursorInput` 同款用法），**判 `pressed`** 后才重算方向（否则鼠标随便动一下就自己走起来）；抽出私有 `setDirection(direction, run)`，**方向或走/跑真的变了才 `onStateChanged()`**（同扇区内的高频 move 不空刷 `refreshMotion` → 不反复 crossFade/重播动画，这就是八方向量化自带的天然节流）。
- 死区两面用法：**按下时**在死区内 = 只记 `pressed`、方向留零（指针拖出死区后由 MOUSE_MOVE 补上方向，所以踩在脚下按下再拖出去照样能走）；**按住期间**滑回死区 = 直接 return 保持上一次方向（既不转向也不停下，避免指针拖过角色身上时一停一走）。抬起仍清零并 `onStateChanged`，但"死区内按下又原地松开"（压根没走过）不通知宿主。
- 拖动途中**不做** UI/怪物命中判定（划过界面或怪物不应中断移动）；排除规则只在按下那一刻做。
- 同步更新注释：`RolePointerInput` 头注释、`configs/role.ts` 的 `pointerMove` 说明（含 deadZone）、`RoleDisplay.getMoveIntent` 注释；skill `cocos-mouse-button-input` 该节改为「按下 + **按住期间 MOUSE_MOVE 重算**」双段，并补「等值判断是必要节流」「死区两面用法」。

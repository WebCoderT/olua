## #769 同步系列第三刀：快照缓冲 + 服务器时间插值（PR #991，squash `14d7b285`）

第三刀与第二刀（#768 提频）是连着的：帧密了，但客户端那套「每帧走剩余一半」的指数逼近
把收益吃回去了 —— 数学上永远差最后几像素（停下蠕动一小段），延迟随帧率与丢帧漂
（抖一下目标点跳很远就快进，连丢两帧站着不动）。玩家体感是「忽快忽慢」。

### 做了什么

- 服务端两帧加**帧级** `t`（毫秒）：`players` / `monster-ai`。同一拍发出的所有帧共用一个值 ——
  players 用一拍一个 `tickAt`（各间房各取 `Date.now()` 会差出几毫秒），monster-ai 在广播出口取；
  全量帧、离开帧同样带齐；**AOI 按格裁剪后必须原样带上**（`t: data.t`）。
- 新增 `ui/core/SnapshotInterpolator`（纯数字、零 cc 依赖）：缓冲 4 条、同 t 覆盖、
  比最新旧丢弃、超容量挤最旧；采样夹住则线性插值、早于最旧钳到最旧、晚于最新沿最后一段
  速度外插且上限 100ms。
- 新增 `ui/utils/net/ServerClock`：welcome 粗校准（服务端时刻 − 本地收帧时刻）、
  pong 用「发出时刻 + RTT/2」细校准，**直接覆盖不做平滑**（抖动 < 渲染延迟一个零头，
  平滑只引入未知漂移）。
- 玩家（`OtherPlayerManager`）与怪物（`MonsterAI`）**共用同一个插值器**；怪物那边
  `serverX/Y/moving/stepAt` 全退役，缓冲挂 `WeakMap<Node, SnapshotInterpolator>`
  （`types/monster.ts` 不反向依赖 `ui/core`）。
- 朝向改按**这一帧的实际位移**算（位移 0 保持不动），走/站取后一条快照的 moving。
- 诊断层「插值剩余」→「插值落后」（渲染位置离最新已知位置的距离）；旧口径在新实现下无意义。
- 手感参数 `configs/network.realtime.interpolation`（120 / 4 / 100），人眼调、不进断言。

### 踩坑

- `test-client-net.cjs` 用**源码字符串**钉了 `this.pingSentAt = NetDiagnostics.enabled ? Date.now() : null;`。
  时钟校准要用发出时刻，只能改成「一律记」（RTT 入账仍由 `noteRtt` 在诊断关时空操作）——

## #770 按区分片（PR #997 `ae45086e`），issue 已关

在 `~/worktrees/olua-770`（`feat/770-realtime-shard`）做完。四个决策里三个是用户拍的
（**无状态票** / **路径前缀 `/s<k>`** / **取模 `zoneId % N`**），第四个（票据到底「签名」还是「加密」）
是落地时撞上老断言才问的 —— 见下。

### 核心洞察

- 世界与怪物运行时都是**按需创建**（`worldJoin` 才建 Room），所以「分片只装自己的区」不需要过滤层，
  落在**准入闸门**上就够。
- 分片唯一真正的新难题是**票据不能再是进程内内存**（取票与握手会落在不同进程）。
- 票里带区 → 一张票只可能落一个片 → nonce 只需本进程记；就算被重放，`adopt()` 的
  「一个账号只留一条连接」也只会自己踢自己，不构成提权。

### 票据：签名 → 加密（问过用户，选加密）

第一版照决策做成 `base64url(JSON).base64url(HMAC)`，`e2e-all` 立刻红在 `test:e2e:realtime`：
「票据是一串足够长、URL 安全的随机字节（不是可解析的令牌）」（`/^[A-Za-z0-9_-]+$/`，`.` 过不去）。
这条断言守的是**票会进 nginx 日志与浏览器历史**，而签名票的 payload 谁看 URL 谁就能读出用户名。

不用再自己 `timingSafeEqual`。断言一条没改，另加一条「票据里读不出账号名」。

## #742 HTTPS：边缘一层（edge + certbot）+ 官网链接换 https（PR #1033 → master `c70178c3`）

掉落读侧收尾后接手 #742（三站无 443）。部署侧离线能做的全做完，**证书签发与线上验证留人工**。

- **结构**：新增 `edge`（nginx）独占宿主机 `:80`/`:443`，443 终止 TLS 后把同一个 Host 反代到
  `admin:80`（三站分流一行没改）；`certbot` 每 12h `renew`（webroot），edge 每 6h 自己
  `nginx -s reload`（certbot 在**另一个容器**里，这层没有 Docker socket 喊不动它）。
  两个服务都挂 `profiles: ["tls"]`，开关 = `deploy.env` 的 `OLUA_TLS=on`。
- **三处「只在部署那一刻才暴露」的接线**（本地怎么跑都是绿的）：端口归属（TLS 下 admin 退回
  `127.0.0.1:8081`，靠 `OLUA_ADMIN_BIND/PORT`）、`COMPOSE_PROFILES=tls` 写进服务器 compose `.env`、
  证书路径与 certbot 的 `--cert-name olua` 对齐。这三样都由 `deploy.sh` 派生，不再手工补。
- **首次签发用 standalone**（先停 edge 腾出 `:80`），之后续期才走 webroot —— 反了就是鸡生蛋
  （webroot 要 `:80` 上有人供校验文件，而 edge 要证书才能起 nginx）。
- **`OLUA_TLS=off` 就是干净的回滚开关**：那三行不写，compose 回默认，edge/certbot 不被拉起；
  但 **301 会被浏览器缓存**，客户端侧不可逆，所以必须「先签好证书再开」。
- `audit-deploy.cjs` 新增 13 条守点（含「admin 发布口必须可退让」与「官网不许再出现自己的
  http 绝对地址」），逐条反证：改 8443 / 删 ACME 块 / 换证书目录 / 删 certbot profile /
  admin 端口写死 `80:80`，全部如实报红。**官网那条在改链接之前就是红的**（10 个 html、47 处）。
- **客户端零改动**：#742 里「`network.ts` 按 host 判本机/公网」已过时 —— 现在是 `DEV_MODE`
  一个开关，打包走同源 `/api`，实时通道按 `http→ws / https→wss` 推导。`docs/deploy.md` §9.4 一并更正。

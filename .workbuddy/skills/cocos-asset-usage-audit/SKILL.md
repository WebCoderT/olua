# Cocos 资源引用审计与安全归档

目标：**准确**找出「代码/场景里没有任何引用」的资源，并把它们归档到一处，同时**绝不**移动仍在被引用的资源。
难点只有两个：**引用不只有字符串路径**，以及**移动必须保留 uuid**。

## 一、先枚举"引用的所有可能形态"（漏一种就会误删）

| 形态 | 例子 | 判定 |
|---|---|---|
| 路径字面量 | `"common/mp"`、`"item/fs_2"` | 相等即命中（写代码时都不带扩展名） |
| 模板串前缀 | `` `clothes/in/${id}` `` | 取 `${` 之前作前缀 |
| 图集分页 | 代码写 `skill/plist/s_1102@0`，目录里有 `@0/@1` | 同基名（去 `@N`）的 `plist` 与 `png` **成对同活**，任一方被引用则两个都算用到 |
| 目录加载 | `loadDir("clothes/out/001")` | 资源路径以「引用值 + `/`」开头 |
| **按名字取图** | `` commonImage(name) => `common/${name}` `` | ⚠️ **不能用模板前缀判**（模板对目录下每个文件都成立 = 等于没判）。必须收集「代码里真正被点名的名字」，逐个比对 basename |
| 依赖链 | `map/0.tmx` → `<tileset source="x.tsx">` → `<image source="y.png">` | 从 tmx 与 tsx 原文正则抽出 source，递归传播 |
| 编辑器 uuid 引用 | 场景/prefab 里写 uuid | 先建 `uuid → 路径` 表（.meta 的 `uuid` 与 `subMetas[*].uuid`），再在 `.scene/.prefab/.json/.ts` 全文里搜 uuid 是否出现 |

**先自己确认哪几种在实际工程里存在**：如果场景里 0 命中，说明全工程都靠代码字符串引用，那就把精力放在字符串与按名取图上（本项目 olua 就是这样）。

## 二、最容易踩的两个误判

1. **裸名匹配会被"节点名"污染**：代码里 `new Node("hp_bar")` / `createSprite("combat_icon", ...)` 的字符串会命中 `main/hp_bar.png`。
2. **裸名匹配会被"数字/通用词"污染**：字符串 `"1"` 命中 `main/head/1.png` 与 `loading/1.jpg`；`"exp"` 命中 `main/exp.png`（真正用的是 `bottom-nav-bar/exp`）。
   → 裸名只能当**保守判据**（多算"已用"），**绝不能单独据此下结论说某文件没用**；只靠它筛出来的"未使用"要先人工复核。

## 三、分三层输出，别只输出两桶

- **L1 有引用**：给出命中原因（哪个字符串/哪个文件/哪种模式）—— 报告里能一眼看出判据，用户才敢信。
- **L2 未引用（按名取图目录里没被点名的）**：这类目录（HUD 图片目录）多半是"整套素材还没接线"，标记为**待确认**而不是直接移。
- **L3 未引用（其他目录）**：真正的归档候选。

判定顺序建议：路径字面量 → 模板前缀（跳过按名取图目录）→ 图集分页 → 目录引用 → 依赖链 → 图集同族 → 裸名（保守）。

## 四、安全归档（最容易出事的一步）

1. **先问范围**。未使用 ≠ 可删：`item/` 里没配置的装备图标、`wing/` 整套翅膀、`role/plist` 外观图集、`skill/plist` 特效图集，都是"待接线"而非垃圾。用「低风险（编辑器残留/废弃态）／中（界面没用到的图）／高（成套待接线素材）」三档让用户选，**不要默认全移**。
2. **问目标位置**，三者语义不同：
   - `assets/resources/unused/`：仍被编辑器导入、仍随 resources 包发布（只是归类）
   - `assets/_unused/`：编辑器仍导入，但不进 resources 包
   - 工程根 `_unused-resources/`（**assets 之外**）：编辑器完全不导入，真正减包体
3. **资源与 `.meta` 成对 `mv`**（uuid 是场景与配置的锚点）。错开一步就会让编辑器重新分配 uuid。
4. **目标目录在 assets 下时必须补目录 meta**：复制任一同级目录的 `.meta` 模板（`importer: "directory"`），`uuidgen` 生成新 uuid，否则编辑器会另建一个并产生两份。
5. 保留**原目录结构**（`unused/map/di_zhuan_4.jpg`），还原时一条命令即可。
6. 移动后**校验三件事**：源目录无孤儿 `.meta`；被移动路径不再出现在任何代码字符串里；归档目录里没有缺 `.meta` 的资源（编辑器工程文件如 `.tiled-project` 本来就没有，属正常）。
7. 把**还原命令**和**清单**写进报告文件（工程根，不要写进 assets 下——会被当资源导入）。

## 五、顺手的附加价值

比对过程会自然暴露出「**配了路径但文件不存在**」的引用（静态字符串找不到对应文件）。
这类是**静默失败**（不报错、只是不显示），价值很高，一定要在报告里单列一张表：
`引用处 | 写的路径 | 实际文件 | 现象`。
本项目一次就查出 6 处（位图字体 `fonts/combat`、`common/big-button|small-button`、`effect/upgrade` 帧目录、`effect/skill/s_XXX@0` 实际在 `skill/plist/`、状态图标 `skill/2009` 实际是 `skill/icon/2009.png`）。

## 六、脚本骨架（Python，直接改着用）

```python
# 1. 收集待审资源（可按用户要求排除某些顶层目录，如 npc/monster/weapons/clothes）
# 2. 从 .meta 建 uuid -> 路径（含 subMetas）
# 3. 遍历 assets（**排除 resources 自身**）读 .ts/.scene/.prefab/.json 全文
#    用 re.findall(r"""(['"`])((?:\\.|(?!\1).)*?)\1""", text) 抽字符串字面量
# 4. 字符串分两桶：含 "/" 且首段是已知顶层目录 -> path_strings；其余 -> bare_names
# 5. 逐文件判定（顺序见上），返回 (used_reason | None)
# 6. 图集同族、tmx->tsx 依赖传播
# 7. 输出：分组报告（含每组明细与命中原因）+ 待归档清单 json
```

性能提示：资源上万时**不要**遍历全库 `json.load` 所有 `.meta`（本项目 8 万个 meta 跑到被 kill）。
先按用户排除项把范围缩小（本项目 584 个），只读范围内的 meta，秒级完成。

## 七、交付物模板

- `resources-分组报告.md`：概览数字 → 每组（来源说明 + 有引用/未引用清单，用 `<details>` 折叠）→ 已归档明细 + 还原命令 → 配置指向缺失资源的问题表。
- 归档目录 + 目录 meta。
- 记忆里记一条：判定口径（尤其"按名取图目录不能用模板判"）与归档位置，避免下次重复踩。

# 数值怎么调（olua：逐条配在库里）

**一句话口径**：数值的唯一权威是数据库（出厂快照 `server/data/config-sync.sql`），
**没有任何曲线在运行时展开**。想改一个数就改那一行 —— 管理端改完即时生效，
要让改动进「出厂值」就 `make config-export` 重导快照并提交。

> #655 之前这里是一整套「分段线性曲线 + 各域按曲线派生」的做法。用户明确否掉了它：
> 「每一条数据都单独配置，而不是通过曲线生成」。**别再引入曲线** —— 一个数改错不该连带十级。
>
> **唯一的例外是等级（#786）**：上限从 60 改成 100 万级后，一行一级存不下（60MB 库 /
> 1.5GB 快照 / 客户端几百 MB 内存），所以等级回到「4 条曲线 × 若干段」的参数化形态：
> 库里只存段参数（起始等级 / 结束等级 / 起始值 / 每级增量 / 每级增量的增量），
> 服务端与客户端按需求值（`levelConfigOf` / `roleLevelAttributesOf`）。
> **别拿这个例外推广**：其它表仍是逐条配置，等级也只在「上限量级」这一层抽象，
> 运营改的仍然是「这一段从哪级到哪级、起始多少、每级涨多少」。

## 一、数值住在哪（改之前先看这张表）

## 二、掉落：每只怪一份表（配置法）

**优先级的唯一写法**：`monster_drops` 里该怪的行 > 它引用的 `drop_tables` 具名表（common / elite / boss）> 兜底 `default`。
三个都在库里，客户端不抽表（`DropManager` 只演散落与拾取，抽表与入包都在服务端结算）。

- **`entries`**：每条独立配 `goodId` / `weight`（权重，相对值）/ `chance`（额外概率）/ `count`（单件数量区间）。
  **稀有度只体现在 weight**，别再叠一层 `chance` —— 两处调稀有度会互相掩盖。
- **`picks`**：本次**掉几件**（抽取次数），数字或 `[min, max]`。每次独立按权重抽，因此**同一条目可重复命中**，
  重复的合并数量。默认按定位给：普通 `[1,3]` / 精英 `[2,6]` / BOSS `[3,10]`。
  注意区分：`picks` 是件数，`count` 是单件物品的堆叠数。
- **权重用「同一量纲预算」**：先定该定位的**装备权重合计**（如普通 44 / 精英 70 / BOSS 96），
  再 `单件预算 = 预算 ÷ 窗口内基础件数`，最后乘前缀倍率 × 后缀倍率 × 部位倍率。
  一条条拍权重，最后一定出现「BOSS 掉得比小怪还寒酸」。
- **窗口口径**：每个部位取 `level ≤ 怪物等级` 且 `怪物等级 − level ≤ 10` 的最近 2 档 ——
  既保证稀疏部位有货，又不让高等级怪掉 1 级垃圾。
- **想批量改**：写一次性脚本读库 → 算 → 写回（`node --disable-warning=ExperimentalWarning` + `node:sqlite`），
  别去手改 `config-sync.sql` 的 INSERT 行（那是导出物，下次导出就被覆盖）。

## 三、掉落散落：铺点用纯函数，别用随机

需求原话常是「掉落物堆在一个点上了，散开」。做法（客户端 `DropScatter`）：

1. **先确认有没有隐藏缩放**：查图层 / 相机有没有 `scale`。正交 2D 且图层无 scale 时，
   世界坐标里的距离就是屏幕距离，可以直接在世界坐标铺点。
2. 写纯函数 `scatterDropPositions(count, minDistance)`：以落点为圆心从内圈往外（半径 = 圈数 × 间距）取候选点，
   每个候选必须与**所有已放点**距离 ≥ 间距才采用（贪心铺满内圈，确定性、无随机 —— 才能断言）。
3. **间距 = 图标宽 + 留白**（如 40 + 12 = 52）。
4. **别用「y 方向乘 0.5 压扁」凑椭圆**：垂直间隔只剩一半，40px 高的图标会互相压住。
5. 校验：1~40 件逐对算最近距离，断言 ≥ 间距。

## 四、调数值前的四个必查

1. **等级上限只有一个来源**：`growth_scalars.roleMaxLevel`（出厂 100 万）。
   改它会**自动把四条曲线末段 `to_level` 拉平**（屏幕上不会同时出现「末段到 100 万」和「上限 200 万」）；
   求值本身支持外推，所以「上限调大」不必先改曲线。
   代码里再有 `if (level >= 30)` 这类硬编码，就会出现「怎么升都停在 30」——
   `ROLE_LEVEL_MAX`（防脏数据上界）也在 `role-data.util.ts`，它必须 ≥ 运营上限。
2. **别把配置数组引用塞进运行时对象**：`this.attack = row.attack` 拿到的是同一个数组 / 对象引用，
   运行时原地改就污染了配置表。写 `[...row.attack]`。
3. **批量改数据后要 grep 计数**：删「逗号开头的注释」会把逗号一起吃掉，改完对比块数（`grep -c '…),'`）。
4. **babel loose 会把 `[...map.values()]` 编成 `[].concat(map)`**（得到 `[Map]` 而不是条目数组），
   配置里遍历 Map 一律 `Array.from(map.values())` 或 `map.forEach` —— 编辑器里跑得好、打包后配置全空。

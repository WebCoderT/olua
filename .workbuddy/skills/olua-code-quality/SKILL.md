# olua 代码质量：死代码与重复代码的排查、判定与清理

工具已固化：`server/package.json` devDependencies（ts-prune + jscpd），Makefile 两个目标。

## 一、工具与命令

```bash
make code-prune   # ts-prune 扫三端未用导出（已内置已知误报过滤）
make code-dup     # jscpd 扫三端 + tools 的重复块（≥120 token）
```

- 运行前提：`cd server && npm install`（两个工具在 server devDependencies）。
- `code-prune` 的白名单（Makefile 里的 grep -vE）对应**已判定为合理形态**的输出：
  共享快照 re-export（`game-data.ts` / `game-data.generated.ts`）、gen-api 双端生成物
  （`api/models.ts` / `ApiModels.ts` / `utils/net/Api.ts`）、Cocos 场景挂载类 default、
  realtime 协议帧 interface（契约文档）、`remainingAttempts`（e2e-guard.cjs 动态 require）。
  新增合理形态时**更新 Makefile 白名单并注释理由**，不要每次手抄输出。

## 二、候选 ≠ 必删：复核口径（最重要）

ts-prune / jscpd 的每条输出都要用 Grep 全仓复核后再动手，五类必然误报：

1. **e2e / 脚本动态引用**：`server/test/*.cjs` 用 `require` 拿 dist 导出（如 `rateLimit.remainingAttempts`），
   ts-prune 看不见 → 看着像死码，删了 e2e 直接红。
2. **gen-api 生成物**：`client/assets/ui/utils/net/Api.ts` 文件头标 `@generated by tools/gen-api.cjs`，
   里面零引用的类型（`HealthApi`、一整页 `XxxQuery`）是两端契约的一部分，**不许手删**——
   改就改服务端 DTO 再 `npm run gen:api`。
3. **Cocos 场景挂载类**：`Game` / `Login` / `RoleSelector` 这类 default export 组件类被场景按 UUID 引用，
   零 import 也**绝不能删**。
4. **模块内自用**：ts-prune 报 `used in module` 的导出可能是同文件 helper（如 hudLayout 的 `commonImage`），活的。
5. **类型被字符串场景引用**（Sprite 组件属性名等）：删前先想引擎反射。

复核动作：对符号名全仓 Grep（限定 `server/src`、`server/test`、`admin/src`、`client/assets/{ui,types,skills,configs}`、
`tools`，**别扫 `client/assets/resources`**——几万素材文件会把 grep 撑爆甚至被沙箱杀掉）。

## 三、重复代码的判定原则：可读性优先于 DRY

jscpd 的重复块先定性再动手，四类**合理形态不要抽**：

1. **数据表条目**（`configs/skill-data.ts` 280 行自重复、`configs/layout/dialogs.ts` 68 行）：
   重复的是配置数据本身（每技能的数值阶梯、每个弹窗的布局数值）。
   抽工厂会把「一眼可见的数值」藏进间接层——配置文件的可读性就是它的价值。
2. **双端生成物**（admin `api/models.ts` ↔ client `ApiModels.ts`，3675 行）：`gen-api` 的产物，改动走源头。
3. **DTO 装饰器样板**（`soul.dto.ts` ↔ `title.dto.ts` 的 Update DTO）：NestJS whitelist 只认校验装饰器，
   抽基类要连带处理 `@ApiProperty` 文案差异（「该阶」vs「该级」）与 emitDecoratorMetadata 的类顺序 TDZ 坑
   （见 olua-server 技能），抽象成本 > 收益。
4. **admin 配置页同构样板**（九个 Page 之间 ~400 行）：页面模板同构是刻意的（照抄上一页改字段），
   抽公共组件的泛型层级会伤可读性。要动就整线一起设计，别顺手抽一半。

值得抽的重复：同一逻辑在**代码层**出现两份且无语义差异（如 #257 先例：title/soul 仓储共用
`attributesFromRow`）——判定标准是「改一处忘另一处会不会出 bug」。

## 四、清理的执行纪律

1. **删码连注释一起删**：死常量头上的 JSDoc（往往解释着不存在的机制）比代码更误导，一并清。
2. **孤儿 import 一起清**：删 `getMapOffset` 后 `view` 从 "cc" 的 import 里没了引用，必须同步摘。
3. **两端编译验证**：`cd server && npm run build` + client 的 `tsc -p tools/tsconfig.check.json`，0 错才算完。
4. **全绿再提交**：`make ci`（十二套 e2e + 审计）过了再 PR；本机另有 `make client-test`。
5. **改动前后必须拉取**：`git fetch` + 同步 master（提交纪律，见 MEMORY.md）。

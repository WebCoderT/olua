# 真彩地图转换：.map + WIL/WIX → 大图 / TMX / resources/map

> 单张入口：`scripts/mir2map_convert.py`（纯 Python + Pillow + numpy）。
> 批量入口：`scripts/mir2map_batch.py`（带**自动判据**：每张图按候选规则渲染并与官方缩略图算相关性，取最高分；< 0.70 用缩略图放大兜底并标记 `thumb-fallback`）。
> 已用 62 张（DT2101~DT2162）实测：57 张 > 0.78（多数 0.87~0.999），4 张兜底。

## 用法

```bash
# 单张（大图 + TMX + meta）
python3 scripts/mir2map_convert.py --dir "<地图目录>" --out <输出> --name <名> [--export-tiles]

# 批量：原始地图目录 → 客户端 resources/map/<id>（id = DT号-2101，DT2101→0）
python3 scripts/mir2map_batch.py --src 原始地图 --out client/assets/resources/map [--only DT2101,DT2102] [--dry]
```

批量产出（每张图一个目录）：`<id>.tmx`（`<map>` 声明 48×32 格；底图按 2048 分页成若干 `<imagelayer>`，带 `offsetx/offsety`）、
`<id>_pNN.jpg`、`preview.jpg`、`meta.json`（来源 / 规则 / 相关性 / 页数）。

## 解码规则（硬结论，别再试错）

### .map 容器

| 项 | 规则 |
|---|---|
| 头 | 52 字节；`w=u16@0`、`h=u16@2`（**先宽后高**）；标题串 "Legend of mir" 从 @4 开始（有的版本在 @16） |
| 格长 | **14 字节**（`len == 52+14*w*h`）或 **12 字节**（`len == 52+12*w*h`）两族；还有个别 36 字节的变体（DT2162，未破译，走缩略图兜底） |
| 字段 | 14B：bg(2)/mid(2)/obj(2)+8 标志；12B：bg/mid/obj+6 标志 |
| 索引 | 低 15 位（`&0x7FFF`）、1 基、0=无；高位 0x8000 恒置 |

### 地面：三种族（按素材形态选，公式都是**列主序**）

| 族 | 条件 | 规则 |
|---|---|---|
| A 块图 | 有 `Tiles*.wil`，每张 **96×64**，张数 == `w/2 × h/2` | 块(bx,by) → 第 `bx*(h/2)+by+1` 张，贴到 `(bx*96, by*64)` |
| A′ 偏移库 | 同上但 WIL 张数 > 块数（如 9794 张 / 4897 块） | 仍然 1..块数 取前段；「后半段」是另一套小图，不用 |
| B 逐格 | 只有 `Objects*.wil`，每张 **48×32**，张数 == `w*h`（或 2×） | 格(i,j) → 第 `i*h+j+1` 张（**列主序**；行主序出来是噪声 0.007，列主序 0.81） |
| C 大块 96×96 | 有 `SmTiles*.wil`，每张 **96×96** | 值 v（存在 mid 字段）→ 贴到块 `((v-1)%gw, (v-1)//gw)`（行主序摆放），gw = w/2 |

### 三条通用坑

- **bg/mid/obj 里的「1..N 连续排列」不是渲染索引**，是索引元数据（每块/每格恰好一个值，扫描序赋值）。按它渲染相关性会掉到 0.0~0.3——A 族 bg 反证是 0.27，位置序 0.95。**判据以缩略图相关性为准，不以「值看起来像索引」为准。**
- **翻转**：瓦片行自下而上存储，绘制前上下翻转（`rgb[::-1]`）。A/B/C 三族都要。
- **物件（A 族）**：obj 字段 = 物件号 → `Objects*.wil`；摆放 `x = i*48, y = (j+1)*32 - 图高`（底部对齐格子下边缘），同样上下翻转；同号物件只解一次。

### WIL / WIX

- WIX：44 字节标题 + `count=u32@44` + 偏移数组 int32 LE @48（数组长度 == 文件大小）。
- WIL：每图 8 字节头 `(w,h,px,py)` u16 LE；**未压缩 RGB565**（R5→×255//31、G6→×255//63、B5→×255//31）；px=7、py=-44 是引擎常量，`py>32767` 时减 65536。
- numpy 批量解码：`np.frombuffer(wil, '<u2', w*h, off_start+8).reshape(h,w)`，比逐像素快两个数量级。

## 输出到 Cocos（客户端）的形态

- **Cocos 3.8.7 原生支持 `<imagelayer>`**（引擎 `cocos/tiledmap/tmx-xml-parser.ts` 的 `_parseImageLayer`，支持 `offsetx/offsety`）。
- 大图不能整张当纹理（有的图 14976×8896，超 4096 上限）→ 按 **2048×2048 分页**，每页一个 imagelayer，`offsetx/offsety` 定位；页尺寸取实际剩余（最后一页不补边）。
- `<map>` 头仍按真实几何写（`tilewidth=48 tileheight=32 width=格数`），服务端 `tools/import-map-resources.cjs` 靠它算像素尺寸。
- 每张图同时出 `preview.jpg`（宽 512）——客户端小地图按 `map/<id>/preview` 找。
- 图层命名：第一页叫 `ground`，其余 `ground_p01`…（管理端详情按名字展示）。

## 验证方法论（拼图「看着对但细节不对」时）

1. **先核文件大小**：`52 + 14*w*h`（或 12B）对上，宽高就不会读反。
2. **缩略图相关性**：素材目录的官方 bmp 是唯一外部裁判。**把拼图缩到缩略图原尺寸再比**（放大缩略图会失去区分度）。正确解法 0.87~0.999；错误解法普遍 < 0.5。
3. 缩略图纵横比常是「1.5px/格宽 × 1px/格高」，会带来 0.73~0.83 的天然折损——**同一张图的候选规则之间比**，不要拿不同图的分值横比。
4. **黑砖会污染接缝指标**：黑边对黑边也算「连续」，用接缝判旋转/翻转时避开纯黑区。
5. 每个结论都要有**反证**：错解法必须产出明显错的画面，而不是「差不多」。

## 注意

- 素材目录（`原始地图/【真彩地图】DTxxxx-*/`）与 `client/assets/resources` **都不入库**。
- 换图后必须：`node tools/import-map-resources.cjs` → `make config-export`（重导后 `-- config-version` 归 0）。
- 兜底图（`thumb-fallback`）是视觉降级：形状对、细节糊。重开条件 = 拿到对应共享瓦片库或破译 36 字节格格式。

## 换图后 e2e 坐标适配（#1150 实测清单）

新图普遍比旧图小得多（旧图 1 是 8192 宽，新图 1 只有 1872×1344）。写死旧图坐标的测试会以**三种方式**红：

1. **走管理端 API 的播种/摆点/复活点**（`POST /admin/maps/:id/spawn-areas | npcs | collisions | revive-point`）：
   越界直接 400（刷怪区/NPC/复活点要求在图内；碰撞盒只拒**整块**在外）。改测试里的坐标常量进新图边界。
2. **pos 帧 / 靶子坐标在图外**：AOI 广播按格子裁剪，图外的靶/玩家收不到帧——表现为「等待超时」且
   观察窗口内 AI 帧数 = 0（e2e-status 的灼烧靶就是这么定位的）。分成距离闸（party）也量不准。
3. **出厂断言**：原来「每张图都有碰撞盒 / 都有复活点 / 全部 cy ≤ 0」这类全称断言，换图后只有图 0
   带出厂配置（3 刷怪区 / 4 围墙 / 1 复活点 / 1 传送官），要改成「图 0 有 + 其余与快照一致」。
   上墙 cy=24 半截在图内，「全部 cy ≤ 0」要放宽成 `cy < h`。

排查手法：先看失败断言是「API 400」还是「等待超时」——前者对界改坐标，后者用诊断输出确认
「观察窗口内帧数=0」再挪靶。图尺寸查 `maps` 表 `pixel_width/pixel_height`（世界坐标 x∈[0,W]、y∈[-H,0]）。

# 真彩地图转换：.map + WIL/WIX → 大图 / TMX

> 唯一入口：`scripts/mir2map_convert.py`（纯 Python + Pillow，无其他依赖）。
> 规则已用 DT2101（泡点、擂台）验证：官方缩略图相关性 0.949、接缝比 ≈1.0、用户肉眼确认「完全正确」。
> 脚本输出与人工调参的正确导出**逐像素一致**（diff bbox = None）。

## 用法

```bash
python3 .workbuddy/skills/mir2-map-convert/scripts/mir2map_convert.py \
  --dir "<含 .map + Tiles*.wil/.wix + Objects*.wil/.wix 的目录>" \
  --out <输出目录> --name <基准名> [--export-tiles]
```

产出：`<名>-纯地面.png` / `-地面.jpg` / `-完整地图(地面+物件).png` / `-物件层(透明).png`
/ `<名>.tmx`（imagelayer ground + objectgroup objects 带 cell/wil_index 属性）/ `<名>-meta.json`
（`--export-tiles` 额外导出单张瓦片/物件 PNG）。

## 解码规则（硬结论，别再试错）

| 层 | 规则 |
|---|---|
| `.map` | 头 52 字节；**w=u16@0、h=u16@2（先读宽再读高，别读反）**；每格 14 字节 = bg(2)/mid(2)/obj(2)+8 标志；文件大小必须 = `52 + w*h*14` |
| 索引 | 低 15 位（`&0x7FFF`）、1 基、0=无；高位 0x8000 恒置 |
| 地面 | `w/2 × h/2` 个 **96×64** 块；块(bx,by) → Tiles WIL 第 `bx*(h/2)+by+1` 张（**列主序**，行主序会拼成竖条纹）；每图块数与 WIL 张数正好相等（专用图集） |
| 翻转 | **瓦片行自下而上存储**，绘制前 `transpose(Image.FLIP_TOP_BOTTOM)`，否则接缝竖向错位 |
| bg 字段 | **旧版 48×32 小瓦片的遗留，真彩图里勿用**（大量 0 但地面铺满；个别值与位置序不符） |
| 物件 | map 的 obj 字段给出物件号与所在格 (i,j)；摆放 `x = i*48, y = (j+1)*32 - 图高`（底部对齐格子行下边缘），同样上下翻转 |
| WIX | 44 字节标题 + count=u32@44 + 偏移数组 int32 LE @48 |
| WIL | 每图 8 字节头 (w,h,px,py) u16 LE；**未压缩 RGB565**（R5 G6 B5 → ×255//31 / ×255//63）；px=7、py=-44 为引擎常量，py>32767 时需 -65536 |

## 验证方法论（拼图「看着对但细节不对」时）

1. **先核文件大小**：`52 + w*h*14` 对上，宽高就不会读反。
2. **缩略图相关性**：素材目录常有官方缩略图 bmp（72×58）；**把拼图缩小到缩略图原尺寸比**，
   不要把缩略图放大比——放大后一切相关性都趋近、分辨不出对错。DT2101 实测：正确解法 0.949，错误解法 0.28~0.81。
3. **黑砖会污染接缝指标**：黑边对黑边也算「连续」，靠接缝判断旋转/翻转时先避开纯黑瓦片区。
4. **错在哪一层要分层看**：像素内 RGB565 布局对了但整图是条纹 → 错在索引映射（列主序/行主序）；
   像素全糊 → 错在解码层。
5. 每个结论都要有**反证**：候选规则穷举后，错解法必须产出明显错的画面，而不是「差不多」。

## 注意

- 素材目录（如 `【真彩地图】DT2101-泡点、擂台/`）**不入库**（与 `client/assets/resources` 同纪律）。
- 物件层若出现「大图被切成 48px 竖条」的观感，先怀疑该图是多个独立小物件拼接错，而不是解码错；
  锚点以 map 的 obj 字段格子为准，不要目测摆。

# 契约管线：一份文档 → 两端接口文件

## 一、链路（单向，只往一个方向流）

```
server/src（控制器 + DTO + 装饰器）           ← 唯一需要手写的地方
      │  cd server && npm run swagger:emit
      ▼
server/openapi.json（机器可读契约，提交进仓库）
      │  node tools/gen-api.cjs
      ▼
客户端 assets/ui/utils/net/{ApiRoutes,ApiModels,Api}.ts
管理端 admin/src/api/{routes,models,endpoints}.ts
```

一条命令跑完三步：`cd server && npm run gen:api`。

**为什么值得这么绕**：「服务端改一个字段、另外两端忘了改」会变成**编译报错**，而不是线上出现一个 `undefined`。

## 二、生成器 `tools/gen-api.cjs` 读哪些约定

| 文档里的字段 | 由谁写 | 决定什么 |
|---|---|---|
| `operationId`（`<模块>.<方法>`） | `@ApiPublicDoc` / `@ApiPlayerDoc` / `@ApiAdminDoc` 的 `operationId` | 生成到哪个模块的哪个方法 |
| 路径是否 `/admin/...` | 控制器 `@Controller("/admin/...")` | 归客户端还是管理端（归错**直接抛错**，不做静默兼容） |
| `x-olua-audience` | 三个装饰器自动加 | 是否带令牌（`public` → `auth: false`） |
| `x-olua-data-schema` / `x-olua-data-nullable` | `@ApiDataResponse(...)` | 响应里 `data` 的类型（缺省 = `null`） |
| `x-olua-query-schema` | `@ApiQueryModel(XxxQueryDto)` | query 参数对应的命名类型 |
| `x-olua-permissions` | `@ApiAdminDoc({ permissions })` | 生成物注释里的「所需权限」（两端对照用） |

`MODULES` 表在生成器里把 `operationId` 前缀映射到「目标端 + 导出名」：
`health/auth/role → 客户端`，`adminAuth/adminAccount/adminAdmin/adminRole → 管理端`。

生成器能处理的 schema 形态：`allOf`（继承）、`$ref`、数组、可空（`nullable`）、枚举字面量、路径参数、query 聚合类型。

用法：

```bash
node tools/gen-api.cjs            # 默认：写盘（Cocos 侧自动补 .meta）
node tools/gen-api.cjs --check    # 只比对，不写盘（守卫用；退出码非 0 表示生成物落后）
node tools/gen-api.cjs --json     # 输出摘要（有多少接口、多少文件）
```

## 三、手写 vs 生成的边界

| | 生成（禁止手改，带 `@generated by tools/gen-api.cjs` 头） | 手写 |
|---|---|---|
| 客户端 | `ApiRoutes.ts` 路径表 / `ApiModels.ts` 类型 / `Api.ts` 接口方法 | `HttpClient`（请求实现）/ `ApiCodes`（业务码 + 文案 key）/ `ApiError` / `Session` / `RoleSync` / `NetworkSetup` |
| 管理端 | `routes.ts` / `models.ts` / `endpoints.ts`（`authApi`·`accountsApi`·`adminsApi`·`rolesApi`） | `config.ts` / `http.ts` / `types.ts`（错误模型 + 业务码 + 权限点 + 展示字典）/ `index.ts` barrel |

`*.api.ts` 那种手写的接口模块**已经删掉了**；页面全部走 `../api` barrel，所以换生成物时**页面 import 一行不用改**。

## 四、守卫脚本

### `tools/audit-api-generated.cjs`（生成物 vs 文档）

| 段 | 查什么 |
|---|---|
| A | 生成物与「重新跑一遍生成器」的结果**逐字节一致** |
| B | 头标记 `@generated by tools/gen-api.cjs` 必须在（抹掉 = 手写） |
| C | 文档里每个接口都落到了方法上，且**没有跑到另一端**去 |
| D | `import` 的类型不悬空（引用了文档里不存在的类型要报） |
| E | 接口路径只出现在**路径表**里（业务代码里出现 = 硬编码） |
| F | Cocos 侧生成物的 `.meta` 齐全（管理端是 Vite 工程，不写 `.meta`） |
| G | 契约完整度：每个接口都有 `operationId`、分组、`audience` |

### `tools/audit-api-hardcode.cjs`（三端地址 / 请求 / 路径的唯一来源）

- 客户端地址唯一来源 `assets/configs/network.ts`，管理端 `admin/.env.*` 的 `VITE_API_BASE_URL`，服务端 `server/.env`；
- 请求唯一出口：客户端 `HttpClient.ts`、管理端 `http.ts`；
- 路径唯一来源：两端的**生成物**；且**唯一来源文件必须带生成标记**（标记被抹掉就等于硬编码）；
- 顺带查环境变量键是否都登记进了 `.env.example`（注释与日志行不算）。

## 五、两个容易踩的实现细节

1. **生成类型必须写 `export type X = { ... }`，不能用 `export interface X { ... }`**。
   `interface` **没有隐式索引签名**，赋给请求层的 `Record<string, string | number | null | undefined>`（query 参数）会被 TS 拒；对象字面量类型别名有。
2. **`--check` 也要补 `.meta`**。生成器在「内容没变」的分支里同样调 `ensureMeta`，否则新克隆的仓库、或 meta 被误删时会静默缺 meta —— 表现为 A/B/C 段全过、只有 F 段单独失败。

## 六、反向验证（改守卫时照这个清单自测）

故意制造破坏 → 守卫必须拦下 → 跑完自动还原。已验证拦得住的 8 类：

1. 手改生成物内容；
2. 抹掉生成标记；
3. 往业务代码里塞接口路径；
4. 删掉生成物里的一个方法；
5. `import` 一个不存在的类型；
6. 删掉 `.meta`；
7. 抹掉「唯一来源文件」的生成标记；
8. 删掉「唯一来源文件」。

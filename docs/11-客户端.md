# 11 · 客户端

> Cocos Creator 3.8.7 + TypeScript，没有 npm 脚本（用编辑器打开），单测靠 `tools/test-*.cjs` 直接跑 node。
> 这一篇讲清「一个点击到屏幕变化」中间有哪几层，以及哪些东西**故意不在客户端**。

## 一、四个场景

```
Loading  ──→  Login  ──→  RoleSelector  ──→  Game
  拉配置      账号登录      选角 / 建号        进图 + 世界 + HUD
```

| 场景 | 入口 | 做什么 | 失败时 |
|---|---|---|---|
| `Loading` | 启动 | 拉配置快照 + 三套外观数据（`ConfigLoader`） | **停在 Loading** + 明确文案 + 重试，不构建 Game 世界 |
| `Login` | 手动 | 注册 / 登录，写会话令牌 | 提示留原页 |
| `RoleSelector` | 登录成功 | 角色列表 / 建号 / 删号 / 选中（`RoleApi.select`） | 提示 |
| `Game` | 选中角色 | `installNetwork()` → 接 `RoleSync` 出口 → 连实时通道 → 进图 → 建 HUD | 见第七节 |

**`Game.start()` 是全部接线的组合根**：`RoleSync.onFailed/onSaved/onConflict/onMissing/onKicked`、
`RealtimeClient.onStatusChange`、`CombatChannel.on*` 十余个出口全在这里绑到具体 Manager 上。
「某个帧没落地」的第一嫌疑永远是这里漏了一条 `.bind`。

## 三、六层渲染与一个必踩的坑

```ts
enum Layer { MAP, DROP, GAME, MONSTER, EFFECT, UI }   // MONSTER 在 GAME 之上，特效在怪物之上
```

| 层 | 放什么 |
|---|---|
| `MAP` | 地图瓦片 / 碰撞 |
| `DROP` | 地面掉落物 |
| `GAME` | 主角、其他玩家 |
| `MONSTER` | 怪物 |
| `EFFECT` | 技能特效、飘字 |
| `UI` | HUD、弹窗、引导遮罩 |

⚠️ **坑：挂载图层之后动态新建的子节点不会继承 `layer`**。引擎新建节点的 `layer` 恒为 `DEFAULT`，
不在相机 `visibility` 内，于是「背包刷新 / 装备槽换装 / 属性列表重建」这些**动态重建**的内容会渲染不出来。
`LayerManager.setNodeToLayer` 给整棵子树注册了「新增子节点自动继承图层」监听，就是为这个。
自己 `new Node()` 挂到 UI 里时必须走它，不要手动设 `node.layer`。

## 五、网络三件套（HTTP）

```
业务代码
  ↓ 只写「路径 + 入参 + 返回类型」
ApiRoutes.ts        ← 路径的唯一定义处（role.bagOp = id => /roles/:id/bag-op）
  ↓
Api.ts（生成物）    ← 每个 operationId 一个方法，签名来自 openapi.json
  ↓
HttpClient          ← 拦截器链 → 超时 → 网络层重试 → 解包 → 错误归一 → 需要重登时回登录场景
```

为什么分三层：**`Api.ts` 是生成的**（`node tools/gen-api.cjs`），手改会在下次生成时被覆盖；
路径写死在业务里则改一个路径要改十几处。所以业务永远调 `Api.ts`，而 `Api.ts` 只从 `ApiRoutes.ts` 取路径。

`HttpClient` 的四个口径：

| 口径 | 说明 |
|---|---|
| **用 XMLHttpRequest 不用 fetch** | Cocos 在 Web 与原生两端都保证有 XHR；fetch 在部分原生环境不存在，用它会「同一份代码两端行为不一致」 |
| **统一响应包裹** | `{ code, message, data, timestamp }`；`code !== 0` 一律抛 `ApiError` |
| **`silent: true`** | 失败不交给全局提示出口。给「后台自动跑、玩家没主动触发」的请求用（典型是 `RoleSync`，否则后端一挂打怪期间每 1.5 秒弹一次）。**但令牌失效依旧回登录场景** —— 那不是「可以静默」的错误 |
| **`unauthorizedHandler`** | 请求层不认识场景，由组合根接上「回登录场景」 |

`ApiError` 的 `kind`（network / http / biz / timeout…）决定提示文案；
业务码语义见 [03](./03-服务端与接口契约.md) 与 `client/assets/ui/utils/net/ApiCodes.ts`（手写镜像，逐键比对）。

## 六、实时通道（WS）

```
取票据 POST /realtime/ticket（一次性、30 秒过期）
  → 建连 ws://…/realtime?ticket=…
  → 收 welcome（带 heartbeatMs）
  → 应用层心跳（间隔以服务端给的为准）
  → 掉线：指数退避重连
```

四条必须记住的判定：

| 情况 | 处理 | 为什么 |
|---|---|---|
| **401 / 40100**（令牌失效） | **停**，请求层已送回登录 | 重连没有意义 |
| **票据过期 / 网络抖动** | **重新取一张票**再连 | 绝不能把人踢回登录页 —— 他什么都没做错 |
| **close 4000（被顶掉）** | **不抢回来**，停在这里 | 抢的话两个客户端会互相踢、来回刷（这条是「别处已经有人连上了」，不是「网络不好」） |
| close 1001（服务端关闭中） | 照常重连 | 优雅重启 |

**心跳必须是应用层的**：浏览器拿不到协议层 ping/pong 帧，客户端要量往返、要判断「多久没响应算掉线」，只能自己发。

`RealtimeClient.onStatusChange` 给三个布尔（`lost` / `reconnected` / `willRetry`）——
组合根据此决定提示哪一句。三者合成一个「连上了/没连上」的话，服务端挂掉期间就会刷屏。

### `CombatChannel`：28 种帧

| 方向 | 帧 |
|---|---|
| 客户端 → 服务端 | `cast` / `pick` / `pos` / `worldJoin` / `mapEnter` / `chat` / `party*` / **`pathFind`**（#811） |
| 服务端 → 客户端 | `welcome` / `ping` / `pong` / `error` / `cast` / `settle` / `targetsReset` / `world` / `worldJoin` / `mapEnterResult` / `picked` / `players` / `chat` / `quest` / `party` / `partySnapshot` / `partyInvite` / `expGain` / `roleUpdate` / `status` / `monster-ai` / **`posCorrect`** / **`path`** / **`world.reload`**（#809） |

每个 `on*` 出口都由 `Game.start()` 接到具体 Manager。**没接的出口会静默丢弃**（只打一次 warn），
表现是「功能不生效但没报错」—— 排查时先看这里。

**`world.reload`（#809，客户端暂时放置）**：这张图的房间被管理端重载（或到点强制重刷）后服务端发的
通知帧，`data = {roomId, mapId, slot, forced}`。客户端**目前没有接**（走到帧分发末尾被忽略，无副作用）：
接帧的价值只是一条「本图怪物已重新刷新」的提示，而提示文案要走 `texts` 快照链（服务端登记 key →
管理端 → 快照下发），不值得为一条提示扩三端。**重开条件**：任务面板 / 提示系统改版顺路接，
或玩家反馈「怪怎么突然变了」成为共性问题。`world` 帧永远比它先到（服务端保证顺序），
所以就算丢了这帧，怪物列表也已经是新的。

`CastChannel.sendCast` 的 `castId` 是**会话内单调递增**（断线重连服务端会清账，这里不回绕）。
`sendPosition` 内部按 4Hz 节流（AI 的目标检测不需要逐帧精度），换图时要 `resetPositionThrottle()`。

**位置的两个新出口（#811）** —— 客户端在这两处**不做决策**，只执行：

| 帧 | 客户端做什么 |
|---|---|
| `posCorrect` | `RoleDisplay.applyServerCorrection(x, y)`：差 < 64px 记目标按 34%/帧插值、≥ 64px 瞬移，两档都先 `stopRigidBody()`；`AutoBattle` 同时**作废当前路点**（否则一边被拉回一边朝旧目标走）+ 卡住计数清零 + 抽一次 `texts.position_corrected_tip` |
| `path` | `AutoBattle.applyServerPath(frame)`：`seq` 对不上直接丢（用户可能又点了一下）；`unreachable` 时点击寻路 → `giveUpPointMove`、追怪 → `giveUpCurrentTarget`；正常则用服务端路点**替换**本地 A* 那份 |

`repathTo()` 是「本地 A* 先算 + 同时发 `pathFind` 抢 `pendingPathSeq`」：
本地那份只负责「点了立刻有反应」，服务端那份负责正确性。本地不保留「服务端不可达但本地觉得能到」的兜底 ——
两端网格生成口径与 `auto_battle.cellSize / clearance` 同源，打架就是 bug，该修而不是兜。

## 七、配置加载：为什么「拉不到就进不去」

`ConfigLoader.loadGameConfig()` 并行拉四个接口：

| 接口 | 频率 | 理由 |
|---|---|---|
| `gameConfig.snapshot` | **进程内只拉一次**（32 段） | 十几张表、只跟版本有关，重复拉纯浪费 RTT |
| `gameConfig.equipAlign` | **每次进图** | 地图外观几何是「人眼调一版、立刻要看效果」 |
| `gameConfig.equipInAlign` | **每次进图** + **开弹窗再拉一次** | 内观只在弹窗里出现，玩家保存完的第一反应是再点开看一眼 |
| `gameConfig.equipmentAppearance` | **每次进图** | 边框 / 底图同理 |

- **快照是硬依赖**（#604）：返回 `ok: false` 时调用方**停在 Loading**，不构建 Game 世界。
  客户端那几份出厂表已随 #603 逐域退场，「拉不到就按本地玩」等于「按空表玩」——
  一个空着却看不出来的游戏比一个炸得响的错误难查。
- **失败分两类**：`network`（请求没成）与 `contract`（拿到了但缺段 / 形状不对，逐条列出 key 与中文名）。
  两类都**不置「已加载」**：一次抖动不该永久退化成空表。
- **几何失败不致命**（#527）：外观 / 内观缺行 = 按装备表里的出厂几何画（那本来就是「工作台还没调过」的语义），
  所以只 `console.warn`。但也绝不静默 —— 一个 404 会被当成「保存没生效」。
- **去重并发**：同一次进图的重复调用共享同一个 Promise。

> 判据提醒：验收动作是不是「保存 → 退回选角再进图」？
> 是 → 走的是每次进图那条；否 → 走快照，**改了要重启服务端**（快照进程内只拉一次）。

## 八、存档三件套

| 文件 | 职责 | 详见 |
|---|---|---|
| `core/StorageManager` | 本地读写、`ensureRoleDefaults` 补齐旧档、`updateOnlineRole` 唯一落盘出口 | [04](./04-角色与存档权威.md) 第十节 |
| `utils/net/RoleSync` | 1.5s 防抖推送 + 四条自愈出口 | [04](./04-角色与存档权威.md) 第七节 |
| `core/StorageManager.applyServerRoleUpdate` | `roleUpdate` 帧照搬（唯一入口）+ 迟到帧守卫 | 同上第十一节 |

**「改了本地就以为改了服务端」是这里最常见的误解**：`role.bag` / `role.equipments` / `bindGold` 等都是
服务端独占字段，本地改完下一次存档会被回填成库里的值 —— 表现就是「按下去没反应」。
所以背包动作必须走 `runBagOp`，成长走 `upgradeGrowthOnServer`，购买走 `purchaseOnServer`。

## 九、掉落与拾取（表现侧）

```
kill 事件（monster-ai 帧 + settle.reward.drops）
  → DropManager 在地面造节点（按 drop_params 的散落半径/最小间距）
  → 玩家走/点靠近（autoPickupRadius 内自动）
  → sendPick(castId, index)
  → picked 帧：入包格子照搬本地 + 收掉地面节点 + 刷新背包
```

- **点远处的掉落物不再隔空取物**（#817）：`ScreenClickInput.pickupOrWalk` 先量角色到节点的距离，
  超出 `autoPickupRadius` 就 `AutoBattle.requestMoveTo` 走过去，走进来那一帧才由 `autoPickup` 发 `pick`。
- 服务端另有独立的距离闸 `pickAcceptRadius`（出厂 200px，**与客户端这把 40px 的尺子不是一回事**）：
  客户端这把管手感，服务端那把管归属。取不到位置 / 位置超过 5 秒没更新 / 图不一致 / 超距 一律拒。

- 绑定与溯源的**展示**在 `configs/items.bagMetaOf`（只读元数据，搬运 / 整理 / 回收都原样带走）。
- `pickReplyTimeout`（默认 5s）是「发了 pick 但没回」的超时，不是服务端的冷却。
- 拾取失败（`bag_full`）只飘一句提示，地面掉落物**保留**，腾出格子后可再拾。

## 十一、单测与门禁

客户端没有 npm 脚本，两套门禁在根 Makefile：

```bash
make client-check                  # Cocos 自带 tsc 类型检查，0 错才算过
make client-test                   # 跑 client/tools/test-*.cjs 全部（67 个）
make client-test-one T=test-bag-bind
```

`tools/test-*.cjs` 是**直接 require `assets/configs` 的纯函数**跑 node 的（所以配置层不能 import 引擎）。
判绿看 exit code —— 成功时静默。

常用生成工具：

| 命令 | 作用 |
|---|---|
| `make client-gen-monster` | 从 Tiled / 配置生成怪物常量 |
| `make client-gen-drops` | 生成掉落相关常量 |
| `make client-gen-declarations` | 生成声明文件 |
| `make client-clean-frames` | 清空帧（`-apply` 才真删） |

## 十二、Cocos 侧的已知坑（都踩过）

| 坑 | 正确做法 |
|---|---|
| 点击 / 触摸不响应 | 节点必须有 `UITransform` 且尺寸非 0 |
| 动画播完不回到 idle | `AnimationState` 要手动 `stop()`，别指望自动 |
| 节点已销毁还回调 | `isValid(node, true)` 判「连同组件一起」 |
| 坐标算错 | 几何锚点是**画布中心**，不是左下角 |
| 分辨率适配 | 三层（设计分辨率 / 安全区 / 实际屏幕），别只改一层 |
| `Game` 挂 Canvas | 六个图层建好之后再 `setWorldPosition(0,0,0)`（#692） |
| 动态子节点不显示 | 见第三节（layer 继承） |
| 显隐与摆位对不上 | 要绑定「片段是否就绪」（#726） |
| `[...map.values()]` | 打包 loose 会降级成 concat → 用 `Array.from` |
| `padStart` / `Object.entries` | 客户端 tsconfig 不引 ES2017 → 用切片 / `Object.keys` |

## 十三、排障

| 症状 | 第一嫌疑 | 查法 |
|---|---|---|
| 卡在 Loading | 快照拉不到（网络 / 契约） | Loading 页文案区分 `network` / `contract`；看 console |
| 进了游戏但一片空白 | 图层没挂 / 相机 visibility | 见第三节 |
| 某个功能「没反应」 | 帧出口没接线 | 看 `Game.start()` 里对应的 `.bind` |
| 数值改了不回显 | 本地改了独占字段，被回填 | 见第八节 |
| 换装后外观没变 | 几何覆盖没拉（每次进图才拉） | 退回选角再进图；或看 `equipAlign` 请求 |
| 打怪不掉东西 | 掉落帧到了但节点没造 | 看 `DropManager` 是否收到 `drops` |
| 「已在别处被修改」 | 有写点没更新 `revision` | 见 [04](./04-角色与存档权威.md) 第七节 |
| 一直掉线重连 | 票据取不到 / 令牌过期 | 区分 `401` 与票据过期（日志不一样） |
| 两个客户端互相踢 | 被顶掉（4000）后还在抢连 | 见第六节 |
| 类型检查报错 | 手工改了 `Api.ts` | 重跑 `node tools/gen-api.cjs` |

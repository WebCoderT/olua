## 零、现状（实测）

| 子系统 | 表 | 行数 | 实际能力 |
|---|---|---|---|
| 好友 | `role_friends` / `role_blocks` / `role_enemies` / `role_reports` | 有数据 | 加好友、拉黑、举报可用 |
| 组队 | `parties(id, leader_role_id, created_at)` / `party_members(party_id, role_id, joined_at)` | **5 队 / 9 人** | 建队、加入、退出、同图队友经验分成（#399） |
| 帮会 | `guilds(id, name, notice, leader_id, level, funds, …)` / `guild_members` / `guild_applications` | **0 行** | 建会、审批、公告；`level` / `funds` **无业务** |

**组队缺的**：邀请/申请状态机、队长转让、踢人、解散、成员上限、分配方式、队伍频道（`CHAT_CHANNELS`
只有 `world` / `guild` / `private`，**没有 party**）、离线成员清理、跨图队伍。

**帮会缺的**：等级如何涨、资金从哪来去哪、帮会技能、帮会战。现在 `level` / `funds` 只是两列数字。

## 一、五个结构性问题

### 1.1 组队没有状态机

`party_members` 一插即入队，没有「邀请中 / 待确认 / 已加入」。后果：
不能拒绝、不能邀请离线、不能防「被拉进队」。

### 1.2 分配方式不存在，与 18 篇的掉落模型冲突

18 篇的掉落归属在 **spawn 时固化**（`owner` + `partyId` 快照）。要做「队长分配」，
就必须允许**保护期内由队长改归属** —— 这是对 18 篇模型的一处扩展，必须显式写清，
否则实现时会两边打架。

### 1.3 没有队伍频道，组队等于「各打各的」

现在的沟通只能靠私聊或世界频道。队伍频道是组队玩法的**最低配置**，缺了它就没有协作。

### 1.4 帮会的等级与资金没有闭环

| 应然 | 现状 |
|---|---|
| 等级靠成员活跃/贡献涨 | 没有来源 |
| 资金靠捐献与税收 | 没有来源 |
| 等级与资金有用途 | 没有用途 |

一个「只有两个数字列」的帮会，玩家没有理由加入。

### 1.5 组队与副本/帮会战的结构没对齐

20 篇的副本要「一队人进一个独立 room」，#403 的帮会战要「两个帮会进一个战场」。
现在的队伍连「成员上限」都没有，没法作为副本的单位。

## 二、目标形态

### 2.1 队伍：完整状态机

```
        invite ──接受──> member ──退出/被踢──> out
创建 ──> │              │
        └──拒绝/超时──> out      队长转让（leader 变 member，另一 member 变 leader）
```

| 项 | 规则 |
|---|---|
| 建队 | 任意在线角色；建队者 = 队长 |
| 邀请 | 队长或成员可邀请；被邀请方 30 秒内确认；**离线不能邀请** |
| 上限 | `party_max_members`（默认 **5**） |
| 队长 | 可转让；队长下线 5 分钟后自动转给最早加入的在线成员；无在线成员则队伍解散 |
| 踢人 | 仅队长；被踢者 60 秒内不能再申请同队 |
| 解散 | 仅队长；成员全部变「无队伍」 |
| 跨图 | **允许**（成员可在不同图），但分成与分配只对**同图**生效（沿用 #399 口径） |
| 离线 | 成员离线保留 10 分钟位置，超时移出队伍 |

### 2.2 掉落分配：自由 + 队长分配（已定）

| 模式 | 规则 |
|---|---|
| `free`（默认） | 沿用 18 篇：归属者 + 队友保护期，谁先捡到谁的 |
| `leader` | 保护期内（30 秒）**队长可把归属转给任一在线队友**；转出后原归属者失去优先权 |

**对 18 篇的扩展（必须同步改那篇）**：

- `world_drops.owner` 由「不可变」改为「保护期内可由队长修改」；
- 修改要广播 `dropOwner`（新帧）让同图队友看到「现在是 XX 的」；
- 只允许改成**同队成员**；非队长调用 → `not_party_leader`；保护期过后 → `protect_expired`；
- 队长分配模式下，**非队长仍可捡自己的**（不变成「必须队长点」）—— 否则拾取体验很差。

### 2.3 队伍频道

`CHAT_CHANNELS` 加 `"party"`：

| 项 | 规则 |
|---|---|
| 广播范围 | 本队全体在线成员（**跨图也收**） |
| 权限 | 只有队伍成员能发；无队伍发送 → `not_in_party` |
| 与 `world` 的区别 | `world` 是全服（30 篇），`party` 只到队伍 |

### 2.4 帮会：等级与资金闭环

**等级**：

| 项 | 规则 |
|---|---|
| 经验来源 | 成员在线时长（1 点/分钟/人）+ 成员完成日常任务（10 点/次）+ 帮会战参与（100 点/场） |
| 升级 | 达阈值自动升；`guild_level_rules` 配置每级所需经验与人数上限 |
| 收益 | 人数上限 +5/级；帮会技能等级上限 +1/5 级；帮会频道发言等级门槛降低 |

**资金**：

| 项 | 规则 |
|---|---|
| 来源 | 成员捐献（绑定元宝）；交易税分成（`trade_tax × 10%` 划给卖家所在帮会，见 26 篇） |
| 用途 | 升级帮会技能（一次性消耗）；帮会战报名费；帮会公告置顶 |
| 权限 | 只有会长/副会长能动用；每笔走 `economy_log(kind='guild')` |
| 上限 | 资金上限 = `level × 100000`，超出部分不再入账（防无限囤积） |

**帮会技能**：新表 `guild_skills(guild_id, skill_id, level)`，效果是全帮 buff
（攻击 +x% / 经验 +x% / 掉落 +x%），在 `roleAttributeSourceOf` 的**加算段**生效（不进转生乘算）。

### 2.5 帮会战（#403 的口径）

| 项 | 规则 |
|---|---|
| 报名 | 会长用资金报名，按等级段匹配（差 ≤ 3 级） |
| 战场 | 20 篇的「副本」机制：`slot = "i<seq>"` 的独立 room |
| 胜负 | 60 分钟内击杀数 / 占点分高者胜 |
| 奖励 | 胜方资金 + 帮会经验 + 成员个人奖励（走邮件，与 27 篇 BOSS 参与度同一套出口） |
| 本期 | **排在副本（20 篇第④刀）之后**，本篇只定口径不实现 |

### 2.6 好友与拉黑的补强

| 项 | 规则 |
|---|---|
| 好友上限 | 100（`friend_max`） |
| 在线状态 | 好友列表显示在线/所在图（**只显示图名，不显示坐标**） |
| 拉黑 | 拉黑后对方不能私聊、不能邀请入队、不能交易（26 篇已引用） |
| 举报 | 保留现有；加「举报后 24 小时内不再匹配到同队」（仅影响组队匹配，不做自动处罚） |

## 三、数据模型

```sql
-- 队伍加状态（现有表结构太薄）
ALTER TABLE parties ADD COLUMN status TEXT NOT NULL DEFAULT 'active';  -- active / disbanded
ALTER TABLE parties ADD COLUMN loot_mode TEXT NOT NULL DEFAULT 'free'; -- free / leader
ALTER TABLE party_members ADD COLUMN role TEXT NOT NULL DEFAULT 'member'; -- leader / member
ALTER TABLE party_members ADD COLUMN state TEXT NOT NULL DEFAULT 'joined'; -- invited / joined

-- 帮会等级规则
CREATE TABLE guild_level_rules (
  level        INTEGER PRIMARY KEY,
  need_exp     INTEGER NOT NULL,
  max_members  INTEGER NOT NULL,
  max_funds    INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL DEFAULT 0
);

-- 帮会技能
CREATE TABLE guild_skills (
  guild_id   TEXT NOT NULL,
  skill_id   TEXT NOT NULL,
  level      INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (guild_id, skill_id)
);

-- 帮会技能定义（配置表）
CREATE TABLE guild_skill_defs (
  id         TEXT PRIMARY KEY,
  label      TEXT NOT NULL,
  max_level  INTEGER NOT NULL DEFAULT 10,
  cost_funds INTEGER NOT NULL DEFAULT 0,
  effect     TEXT NOT NULL DEFAULT '{}',   -- JSON: {attackPercent:1, expPercent:1}
  updated_at INTEGER NOT NULL DEFAULT 0
);
```

`guilds` 加两列：`exp`（当前等级经验）、`notice_top_until`（公告置顶到期时间）。

## 六、边界情况

| # | 情形 | 期望 |
|---|---|---|
| 1 | 邀请时对方已满队 | 拒（`party_full`） |
| 2 | 邀请时对方在别的队 | 拒（`already_in_party`） |
| 3 | 同一人 30 秒内收到两次邀请 | 第二次覆盖第一次（只保留最新一条） |
| 4 | 队长下线 | 5 分钟后自动转让；期间队伍照常活动 |
| 5 | 队长退役（删号） | 立即转让；无成员则解散 |
| 6 | 队伍只剩 1 人 | 队长可解散；成员退队后队伍自动解散 |
| 7 | 被踢者重新申请 | 60 秒内拒（`kicked_cooldown`） |
| 8 | 队长分配把掉落转给不在队的角色 | 拒（`not_in_party`） |
| 9 | 保护期过后队长还想改归属 | 拒（`protect_expired`） |
| 10 | 队长分配模式下队长离线 | 掉落按原归属走（保护期照常），**不改归属**（避免队长不在时无人可分配） |
| 11 | 队伍频道发言时队伍已解散 | 拒（`not_in_party`） |
| 12 | 队伍跨图，A 在图 1、B 在图 2 | 队伍频道正常；经验分成**只对同图**生效（沿用 #399） |
| 13 | 帮会经验达阈值但人数已达上限 | 照样升级（人数上限随等级涨） |
| 14 | 帮会资金超上限 | 超出部分不入账，捐献时提示「已达上限」 |
| 15 | 两位副会长同时动用资金 | 乐观锁 + 资金不能为负；第二笔 20006 |
| 16 | 帮会技能等级超过 `max_level` | 拒（`skill_max`） |
| 17 | 帮会解散 | 资金退还？**不退**（记 `economy_log(kind='guild_disband')` 销毁）；成员变无帮会 |
| 18 | 帮会被合并（区服合并，#295 阶段三） | 保留人数多的一方，另一方成员转为申请者 |
| 19 | 拉黑后已有的队伍关系 | 不自动踢人；但升级为「不能新邀请」 |
| 20 | 帮会战报名时人数不足 | 拒（`not_enough_members`，至少 3 人） |
| 21 | 帮会战进行中有人退会 | 允许，但该成员不计奖励 |
| 22 | 同一账号两个角色在同一队 | 拒（防多开刷分成） |

## 八、验收

| 用例 | 断言 |
|---|---|
| `e2e-party-invite` | 邀请 → 接受 → 成员 2 人；拒绝 → 无变化；超时 → 邀请失效 |
| `e2e-party-leader` | 队长下线 5 分钟 → 自动转让给最早加入的在线成员 |
| `e2e-party-kick` | 被踢后 60 秒内再申请 → 拒 |
| `e2e-loot-leader` | 队长把 A 的掉落转给 B → B 可捡、A 不可捡；保护期过后再转 → 拒 |
| `e2e-party-chat` | 队伍频道消息只有本队收到（含跨图成员） |
| `e2e-guild-level` | 成员在线累积经验 → 达阈值升级 → 人数上限 +5 |
| `e2e-guild-funds` | 捐献 → `funds` 增加且 `economy_log` 有一条；超上限部分不入账 |
| `e2e-guild-skill` | 升级技能 → 全帮属性加成生效（加算，不进转生乘算） |

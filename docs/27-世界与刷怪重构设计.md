# 27 · 世界与刷怪重构设计

> **状态**：设计稿，未实现。[21 总表](./21-系统差距总表.md) 判定「重构 · P0」。

## 零、现状（实测）

| 项 | 实测 |
|---|---|
| 刷怪区 | `map_spawn_areas` **64 行**，11 张图（map3 最多 18 区） |
| 各区 Σmax | 228 / 12 / 20 / 145 / 191 / 33 / 35 / 35 / 33 / 33 / 25 |

（`map_spawn_areas` id 187/188）从未生效过。这条数据说明「改了配置看不见效果」是真的，
不是玩家错觉。

## 一、五个结构性问题

### 1.1 播种只发生一次，配置改了不回溯

`loadMap` 的逻辑是「库里已有实例 → 沿用它」。于是任何刷怪区改动都只对
「下次世界被清空」生效，而世界只在进程重启时被清空 —— 也就是「改完等运维重启」。

### 1.2 密度固定：一张图从早到晚一个样

`max` 是「同时存活上限」，刷满就不刷。这带来两个后果：

- **人多时不够打**：5 个人抢 28 只怪，刷新速度不随人数变；
- **深夜空转**：0 人在线还在按定时器刷（20 篇已定「无人冻结」，但「有人但很少」时没有梯度）。

### 1.3 BOSS 与普通怪没有区别

`monsters.tier` 只有 `normal` / `boss` 两值，`boss` 只是属性高。没有：
固定的刷新时间窗、全服公告、击杀记录、参与度奖励。

### 1.4 没有图内事件

「这张图现在正在发生什么」只有怪物。没有攻城、没有守卫、没有区域占领 ——
玩家在同一张图待久了只会重复刷同一批怪。

### 1.5 AI 的「记恨」不是仇恨表

现在 `targetId` 单个目标 + 记恨超时。多人打同一只怪时，怪只会打「最后打它的人」，
没有威胁值累计，所以坦克职业不存在（也没有这个职业定位）。

## 二、目标形态

### 2.1 单图热重载（20 篇第①刀的实现细节补全）

```
管理端改刷怪区 → 写 world_reload_requests(zone, map, mode)
                        │
       实时进程每 1 秒读 pending
                        │
      ┌─────────────────┴──────────────────┐
      │ 该 room 无人                       │ 有人
      ▼                                    ▼
  立刻执行                             mode=respawn？
  （删实例 → 清内存 → 重新播种）         │
                                  是 ──┴──> 排队等空窗
                                            │
                                  超 forceAfterMs（5 分钟）
                                            ▼
                                     强制执行 + 广播 world.reload
```

| 项 | 规则 |
|---|---|
| `mode='respawn'` | **对齐到目标数**（不是删了重播，已定 E2）：按新配置算每区 `target`，多出来的删「未被攻击过」的、少了的立即补；正在被打的怪保留 |
| `mode='reload'` | 全部清掉重播（连 AI 状态一起），用于改怪物属性 |
| 排队期间再次请求 | 合并成一条（同图同 mode 只保留最新一条） |
| 强制执行 | 广播 `world.reload`，客户端重拉 `world` 帧；**被清掉的怪不发击杀、不给奖励** |
| 幂等 | 同一 `request id` 重复执行只生效一次（`done_at` 非空则跳过） |

### 2.2 投放密度与重生节奏

#### 2.2.1 投放密度曲线

在 `map_spawn_areas` 上加三个可空列，空 = 用 `max`：

| 列 | 含义 |
|---|---|
| `density_peak` | 高峰系数（默认 1.0） |
| `density_off` | 低谷系数（默认 1.0） |
| `peak_hours` | 高峰时段（如 `"19:00-23:00"`，空 = 无峰谷） |

生效公式：

```
target = clamp(round(max × factor(now) × crowdFactor), min, max × density_peak)
factor(now) = 在 peak_hours 内 ? density_peak : density_off
crowdFactor = 1 + min(0.5, (在线人数 - 1) × 0.1)      // 每多一人 +10%，最多 +50%
```

**为什么用系数而不是「每人配几只」**：系数可空、默认 1.0，**不改现有行为**；
配上之后才生效，运营可以逐图灰度。

**补种由 tick 驱动（已定 E2）** —— 这是 #669 的真正解法：

```
每秒 tick：
  for each 刷怪区：
    target  = clamp(round(max × factor(now) × crowdFactor), 0, max × density_peak)
    alive   = 该区 area_id 下「存活」的实例数
    if alive < target:  补 min(target - alive, 2) 只（每次最多补 2，见下）
    if alive > target:  删最久未被攻击的 (alive - target) 只
```

| 规则 | 说明 |
|---|---|
| 触发 | **每秒一次**（与世界 tick 同频），不是「图空了才播」 |
| 限速 | 每次最多补 **2 只** —— 否则改完配置一进图满屏怪，像刷屏 |
| 上限 | 补齐后总数不超过 `max × density_peak`（`max` 仍是硬上限） |
| 多余怎么办 | `alive > target`（如晚高峰过去、`crowdFactor` 回落）→ 删最久未被攻击的；**正在被打的不删** |
| 与热重载的关系 | `mode='respawn'` 就是「立刻跑一次对齐」，不再有「删了重新播种」这条路径 |
| 与重生的关系 | 补种受「重生」节制：一只怪死了要等 `respawnAt` 才回来（走 2.2.2），补种只负责「从没被填满过」的部分 |

> **为什么限速 2 只/秒**：一次补齐 228 只（map0 的 Σmax）会让后进图的玩家看到「怪批量凭空出现」。
> 2 只/秒 × 60 秒 = 120 只/分钟，够快又看不出机械感。

#### 2.2.2 重生：位置 / 时长 / 节奏（本轮已定）

现状一句话：**每只怪从自己死亡时刻起 +30 秒、在自己出生点满血站起来**。
三处都要改，而且三处互相牵连。

**位置 —— 每次复活在所属刷怪区内重新取点**

| 项 | 规则 |
|---|---|
| 落点来源 | `pickPointInArea(area.cx, area.cy, area.w, area.h)`，与播种**同一个函数**（矩形内均匀取值） |
| 归属来源 | 实例的 `area_id`（**新增列**）。播种时由刷怪区传入，之后不变 |
| 落点校验 | 依次剔除：① 落在该图任一碰撞盒内 → 重取；② 距任一在线玩家 < `respawnSafeRadius`（默认 **128px**）→ 重取；③ 距同区其它存活怪 < 32px → 重取 |
| 重试上限 | 最多 **8 次**。仍不合法 → **原地复活**（出生点）+ 记 `map_monitor_events(kind='respawn_blocked')`，不报错也不无限重试 |
| 老档兼容 | `area_id` 为空（206 行存量实例）→ 按 `(x, y)` 反查包含它的刷怪区，命中则回填；命中不了（区域已被删）→ 原地复活，`area_id` 保持空 |
| instanceId | **不变**。换位置不换实例，否则「打到一半的怪」会变成另一只，伤害归属与掉落来源全断 |

> **为什么必须加 `area_id`**：同一 `monster_key` 可能出现在多个刷怪区（map3 有 18 个区，
> 怪物就那几只复用）。只按 `monster_key` 反查会刷到隔壁区去 —— 那是运营不可能接受的
> 「我画了两个区，怪全挤在其中一个」。

**时长 —— 刷怪区 > 地图 > 全局，三级继承**

```
respawnMs(area) = area.respawn_ms
               ?? map_rules.respawn_ms_override
               ?? WORLD_RESPAWN_MS (30000)
```

| 级 | 落点 | 列 | 谁改 |
|---|---|---|---|
| 区 | `map_spawn_areas.respawn_ms` | **新增，可空** | 运营逐区配（`SpawnAreaForm` 加一个输入框） |
| 图 | `map_rules.respawn_ms_override` | 20 篇已规划 | 运营逐图配（「规则」页签） |
| 全局 | `worldRespawnMs` 配置 | 已有 | 运维改 env |

**为什么是继承而不是「必须填」**：空值就是继承，新建区域不用先表态；
99% 的区域会一直空着，只有 BOSS 区（快刷）和活动区（慢刷）才需要单独填。

**节奏 —— 逐只独立计时 + ±20% 抖动**

```
respawnAt = killedAt + round(respawnMs(area) × (0.8 + rand() × 0.4))   // 0.8 ~ 1.2
```

| 项 | 规则 |
|---|---|
| 计时基准 | **每只自己的 `killedAt`**，不是区域统一时点 |
| 抖动 | 在**死亡瞬间**算好并写进 `respawn_at`（绝对值），所以客户端拿到的 `respawnInMs` 倒计时天然带抖动，不需要额外字段 |
| 为什么抖动 | 一波 AOE 同时打死的 6 只怪不加抖动会**同一秒集体冒出来**，看起来像假的；±20% 把 30 秒摊成 24~36 秒 |
| 与密度曲线的关系 | 密度曲线管「目标存活数」，重生时长管「补得多快」。两者相乘决定实际压力：白天人多 → `crowdFactor` 抬目标数 → 同时靠短重生补齐 |
| 与无人冻结的关系 | 冻结期间不算「错过」，恢复时 `processRespawns(map, now)` 只补一次（20 篇已定） |

**为什么不整区整批刷**：整批刷（区内死怪到点一起复活）确实更好理解、也更好配，
但清完一个区就要**干等一整轮**才有下一只，清图正反馈会断。逐只独立 + 抖动是主流做法，
玩家感受是「一直有怪从旁边冒出来」，而不是「刷完一波等下一波」。

**位置跳变不需要插值**：复活是「怪重新出现」，不是「怪从尸体处走过去」。
死亡期间客户端画的是尸体/消失态，复活时按新坐标直接出现即可 —— [28 篇](./28-实时同步与分片设计.md)
的插值只对**存活怪物在视野内的移动**生效，不覆盖这一次重生。

### 2.3 BOSS 定时窗（已定：定时窗刷新）

```sql
CREATE TABLE world_boss (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  zone_id      TEXT    NOT NULL,
  map_id       TEXT    NOT NULL,
  monster_key  TEXT    NOT NULL,
  cx           REAL    NOT NULL,
  cy           REAL    NOT NULL,
  windows      TEXT    NOT NULL,          -- JSON: ["20:00", "22:00"]
  spawn_lead_ms INTEGER NOT NULL DEFAULT 60000,  -- 提前 1 分钟公告
  alive_ms     INTEGER NOT NULL DEFAULT 1800000, -- 存活 30 分钟未杀则消失
  last_spawn_at INTEGER NOT NULL DEFAULT 0,
  last_kill_at  INTEGER NOT NULL DEFAULT 0
);
```

| 环节 | 行为 |
|---|---|
| 预告 | 到 `窗口 - spawnLead` → 全服公告「XX 将于 1 分钟后出现在 Y 图」 |
| 出现 | 到窗口 → 在 `(cx, cy)` 生成实例（`tier='boss'`），全服公告 |
| 战斗 | 沿用现有 AI 与伤害结算 |
| 击杀 | 记 `last_kill_at`；全服公告「XX 已被 YY 击杀」；**参与度奖励**见下 |
| 超时 | 存活超过 `alive_ms` → 消失（不留尸体），公告「XX 已离开」 |
| 掉线 / 重启 | 定时器从 `last_spawn_at` 恢复；错过的窗口**不补刷**（避免重启后连刷三只） |

**参与度奖励**：击杀瞬间，对「最近 60 秒内对它造成过伤害」的所有角色各发一份**按伤害占比**的奖励。
这是网络游戏的常规做法，也能防「补刀抢奖励」。

- 伤害占比 < 5% 不给（防蹭）；
- 奖励走邮件（离线也能收），**与掉落物分开**（掉落仍是世界实体，谁捡到谁的）。

### 2.4 图内事件（结构留位，本期只做一种）

```sql
CREATE TABLE map_events (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  zone_id     TEXT NOT NULL,
  map_id      TEXT NOT NULL,
  kind        TEXT NOT NULL,        -- invasion（入侵） / guard（守卫） / occupy（占领）
  starts_at   INTEGER NOT NULL,
  ends_at     INTEGER NOT NULL,
  payload     TEXT NOT NULL DEFAULT '{}',
  state       TEXT NOT NULL DEFAULT 'pending'  -- pending / running / done / cancelled
);
```

本期只做 **`invasion`（怪物入侵）**：事件开始 → 在指定区域刷一批怪（走刷怪区的同一套生成器）→
玩家在 `ends_at` 前清完则给全图奖励，否则事件失败（怪保留一段时间后消失）。

> 为什么只做一种：事件框架的真正成本在「状态机 + 奖励 + 管理端配置」，做一种跑通比做三种半成品有用。

### 2.5 AI 仇恨（威胁值）

把 `targetId` 从「单个目标」升级成「威胁表」：

```ts
threats: Map<roleId, number>   // 内存，随实例存亡
```

| 事件 | 威胁变化 |
|---|---|
| 造成伤害 | `+damage` |
| 治疗（对攻击者） | `+heal × 0.5` |
| 进入视野未出手 | `+1/秒`（拉怪） |
| 目标死亡 / 离图 | 移除该条 |
| 目标消失后 | 按最高威胁重选 |

**本期只改「选目标」这一处，不改伤害**：威胁值决定打谁，不提供任何加成 ——
这样即使仇恨算错，也不会影响战斗数值。

#### 2.5.1 脱战与回家（已定 E3）

现在注释写「离开检测范围就丢目标」，代码只在目标死亡/超时/换图时丢 ——
所以怪能跨整张图无限追人（B34）。改成：

| 状态 | 进入条件 | 行为 |
|---|---|---|
| 战斗 | 威胁表非空 | 追 + 打（现有逻辑） |
| **脱战** | 最高威胁目标距离 > `leashRange`（默认 **600px**） | 清空威胁表，记录 `returningSince` |
| 回家 | 脱战且离出生点 > 16px | 直线走回出生点，**途中不索敌、不接受新威胁** |
| 待机 | 回到出生点 | 恢复正常（主动怪索敌 / 被动怪等挨打） |

| 参数 | 默认 | 说明 |
|---|---|---|
| `leashRange` | 600px | 大于普攻距离（60）很多，小于图宽；太大等于不脱战 |
| `returnSpeedRate` | 1.5 | 回家走得比追击快，避免玩家「拖着怪遛」 |
| 回家超时 | 20 秒 | 到点还没走回去（被地形挡住）→ 直接吸附到出生点，避免永久卡住 |

> **为什么不用「超时脱战」**：超时脱战会让玩家绕着怪转圈就把仇恨耗掉，感觉像 bug。
> 距离是玩家能看见的量（跑远就脱战），符合直觉。

#### 2.5.2 移动与碰撞（已定 E4）

现在 `stepMonster` 直接改坐标，无碰撞无边界（B35）：怪能穿墙、能被击退出图。

| 项 | 规则 |
|---|---|
| 每帧位移 | 方向向量 × `moveSpeed` × Δt，与现在一致 |
| 碰撞检测 | 用 [20 篇](./20-地图模块重构设计.md) 的碰撞盒：**目标点在被挡格内** → 沿墙滑行（保留与墙平行的分量，丢掉垂直分量） |
| 卡住判定 | 连续 **3 帧**实际位移 < 1px → 换一个切线方向（±60°）重试 2 次；仍不行 → 停在该点待机 |
| 地图边界 | 坐标钳在 `[0, mapWidth] × [-mapHeight, 0]`；被击退出图不可能发生 |
| 不用 A* | 145 只怪每 100ms 各跑一次 A* 会打满单核（20 篇已算）；直线 + 滑行足够绕开单块墙 |
| 击退 | 也走同一套碰撞：击退方向被挡则**原地不动**，不穿墙 |

> 滑行而不是「撞了就停」：撞了就停会让怪卡在墙角抽搐；滑行看起来像「贴着墙追」，
> 是最省 CPU 又最不难看的做法。

### 2.6 无人冻结与恢复（20 篇已定的落地细节）

| 场景 | 行为 |
|---|---|
| room 在线 0 人 | 停 tick（不刷怪、不推进 AI、不跑状态周期） |
| 有人进入 | 按 `emptySince` 补算「错过了多少刷新周期」，但**最多补 1 轮**（不是补满，否则一进图满屏怪） |
| `simulateWhenEmpty=1` 的图 | 照常跑（如活动图需要世界持续推进） |
| 长时间无人 | `WORLD_MAP_IDLE_MS` 后卸载实例（现状保留） |

### 2.7 动态难度（本轮纳入）

按「这张图里当前玩家的平均等级」缩放怪物，让同一张图对不同等级段都有意义。

| 项 | 规则 |
|---|---|
| 缩放对象 | **只缩放生命与防御**，**不缩放攻击** |
| 系数 | `scale = clamp(avgLevel / areaLevel, 0.7, 1.5)`；`areaLevel` = 该刷怪区 `monster_key` 对应的 `monsters.level` |
| 生效范围 | 只有「常规刷怪区」的怪；**BOSS 与事件怪不缩放**（它们的强度是设计好的） |
| 重算时机 | 每 30 秒按房间内在线玩家重算一次，**只影响新刷出的实例**（已存在的怪不改血，避免「打到一半血变多」） |
| 极端值 | 系数上限 1.5：防止「一堆大号进新手村把怪变成 BOSS」；下限 0.7：防止「1 级号进高级图把怪变纸」 |

> **为什么不缩放攻击**：23 篇已经加了严格等级压制（越 20 级伤害归 0）。如果攻击也缩放，
> 低等级玩家进高级图会被「压低伤害 + 提高受伤」双重惩罚，等于禁止越级。
> 只缩放生命与防御，效果是「打不动但打得死」，符合「越级有代价但不绝望」。

### 2.8 怪物群体 AI（本轮纳入）

| 项 | 规则 |
|---|---|
| 触发 | 一只怪被攻击时，以它为中心、AOI 半径内（默认 512px）的**同 `monster_key`** 怪有 `groupAggroChance`（默认 0.3）的概率加入 |
| 上限 | 一次最多拉 `groupAggroMax`（默认 3）只 |
| 不跨类型 | 不同 `monster_key` 不互相拉（避免「打兔子引来狼王」） |
| 与仇恨表 | 加入的怪把攻击者加入自己的威胁表（威胁值 = 首次 1），之后照常按威胁选目标 |
| 与 AOI | 用 [20 篇](./20-地图模块重构设计.md) 的 9 邻格查询，**不遍历全图** |
| 冷却 | 同一只怪 10 秒内只响应一次「同伴呼叫」 |

### 2.9 攻城与领地（本轮纳入，排在帮会战之后）

| 项 | 规则 |
|---|---|
| 领地 | 新表 `map_territories`：地图上的可占领点（`cx/cy/radius`），归属帮会 + 占领时间 |
| 攻城 | 复用 `map_events` 的 `occupy` 类型：每周固定窗口开放 60 分钟，帮会需在窗口内**持续占领中心点**（圈内人数多者得分） |
| 判定 | 结束时得分最高的帮会占领；无人则保持原状 |
| 收益 | 领地给「该图掉落加成 / 传送免费 / 税收分成」三选一（`territory_benefit` 配置） |
| 前置 | **必须先有帮会战（#403）** —— 攻城是「有组织的大规模对抗」，没有帮会战就没有组织度 |
| 本期状态 | **只建表 + 管理端配置 + 判定逻辑**，不开放；等 #403 落地 |

## 四、协议

| 帧 | 方向 | 说明 |
|---|---|---|
| `world.reload` | S→C | 单图重载完成，客户端重拉 `world` 帧 |
| `bossNotice` | S→C | 全服公告（预告 / 出现 / 被击杀 / 离开），正文服务端拼好 |
| `mapEvent` | S→C | 图内事件状态变化（开始 / 结束 / 失败） |
| `world` | S→C | 加 `event?: {kind, endsAt}`（当前图正在发生的事件） |

`bossNotice` 与 18 篇的 `dropNotice` 可以共用一个「全服公告出口」（`broadcastAll`），
只是 `type` 不同 —— 实现时抽一个 `AnnounceService`，别写两套。

## 六、边界情况

| # | 情形 | 期望 |
|---|---|---|
| 1 | 改刷怪区时图里有 3 个玩家正在打怪 | `mode=respawn` 排队，5 分钟后强制；正在被打的怪保留 |
| 2 | 排队期间又改了一次刷怪区 | 合并成一条，用最新配置 |
| 3 | 强制重载时怪已被打成 1 血 | 直接清掉，**不给击杀奖励**（否则可以刷） |
| 4 | 重载时玩家正在拾取掉落物 | 掉落物不受刷怪重载影响（18 篇：掉落是世界实体，与怪解耦） |
| 5 | 重载后 `Σmax` 仍然大于实例数 | 正常（`max` 是上限，实际按密度与刷新节奏逐步补） |
| 6 | `peak_hours` 格式错误 | 管理端 40000 拒；服务端读到非法值按「无峰谷」处理并 warn |
| 7 | `density_off = 0` | 允许（低谷不刷），但 `min` 不为 0 时按 `min` 保底 |
| 8 | 在线 100 人时 `crowdFactor` 封顶 | +50% 封顶，不允许无限膨胀 |
| 9 | BOSS 窗口重叠（两个 BOSS 同一分钟） | 都刷，公告按 `id` 顺序逐条发（不合并） |
| 10 | BOSS 出现时该图无人 | **仍然刷**（到点就得出现），但 AI 冻结 |
| 11 | BOSS 存活超时消失时正在被打 | 照样消失（不因残血延期），公告「已离开」—— 这是运营节奏，不是惩罚 |
| 12 | BOSS 被击杀瞬间服务重启 | 计时器恢复后按 `last_kill_at` 算，不重复刷 |
| 13 | 错过多个窗口（停服 3 小时） | **不补刷**，只刷「当前或下一个」窗口 |
| 14 | 参与度奖励算出 0（伤害占比 <5%） | 不发（不发票子式的 1 金安慰奖） |
| 15 | 参与度奖励时角色已下线 | 走邮件 |
| 16 | 同一角色多开打 BOSS | 每个角色各算各的（不做账号维度合并） |
| 17 | 事件进行中重载刷怪区 | 事件怪不受影响（事件有自己的生成器），只重载常规刷怪区 |
| 18 | 事件结束但怪没清完 | 怪保留 `grace_ms`（默认 5 分钟）后消失，不奖励 |
| 19 | 事件奖励重复领取 | 用 `map_events.state` 的 `done` 做幂等，一个角色只领一次（`role_event_reward` 记一行） |
| 20 | 无人冻结期间 BOSS 到点 | **到点要刷**（冻结只停 AI 与常规刷怪，不停定时任务） |
| 21 | 进图补算「最多 1 轮」导致图里怪很少 | 正常，下一次刷新周期补齐；不补满是刻意的（避免一进图被围） |
| 22 | 威胁表在目标离图后仍残留 | 目标消失时移除该条；重选目标时跳过不可见目标 |
| 23 | 治疗拉仇恨导致奶妈被打 | 这是设计意图（有坦克职业后才需要权重表） |
| 24 | `world_boss` 配了不存在的 `monster_key` | 到点生成失败 → 记 `map_monitor_events(kind='boss_error')` + warn，不重试 |
| 25 | 同一 `monster_key` 在两个窗口配了两次 | 允许（两个独立 BOSS 实例），但公告文案要带地图名以区分 |
| 26 | 复活时刷怪区内站满玩家，8 次都取不到安全点 | **原地复活** + 记 `map_monitor_events(kind='respawn_blocked')`；不卡住、不无限重试、不把怪刷到人身上 |
| 27 | 整个区画在墙上（碰撞盒全覆盖） | 同上（原地 + 记事件）。这是运营配错了框，管理端应在保存时对「区内可站立面积 = 0」直接拒 |
| 28 | 刷怪区被删，场上怪还活着 | 实例继续存在（文档 20 篇：删区不杀场上的怪）。死一次后 `area_id` 悬空 → 原地复活，不再重随机 |
| 29 | 同区 200 只怪在 1 秒内被 AOE 全清 | 一次 tick 批量处理全部到期实例，**不给每只挂定时器**（否则 200 个 timer） |
| 30 | `respawn_ms` 填 0 或负数 | 管理端拒（下限 1000ms）；库里读到非法值按「继承上一级」并 warn |
| 31 | 玩家在 tick 之后才走到复活点 | 允许（怪正常出现）。安全半径只保证「复活那一刻不重叠」，不追责此后移动 |
| 32 | 复活时该图无人 | 照常复活（`simulateWhenEmpty=true` 时）或延后到有人（`false` 时补一次），两种都只走 `processRespawns` 一条路 |

## 八、验收

| 用例 | 断言 |
|---|---|
| `e2e-reload-empty` | 空图改刷怪区 → 1 秒内实例按新配置重播 |
| `e2e-reload-busy` | 有玩家时改 → 排队；把 `forceAfterMs` 压到 100ms → 强制执行且广播 `world.reload` |
| `e2e-reload-idempotent` | 同一请求执行两次 → 只重播一次 |
| `e2e-density-peak` | 把 `peak_hours` 设成当前时段、`peak=2.0` → 目标数翻倍 |
| `e2e-density-crowd` | 5 人在线 → 目标数 × 1.4（+10%/人，封顶 50%） |
| `e2e-boss-window` | 窗口前 1 分钟有预告公告；到点出现在坐标；30 分钟未杀 → 消失并公告 |
| `e2e-boss-reward` | 两人分别造成 80% / 20% 伤害 → 奖励按比例；第三人 3% → 不发 |
| `e2e-boss-norestore` | 模拟停服跨过两个窗口 → 重启后只刷下一窗口，不补刷 |
| `e2e-event-invasion` | 事件开始刷怪、清完后发奖、`state=done`；同角色再领 → 拒 |
| `e2e-threat` | A 打 100 伤害、B 打 200 → 怪打 B；B 离图 → 改打 A |
| `e2e-respawn-reroll` | 同区两只怪连死两次 → 四次复活坐标互不相同，且都落在该区矩形内（`area_id` 回填正确） |
| `e2e-respawn-jitter` | `respawn_ms=10000`，连死 50 次 → `respawn_at - killed_at` 全部落在 8000~12000，且不是同一值 |
| `e2e-respawn-inherit` | 区 `respawn_ms` 空、图 `override=5000` → 5000；再清空图覆盖 → 30000 |
| `e2e-respawn-blocked` | 区内站满 4 个玩家盖住整区 → 复活在原出生点，`map_monitor_events` 出现 `respawn_blocked` |
| `e2e-respawn-legacy` | 造一行 `area_id` 为空的存量实例 → 加载时按坐标反查回填；坐标不在任何区内 → 保持空、原地复活 |

手工验收：BOSS 公告出现在屏幕上方且不挡住操作；事件进行中地图上有明确标识；
强制重载时有提示（不要静默把怪清掉）。

## 十、已定参数

| 项 | 结论 |
|---|---|
| 热重载 | 等空窗，超 **5 分钟**强制（20 篇已定） |

| 图内事件 | 只做 `invasion` 一种，结构留 `map_events` |
| 仇恨 | 威胁表只影响选目标，不加成 |
| 无人冻结 | 停 AI 与常规刷怪，**不停 BOSS 定时任务** |
| 动态难度 | **做**：只缩放生命/防御（0.7~1.5），不缩放攻击，30 秒重算、只影响新实例 |

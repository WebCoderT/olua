# 09 · 成长与养成

> 等级、阶位、时装三套东西都在改同一批属性，但**只有一条升级链**。
> 这一篇讲清等级曲线怎么参数化、三货币从哪来到哪去、三条成长线与时装各自的规则。

## 一、三套养成，一份属性

| 维度 | 存档字段 | 谁推进 | 影响属性 |
|---|---|---|---|
| **等级** | `level` / `exp` | 击杀经验 / 泡点 / 升级卷轴 | 全部 12 项（曲线） |
| **阶位** | `title` / `soulOfWar` / `rank` | `POST /roles/:id/growth-upgrade` | 12 项（整份加成） |
| **时装** | `fashionCloth` / `fashionsOwned` | `fashion-buy` / `fashion-wear` | **不改数值**，只换外观 |

三者最终都汇到 `summarizeRoleAttributes` 一处相加（见 [05](./05-装备链路.md) 第八节）——
所以「战力为什么是这个数」只有一个地方要查。

## 二、等级曲线：4 条 × 6 段

```sql
-- role_level_curves（24 行）
curve | seq | from_level | to_level | start_value | per_level | accel
```

段内公式：

```
value(level) = start_value + per_level × k + accel × k × (k−1) / 2      （k = level − from_level）
```

前 5 段 `accel = 0`（段内线性）；**只有 `exp` 是二阶的**（升级经验越涨越快）。
段与段之间允许跳变（每 10 级跳一次，原数据就是这样）。

### 为什么只有 4 条

原来 16 列里一半是派生的，且 1..60 级实测**精确成立**（不是近似）：

| 派生列 | 比例 |
|---|---|
| `max_mp` | `round(hp × 0.5)` |
| `hp_recover` | `round(hp × 0.01)` |
| `attack_min` | `round(attack_max × 0.7)`，三系攻同值 |
| `defense_min` | `round(defense_max × 0.7)`，三系防同值 |

比例在 `ROLE_LEVEL_RATIOS` 里写死，**不开放管理端** —— 多开一个口子就多一种「三系攻防被调歪了没人发现」的可能。

### 出厂四条的末段（#786：上限扩到 100 万级）

| 曲线 | 末段（51 级起） | 说明 |
|---|---|---|
| `exp` | 起始 67600，每级 +3950，accel 100 | 到 100 万级约 `5.0e13` |
| `hp` | 起始 37700，每级 +6780 | 到 100 万级约 67.8 亿 |
| `attack_max` | 起始 4800，每级 +860 | 三系攻同值 |
| `defense_max` | 起始 1440，每级 +258 | 三系防同值 |

### 三条边界

1. **超出最后一段就外推**：`level > to_level` 时继续用末段公式。
   所以「调大 `roleMaxLevel`」不需要同时改 4 条曲线的末段。
2. **段被配断了**（运营把某段删了）：取 `from_level` 最接近且不超过该级的那一段，行为等价于「前一段继续延伸」。
3. **任一曲线缺了这一级 → 不出整行**（`buildRoleLevelRow` 返回 null）。
   半截属性（有血没攻）比「没有这一级」更难排查，所以宁可不给。

运行时求值带 memo（4096 条上限），升级循环里每一级问一次也不会打库。

> 📌 **注释已过期的地方**：`roles.service.ts` 的 `applyKillExp` 注释里还写着
> 「按 `role_levels.exp`（60 行逐级配好）判定」—— `role_levels` 表已随 #786 删除，
> 现在读的是 `role_level_curves`。读到旧注释别去找那张表。

## 三、升级链：唯一一条

```ts
// RolesService.applyKillExp —— 击杀 / 泡点 / 卷轴之外的所有经验都走这里
let expNow = 存档exp + gain;
let expNeed = expNeedOf(level);
while (level < maxLevel && expNeed > 0 && expNow >= expNeed) {
  expNow -= expNeed; level += 1; leveledUp = true; expNeed = expNeedOf(level);
}
data.exp = expNow;
applyAuthoritativeAttributes(level, data);       // 等级变了属性就变
if (leveledUp && options.refillOnLevelUp) { data.hp = maxHp; data.mp = maxMp; }
revision + 1
```

五个口径：

| 口径 | 说明 |
|---|---|
| **循环升级** | 一次给的经验足够连升多级（大额经验 / 卷轴 / 后台改） |
| **封顶** | `level < maxLevel`（`growth_scalars.roleMaxLevel`，出厂 100 万） |
| **补满血蓝按路径** | 击杀者侧补（`refillOnLevelUp: true`）；**队友分经验不补**（队友打怪不是我在挨打） |
| **升级入口只有一个** | 泡点、击杀、队友分账全都调这个函数 —— 泡点涨的级和打怪涨的级必须是同一种级 |
| **失败返回 null** | 被踢下线 / 归属不符 → 调用方跳过奖励，不视为错误 |

满级后泡点会**短路**：经验没有去处，每拍白写一次库还推进 revision，会让客户端多收无意义的 `roleUpdate` 帧。

## 四、三种货币

| 币种 | 字段 | 主要来源 | 主要消耗 |
|---|---|---|---|
| 元宝 | `gold` | 充值 / 运营发放 / 后台改 | 目前没有出厂消耗口（预留给直购） |
| **绑定元宝** | `bindGold` | **回收装备**、货币道具、任务/成就/邮件、后台 | **商城购买**、三条成长线升级、时装购买 |
| 银子 | `silver` | 运营发放 | 目前没有出厂消耗口 |

三条纪律：

- **账本一律服务端写**（`SERVER_LEDGER_FIELDS`），客户端只从 `roleUpdate` 帧照搬。
- **读法统一「负数按 0 起算」**：`Math.max(0, Math.floor(Number(data[currency]) || 0))`。
  存档里出现负数（手改库）不会变成「花一次反而多钱」。
- **回收进 `bindGold` 不进 `gold`** —— 这是刻意的：回收是「游戏内产出」，不该变成可提现的元宝。

## 五、三条成长线

| 线 | 表 | 行数 | 存档字段 | 下一阶怎么算 |
|---|---|---|---|---|
| 称号 | `titles` | 34 | `title` | `upgrade_order` 成长链的下一个 |
| 战魂 | `souls` | 37 | `soulOfWar` | 同上 |
| 军衔 | `ranks` | 100 | `rank` | **`level + 1`**（天然按阶） |

### 每条线的配置列

| 列 | 用途 |
|---|---|
| `level` / `label` / `description` | 阶号与文案 |
| `bind_gold` | **升级成本**（绑定元宝） |
| `acquire_channel` | `upgrade`（玩家可升）/ `grant`（运营发放）/ `unavailable`（未开放） |
| `upgrade_order` | 成长链顺序 —— **阶号与顺序解耦**，管理端拖动列表改的就是它 |
| `animation` / `animation_frame_rate` | 称号与战魂的外显动画（军衔是头顶那行红字，没有动画） |
| 12 个属性列 | 当前阶提供的整份加成（未激活 `< 1` 则不加成） |

### 升级请求的处理

```ts
const target = this.resolveGrowthTarget(kind, current);   // 算下一阶（防跳级、防并发错位）
if (!target || target.level !== dto.targetLevel) → 20019 目标不合法
if (bindGold < target.bind_gold)                → 20011 绑定元宝不足
data[field] = target.level; data.bindGold -= target.bind_gold;
applyAuthoritativeAttributes(existing.level, data);       // 阶位变了属性跟着变
revision + 1
```

**为什么客户端要报 `targetLevel`**：服务端算出「下一阶是几」之后与客户端报的比一次。
不一致就拒 —— 客户端按旧配置点了「升到 3 阶」而运营已经把 3 阶删了，这种情况必须当场失败，
不能「按客户端说的升」。

一个特殊的失败：`GROWTH_CHANNEL_LOCKED` —— 玩家当前阶不在升级链上
（运营把这个已获得的称号切出了 `upgrade` 渠道，`upgrade_order` 清空）。此时无法定位下一阶，拒绝续升。

## 六、时装

| 项 | 规则 |
|---|---|
| `acquire_channel = upgrade` 且 `sell_price > 0` | 可购买 |
| `grant` | 运营发放（管理端 PATCH `fashionsOwned`） |
| `unavailable` | 未开放（出厂 20 件里绝大多数是这个） |
| 购买 | 扣 `bindGold` → `fashionsOwned.push(id)`，**重复购买拒收**（20016，不做「已拥有转退款」） |
| 穿 / 脱 | `POST /roles/:id/fashion-wear`，**拥有才给穿**（不在清单 → 20017） |
| 数值 | **时装不改任何数值**（`fashions` 表里有 12 个属性列，但目前不参与 `summarizeRoleAttributes`） |
| 存档 | `fashionCloth` 走普通回填；`fashionsOwned` 是**独占字段**（库里没有就删上报值） |

老档迁移：`fashionsOwned` 上线前的存档没有这个键 —— 第一次穿 / 脱时把**当前穿着**认领进清单
（它只能是历史合法穿着），空档给空清单。

跨设备：改穿发生在另一台设备时由 `roleUpdate` 帧带回，客户端 `applyFashionChange` 换外观
（不重算数值，只刷地图主角 / 内观 / 预载）。

## 七、战力权重（`combat_weights`）

7 行，管理端可改：

| key | 出厂权重 |
|---|---|
| `physicalAttack` / `magicAttack` / `taoistAttack` | 5 |
| `physicalDefense` / `magicDefense` / `taoistDefense` | 10 |
| `maxHp` | 15 |

战力 = Σ 权重 × 值，其中**区间属性取两端之和**、`maxHp` 取单值。
两个反直觉的地方都是客户端的既有口径，改之前先确认没有别的地方依赖这个数。

## 八、商城

**商品是关联数据**：一件商品 = 装备变体（`equipment_variants`）+ 两个运营字段（售价 / 购买等级，
在 `mall_goods` 表）。运营不能凭空造商品 —— 上架时服务端校验 id 在装备目录里；
已上架的商品**只许改售价与购买等级**，名称 / 图标 / 部位归装备管理管。

| 表 | 内容 |
|---|---|
| `mall_categories` | 分类（动态增删，出厂 2 个） |
| `mall_goods` | `id`（= 物品/变体 id）/ `category_id` / `price` / `required_level` |

购买流程（`POST /roles/:id/mall-purchase`）：

```
商品不在上架清单 → 404（没有「玩家能买到别的东西」的口子）
required_level > 当前等级 → 20027（客户端按钮置灰只是提示，不是防线）
bindGold < price → 20011
扣 bindGold → 行优先找第一个空格入包（装备不可叠，每件一格）
背包没有空格 → 20012（服务端不扩容：尺寸归客户端配置）
revision + 1
```

> 📌 `purchaseMallGood` 的注释里还提到 `mall_prices` / `mall_settings` 两张表 ——
> 那是旧实现，库里已经没有它们了。现在定价只读 `mall_goods.price`。

## 九、技能解锁

| 项 | 现状 |
|---|---|
| 学哪些技能 | 建号时 `skills` 表 `owner = role` 的全部技能，**1 级**（`buildInitialRoleData`） |
| 等级门槛 | `skills.level_req` 列存在，客户端按它显示「可学/不可学」 |
| 技能等级 | 存在存档 `data.skills = { skillId: level }`，进伤害公式（`damage_coefficients[level-1]`） |
| **升级入口** | **尚未开放**（客户端没有任何写点）。所以 `skills` 在权威清单里「宁可比写点宽一格」 |
| 怪物技能 | `owner = monster` 的行，只给 AI 用，不发给玩家 |

## 十、排障

| 症状 | 第一嫌疑 | 查法 |
|---|---|---|
| 升级后属性没变 | `applyAuthoritativeAttributes` 没被调用 / 等级不在曲线内 | 搜 warn `战斗属性未重算` |
| 一次给了经验却不升级 | `expNeedOf` 返回 0（曲线该段被删） | 查 `role_level_curves` 的 `exp` 段 |
| 连升很多级只升了 1 级 | 升级循环被改成 `if` | 看 `applyKillExp` 的 `while` |
| 战力与手算不符 | 区间取了平均（应该取两端之和） | 见第七节 |
| 调大了等级上限但升不上去 | 只改曲线末段、没改 `roleMaxLevel`（或反之） | 两处都要动 |
| 称号升不了 | 渠道被改成 `grant` / `unavailable`，或 `upgrade_order` 重复 | 查那几行 |
| 「目标阶位不合法」 | 客户端配置与服务端的成长链不同步 | 比对 `upgrade_order` |
| 时装买了穿不上 | `fashionsOwned` 没写进去（独占字段被删） | 查存档与购买返回的 `owned` |
| 商城价格不对 | 改的是装备表而不是 `mall_goods.price` | 查 `mall_goods` |
| 货币道具用完钱没加 | 见 [06](./06-物品与背包.md) 第七节 | — |

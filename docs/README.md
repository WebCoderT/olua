# olua 代码文档

> 37 篇，约 15264 行（36 篇编号文档 + 1 篇实测清单）。目标不是「介绍项目」，而是**把每条链路讲到能照着改、照着重现**：
> 数据从哪张表出来、经过哪个函数、落到谁的屏幕上、改哪一处会让它静默失效。
>
> 全篇贯穿一条纪律：**文档里每个数字都能用一条命令复核**（见 [五、数字从哪来](#五数字从哪来)）。

---

## 一、怎么用这份文档

### 想把它跑起来

```
README（仓库根） → 01 总览（认路）
                 → 13 部署运维（起容器 / 起本机 / 域名与密钥）
                 → 03 服务端与接口契约（调接口 / 看 Swagger）
```

### 想改一个数字（不改代码）

```
12 管理端（第九节「改配置后的生效路径」）
  → 16 配置位置总表（这个配置在哪个页面 / 哪张表 / 多久生效）
  → 02 数据与配置体系（走快照还是走独立接口）
  → 15 数据表清单（这个数在哪张表哪一列）
```

### 想搞清楚一件事怎么走的

按链路找：**装备 → 05**、**物品背包 → 06**、**战斗伤害 → 07**、**世界怪物 → 08**、
**成长 → 09**、**任务社交 → 10**。每篇结构相同：全景图 → 表结构 → 关键函数 → 排障表。

### 想加一个新东西

| 加什么 | 去哪看「要同步改哪几处」 |
|---|---|
| 新装备 | [05 第六节](./05-装备链路.md)（六步） |
| 新道具（药 / 材料 / 货币 / 卷轴） | [06 末节](./06-物品与背包.md)（按类型的连带检查） |
| 新配置表 | [15 第六节](./15-数据表清单.md)（五处登记） |
| 新快照段 | [15 第六节](./15-数据表清单.md)（三处 + 三个测试） |
| 新接口 | [03](./03-服务端与接口契约.md) + `make gen-api` |
| 新管理端页面 | [12](./12-管理端.md)（路由 + 导航 + 权限 + 审计） |

## 四、读法约定

全篇统一了几种标记，认出它们能省不少时间：

| 标记 | 含义 |
|---|---|
| **📌** | 「这条容易记错」或「注释/文档与代码不一致，以这里为准」 |
| **⚠️** | 会丢数据 / 会静默失效 / 不可逆的操作 |
| **排障** 表 | 三列固定：**症状 → 第一嫌疑 → 查法**。第一列写的是你在屏幕上看到的东西，不是原因 |
| **「改了何时生效」** 表 | 回答「我改了为什么没反应」，按四层（库 / 快照 / 独立接口 / 客户端）分 |
| 代码块 | 都是**真实签名或真实 SQL**，可以直接复制去跑；截断的部分用 `…` |
| 引用注释 | 形如「顺序很关键 —— 上报的格子契约里没有 `bound`」的，是源码里原话，不是我的总结 |

关于**数字**：所有「N 个 / N 张 / N 条」都是实测值，测量命令见下一节。

## 六、维护这份文档

三条规矩：

1. **改了代码就顺手改文档，但别改「数字口径」**。数值变了（多了一张表、多了一个接口）该改；
   但别把「区间 → 掷点 → 系数」这种**机制描述**换成当前的具体数值 —— 运营随时改数，机制才稳定。
2. **`14-接口清单` 是生成物**。它的正确改法是 `make gen-api` 后重跑导出，不是手编。
3. **发现文档与代码不一致时，写在 `📌` 里显式说明，不要默默改掉**。
   「注释说 A、代码是 B」本身就是重要信息 —— 下一篇踩坑的人需要知道该信谁。
   目前记录在案的三处见 [15 第八节](./15-数据表清单.md)。

新增一篇的规矩：

- 编号 + 中文短名（`17-xxx.md`），首行 `# 17 · xxx`；
- **末尾必须有 `下一篇` / `上一篇`**，把链子接上（链断了几篇之后就没人顺着读了）；
- 必须包含**排障表**与至少一处**「改了何时生效」或「加东西要动哪几处」**——
  只有描述没有可执行动作的篇，属于没写完。

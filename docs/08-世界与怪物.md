# 08 · 世界与怪物

> 「这只怪还剩多少血」只有一个答案，它在实时进程的内存里。
> 这一篇讲世界状态怎么建、怎么跑、怎么落库，以及为什么改刷怪区不一定马上生效。

## 一、权威在哪：一份内存 + 一份投影

```
实时进程（3101）                          共享 SQLite
WorldService.maps: zone:mapId → 实例表      world_monsters（投影 / 重启恢复的来源）
  { instanceId, monsterKey, hp, alive,        instance_id | map_id | monster_key | x | y | hp
    killedAt, respawnAt, dirty }              | max_hp | alive | killed_at | respawn_at | zone_id
        │ 受击只标 dirty                      ▲ 脏实例按节流批量写回（默认 5s）
        └──────────────────────────────────────┘
```

- **世界状态只在实时进程内存**，存档进程拿不到。所以「管理端要看这张图现在什么样」只能读投影（第
  十节的监控就是干这个的）。
- **坐标的持久真相是出生点**：走动不回传、不落盘。重启后所有怪回出生点重新游走 ——
  几秒钟的表现层状态，不值得为它加一张表。
- **血量是真状态**：受击改内存并标脏，按节流批量写库（不然一次出手一次 SQLite 写，
  与玩家存档防抖叠在一起写放大明显）。

## 二、分域：`zone:mapId`

同一张图**每个区各有一份独立世界**（区与区互不相干）：

| 项 | 规则 |
|---|---|
| 分域键 | `zone:mapId` |
| 区号来源 | 账号行的 `zone_id`（进图时现查，`?? 1`） |
| 实例 id | `m<mapId>_z<zone>_<n>` —— 带区段，跨重启稳定不重号 |
| 发牌序号 | 按分域记，加载时从库里最大值续起 |
| 合并区 | 管理端操作统一改写发牌；`world_meta.epoch` 变化触发所有进程作废内存世界 |

出厂 2 个区（`zones` 表：一区 / 二区），11 张地图。

## 三、播种：`map_spawn_areas` 是唯一来源

刷怪**区域**不再由客户端上报（#295 阶段一起归服务端，#667 起管理端地图页可绘制）：

| 列 | 含义 |
|---|---|
| `map_id` / `name` | 哪张图、这块区域叫什么 |
| `monster_key` | 刷哪种怪（对照 `monsters` 表） |
| `min` / `max` | 数量区间 —— **播种按 `max` 展开**（不是随机取一个数） |
| `cx` / `cy` / `w` / `h` | 区域中心与宽高（世界坐标） |

播种在 `loadMap` 里，三层兜底 **内存 → 库 → 播种**：

```
1. 内存里有这个分域 → 直接用
2. 库里 world_monsters 有这图这区的行 → 全部恢复（maxSeq 续号）
3. 库是空的 → 按 map_spawn_areas 播种
```

四条关键口径：

- **只播空分域**：库里（或恢复后）已有实例就一概沿用、刷怪区整份忽略。**不做「逐只补缺」**
  —— 死亡未重生的实例还在库里占位，按区域补会把它顶掉。
- **每个区各播一份**：一区播了不影响二区。
- **怪 key 不存在 → 跳过并 warn**（不静默、不崩）。
- **区域越界只告警不拦**（#586）：拦掉会让「改了配置忘了重跑导入」变成「这张图一只怪都没有」，
  那比怪刷在图外更难查。判定用库里这张图的几何（`pixel_width = 0` 时跳过判定，避免噪声）。

## 四、tick 的三件事

默认 1000ms 一次（`WORLD_TICK_MS`）：

| # | 事 | 为什么 |
|---|---|---|
| 1 | **代际巡检**：`world_meta.epoch` 变了 → 整份内存世界作废（**不落盘**） | 库里已是改写后的权威，落盘会把旧 id 写回去。未落盘的几秒伤害随之丢弃 —— 合并区这类稀有操作的代价 |
| 2 | **重生**：死亡满 `worldRespawnMs`（默认 30s）的实例复活（满血、回出生点）并通知观看者 | 死亡不是「删掉再建」，是同一个 `instanceId` 复活 —— 客户端不用重建对象 |
| 3 | **落盘**：脏实例批量写回 SQLite | 受击只标脏，写由这里节流完成 |

**生命周期的三条**：

- **惰性加载**：第一个观看者进图时才从库恢复 / 播种。
- **空闲卸载**：玩家全下线不等于立刻卸载，空闲满 `worldMapIdleMs`（默认 10 分钟）才从内存卸
  （状态已在库）。卸载期间不跑重生，重新加载时按当前时刻**一次性补上到期的**。
- **优雅关闭**：停 tick、全量 flush。所以节流间隔只影响「进程被硬杀时最多丢几秒状态」。

**观看者名单只有一份，且换图必须退出（#821）**：`world.viewers` 同时决定广播收件人、怪物 AI
跑不跑、监控采不采样、空闲卸载的计时起点。不变量是「一个账号同一时刻只在一张图里」，由
`world.join()` 自己保证 —— 登记新图前先 `leave(accountId)`（等价 `leaveAll`，把人从每一份
名单里退掉）。断线、被踢、换图三条路径共用 `leave` 这一个出口。

> 修之前 `join` 只加新集合、`leave` 只在断线调用 —— 换图不退出旧图，旧图永远「有人看」：
> AI 一直跑、采样一直写、世界频道还在往不在那儿的人投递，内存只增不减。专项回归见
> `server/test/e2e-world-viewers.cjs`（22 条），设计口径见 [20 篇 5.6](./20-地图模块重构设计.md)。

## 五、怪物 AI

住在实时模块（`monster-ai.service.ts`）。它做五件事，**每件都在服务端**。

### 位置与血量从哪来（#855）

**位置的唯一副本是 `PlayerPresenceService` 的在场表**：`pos` 帧只喂它一处，AI 只读不算 —
索敌用 `presence.aiTargetsOn(zoneId, mapId)`，追击 / 出手 / 击退方向 / 命中回填全读 `positionOf`。
AI 自己**不再存 `positions`**，所以「两份坐标谁更新」这个问题不存在了（原实现一份 `pos` 能骗两边）。
怪物打中玩家之后 `presence.markHp(accountId, hp)` 把权威血量写回在场表，**不刷 `updatedAt`**
（刷了就等于给「位置其实已超时」的人续命）。口径细节见 [27 篇 2.5.3](./27-世界与刷怪重构设计.md)。

### 目标选择

| 怪的类型 | 规则 |
|---|---|
| 主动怪 | 常驻发现（进入检测范围即目标） |
| 被动怪 | 被打伤后记恨打它的人（结算侧 `provoke` 进来） |
| 候选过滤 | 位置上报超时（`monsterAiPosStaleMs`，默认 2000ms）/ `hp <= 0` / 换图 —— 三类直接排除。**尸体由此进不了候选**，不需要另设「判死」分支 |
| 牵引超界 | 目标离怪超过 `leashRange`（默认 600px）→ 脱战，见下 |
| 失败账本 | 同一对「这只怪 + 这个人」累计 3 次结算不出来，才在索敌时跳过（#856）；打中即清零。**只清这一只怪的目标**，不牵连全图 |
| 目标作废 | 出手结算不出来（玩家已倒下 / 不在线）→ `endChase`：清 target、清记恨、转回家；**这次出手整次不发**（命中与 `casts` 都不发） |

最后一条是 #670 的根因修复：`applyMonsterHit` 返回 null 时若只当「这一下落空」，记恨不清、
下一拍继续放技能，客户端就会看见**一只怪对着尸体连放技能**。

### 脱战与回家（#853 / #858）

`MonsterRuntime.state` 三态：`idle` / `chase` / `return`。`stepMonster` 的判序：
击退 → 施法硬直 → 回家 → 目标校验 → **牵引半径** → 索敌 → 出手 / 追击 → 待机游走。
牵引判定必须放在**出手之前** —— 只放索敌之后的话，600px 外的远程技能照样够得着，脱战就变成
「不追但照打」。回家是**独立一档**而不是「清 target」：清完怪会停在玩家把它拉到的位置继续游走，
看起来像原地抽搐。`returnTimeoutMs`（默认 20 秒）到点还没走回去就**吸附**到出生点
（被地形挡住 / 出生点落在碰撞盒里都不会永久卡在半路）。
脱战 / 目标失效 / 超界三条路统一走 `endChase`（清 target + **清 `provoked`** + 转 return）——
它也是 #858「记恨永不清」的唯一收口。

### 移动

待机游走（停留点 + 随机方向 + 活动半径）、追击、回家**共用一套带碰撞的位移** `slideMove`：
整步走得通就走 → 撞墙按主方向拆两个分量各试一次（走通的那个照走 = 沿墙滑行）→ 都不通原地不动；
坐标恒钳在图内。**击退走 `pushPoint`**：被挡就原地（不滑行、不试切线）。
连续 3 帧**一步都没动** → 换 ±60° 切线（左右交替）走 6 帧，两轮都不行就停下待机。
几何来自 `MapService.walkGeometryOf()`（`maps.pixel_width/height` + `map_collisions`，AI 侧 5 秒 TTL）；
**没几何（`pixel_width = 0`）的图退回「直接改坐标」的老行为**。
速度用快照里每只怪的 `moveSpeed`（像素/秒，与客户端同一数值），回家额外乘 `returnSpeedRate`（1.5）。
参数都在 `runtime_params.monster_ai`（管理端「运行时参数 → 怪物 AI 与脱战」）。

> ⚠️ 「卡住」的门槛是**浮点误差级（0.01px）**，不是 1px：出厂 `move_speed` 是个位数
> （大批怪是 2px/s，每帧只走 0.1px），拿 1px 当门槛会把所有慢速怪判成卡住 ——
> 既不报 `moving`（客户端不播走路动画），还会 3 帧后开始无意义地拐弯。

### 无人看就冻结（#857）

没人看这张图时**冻结**运行时而不是删掉（删掉等于「反复进出图免费回血、回出生点」）：
有人重新进图立刻解冻，血量 / 位置 / 记恨全保留；空置超过 `FREEZE_RECYCLE_MS`（10 分钟，
= 世界层 `worldMapIdleMs` 默认值，那时世界分域本身已卸载）才真正回收。

### 出手

进入距离后**先试技能、再普攻**（#372）：

- 顺序：状态型整体先于伤害型（buff 先上），同类型按 `priority` 升序；已在身上的状态不重复放。
- 距离：伤害型要够得着（技能 `distance` 钳到普攻距离下限）；状态型不看距离。
- 硬直：`castLockMs`（0 回落 `attackActionTime`）期间不移动不出手，同时把普攻间隔一并推后。
- 状态生效：`attackMultiplier` 乘伤害、`defenseMultiplier` 乘被玩家打时的防御（伤害公式见
  [07](./07-战斗与伤害结算.md) 第三节），到期惰性清理。

### 广播

按 `monsterAiBroadcastMs`（默认 100ms，#768 起默认 10Hz；`MONSTER_AI_BROADCAST_MS` 可回退）节流：**只发有变化的怪**
（位置变了 / 移动标记变了 / 血量变了）加上这段时间的命中事件、技能释放与玩家击杀（#689）。
站着的怪不发第二遍。

### 刻意不做的

| 不做 | 理由 |
|---|---|
| ~~玩家侧状态数值不参与~~ | **已改**（#822）：玩家侧的 `attackMultiplier` / `defenseMultiplier` / `blockChance` / `blockFactor` 现在都在服务端结算（`role_status` 表 + `modules/combat/status-combat`）。控制类（晕/定身/沉默）与加减速**暂时放置** —— 它们要先有位置权威（#811） |
| 位置不落盘 | 见第一节。运行时只在内存，冻结/回收都不需要持久化 |
| ~~玩家位置不权威~~ | **已改**（#855）：AI 不再自己存坐标，只读在场表（仲裁后的那一份）；伪造 `pos` 骗不动索敌 |
| 怪物不消耗魔法 | 技能表 `mpCost` 只对角色生效（怪没有资源系统） |
| 威胁表（多目标仇恨） | target 仍是单值 + 布尔记恨；重开条件见 [27 篇九](./27-世界与刷怪重构设计.md) |

## 六、进图门槛（#606）

`maps` 表三个门槛列 + 两条判定（存在性、位置记录）：

```ts
// 判序在 RealtimeService.mapEnterRejectOf：先认图、再认位置，最后才是下面三条数值
if (!maps.exists(mapId)) return { field: "unknown", need: 0, mapLabel: mapId };   // #859
// mapAt 缺失 → 只准进 START_MAP_ID("0")，其余 { field: "start", need: 0, mapLabel }
if (row.level > 0 && row.level > role.level) return { field: "level", need, mapLabel };
if (row.combat > 0 && row.combat > role.combat) return { field: "combat", need, mapLabel };
if (row.soul_of_war > 0 && row.soul_of_war > role.soulOfWar) return { field: "soul", need, mapLabel };
```

**两处消费，同一判据**：

| 消息 | 时机 | 作用 |
|---|---|---|
| `mapEnter` | 客户端切场景**之前**先问一句 | 被拒就地提示、不切图（不会先进空图再被踢回） |
| `worldJoin` | 真正落地那一刻 | **权威**：绕过 `mapEnter` 直发的改包走这条，必须拦得住 |

三条边界（#573 踩出来的）：

1. **登录不算换图**：`worldJoin` 的目标图 == `data.mapAt` 时一律放行 ——
   运营事后调高门槛不能把已经站在图里的人锁在门外（他自己没有任何办法出来）。
2. **服务端还没有位置记录时只准进新手村 `"0"`**（刚建号 / 老档第一次上线，#859）：以前是「不拦」——
   那一刻他在哪由客户端决定，于是新号直落任意图成了门槛的永久后门（`setMapAt` 还会把这次放行记下来）。
   位置一旦记下，就不再接受客户端改口。
3. **不认识的图直接拒**（`field = "unknown"`，#859）：以前没有配置行就没有门槛，世界层照样给它建一份空图 ——
   拼错一个 id 就进了没地形 / 没怪 / 没复活点的表外世界。代价：加新图必须先配 `maps` 行。

`mapAt` 的写点只有两个：**被接受的 worldJoin** 与**管理端摆位**（PATCH 带 `onMap`）。
客户端存档里的同名字段一律回填丢弃（见 [04](./04-角色与存档权威.md) 第二节）。

## 七、地图数据

| 表 | 行数 | 内容 |
|---|---|---|
| `maps` | 11 | `map_id / label / type / level / combat / soul_of_war` + 几何（`grid_cols/rows`、`tile_width/height`、`pixel_width/height`）+ 复活点 `revive_cx/cy` |
| `map_spawn_areas` | 64 | 刷怪区（按图分布：0 号图 5 块 / 3 号图 18 块） |
| `map_collisions` | — | 碰撞体（客户端与服务端同一份） |
| `map_npcs` | — | NPC 摆点（对话 / 商店 / 传送） |
| `zones` | 2 | 区表（`merged_into` 支持合区） |
| `world_meta` | 1 | 世界代际 `epoch` + 坐标原点 `coord_origin` |

`type` 目前 `0` = 城镇（有复活点、无怪）/ `1` = 野外。`level / combat / soul_of_war` 为 0 表示**不设门槛**。

地图**内容**（Tiled 导入的瓦片图 / 碰撞 / 物件）落在客户端 `assets/resources/`，服务端只存几何与门槛 ——
这是「资源目录口径」那条纪律的一部分（见 `client/RESOURCES.md`）。

## 八、实时地图监控（#665 / #745）

管理端要「看这张图现在什么样」，但世界状态在另一个进程的内存里。桥就是两张表：

| 表 | 谁写 | 内容 |
|---|---|---|
| `map_monitor_state` | 实时进程每秒投影 | 该区该图的怪物快照（JSON）+ 采样时间 |
| `map_monitor_events` | 实时进程按事件追加 | 击杀 / 刷新 / 伤害（一次一行） |

管理端 `MapService.monitor(id, { zone, since, limit })` 只做「读 + 拼」。三个必须照实返回的东西：

| 字段 | 为什么 |
|---|---|
| `staleMs` | 没人在那张图里时采集器不采样，快照会停住。页面必须能说「最后采样 3 分钟前」，否则一张停更的图看起来和「图里没人、怪也都不在」一模一样 |
| `zones` | 同一张图每区各一份世界，监控得能切区 |
| `cursor` | 事件按 id 增量拉，页面不会每秒重画 300 行 |

快照坏掉（半截 JSON）→ 返回空列表 + `sampledAt = null`，**不抛 500**：一张图的镜像坏了不该让整个监控接口挂掉。

伤害日志用「这次结算本身」的数字，不用两次快照差分 —— 差分只能说「掉了血」，说不出是谁打的、
用什么打的、这一下多少（见 [07](./07-战斗与伤害结算.md) 第十节）。

## 九、改了刷怪区，什么时候生效

这是最容易「改了没生效」的一处，因为它和配置快照无关：

| 操作 | 生效条件 |
|---|---|
| 改区域数量 / 落点 / 怪种 | **只对空分域生效**。已经播过种的分域沿用库里的实例 → 要等它空闲卸载（默认 10 分钟无人）后重新加载，或重启实时进程 |
| 改 `maps` 门槛 | 立刻生效（每次 `worldJoin` 现查库） |
| 改 `monsters` 数值（血量 / 攻防） | 立刻生效（#258 直读库）；**但已经在场且满血的怪，`maxHp` 变了血量还是旧值** —— 下次重生才对齐 |
| 合并区 / 重排 instanceId | 管理端操作改写 `world_meta.epoch` → 所有进程作废内存世界，下次 join 按库重载 |

> ⚠️ 已知未收口项（#669）：「刷怪区改了要立刻生效」还没有在线重播种入口。
> 现在的做法是等空闲卸载或重启；写文档时**别把「保存即生效」当成事实**。

## 十、排障

| 症状 | 第一嫌疑 | 查法 |
|---|---|---|
| 图里一只怪都没有 | 刷怪区 `max = 0` / 怪 key 在 `monsters` 里不存在 | 看启动日志 `播种 N 只怪` 与 `跳过` 的 warn |
| 怪刷在图外 | 区域越界（旧口径 seed） | 搜 `越出地图边界` 的 warn，去地图页重画 |
| 改了刷怪区没反应 | 分域已播种，只播空图 | 见第九节 |
| 打怪不掉血 | 目标区不对（`unknown_target`） | 查账号 `zone_id` 与实例 id 的 `_zN_` |
| 怪不动 | AI 运行时被清（图没人看） | 进图后等一个广播周期（100ms） |
| 怪对着尸体放技能 | `forgetTarget` 未生效 | 见第五节 |

| 监控页长时间不变 | 图里没人 → 不采样 | 看 `staleMs`，不是 bug |

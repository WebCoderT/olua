## 零、现状（实测）

| 项 | 实测 |
|---|---|
| 等级曲线 | `role_level_curves` 4 条（`hp` / `attack_max` / `defense_max` / `exp`），每条 **6 段**，`to_level` 最大 **1000000** |
| 分段 | 1-10 / 11-20 / 21-30 / 31-40 / 41-50 / **51-1000000** |
| 成长标量 | `growth_scalars(key, value, description)` —— 击杀经验的两个标量从这里读 |
| 货币 | **只有 `bindGold` 一种**（`money_items` 货币道具，出厂 8 档面值） |
| 战力 | `combat_weights` 加权求和 |
| 附属成长 | 称号 `titles`、时装 `fashions`、等级卷轴 `level_scrolls`、魂值（进图门槛用） |

**关键事实**：第 6 段 `51 → 1000000` 是一条公式覆盖 99.99% 的等级空间。
按第 6 段参数（`start 67600`、`per_level 3950`、`accel 100`），等级 200 的单级经验已在百万量级，
**等级 100 万是数值上的占位上限，不是可玩目标**。所以：

> **转生门槛不能设在满级**，否则永远没人能转生。门槛必须是「实际到得了的等级」，
> 且可配 —— 本篇默认 **200**，这是一个「长线第一个整百」的保守起点，运营按实际升级速度调。

## 一、四个结构性问题

### 1.1 没有台阶：一条坡走到黑

升到 200 级之后，玩家能做的只有「继续升」。没有重置、没有分支、没有「换个职业路线」，
长线目标只剩数值堆叠。网络游戏的标准答案是给一个**可重复的循环**（转生 / 觉醒 / 轮回），
让玩家用「重新练一遍」换「永久变强」。

### 1.2 曲线改完要重登才生效

客户端 `configs/apply-snapshot.ts` 拿到新曲线后，**当前等级对应的属性不会重算** ——
玩家要重登（或升级）才看到变化。运营改了攻击曲线，前台看起来「没变」，于是又改一遍，
越改越乱。

### 1.3 战力是纯加权和，没有阈值

`combat_weights` 是「每点攻 +x 战」。这套算法的毛病：**任意两个属性可以互相等价兑换**，
所以「堆血量的坦克」和「堆攻击的刺客」战力一样时，实际强度差很远。战力作为进图门槛（`#606`）就会误判。

### 1.4 称号 / 时装只有属性，没有收集度

拿到就加属性，没有「集齐一套」的额外收益，也没法做「收集度排行榜」这类长线目标。

## 二、目标形态

### 2.1 转生：定义

| 项 | 规则 |
|---|---|
| 门槛 | `rebirth_required_level`（默认 **200**，可配）；必须**满经验**且**不在战斗/队伍/交易中** |
| 代价 | 等级重置为 1、经验归零、**技能全部回 1 级并退还全部技能点**、背包与装备**保留**、称号与时装**保留** |
| 收益 | 转生层数 +1；每层给 `rebirth_bonus_rate`（默认 **0.05**）的**全属性乘算**；额外给 `rebirth_skill_points`（默认 5）技能点 |
| 上限 | `max_rebirth_times`（默认 10）；到顶后再转生 → 拒 |
| 不可逆 | 是。二次确认 + 输入角色名 |

**为什么技能要重置并退点**：技能点是「每级 +1」发的，等级回 1 后如果不退点，
玩家会保留「200 级发出来的 200 点」又拿 1 级的点 —— 直接失衡。退点 + 重分配是唯一自洽的做法。

**为什么背包与装备保留**：转生是「变强循环」，不是「删号重来」。装备一旦清空，
玩家要重新刷一遍 685 件装备池里的同一件，体验极差。

### 2.2 全属性乘算的落点

```
finalAttr = round(baseAttr(level, 转生层数) × (1 + rebirthTimes × rebirthBonusRate) × (1 + 称号/时装/装备加成))
```

- `baseAttr` 仍由 `role_level_curves` 按**新等级**算（转生后 level=1，所以基数很低）；
- 转生加成是**乘在曲线结果上**，不是加平值 —— 加平值会让低等级段变成碾压，高等级段变成无感；
- 装备加成**不参与**转生乘算（否则转生 × 装备 = 双重乘算，数值爆炸）。

### 2.3 曲线不动，但补一条「转生段」

不改现有 6 段（改了所有存档的属性都会跳变）。转生后的成长**复用同一条曲线**，
只是乘了转生系数。这样：

- 老档（未转生）数值一字不变；
- 转生玩家在同一等级下属性更高，但**曲线形状不变**，运营调曲线时两类玩家一起受益。

### 2.4 战力求值：从「加权和」到「分段评分」

不改 `combat_weights` 的字段，只改聚合方式：

```
score(attr) = 该属性在同等级段玩家中的分位（0~1，取最近 7 天快照）
战力 = Σ weight(attr) × score(attr) × scale
```

**代价**：需要「同等级段玩家的属性分布」。做法：每小时对**在线角色**采样一份
`role_power_snapshot`，按每 10 级一段算百分位；**段内样本 < 30 个时退回理论满分** ——
这是唯一能同时解决「新服没人」与「深夜失真」的折中。

```
score(attr) = 段内样本 >= 30 ? 百分位(attr) : min(1, current / (曲线上限 × 1.2))
战力 = Σ weight(attr) × score(attr) × scale
```

**为什么保留理论满分这条退路**：开服第一周永远样本不足，如果强行算分位，战力会剧烈抖动，
而战力又被进图门槛（`#606`）使用 —— 抖动的门槛等于「昨天能进今天不能进」。

### 2.5 生效时机：曲线改完立刻重算

| 场景 | 现在 | 改成 |
|---|---|---|
| 运营改曲线 | 客户端重登才变 | 快照带 `curvesVersion`；客户端收到新版本时**对自己重算一次属性**并刷新面板 |
| 运营改战力权重 | 同上 | 同上（战力是纯客户端展示，重算无副作用） |
| 玩家升级 | 即时（服务端推 `roleUpdate`） | 不变 |

> 注意：**服务端权威属性**（伤害用的那套）本来就每次结算现算，不受影响；
> 这里修的只是**客户端展示**与**战力门槛判定**两处。

### 2.6 称号 / 时装收集度

加一张 `collection_bonus`（`kind` = `title` / `fashion`，`need_count`，`bonus`JSON）。
集齐 N 件给一次加成，加成走「称号/时装加成」那一栏，**不进转生乘算**（避免乘算叠加失控）。

## 三、数据模型

```sql
-- 转生状态（一个角色一行，没有记录 = 没转过生）
CREATE TABLE role_rebirth (
  role_id     TEXT    PRIMARY KEY,
  times       INTEGER NOT NULL DEFAULT 0,
  last_at     INTEGER NOT NULL DEFAULT 0,
  total_spent INTEGER NOT NULL DEFAULT 0   -- 转生消耗的货币累计（给流水对账用）
);

-- 转生规则（单行表，与 growth_scalars 同风格：key-value）
CREATE TABLE rebirth_rules (
  key         TEXT PRIMARY KEY,   -- required_level / bonus_rate / skill_points / max_times / cost_bind_gold
  value       REAL NOT NULL DEFAULT 0,
  description TEXT NOT NULL DEFAULT '',
  updated_at  INTEGER NOT NULL DEFAULT 0
);

-- 收集度加成（称号 / 时装）
CREATE TABLE collection_bonus (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  kind        TEXT NOT NULL,       -- title / fashion
  need_count  INTEGER NOT NULL,
  bonus       TEXT NOT NULL,       -- JSON: {attack:5, hpPercent:2}
  label       TEXT NOT NULL DEFAULT ''
);

-- 战力采样（真分位用；只采在线，保留 30 天）
CREATE TABLE role_power_snapshot (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  role_id    TEXT    NOT NULL,
  level_band INTEGER NOT NULL,     -- floor(level/10)*10
  power      INTEGER NOT NULL,
  attrs      TEXT    NOT NULL DEFAULT '{}',  -- JSON：各属性值（算分位用）
  at         INTEGER NOT NULL
);
CREATE INDEX idx_power_band_at ON role_power_snapshot(level_band, at);
```

存档新增字段（都在 `roles.data`，不新增表）：`attrPoints`（四维分配）、`advClass`（二次转职）。

出厂 `rebirth_rules`：

| key | 默认 | 说明 |
|---|---|---|
| `required_level` | 200 | 门槛等级 |
| `bonus_rate` | 0.05 | 每层全属性 +5% |
| `skill_points` | 5 | 每层额外技能点 |
| `max_times` | 10 | 最多 10 层 |
| `cost_bind_gold` | 0 | 转生消耗绑定元宝（默认免费） |

> **`cost_bind_gold` 默认 0 是有意的**：先让玩家把循环跑通，收费是运营决策。
> 一旦收费，必须处理「钱不够卡在门槛」的提示（与 20 篇传送代价同一个道理）。

## 四、协议

| 接口 / 帧 | 方向 | 说明 |
|---|---|---|
| `POST /roles/:id/rebirth` | C→S | 请求体 `{confirmName}`（必须等于角色名）；返回 `{times, level, skillPoints, attrs}` |
| `roleUpdate` | S→C | 转生成功推送（`level` / `exp` / `data.skills` / `data.skillPoints` / `rebirthTimes` 全变） |
| 快照 `curves` | S→C | 加 `version` 字段（时间戳或哈希），客户端据此判断要不要重算 |
| `combat-weights` | S→C | 同上加 `version` |

**转生必须走 HTTP，不走实时帧**：它会重写 `roles.data` 的一大片（等级、经验、技能、技能点），
属于「存档事务」，走 `save` 那条有乐观锁保护的通道；走实时帧会绕开 revision 检查。

| ⑤ | 战力：`role_power_snapshot` + 每小时采样 + 段内分位（样本 <30 退回理论满分） | 中 |

| # | 情形 | 期望 |
|---|---|---|
| 1 | 等级未到门槛 | 400，`code=rebirth_level_low`，带 `need` / `have` |
| 2 | 等级到但经验不满 | 拒（`rebirth_exp_not_full`）—— 允许「半级转生」会让经验曲线失去意义 |
| 3 | 已在战斗中（有活着的目标 / 最近 10 秒出过手） | 拒（`rebirth_in_combat`） |

## 八、验收

| 用例 | 断言 |
|---|---|
| `e2e-rebirth-basic` | 200 级满经验 → 转生 → `level=1` / `exp=0` / `rebirthTimes=1` / 背包件数不变 |
| `e2e-rebirth-points` | 转生前后技能总点数 = 「新等级应得 + 转生额外」，已学技能全部 1 级 |
| `e2e-rebirth-attrs` | 转生 1 层后 1 级角色属性 = 非转生 1 级 × 1.05（±1 取整） |
| `e2e-rebirth-guard` | 等级不足 / 经验不满 / 在队伍 / 在战斗 → 四种 `code` 各命中一次 |
| `e2e-rebirth-max` | 连转 10 次 → 第 11 次 `rebirth_max_times` |
| `e2e-curve-version` | 改曲线 → 快照 `version` 变 → 客户端重算后攻击力变化（用客户端沙箱断言） |

手工验收：转生弹窗写清「等级归 1、技能重置、装备保留、全属性 +5%」；
转生后 3 秒内有明确提示，不会让玩家以为掉档。

## 九、本轮纳入的四项（你已点选）

这四项原稿被我写成「不做」，已按你的选择纳入。下面是各自的落法（都排在转生之后）。

### 9.1 属性点自由分配

| 项 | 规则 |
|---|---|
| 获得 | 每级 **3 点**（转生层数再 ×(1+层数×0.1)），存 `roles.data.attrPoints` |
| 四维 | 力量（物攻）/ 敏捷（暴击 + 移速）/ 体质（生命 + 物防）/ 精神（法攻 + 法力） |
| 分配 | `POST /roles/:id/attrs/allocate {str, agi, vit, spi}`，一次可加多点，**分配不可撤回**（要重来只能洗点） |
| 洗点 | 消耗 `attr_reset_cost`（默认 500 金）全退；**不走转生那条路**（避免「转生免费洗点」被利用） |
| 进属性聚合 | 四维直接加成到 `roleAttributeSourceOf` 的同一出口，乘算顺序：`(曲线 + 四维) × 转生 × 装备` |

**为什么要洗点货币**：四维与转生叠加后，最优解会随装备变化（今天该堆攻、明天该堆血）。
没有洗点成本的话，玩家会每天洗一次，四维就变成了「免费重配」，失去选择意义。

### 9.2 二次转职

| 项 | 规则 |
|---|---|
| 门槛 | **必须先转生 1 次**（`rebirthTimes ≥ 1`）且等级 ≥ `adv_class_level`（默认 100） |
| 选择 | 每个职业两条分支（如 剑客 → 剑圣 / 剑魔），二选一，**不可反悔**（要换只能重开角色） |
| 影响 | ① 技能表：`skills.occupation` 增加分支值（`warrior_saint` / `warrior_demon`）② 装备限定：`equipments.occupation` 同样支持分支 ③ 外观：`role_appearance` 加 `advClass` 字段 |
| 存储 | `roles.data.advClass`（空 = 未转职） |
| 已有技能 | 转职时**保留通用技能**，分支专属技能按新分支重新给 1 级 |

**为什么必须要求先转生**：二次转职是「长线身份选择」，如果 1 级就能选，它会把转生的意义削掉一半。

### 9.3 真分位战力

| 项 | 规则 |
|---|---|
| 采样 | 每小时对**在线角色**记一份 `role_power_snapshot(role_id, level_band, power, at)` |
| 等级段 | 每 10 级一段（1-10、11-20…），段内样本 < 30 个时**退回理论满分**（避免新服失真） |
| 分位 | `score(attr) = 该属性在段内的百分位`；战力 = `Σ weight × score × scale` |
| 刷新 | 客户端每 5 分钟拉一次（走独立接口，不进快照 —— 它每小时变） |
| 清理 | 保留 30 天，按 `at` 分区删 |

**代价**：多一张每小时几十万行的表（10 万人服）。所以只对**在线**采样，且 30 天清理。

### 9.4 转生专属装备

| 项 | 规则 |
|---|---|
| 标记 | `equipments.rebirth_req`（默认 0 = 不限） |
| 校验 | 穿戴时 `rebirthTimes >= rebirth_req`，否则拒（`rebirth_required`） |
| 掉落 | 不特殊处理：掉出来就能看到，只是穿不上（给玩家一个「转生目标」） |
| 与实例化 | 无冲突：实例只存强化等级，专属是**定义级**属性 |

## 十、暂时放置（写清重开条件）

| 项 | 现在的口径 | 重开条件 |
|---|---|---|
| 主动技能/被动技能的天赋树（比四维更细的成长） | 只做四维点 | 四维被验证「差异化不够」时 |
| 转生后重置职业 | 转职只能一次 | 玩家流失分析显示「选错职业」是主因时 |
| 分位战力的跨服对比 | 只在本区段内比 | 有第二个区、且两边都跑满 30 天数据时 |
| 等级上限突破 100 万 | 保持现有曲线 | 有玩家实际接近上限时（当前不可达） |

## 十一、已定参数

| 项 | 结论 |
|---|---|
| 转生 | **做**，可重复，最多 10 层 |
| 门槛 | 默认 200 级（可配），**不设满级** |
| 代价 | 等级归 1、技能重置退点；装备与背包保留 |
| 收益 | 每层全属性 ×1.05（乘算）+ 每层 5 技能点 |
| 曲线 | 6 段**不动**，转生走乘算 |
| 战力 | **真分位**（每 10 级一段、段内百分位、样本 <30 退回理论满分） |
| 收费 | 转生 `cost_bind_gold` 默认 0；**属性洗点 500 绑定元宝** |
| 属性点 | **做**，每级 3 点，四维 |
| 二次转职 | **做**，需转生 ≥1 次且 ≥100 级，二选一不可反悔 |
| 转生专属装备 | **做**，`equipments.rebirth_req` |

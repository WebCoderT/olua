### 1.3 合区的遗留

`merge()` 只做三件事：搬 `accounts.zone_id`、重排 `world_monsters`、打标记 + 升代际（`zone.service.ts:78-113`）。由此留下五个尾巴：

| # | 遗留 | 机制 | 后果 |
|---|---|---|---|
| 1 | **死区会被重新播种** | pending 的 `world_reload_requests` 不清 → `room-reload.service.ts:71` 拼出 from 区房间 → `world.reloadRoom`（`world.service.ts:242`）`ensure` + 重新播种 | 已合并的区刷出一批怪，`instanceId` 还带旧区段 |
| 2 | 监控残留 | `map_monitor_state` / `map_monitor_events` 按 (区, 图) 留存 | 管理端地图监控仍能选到死区 |
| 3 | **代际是全局的** | 单行 `world_meta.epoch`，合并 +1 后所有区的内存世界一起作废（`world.service.ts:284-303`） | 合一个区，全服玩家都看到本图怪重建一次 |
| 4 | 在线玩家不落地 | 合并后在线连接的在场身份仍是旧区房间 | 玩家在世界频道/组队里"半在新区半在旧区"，直到下次进图 |
| 5 | 位置快照不带区 | `role_positions` 只有 `map_id`，角色换区后旧坐标仍"有效" | 任务距离校验拿到跨区坐标 |

### 1.4 一个账号只能在一个区（当前模型）

`accounts.zone_id` 被五处当权威读：注册写入（`auth.service.ts:62`）、账号视图回显（`account.dto.ts:75`）、
实时进图解区（`realtime.service.ts:818/877`）、跨区攻击判定（`combat-settlement.service.ts:668`）、

账号视图改成「角色所在区集合」），**剩下一处（注册写入）变成 `active_zone_id` 的初始值**，只作浏览态。

## 二、目标模型

### 2.1 四条原则

1. **区是角色的属性，不是账号的属性。** 账号只负责身份与安全（密码、封禁、令牌）；「在哪个世界玩」由角色决定。
2. **跨区默认拒绝，拒绝发生在服务端。** 客户端隐藏入口只是体验层；每一条跨区路径都要有服务端校验和 e2e。
3. **管理端一次只在一个区里工作。** 不做绑区（所有管理员都能切到任意区），但每个请求必须带一个区；
   「全部区」聚合视图不存在 —— 混合数据配单区按钮，是最容易点错的一种界面。
4. **区是服务端算出来的上下文，不是请求参数。** 玩家侧不传、传了不认；管理端必须传，但那是"我在看哪个区"，
   不是权限 —— 所有管理员能切任意区，区只约束数据范围（见 3.8）。
   这条落到代码上就是两条纪律：仓储的 zone-scoped 查询**没有无区重载**，玩家侧接口**没有 zoneId 入参**。

### 2.2 表结构

```sql
-- zones：补运营字段（status / opened_at / sort / recommended / note）
ALTER TABLE zones ADD COLUMN status      TEXT    NOT NULL DEFAULT 'open';  -- open | maintenance | closed
ALTER TABLE zones ADD COLUMN opened_at   INTEGER NOT NULL DEFAULT 0;       -- 对外展示的开服时间（运营可改）
ALTER TABLE zones ADD COLUMN sort        INTEGER NOT NULL DEFAULT 0;       -- 注册/选服排序（小在前，同值按 id）
ALTER TABLE zones ADD COLUMN recommended INTEGER NOT NULL DEFAULT 0;       -- 推荐区（选服弹窗置顶）
ALTER TABLE zones ADD COLUMN note        TEXT    NOT NULL DEFAULT '';      -- 仅管理端可见

-- accounts：zone_id 改名（语义从「账号归属区」降级为「当前浏览区」= 服务端会话）
-- 只存"我上次在看哪个区"，不参与任何归属判断；改名是为了让读点自己暴露出来
ALTER TABLE accounts RENAME COLUMN zone_id TO active_zone_id;

-- roles：区下沉到角色（唯一权威）
ALTER TABLE roles ADD COLUMN zone_id INTEGER NOT NULL DEFAULT 1;
CREATE INDEX IF NOT EXISTS idx_roles_zone ON roles(zone_id);
-- 唯一索引替换：每区 6 个同名限制
DROP INDEX IF EXISTS idx_roles_account_name;
CREATE UNIQUE INDEX IF NOT EXISTS idx_roles_account_zone_name ON roles(account_id, zone_id, name);

-- guilds：帮会绑区（名字仍全局唯一，见 3.5）
ALTER TABLE guilds ADD COLUMN zone_id INTEGER NOT NULL DEFAULT 1;
CREATE INDEX IF NOT EXISTS idx_guilds_zone ON guilds(zone_id);

-- 管理端：记住上次选的区（换浏览器也一致）；不建 admin_zones（Z6 不绑区）
ALTER TABLE admins ADD COLUMN last_zone_id INTEGER;

-- 审计带区（"按区查谁干了什么"）
ALTER TABLE audit_logs ADD COLUMN zone_id INTEGER;

-- 公告按区（NULL = 全服）
ALTER TABLE announcements ADD COLUMN zone_id INTEGER;

-- 世界代际下沉到区（替换全局单行 world_meta）
CREATE TABLE IF NOT EXISTS zone_world_meta (
  zone_id INTEGER PRIMARY KEY,
  epoch   INTEGER NOT NULL DEFAULT 0
);
```

`accounts.active_zone_id` **保留**，但只表示「浏览态」：选服 / 选角阶段的服务端会话。
它不是归属、不是权限、不参与跨区判定；进图之后一切读在线角色的 `zone_id`。
账号级（跨端共享）是刻意的：同一账号在手机与模拟器上看到同一个区，切区是账号偏好而非设备状态。

### 2.3 登录 → 选服 → 选角 → 进图

```
POST /auth/login ─→ token（载荷不含区：sub / username / ver）
      │
      ├─ GET /zones/mine（auth）→ [{id,name,status,openedAt,sort,recommended,roleCount,lastPlayedAt}]
      │     ├─ 有角色的区 = 1 个 → 服务端自动选中（不弹窗）
      │     ├─ 有角色的区 ≥ 2 个 → 弹「选择区服」（通用弹窗）
      │     └─ 0 个角色 → 弹窗列全部活区，选完进建角
      │
      ├─ POST /zones/select { zoneId } → 服务端写 accounts.active_zone_id
      │     校验：区为 open，且（我在此区有角色 或 该区允许建角）；否则 404 / ZONE_UNAVAILABLE
      ├─ GET /roles        → **无参数**，返回 active_zone_id 那区的角色（选角页）
      ├─ POST /roles { name, occupation, sex } → 建角落在 active_zone_id
      └─ POST /roles/:id/select → 进游戏；服务端把该角色的区回写 active_zone_id（两者恒一致）
```

`zoneId` **不进令牌**：令牌是账号级凭证，进游戏时按角色解析区；否则玩家切区就得换令牌。

`GET /zones/mine` 是**唯一**会一次列出多个区的玩家接口 —— 它是账号级聚合（各区的角色数），
不含任何别的区的游戏数据。除此之外，玩家侧每一个读接口都只返回**一个区**的内容。

`active_zone_id` 落空时（区被合并 / 关闭）在**登录阶段**重选，顺序：最近在线角色所在区 →
有角色的第一个活区 → 推荐区 → 1 区。**不在每个读接口里做兜底** —— 读接口拿不到有效区就是
服务端状态异常，应当 `ZONE_UNAVAILABLE`，而不是悄悄换成 1 区（客户端零兜底原则）。

### 2.4 读路径按区收口（硬不变量）

> 这一节是「不允许跨区攻击」的落地方式。**不靠每处记得写 `WHERE zone_id`，靠结构上写不出无区查询。**

#### 规则 1 · 区只有四个来源，客户端一律不能"指定"

| 场景 | 区从哪来 | 客户端能做什么 |
|---|---|---|
| 选服 / 选角（未进图） | `accounts.active_zone_id` | 只能 `POST /zones/select`：切到我在该区有角色的区（或该区 `open` 且允许建角）；服务端校验 |
| 进图后（游戏内全部读写） | 在线角色 `roles.zone_id` | 不能做任何事 |
| 管理端 | `X-Zone-Id`（显式选择，**必填**） | 可切任意区（不绑区）；不传 / 区不存在 → 400 `ZONE_REQUIRED` |
| 未登录公共读 | 显式 `?zoneId=`（**仅**公告 / 区目录） | 能指定，但只影响只读展示，不返回任何玩家数据 |

推论：玩家侧 controller **不存在** `@Query("zoneId")`／`@Body().zoneId` 读点。
真出现了就是设计事故，由下面的守点拦。

#### 规则 2 · 仓储层没有「无区重载」

zone-scoped 表（`roles` / `guilds` / `role_mails` / `friends` / `party*` / `role_positions` /
`world_monsters` / `map_monitor_*` / 榜单物化）的查询函数，**签名必须带区**：

```ts
// 改法：删掉单参版本，改成区在前
findById(zoneId: number, id: string): RoleRow | undefined;
list(zoneId: number, filter: RoleFilter): RoleRow[];
count(zoneId: number, filter: RoleFilter): number;
```

删掉 `findById(id)` 之后，**所有调用方都编译不过**，被迫显式交出区 ——
漏过滤从「review 靠眼」变成「`tsc` 拦下」。这是本设计里唯一真正的根因修复。

不分区（保留单参）：`zones` / `accounts` / `admins` / `game-config` 全部配置表 /
`audit_logs`（有 `zone_id` 但允许 `NULL` = 全服操作）。

#### 规则 3 · 跨区对象一律 404，不区分"不存在"与"不是你的区"

统一入口（新建 `server/src/common/utils/zone-scope.util.ts`）：

```ts
/**
 * 跨区一律当作不存在；由调用方传本域「找不到」的码 ——
 * 不要统一成一个 ZONE_xxx，否则加好友失败会提示「区服不存在」。
 */
export function mustSameZone(
  mine: number,
  target: number | null | undefined,
  notFound: BizException,
): void {
  if (target == null || target !== mine) throw notFound;
}

// 用法（社交）：mustSameZone(me.zoneId, target.zoneId, BizException.notFound(BizCode.SOCIAL_ROLE_NOT_FOUND, "没有找到这个角色名"))
```

**为什么不用 Guard 统一拦**：Guard 只看得到 URL，看不到「这个 `roleId` 属于哪个区」。
万能守卫只能猜资源归属，猜就必然漏。所以分工是：**Guard 只解释"我是哪个区"，
资源归属由仓储签名 + service 里一次 `mustSameZone` 保证**。

| `GET /admin/guilds` | `zone_id = :current` |
| `GET /admin/maps/*` | 请求区必须 == `X-Zone-Id`，否则 400（不允许"头里 A 区、URL 里 B 区"） |
| `GET /admin/mails`、`/admin/announcements` | 批次/公告的目标区 = 当前区；列表 `zone_id = :current OR NULL` |
| 所有写接口 | 目标资源区 ≠ 当前区 → 404；账号级操作（封禁/改密/删号）例外，但页面必须提示影响全区 |

#### 守点：`tools/audit-zone-scope.cjs`（进 `make audit`）

四条机器规则，一条违反即红（宁可误报，白名单必须写理由）：

| # | 检查 | 白名单 |
|---|---|---|
| 1 | 玩家侧 controller 出现 `@Query("zoneId")` / `@Body() ... zoneId` | `announcement`（公共读）、`zone.controller`、`admin/*` |
| 2 | `database/repositories/*.ts` 中，**读** `<zone-scoped 表>` 的 SQL 没有 `zone_id =` / `zone_id IN` | 跨区聚合（`zones`、`accounts`）、按 id 取 `zones` 行 |
| 3 | zone-scoped 仓储出现单参 `findById(` / `list(` 定义（无 `zoneId` 形参） | 迁移前存量清单，逐条带 issue 号 |
| 4 | `server/src/modules` 下出现 `zoneId` 从请求入参解构（`dto.zoneId` / `query.zoneId`）且不在白名单 | `admin/*`（区是必填上下文）、建区/合区、审计的按区筛选 |

规则 2 的**两种不算**（写进脚本注释，实现见 `tablesIn` / `rolesAreDecorative`）：

- **`UPDATE <表>` 不算读**：写错行由「仓储签名带区 + 上游已解区」保证（拿 id 的那一步是
  `findById(zoneId, id)`，跨区直接 404）。`INSERT INTO` 仍要检 —— 少了 `zone_id` 列是真错。
- **`roles` 只作「按主键取一行的装饰」时不算**：`(SELECT r.name FROM roles r WHERE r.id = g.leader_id)`
  与 `JOIN roles r ON r.id = m.role_id` 这类，行被外层 id 钉死，捞不出别区的行；成员列表 / 举报 /
  审计流水 / 账号角色数全是这种写法，硬检会逼出几十条豁免，真漏点反而被淹没。
  **判据是「全部引用都是装饰」** —— 只要方法体里还有一处裸 `FROM roles`（`WHERE id = ?`、`WHERE name = ?`），照旧违规。

反证方式：临时塞一个 `findById(id)` 与一个 `@Query("zoneId")`，脚本必须 `exit=1` 且两处都被点名；
删掉后回绿。**不做「警告」模式** —— 警告等于不设防。P1 实测还多塞了三种 `roles` 写法
（裸查 / 带别名但非主键钉死 / 装饰 + 裸查混用），全部被点名。

#### 客户端与管理端的差别（不要混为一谈）

- **客户端**：零区参数。它连"我在哪个区"都不知道（`GET /zones/mine` 只用于渲染选服弹窗）。
  防的是**玩家**：改包、拼请求、遍历 id，都只能碰到自己当前区。
- **管理端**：可以传区，且**必须**传 —— 但它传的是"我现在看哪个区"，不是"我有多大的权限"。
  所有管理员都能切到任意区（Z6 不绑区），因此管理端的区约束不是安全边界，而是**数据正确性边界**：
  防止「A 区列表里点到一个 B 区 id」这类跨区误操作。追责靠审计（`audit_logs.zone_id`），不靠行级隔离。

## 三、逐域改动

### 3.1 认证与角色

| 项 | 改法 |
|---|---|
| 注册 | 不再收 `zoneId`；账号只建身份。DTO 保留一版兼容（服务端忽略并标 deprecated），下一版删 |
| 建角 | **`CreateRoleDto` 不收 `zoneId`**：落在 `accounts.active_zone_id`；服务端校验该区 `open` 后写入 `roles.zone_id` |
| 上限 | `COUNT(*) WHERE account_id=? AND zone_id=?` 与 6 比；错误码沿用 `ROLE_LIMIT_EXCEEDED` |
| 唯一 | 应用层查重 `findByAccountZoneAndName`；表上唯一索引换成三列 |
| 列表 | `GET /roles` **无参数**，只返回 `active_zone_id` 那区；`RoleSummaryDto.zoneId` 只作展示 |
| 选区 | 新增 `POST /zones/select { zoneId }`：写 `active_zone_id`；校验区「活且未合并」，**换区时清掉在线角色**（否则 `GET /roles` 出 B 区、进图按在线角色落 A 区）。「有角色 / 可建角」的判定等区状态机（[#961](https://github.com/WebCoderT/olua/issues/961)）落地后再加 |
| 账号视图 | `AccountDto.zoneId` 删除（它是账号的最新区，不是权威）；管理端账号列表改显示「角色所在区」集合 |
| 选服数据 | 新增 `GET /zones/mine`：一次返回区 + 我的角色数 + 最近一次在线角色的区 |

**为什么上限是每区 6 个**：区是独立服，玩家在新区应当获得完整角色位；总额封顶会让"老区满了不能去新区"变成运营事故。

### 3.2 实时与世界

| 点 | 现状 | 改法 |
|---|---|---|
| 进图解区 | `accounts.findById().zone_id`（`realtime.service.ts:818/877`） | 按 `roles.findById(roleId).zone_id` |
| 跨区攻击 | 读账号区（`combat-settlement:668`） | 读在场身份 `identityOf(accountId).zoneId`（同一份权威，不再查库） |
| 维护区 | 无 | `join` 前读 `zones.status`：`maintenance`/`closed` → 拒（新错误码 `ZONE_UNAVAILABLE`） |
| 维护在线 | 无 | 世界 tick 每 5s 读一次 `zones.status`；转 maintenance → 广播 `zoneMaintenance{ inMs }`，60s 后断开该区连接；世界正常落盘 |
| 代际 | 全局 `world_meta.epoch` | 逐区 `zone_world_meta`：tick 读全表（区数个位数）比较内存 Map，只作废变化区 |

维护**不冻结世界**：冻结会让未落盘的伤害/血量停在一个说不清的状态；广播 + 倒计时断开，世界照常 tick 与落盘。

### 3.3 聊天

| 频道 | 改法 |
|---|---|
| `world` | 收件人从 `presentAccountIds()` 改为「本区在场账号」：`presence` 增加 `presentAccountIdsOf(zoneId)`（按 `identity.zoneId` 过滤） |
| `map` | 已按房间（`roomKey`），无需改 |
| `guild` | 成员同区后天然隔离；投递前仍校验「发送者区 = 帮会区」（防御性） |
| `private` | 只在本区找人（`roles.findById(identity.zoneId, toRoleId)`）：跨区与「查无此人」**同一种回复** —— 说「不同区服」等于承认这个 id 存在 |

注意：`world` 的收件人**不能按房间过滤**——它本来就是跨图频道；必须按 `identity.zoneId`。

### 3.4 组队

| 点 | 改法 |
|---|---|
| 邀请 | 目标角色必须与发起人同区，否则 `PARTY_ZONE_MISMATCH`（新错误码） |
| 接受 | 再校验一次（邀请可能跨了合区/维护切换） |
| 同图队友 | `sameMapMates(roleId, mapId)` → `sameRoomMates(roleId, roomId)`，用 `zone:map:slot` 一次比完 |
| 经验分成 | `withinShareDistance` 加 `zoneId` 与 `slot`（`presence.positionOf` 已带） |
| `locationOf` | 返回值加房号 `roomId`（`zone:map:slot`，presence 拼好），调用方不再自己拼 |

### 3.5 帮会

| 点 | 改法 |
|---|---|
| 创建 | 帮主角色区写入 `guilds.zone_id`（不接受前端传区） |
| 列表/搜索 | `WHERE zone_id = ?`（按当前角色区） |
| 申请/加入 | 目标帮会区 = 申请人角色区，否则拒 |
| 帮会频道 | 成员同区后天然隔离（3.3 仍有防御校验） |
| 帮会战（#403） | 只在本区内匹配 |
| 名字唯一 | **保持全局唯一**（`name` 仍是 UNIQUE）：跨区同名会让搜索、举报、客服沟通无法区分 |

**存量迁移口径**（Z3）：`guilds.zone_id` 按帮主角色区回填；成员角色区 ≠ 帮会区的行**删除**，并发一封系统邮件
（`role_mails` 直插，模板 `guild_zone_reset`：说明帮会已按区重组、可重新加入本区帮会）。

**合区撞名（Z8）**：`from` 区帮会整体改挂 `to` 区；若目标区已有同名帮会，改名为
`原名截断(nameMax - 后缀长) + "·" + 源区名`，后缀放不下时退化 `·z<fromZoneId>`。系统改名**绕过玩家输入长度校验**，
但总长仍截到 `nameMax`；改名清单进合并报告。

### 3.6 排行榜

| 项 | 改法 |
|---|---|
| 物化 | `Record<board, BoardSnapshot>` → `Map<zoneId, Record<board, BoardSnapshot>>`，**按需分桶**：某个区第一次被请求时才算它那一份，之后只刷已经算过的区 |
| 取数 | 设计稿原写「一次扫描按 `zoneId` 分桶」，落地改成**每区一条 SQL**（`listForLeaderboard(zoneId)` → `WHERE zone_id = ?`，走新增的 `idx_roles_zone`）。理由：分桶要先知道「有哪些区」，而区清单是运营数据（随时开区 / 合区）；「谁被请求才算谁」本身就决定了该算哪些区，比多一条 `zones` 依赖更省 |
| 名次 | 每区内竞赛排名（1、2、2、4 不变） |
| `me` | 按角色所在区取自己的名次（`RolesService.zoneOf`：在线角色的区，没有则账号的当前浏览区） |
| `topN` | 每区各截 `topN`（默认沿用现配置）—— 不是全服截完再分组，那样小区永远上不了榜 |
| 接口 | `GET /leaderboards/:board` **不收 `zoneId`**，只出当前角色区；管理端看榜走 `GET /admin/leaderboards/:board`，区取自 `X-Zone-Id`（不另收 query；缺失 / 无效 → 400 `ZONE_REQUIRED` 50029） |
| 空区 | 返回空榜（`list = []` / `total = 0` / 有 `computedAt`），不是 500 也不是 404 |
| 全服榜 | **下线**（Z4）；`zoneId` 字段保留在条目里，客户端不再混排 |

### 3.7 公告 / 邮件 / 群发

| 项 | 改法 |
|---|---|
| 公告 | `announcements.zone_id`：`NULL` = 全服；生效查询 `WHERE (zone_id IS NULL OR zone_id = ?)` |
| 登录页公告 | 没有角色 → 只取全服公告（`zone_id IS NULL`） |
| 游戏内公告 | 按当前角色区取「全服 + 本区」 |
| 管理端 | 公告表单加「投放范围：当前区 / 全服」，默认当前区；「全服」是影响面权限（`announcement:publish-all`，SUPER 持有），与区可见性无关 |
| 群发 | [#438](https://github.com/WebCoderT/olua/issues/438) 的筛选条件加「按区」，SQL join `roles.zone_id`；批次模型不变 |
| 邮件 | 角色邮件天然按区（`role_mails.role_id`）；账号级邮件（封禁通知）不分区 |

### 3.8 管理端单区上下文

> 口径（Z6 / Z12）：**不绑区**。一个超管、一个客服、一个只读观察员，能看到的区集合完全一样 = 全部。
> 唯一的约束是「一次只在一个区里干活」。

| 项 | 改法 |
|---|---|
| 不绑区 | **不建 `admin_zones`，不做可见集**。所有管理员都能切到任意区（含 `closed` 区，便于查历史） |
| 区必填 | `X-Zone-Id` 必填；缺失或区不存在/已合并 → 400 `ZONE_REQUIRED`。**没有「全部区」这个值**（白名单接口除外，见本节末） |
| 守卫 | `ZoneContextGuard`：只做「区存在吗」的校验，把 `zoneId` 放进 `request.zoneId`；**不判资源归属**（那是各 service 的事） |
| 列表 | 一律 `WHERE zone_id = :current`；账号列表用 `EXISTS(roles … zone_id = :current)`，只出本区有角色的账号 |
| 详情 | 账号详情只列当前区角色；别区折叠成「另在 N 个区有角色」，点切换再展开 |
| 写操作 | 目标资源区 ≠ 当前区 → **404**（防"列表是 A 区、id 是 B 区"的错点）；不做权限判断 |
| 账号级操作 | 封禁 / 改密 / 删号仍作用在账号上（影响所有区），提交前弹确认并写明「该账号在 N 个区有角色」 |
| 审计 | `audit_logs.zone_id` = 当前请求区；账号级操作照记（便于「这个客服在几区干过什么」） |
| 登录页 | 管理端登录表单加「区服」下拉（数据来自 `GET /admin/auth/zones`，`@Public`，只回 id/name/status/sort，含已关闭区）；**未选区不能登录** |
| 登录后切换 | Layout 顶栏常驻区切换器；切换只换 `X-Zone-Id` 并重拉当前路由数据，**不整页跳登录** |
| 注入点 | `admin/src/api/http.ts` 的统一请求拦截器统一带 `X-Zone-Id`（读 session store）—— 页面不各写一份，否则迟早有页面忘带 |
| 记住选择 | 上次选区存 localStorage + 服务端 `admins.last_zone_id`（换浏览器也一致）；区被合并时回退到第一个活区 |

**为什么写操作跨区给 404 而不是 403**：这里不是权限问题（他本来就能看那个区），是**上下文不一致**。
404 让「A 区页面 + B 区 id」这种拼接请求直接失败，而不是悄悄改到另一个区去。

**为什么不绑区**：已拍板「一个账号可以查看所有区的信息」。内部工具靠审计与实名追责，
行级隔离会让「客服临时帮另一个区看一眼」变成配置工单，收益远小于成本。
重开条件：出现跨区误操作导致的数据事故，且审计无法定位责任人。

**不需要区上下文的接口**（白名单，必须显式登记，否则守点会红）

| 类别 | 接口 | 理由 |
|---|---|---|
| 区目录 | `admin/zones`（列表 / 开区 / 合并 / 改状态） | 它本身就是全区的清单 |
| 管理员 | `admin/admins`、`admin/auth` | 账号级，不属于任何区 |
| 系统与外观 | `admin/system`、`admin/ui-effects`、`admin/audio-settings` | 全局设置 |
| 游戏配置 | `admin/items`、`admin/equipments`、`admin/skills`、`admin/monsters`、`admin/quests`、`admin/mall` 等全部 `game-config` 接口 | 配置全区共享，按区覆盖见「七、暂时放置」 |
| 审计 | `admin/audit-logs` | **刻意跨区**：追责要看"这个人在哪些区干过什么"。支持可选 `?zoneId=` 筛选，无筛选 = 全部 |

### 3.9 区服运营

**状态机**

```
open ──维护──▶ maintenance ──恢复──▶ open
  │                 │
  └──────关闭───────┴──▶ closed（不可逆）
```

| 状态 | 注册 | 登录 | 进图 | 选服弹窗 |
|---|---|---|---|---|
| `open` | ✅ | ✅ | ✅ | 正常 |
| `maintenance` | ❌ | ❌（提示维护中） | ❌ | 置灰 + 「维护中」 |
| `closed` | ❌ | ❌ | ❌ | 不显示 |

**区服列表聚合**（管理端）：账号数（该区有角色的去重账号）、角色数、在线数、世界实例数、帮会数、待处理重载数。
**开区表单**：区名 / 开服时间 / 排序 / 推荐 / 备注；区名仍 1~20 字唯一。

### 3.10 合区的完整清单

**事务外预检**（不通过就不让点「合并」）

1. `from` / `to` 都是 `open`，且不是同一个区
2. `from` 区在线人数 > 0 → 提示「在线玩家会被断开并回到登录」
3. `from` 区 pending 重载请求数 → 提示「会作废」
4. 帮会撞名预检 → 列出将被改名的帮会清单

**事务内**（一个事务，失败整体回滚）

| 步 | 动作 |
|---|---|
| 5 | `roles.zone_id` from → to（三列唯一索引在新键下复核） |
| 6 | `world_monsters` 重排发牌（现有逻辑，续序不重号） |
| 7 | `guilds.zone_id` from → to；撞名按 3.5 改名 |
| 8 | `world_reload_requests`：from 区 pending → `failed`（detail = `zone_merged`） |
| 9 | `map_monitor_state` / `map_monitor_events`：删 from 区（运行时投影，无需保留） |
| 10 | `role_positions`：删 from 区角色（角色换区后旧坐标失效） |
| 11 | `zones.markMerged(from → to)` |
| 12 | `zone_world_meta`：from / to 各 +1，**其他区不动** |

**事务后**

13. 断开 from 区在线连接（`zoneMerged` 帧 → 客户端回登录并提示「本区已并入 X 区」）
14. 写审计 + 合并报告（账号 / 角色 / 实例 / 帮会 / 改名清单 / 作废请求数）

## 四、迁移

> 表结构变更走 `DatabaseService` 启动时的 `ensureColumn` / `exec`（幂等，现网升级即执行）；
> `make migrate` 只管**存档 data.schemaVersion**（见 [33](./33-存档与账号设计.md) I2），两者不要混。

| 序 | 迁移 | 要点 |
|---|---|---|
| M1 | `roles.zone_id` + 回填 | `UPDATE roles SET zone_id = COALESCE((SELECT active_zone_id FROM accounts WHERE accounts.id = roles.account_id), 1)`（回填在 M8 改名之后，或按旧列名跑一次） |
| M2 | 唯一索引替换 | 先 `DROP INDEX idx_roles_account_name`，再建三列唯一索引；建前查重（沿用 `ensureRoleNameUnique` 的"先查后建、报错不崩"策略） |
| M3 | `guilds.zone_id` + 回填 | 按帮主角色区回填；删跨区成员（`guild_members`），插系统邮件 |
| M4 | `zones` 新列 | `status='open'`；`opened_at = created_at`（一区 `created_at=0` 保持 0，运营可改） |
| M5 | `zone_world_meta` | 建表，用当前 `world_meta.epoch` 初始化**所有活区**一行 |
| M6 | `admins.last_zone_id` + `audit_logs.zone_id` | 加两列；**不建 `admin_zones`**（Z6）；存量 `audit_logs` 不回填（历史操作本来就没区上下文） |
| M7 | `announcements.zone_id` | 默认 `NULL`（存量全部当全服公告） |
| M8 | `accounts.zone_id` → `active_zone_id` 改名 | `ALTER TABLE accounts RENAME COLUMN zone_id TO active_zone_id`；**与 M1 同批**（先改名、再回填）；改名后 `grep -rn "accounts.*zone_id"` 应归零 |

M1 与 M8 是**同一步的两半**：先改名，回填语句才能用 `active_zone_id`。分两次跑会出现「列名对不上」。

迁移必须**可重复执行**：每一步先查列/表是否存在，回填用 `COALESCE`，不依赖上一次的副作用。

## 六、验收

**e2e（全部双区播种）**

| 套件 | 断言 |
|---|---|
| `e2e-zone-no-param` | **玩家侧每个读接口都带 `?zoneId=<别区>` 打一遍**：返回内容与不带完全一致（参数被忽略，不是「按参数查」）；所有以 `roleId` / `guildId` 为入参的写接口指向别区对象时 **404** |
| `e2e-zone-roles` | 两区各建 6 角；第 7 个 400；同名跨区允许、同区拒绝；`/roles` 只返回会话区；`/zones/select` 到无角色且不许建角的区被拒 |
| `e2e-zone-chat` | 1 区 world 帧不进 2 区连接；跨区 private 拒；同区照旧 |
| `e2e-zone-party` | 跨区邀请拒；跨区同 `mapId` 不分成；同区同房分成照旧 |
| `e2e-zone-guild` | 创建绑区；跨区申请/加入拒；列表只本区；迁移后跨区成员被移出 |
| `e2e-zone-leaderboard` | 两区各 3 角色，榜只含本区；`me` 名次正确 |
| `e2e-admin-zone-context` | 不带头 → 400 `ZONE_REQUIRED`；头里区不存在/已合并 → 400；A 区列表不含 B 区角色；账号详情只列 A 区角色；切到 B 后同一接口数据变；带 A 区头去改 B 区角色 → 404；同一管理员能切任意区（不绑区） |
| `e2e-zone-merge` | 角色/帮会/实例搬迁；撞名改名；reload 请求作废；监控清理；**其他区 epoch 不变** |

## 八、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 单进程下漏一处过滤 = 跨区可见 | 所有区共享一个实时进程与内存表 | 每个跨区点都配双区 e2e；code review 清单按「读 `zoneId` 了吗」过 |
| 排行榜内存 × 区数 | 每区一份全量索引 | 角色总量不变，索引是同一批对象分桶；区数到两位数再评估懒加载 |
| 合区后在线玩家漂移 | 连接里的在场身份还停在旧区 | 事务后强制断开 + `zoneMerged` 帧；重连按角色新区进图 |
| `active_zone_id` 被当权威读 | 名字里还有 zone，容易有人拿它判归属 → 跨区误判 | 注释与守点双保险：只认 `roles.zone_id`；`accounts` 的列只出现在选服/选角两处 |
| 旧客户端仍带 `zoneId`（注册 / 查询参数） | 旧包把 `?zoneId=` 拼在 URL 上或注册时提交 `zoneId` | 服务端**忽略**且不报错（避免旧包白屏）；建角响应回显实际落入的区；发版后统计这类请求应归零 |
| 帮会改名超长 | `nameMax` 是小配置 | 截断 + 后缀降级 `·z<id>`；改名清单给运营复核 |
| 迁移锁库 | 帮会成员清理 + 邮件批量插 | 分批 500 行一个事务；迁移窗口选低峰 |

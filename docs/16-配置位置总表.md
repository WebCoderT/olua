# 16 · 配置位置总表

> 这一篇只回答一个问题：**某个配置项，我在哪儿改？**
>
> 之所以单独成篇：**38 张配置表 ≠ 38 个页面**。有的页面一次改好几张表，有的一张表被两个页面
> 改不同列，有的表压根没有页面（只能改库），还有一批配置根本不在库里（客户端 `.ts`、
> 环境变量、代码常量、地图 TMX）。按「表名找页面」会走丢，按「页面找表」会漏入口 ——
> 所以两个方向都列，再加一节专门写**藏在弹窗里的入口**。

---

## 一、配置有五个来源，不是一个

先立好框架，后面所有「在哪改」都是这五类之一。

| # | 来源 | 谁能改 | 典型内容 | 生效方式 |
|---|---|---|---|---|
| **A** | **数据库 38 张配置表** | 管理端 46 个页面文件（含登录 / 注册 / 详情页；侧栏叶子 42 个） | 装备 / 怪物 / 掉落 / 任务 / 地图 / 参数 | 见第五节（4 种） |
| **B** | **客户端 `assets/configs/*.ts`（28 个）** | 改代码 + 重打客户端包 | 布局 / 文案 / 颜色 / 动画 / 网络地址 | 重打包 |
| **C** | **环境变量**（`server/.env` 73 项） | 改文件 + 重启进程 | 端口 / 密钥 / 数据库路径 / 刷新间隔 | 重启 |
| **D** | **代码常量** | 改代码 + 发版 | 等级上限、派生比例、「上限」类校验 | 发版 |
| **E** | **地图 TMX 文件** | Tiled 编辑 + 重新导出 | 地图尺寸 / 图层 / 可行走区域 | 重打资源包 |

**判据口诀**（拿到一个想改的东西，按顺序问）：

```
① 运营在游戏里能感知到数值变化吗？
   能 → 进快照或进服务端结算 → 在库表里（A），继续问第五节「多久生效」
② 只是界面长相 / 文案 / 颜色？
   是 → 客户端 configs（B）
③ 跟这台机器 / 这个部署有关（IP、端口、密钥、路径）？
   是 → 环境变量（C）
④ 是「上限」「比例」「兜底值」这类不该让人随便改的？
   是 → 代码常量（D）
⑤ 是地图形状本身？
   是 → TMX（E）
```

📌 **`C` 与 `D` 的界线值得记一下**：`ROLE_LEVEL_MAX`（一千万级上限）、`mpOfHp = 0.5`、
`hpRecoverOfHp = 0.01`、`floorOfMax = 0.7` 这几个是**故意不开放**的 —— 它们不是「懒得做页面」，
是一改就会让整条数值链失去意义（详见 [09](./09-成长与养成.md)）。

每一行五项：**表名 · 条数（本机实测） · 导航路径 · 路由 · 生效码**。
导航路径按侧栏的真实层级写（`组 / 小节 / 页面`），因为侧栏是全展开的，照着点就对了。

## 四、隐藏入口：不在侧栏、在弹窗或行内按钮里

这是最容易「以为没有」的一类。**2026-11 有人报过「怪物掉落绑定在管理端看不到」** ——
他去翻了「掉落配置」页，而那一页确实没有绑定字段。

### 4.1 掉落相关（三个不同位置，三件不同的事）

| 想配什么 | 位置 | 字段 | 写哪 |
|---|---|---|---|
| 这张掉落表里有哪些东西、权重、数量 | 战斗配置 / **掉落配置** | 条目编辑器 | `drop_tables.entries` |
| 某只怪用哪张表 / 内联条目 / 掉落几件 | 怪物配置 → 行内「**掉落**」按钮 | 来源三态 + 条目 | `monster_drops` |
| 这只怪掉的东西**全部绑定** | 同上，弹窗顶部 | 「掉落整体强制绑定」→ `bind_drops` | `monster_drops.bind_drops` |
| 这件装备一掉出来就绑定 | 装备配置 → 列表「**掉落绑定**」列（第 9 列）/ 编辑弹窗 | `bindOnDrop` | `equipments.bind_on_drop` |
| 全局**随机**绑定概率 | 运行时参数 → 掉落手感与绑定 | 「随机绑定概率（%）」→ `bindChance` | `runtime_params.drop_params.bindChance` |

📌 **「掉落配置」页里没有绑定，也没有 `monster_drops`。** 它只管 `drop_tables`（5 张具名表）。
怪物掉什么、绑不绑定，全在**怪物配置**页的行内按钮里。

📌 **三条判定是「或」**：`monsterBind || bindOnDropOf(基础件) || rand()*100 < bindChance`。
所以「三处都没配」时掉落物永远不绑定 —— 界面上不会出现「已绑定 · 不可交易」，也不会有溯源三行。
这是**配置结果**，不是显示 bug（详见 [05](./05-装备链路.md) 绑定三规则、[06](./06-物品与背包.md) 溯源展示）。

📌 **绑定没有「条目级」开关**：`DropEntryDto` 只有 `goodId` / `weight` / `chance` / `count`。
做不到「这只怪的 A 装备绑定、B 不绑定」。要细粒度只能拆成两只怪 / 两张表。

### 4.2 怪物配置页的三个弹窗

| 弹窗 | 触发 | 改什么 |
|---|---|---|

### 4.3 地图管理页的七个弹窗

一个页面七件事，全靠顶部按钮切换（`DialogKey`：`layers` / `points` / `spawn` / `collisions` /
`monsters` / `sources` / `monitor`）：

| 弹窗 | 改什么 | 表 / 接口 |
|---|---|---|
| 图层 | 地图显示哪些层 | `maps`（`PATCH /admin/maps/:id`） |
| NPC 点 | 地图上摆 NPC | `map_npcs` |
| 刷怪区 | 在哪儿刷、刷什么、刷多少 | `map_spawn_areas` |
| 碰撞 | 可行走矩形 | `map_collisions`（1538 个盒子） |
| 世界怪物 | **只读**：现在这只怪在哪、血多少 | `world_monsters`（投影，不可改） |
| 怪物来源 | 只读：这张图的怪从哪个区来的 | `map_spawn_areas` 反查 |
| 实时监控 | 只读：`staleMs` / 分区 / 光标 | `map_monitor_state` |

### 4.4 装备配置页的变体入口

`equipment_variants`（10275 行）**不是手填的**，是基础件 × 15 组合展开出来的：

| 操作 | 位置 | 影响 |
|---|---|---|
| 改单条变体的属性 / 售价 | 装备配置 → 行内「变体」 | 只改这一行（运营微调） |
| 全量重建 | 装备配置 → 顶部「重建变体」 | 按 `equipment_meta` 倍率重算**全部**（会覆盖手调） |

⚠️ 重建是覆盖式的。手调过某条变体后再点重建，那条会被算回去。

### 4.5 前后缀页为什么同时写两张表

`/equipment-tiers` 改 `equipment_meta` 的档位（5 前缀 × 3 后缀 = 15 组合），而
`equipment_appearance` 的边框 / 背景是按**「前缀|后缀」键**存的。档位加减后映射表要跟着补键，
所以这一页同时 import 了 `equipmentMetaApi` + `equipmentBorderApi` + `equipmentBackgroundApi`。
**这也不是重复实现** —— 改档位不补外观键，那几档就没有边框（回落默认）。

## 五、生效方式：四类，以及「多久」

同一句「我改了怎么没反应」，答案取决于这张表走哪条通道。

### 5.1 四类通道

```
写库（管理端保存）
  │
  ├─ A1 进服务端结算缓存 ──────────► 存档进程：立即（写操作后 refreshAll）
  │   （13 张表 + combat_weights）   实时进程：≤10s（定期重装，跨进程没别的办法）
  │                                 AI 相关：≤1s（SKILL_CACHE_TTL_MS）
  │
  ├─ A2 只走快照 ─────────────────► 客户端进程内只拉一次 → 玩家重进游戏
  │   （32 段里的其余部分）
  │
  ├─ A3 独立接口 ─────────────────► 每次进图拉一次（内观还多一次「开弹窗就拉」）
  │   （equip_aligns / equip_in_aligns / equipment_appearance）
  │
  └─ A4 世界状态 ─────────────────► 已生成的怪不回溯：重播种 / 重启
      （map_spawn_areas 对已存在分域）
```

### 5.2 A1：进服务端结算缓存的 13 张表

`RuntimeConfigService.refreshAll()` 装的就是这份清单（改这张表要一起看它）：

```
equipments → equipment_slots → equipment_variants → role_level_curves
titles → souls → ranks → skills → drugs → items → money_items
level_scrolls → growth_scalars
```

外加 `combat_weights`（由 `CombatWeightsService` 自己装，不在 refreshAll 里 —— **加新表时容易漏这一处**）。

**为什么必须装**：服务端结算走的是**纯函数**（`combat/role-attributes` 拿不到 Nest 注入）。
不装这一层，管理端改的装备/称号/战魂只在客户端生效，服务端还按旧值算 —— 面板 20、实际按 10 算，
而且**没有任何报错**。

**跨进程怎么同步**：管理端的写操作发生在存档进程（3100），`refreshAll()` 只刷自己进程。
实时进程（3101）靠 `realtimeConfigRefreshMs`（默认 **10000ms**）定期重装，`0` 可关。

### 5.3 A2：快照 32 段

`GET /game-config` 返回 32 段，客户端**进程内只拉一次**（`ConfigLoader` 拉完就 `ok:true` 进游戏）。
所以这一类「改完必须重进游戏」—— 退到选角界面**不算**，要进程重启。

判据（[01](./01-总览与架构.md) 里那条）：**验收动作是「保存 → 退回选角再进图」吗？**
是 → A2；不是（要重进一张图）→ A3。

### 5.4 A3：独立接口的三条

```
GET /game-config/equip-align            装备对齐几何
GET /game-config/equip-in-align         内观对齐几何
GET /game-config/equipment-appearance   边框 / 详情背景（快照里也有一份，这里给「换装即刷新」）
```

这三样的共同点：**数据量不小、改动后要立刻看到**。对齐工作台一次要 32 行几何，
放进 32 段的快照里会让每次登录都多背一份，而它其实只在进图时才用得上。

📌 `equipment_appearance` 是**唯一两条通道都走的表**（A2 + A3）。改完边框如果不想重进游戏，
退出重进一张图即可。

### 5.5 A4：世界状态不回溯（唯一需要「重启级」动作的一类）

`map_spawn_areas` 改了之后：

| 你期待 | 实际 |
|---|---|
| 改完立刻按新区刷 | ❌ 已经播种过的分域不会重播（`zone:mapId` 里已有怪就跳过） |
| 清空某张图的怪再进图 | ✅ 会按新区重播 |
| 重启实时进程 | ✅ 全部按新区重播 |

这是 **#669 记录在案的未收口项**：没有「刷怪区保存后强制重播种」的接口。
详见 [08](./08-世界与怪物.md) 的「改了刷怪区何时生效」表。

**掉落、怪物属性、技能挂载都不属于 A4** —— 击杀时现查库（掉落）/ 1s TTL（AI），改完立刻对。

### 5.6 一张「多久生效」的速查

| 改了什么 | 谁来验 | 等多久 |
|---|---|---|
| 装备属性 / 回收价 / 变体 | 进图打怪 / 看面板 | 立即（存档进程）+ ≤10s（实时进程算属性） |
| 掉落表 / 怪物掉落 / 绑定 | 打死一只怪 | **立即**（击杀现查库，不用等） |
| 怪物 AI 参数 / 技能挂载 / 状态 | 看怪的行为 | **≤1s** |
| 等级曲线 / 成长标量 | 升级一次 | 立即（存档进程） |
| 称号 / 战魂 / 军衔 / 药品 / 货币 / 卷轴 | 用一次 | 立即（存档进程） |
| 战斗力权重 | 看战力 / 进图门槛 | 立即 + ≤10s |
| 任务 / 成就 / 时装 / 商城 / 物品 / NPC / 地图玩法 / 特效 / 音效 / 引导 | 重进游戏 | 客户端进程重启 |
| 边框 / 详情背景 | 退出重进一张图 | 一次进图 |
| 装备对齐 / 内观对齐 | 退出重进一张图 | 一次进图 |
| 刷怪区 | 清怪 / 重启实时进程 | 不自动（#669） |

## 六、只能改库的配置（管理端没有入口）

真实存在，且**不是设计意图，是缺口**。

| 配置 | 位置 | 为什么没页面 | 怎么改 |
|---|---|---|---|
| `runtime_params.monster_ai` | 库，第 4 个 JSON 列 | `RuntimeParamsDto` 只声明了 `drop` / `autoBattle` / `guild` 三组 | 直接改库（见下） |
| `equipment_meta.prefix_colors` / `suffix_colors` | 库，两个 JSON 数组 | 前后缀页只开放倍率与文案（`rates` / `labels`），颜色没做编辑器 | 直接改库；空数组 = 用默认白（[05](./05-装备链路.md)） |
| `map_monitor_state` / `map_monitor_events` | 库 | 监控投影，重启可丢 | 不用改 |

`monster_ai` 里的实际键（缺键回落 `FALLBACK_AI` 常量并 warn）：

```json
{"attackInterval":2000,"attackRange":60,"idleMoveInterval":[4000,9000],
 "idleMoveDuration":[300,800],"idleMoveSpeedScale":0.5,"wanderRadius":60,
 "attackActionTime":400}
```

**直接改库的两条纪律**（踩过）：

```bash
# 1. 改之前先 checkpoint，否则你改的是 -wal，拷库/导出会拿到旧值
sqlite3 server/data/olua.db "PRAGMA wal_checkpoint(TRUNCATE);"

# 2. JSON 列用 json_set，别整串替换（手写容易漏键、丢类型）
sqlite3 server/data/olua.db \
  "UPDATE runtime_params SET monster_ai=json_set(monster_ai,'\$.wanderRadius',80) WHERE id=1;"
```

⚠️ **改完别顺手 `make config-export`**。如果你手上还有别的未导出改动，导出会把它们一起带出去，
diff 里几千行分不清哪行是你这次改的。正确做法是先 `make config-check` 看差异范围（[13](./13-部署运维与质量门禁.md)、
[15](./15-数据表清单.md) 第六节）。

| `ROLE_LEVEL_MAX` | `10_000_000` | `modules/roles/role-data.util.ts` | 硬上限即校验门槛，配合曲线外推 |

| 处 | 值 | 位置 | 作用 |
|---|---|---|---|

`ROLE_LEVEL_MAX` 与 `SPECS.max` 曾经就不是一个数（这条踩过）。

### 7.4 地图 TMX（来源 E）

真实路径是**每张图一个目录**（目录名 = `maps.map_id`）：

```
client/assets/resources/map/<id>/<id>.tmx      ← 地图本体（尺寸 / 图层 / 图块数据）
client/assets/resources/map/<id>/<name>.tsx    ← 图块集定义
client/assets/resources/map/<id>/<name>.jpg    ← 图块贴图
client/assets/resources/map/<id>/preview.jpg   ← 预览图
```

TMX 里装的是：地图尺寸（`width` / `height` / `tilewidth`）、图层列表、图块数据。
库里的 `maps` 表**只有玩法配置**（名称 / 类型 / 进入条件 / 复活点 / 怪源）。

所以：
- 改「这张图多大」→ Tiled 改 TMX → 重新导出 → 重打资源包
- 改「进这张图要几级」→ 管理端地图管理 → 保存
- 改「这张图哪里不能走」→ 管理端地图管理的「碰撞」弹窗（**不改 TMX**）

⚠️ **`resources/` 不入 git**（客户端单测要真实素材，所以素材走资源包发布而不是仓库）。
`git ls-files client/assets/resources/map` 返回空是正常的。改 TMX 的交付路径是
`make resources-manifest` → `resources-pack` → `resources-upload`（[13](./13-部署运维与质量门禁.md)），
不是提交。

## 八、四张「看起来像配置、实际不是」的表

混淆它们会做出错误判断（尤其是「我改了怎么没生效」和「这数据怎么跟着 git 走了」）。

| 表 | 它是什么 | 为什么容易误会 | 纪律 |
|---|---|---|---|
| `roles` / `roles.data` | **玩家存档**（九类字段，含背包穿戴） | 里面全是「数值」，看着像配置 | 改它 = 改某个玩家。走 [04](./04-角色与存档权威.md) 的权威规则 |

| `world_monsters` | 世界状态的**投影**（206 行 = 此刻图上有哪些怪） | 看着像怪物配置 | 权威在实时进程内存，这张表是落盘投影 |
| `audit_logs` | 审计日志 | — | 只增不改 |

配套的一条：**配置表 / 运行时表的分类是硬清单**
（`server/scripts/lib/config-tables.cjs` 的 `CONFIG_TABLES` / `RUNTIME_TABLES`），不是按前缀猜的。
`assertAllClassified()` 在导出时全量比对，**多一张未分类的表就当场报错**。
`roles` 在运行时表里 —— 所以玩家存档永远不会跟着 git 走。

## 九、排障表

| 症状 | 第一嫌疑 | 查法 |
|---|---|---|
| 页面上**找不到**某个字段 | 入口在别的页面 / 弹窗（第四节） | 先在本文第二节按表名查「导航路径」，再查第四节「隐藏入口」 |

| 某档前后缀没有边框 | 改档位后没补 `equipment_appearance` 的键 | 4.5；去「装备边框」页补键 |
| `runtime_params` 查 `value` 列报错 | 它是四个 JSON 列 | 第二节 2.4 的表 |
| 邮件 / 公告 / 任务改了要重启吗 | 它们走 A2 | 重进游戏 |
| 客户端改了 `items.ts` 没生效 | 它被快照覆写（7.1 第一类） | 去库改，别改本地 |
| `make config-check` 常红 | 本地库有未导出的运营改动 | 正常现象；别在此时 `config-export`（第六节） |

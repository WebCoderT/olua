## 一、四个结构性问题

### 1.1 事件驱动导致频率不稳

位置帧「变了就发」，所以：站着不动 → 0 帧；一直跑 → 每秒 20+ 帧。
带宽峰值不可预测，而且**接收端无法用固定节奏插值**（不知道下一个包什么时候来）。

### 1.2 帧里带全量字段

每条 `players` 帧都带昵称、外观、状态、血量…… 10 人同图时，
一帧可能 2~3KB，10Hz 就是 30KB/s/人。

### 1.3 没有服务器时间基准，插值只能靠本地猜

客户端收到位置后自己做缓动，不知道「这个位置对应哪个服务器时刻」，
所以网络抖动时会出现「卡顿—追赶—再卡顿」。

### 1.4 全图广播，人一多就爆

没有 AOI，一张图 50 人时每人每秒收 50 份位置更新。这是 #772 里最贵的一条。

## 二、目标形态

### 2.1 10Hz 定频 + 帧内只带变化

| 项 | 规则 |
|---|---|
| 位置上报 | 客户端 **10Hz（100ms）** 上报，无论是否移动（静止也发心跳位置，便于服务端判定「在线且在图上」） |
| 服务端广播 | 同样 **10Hz** 定频，一帧打包「本 tick 内所有变化实体」 |
| 变速 | 移动速度 > 阈值（如 600px/s）时临时提到 **20Hz**（防高速穿模），持续 1 秒后回落 |
| 帧瘦身 | 只发**变化的字段**：位置变化发 `x,y`；血量变化发 `hp`；外观变化才发 `appearance` |
| 完整帧 | 每 **5 秒**发一次全量（防止 diff 累积漂移），或收到 `resync` 请求时发 |

**为什么静止也要发**：服务端要靠位置帧判断「这个人还在图里」。
不发的话，只能靠 WS 心跳，而心跳不在地图维度上 —— 会出现「人在线但不在地图上」的模糊态。

### 2.2 服务器时间基准 + 快照插值

```
服务端每帧带 serverTime（毫秒，单调递增）
客户端维护 offset = serverTime - localTime（滑动平均，去掉异常值）
渲染时用 renderTime = localNow + offset - interpDelay（interpDelay 默认 100ms = 1 个 tick）
在缓冲里找 renderTime 前后的两个快照，线性插值
```

| 项 | 规则 |
|---|---|
| 缓冲深度 | 保留最近 **500ms**（5 帧） |
| 插值延迟 | `interpDelay = 100ms`（一个 tick，保证总有「未来帧」可插） |
| 追赶 | 偏差 > 300ms 时**直接瞬移到最新**（不慢慢追，否则会看到人物滑行） |
| 时钟漂移 | `offset` 每秒重算一次，用中位数而非均值（抗单次抖动） |

### 2.3 AOI 裁剪（与 20 篇共用）

- 格子 **512px**，查 9 邻格（20 篇已定）；
- 广播出口改成「按格子分组，只发给同格及邻格的人」；
- 进入/离开视野要发 `entityEnter` / `entityLeave`（20 篇第②刀），**不能只靠 diff** ——
  否则离开视野的人会「留在屏幕上不动」。

### 2.4 按区分片（已定：按 zone）

| 项 | 规则 |
|---|---|
| 分片键 | `zoneId`（区服） |
| 进程 | 一区一实时进程（同进程可承载多个**空图**，但一个区只在一个进程里） |
| 路由 | 登录/取票时按 `account.zone_id` 返回对应分片的 WS 地址 |
| 跨片 | **不存在**（同区所有人在同一进程，跨区本来就不能互见） |
| 扩容 | 单区到瓶颈时，只能「垂直扩」或把该区按地图再分子片（后者要跨进程广播，暂不做） |

> **这改掉了 #770 的原口径**：原计划「按地图分片」，但按地图分片会引入
> 「同区不同图的人在两个进程」的跨进程广播（世界频道、帮会频道、全服公告都要跨）。
> 按区分片没有这个问题，代价是单区上限受单进程限制。**#770 需要按本篇改正文。**

### 2.5 帧预算

| 场景 | 目标 |
|---|---|
| 同屏 20 人 + 50 怪 | 单帧 < 3KB，10Hz 下 < 30KB/s |
| 同屏 50 人 + 200 怪 | 单帧 < 8KB，10Hz 下 < 80KB/s（需要 AOI 才能达到） |
| 超预算时 | 降级顺序：怪物位置 → 其他玩家位置 → 其他玩家血量 → 自己的状态（**自己的永远不降**） |

### 2.6 位置校验与寻路（#811 已落地）

三道闸，全部在**实时进程**里，客户端零决策：

| 道 | 判据 | 失败 | 出口 |
|---|---|---|---|
| ① 速度 | `dist > maxSpeed × tolerance × Δt + jitterPx + credit` | `reason = "speed"` | 拒帧 + 回 `posCorrect` |
| ② 穿墙 | 扫掠 AABB（线段-矩形精确相交，Liang-Barsky） | `reason = "wall"` | 拒帧 + 回 `posCorrect` |
| ③ 寻路 | 客户端发 `pathFind`，服务端 A* 算完回 `path` | `unreachable` / `snapped` | 只回执，不拒帧 |

**`maxSpeed` 是全局尺子，不是「抄客户端的移速」**：服务端**没有**角色移速属性 ——
移速只存在于客户端刚体（`ROLE_WALK_SPEED=2` / `ROLE_RUN_SPEED=4`，按 PTM 32 折算约 64 / 128 px/s）
和怪物 `move_speed` 里。出厂 `maxSpeed = 400` 留了 3 倍余量给「网络抖动 + 客户端预测 + 未来加速道具」，
`dt` 本身再夹到 `[0, 5s]`。

**三档 `mode`**（`runtime_params.movement.mode`，热切，下一次判定即生效）：

| 档 | 行为 | 用途 |
|---|---|---|
| `off` | 直接放行，连判都不判 | 回滚开关。**读不到配置时的兜底也是 `off`** —— 配坏了不该全服拦人 |
| `log` | 照判、照接受，只记 60 秒一行 warn | **出厂档**。先看真实玩家会不会被误判，再升 `enforce` |
| `enforce` | 拒该帧 + 回 `posCorrect` | 生产档 |

**合法大位移只有三个出口**，都**不**靠「连发两帧」：

1. **换图** —— `join()` 重置基线（`trustedX/Y/At`、`posCredit` 归零）；
2. **复活** —— `hp` 从 `≤0` 变 `>0` 那一帧一律接受。复活走存档进程 HTTP，实时进程**不会被告知**，
   判速度必然误杀；
3. **突进技能** —— 施法帧带落点 → 一次性 `posCredit`，上界 `CAST_DISPLACEMENT_MAX = 320`，
   且**只在结算成功之后**给（写在结算之前等于「报个远点就换一次瞬移，冷却都不用等」）。

**回拉回的是上一次被接受的坐标**（`entry.x/y`），不是「把本帧夹到上限」：
夹出来的点可能落在墙里，而且会让作弊者每帧白赚一段距离、贴着上限蹭墙。

**两端同一张网格**：服务端 `MapGeometryService.buildGrid` 与客户端 `PathGrid.stampRect` 逐行对齐
（按 `clearance` 外扩、按**格子中心**落盒判定、`originY = -height`、octile 启发、禁切角、
起点 4 圈 / 目标 6 圈吸附、`cellSize/2` 视线采样拉直）。格子口径**复用**
`runtime_params.auto_battle.cellSize / clearance`（40 / 20），不另开一套。

**客户端降级**：本地 A* 保留作**即时预判**（点了就走，不等回执），服务端 `path` 帧到达后按 `seq` 替换路点；
`seq` 对不上直接丢。`posCorrect` 到达时：< 64px 记目标做插值、≥ 64px 瞬移，两档都先 `stopRigidBody()`，
并作废当前路点（否则会继续朝着旧目标走）。

## 五、边界情况

| # | 情形 | 期望 |
|---|---|---|
| 1 | 客户端 200ms 内没发位置 | 服务端保留最后位置，不判离线（离线由 WS 心跳判） |
| 2 | 客户端发了超出移动速度的位置 / 穿墙 | 由 [#811](https://github.com/WebCoderT/olua/issues/811) 的三道校验处理（**已落地**，见 2.6）；本层只转发。被拒时服务端自己回 `posCorrect` |
| 3 | 插值缓冲空了（丢包） | 用最后一帧外推，最多外推 200ms，然后停住等新帧 |
| 4 | `offset` 突然跳变（时钟被改） | 中位数过滤 + 单次跳变 > 1s 时重置缓冲 |
| 5 | 传送后位置突变 | 服务端发 `teleport` 标记，客户端**清缓冲直接置位**（不插值） |
| 6 | 玩家进入视野 | `entityEnter` 带全量（位置/外观/血量） |
| 7 | 玩家离开视野 | `entityLeave`；客户端**立即移除**节点（不留残影） |
| 8 | 全量帧与 diff 帧乱序到达 | 用 `t` 排序；`t` 比当前缓冲最新的还旧 → 丢弃 |
| 9 | 分片切换（区服迁移） | 客户端重连（WS 地址变了），不需要无损切换 |
| 10 | 单区超过单进程上限 | 记告警；短期靠降级（减少广播频率到 5Hz），长期靠「按地图子分片」 |
| 11 | 世界频道跨图 | 按区分片后**同进程**，直接遍历所有连接即可（不跨进程） |
| 12 | 帧预算超限 | 按 2.5 的降级顺序丢字段，**不整帧丢弃** |

| 给怪物做服务端 A* | 怪物仍只走 `slideMove` + `clampToMap`（直线 + 卡住重选） | 出现「怪物在复杂地形里卡住」的实测投诉，且 A* 单次耗时压到 1ms 以内 |
| NPC / 动态障碍烙进寻路网格 | 网格只烙 `map_collisions` 静态盒 | 出现「玩家能穿 NPC 走过去」的实测；现在烙了会让刷怪区与运镖路线全变（NPC 可挪，网格 5 秒 TTL 跟不上） |
| 把 `MapGeometryService` 与 `MonsterAiService.geometryOf` 合并 | 暂时各一份（AI 侧那份带缓存与告警，本份带 TTL 与网格） | 两边第二个消费方出现时再合（现在合要改 AI 的缓存语义，收益不抵） |

## 一、四个结构性问题

### 1.1 事件驱动导致频率不稳

位置帧「变了就发」，所以：站着不动 → 0 帧；一直跑 → 每秒 20+ 帧。
带宽峰值不可预测，而且**接收端无法用固定节奏插值**（不知道下一个包什么时候来）。

### 1.2 帧里带全量字段

每条 `players` 帧都带昵称、外观、状态、血量…… 10 人同图时，
一帧可能 2~3KB，10Hz 就是 30KB/s/人。

### 1.3 没有服务器时间基准，插值只能靠本地猜

客户端收到位置后自己做缓动，不知道「这个位置对应哪个服务器时刻」，
所以网络抖动时会出现「卡顿—追赶—再卡顿」。

### 1.4 全图广播，人一多就爆

没有 AOI，一张图 50 人时每人每秒收 50 份位置更新。这是 #772 里最贵的一条。

## 二、目标形态

### 2.1 10Hz 定频 + 帧内只带变化

| 项 | 规则 |
|---|---|
| 位置上报 | 客户端 **10Hz（100ms）** 上报，无论是否移动（静止也发心跳位置，便于服务端判定「在线且在图上」） |
| 服务端广播 | 同样 **10Hz** 定频，一帧打包「本 tick 内所有变化实体」 |
| 变速 | 移动速度 > 阈值（如 600px/s）时临时提到 **20Hz**（防高速穿模），持续 1 秒后回落 |
| 帧瘦身 | 只发**变化的字段**：位置变化发 `x,y`；血量变化发 `hp`；外观变化才发 `appearance` |
| 完整帧 | 每 **5 秒**发一次全量（防止 diff 累积漂移），或收到 `resync` 请求时发 |

**为什么静止也要发**：服务端要靠位置帧判断「这个人还在图里」。
不发的话，只能靠 WS 心跳，而心跳不在地图维度上 —— 会出现「人在线但不在地图上」的模糊态。

### 2.2 服务器时间基准 + 快照插值

```
服务端每帧带 serverTime（毫秒，单调递增）
客户端维护 offset = serverTime - localTime（滑动平均，去掉异常值）
渲染时用 renderTime = localNow + offset - interpDelay（interpDelay 默认 100ms = 1 个 tick）
在缓冲里找 renderTime 前后的两个快照，线性插值
```

| 项 | 规则 |
|---|---|
| 缓冲深度 | 保留最近 **500ms**（5 帧） |
| 插值延迟 | `interpDelay = 100ms`（一个 tick，保证总有「未来帧」可插） |
| 追赶 | 偏差 > 300ms 时**直接瞬移到最新**（不慢慢追，否则会看到人物滑行） |
| 时钟漂移 | `offset` 每秒重算一次，用中位数而非均值（抗单次抖动） |

### 2.3 AOI 裁剪（与 20 篇共用）

- 格子 **512px**，查 9 邻格（20 篇已定）；
- 广播出口改成「按格子分组，只发给同格及邻格的人」；
- 进入/离开视野要发 `entityEnter` / `entityLeave`（20 篇第②刀），**不能只靠 diff** ——
  否则离开视野的人会「留在屏幕上不动」。

### 2.4 按区分片（✅ 已落地 #770）

| 项 | 规则 |
|---|---|
| 分片键 | `zoneId`（区服），`shardOf(zoneId, N) = ((zoneId % N) + N) % N` |
| 进程 | 一区一实时进程（同进程可承载多个**空图**，但一个区只在一个进程里） |
| 路由 | 路径前缀 `/api/realtime/s<k>`；`/api/realtime` 恒指第 0 片并顺带取票，nginx 最长前缀匹配 |
| 跨片 | **不存在**（同区所有人在同一进程，跨区本来就不能互见） |
| 扩容 | 单区到瓶颈时，只能「垂直扩」或把该区按地图再分子片（后者要跨进程广播，暂不做） |

> **这改掉了 #770 的原口径**：原计划「按地图分片」，但按地图分片会引入
> 「同区不同图的人在两个进程」的跨进程广播（世界频道、帮会频道、全服公告都要跨）。
> 按区分片没有这个问题，代价是单区上限受单进程限制。

**票据必须能跨进程校验**，这是分片唯一真正的新增难题（原来票是进程内 `Map`）。做法是**无状态加密票**：

| 层 | 规则 |
|---|---|
| 形状 | `base64url(IV ‖ GCM 认证标签 ‖ 密文)`，AES-256-GCM，密钥 = `sha256(JWT_SECRET)`；明文 = `{ a 账号, u 用户名, z 区, n nonce, e 过期时刻 }` |
| 为什么加密而不是「签名 + 明文」 | 票只能进 URL（握手没有自定义头），于是会落进 nginx 访问日志与浏览器历史；签名票的 payload 是 base64url JSON，谁看 URL 谁就能读出用户名。GCM 一次把「内容不可读」与「篡改必失败」都办了，仍是一个 URL 安全串 |
| 签发 | 存档进程按 `roles.zone_id` 取区（**不是请求参数**，见 39 篇），算分片号，随票一起返回 `shard` |
| 校验 | `openTicket`（GCM 标签不对即抛，不用自己比）→ 判过期 → 判「这张票的区归不归本进程」→ 本进程 nonce 去重 |
| 重放 | 票里带区 → 一张票只可能落一个片 → nonce **只需要本进程记**。就算被重放，`adopt()` 的「一个账号只留一条连接」也只会自己踢自己，不构成提权 |
| 连错片 | HTTP `421` + 业务码 `50150`（**不是 404**，客户端要能区分「地址错」与「接口不存在」）；票里的区不归本进程时响应体带 `data.shard` 指向**这个区该在的片**（路径段不对时不带 —— 那一刻还没解析票，不知道是哪个区，不猜）。进图后才发现则 `close(4003)`，客户端**不退避**、立刻重取票重连（连错 ≥3 次退回退避，防两端口径不一致时打成热循环） |

**三层闸门**（票是 30 秒前的结论，不能当授权用）：

1. 握手路径里的 `s<k>` 与 `REALTIME_SHARD_INDEX` 不符 → `421 / 50150`；
2. 票里的 `z` 算出的分片不是本进程 → 同上（**且不消耗这张票**）；
3. `worldJoin` 时用角色**现在的**区再复核一次（这期间可能被合区搬走了）→ 不符则 `close(4003)`。

**配置与退化**：

| env | 默认 | 含义 |
|---|---|---|
| `REALTIME_SHARD_COUNT` | 1 | 总共几片。`1` 时不拼 `/s<k>`，老客户端零改动 |
| `REALTIME_SHARD_INDEX` | 0 | 本进程是第几片，越界告警 |

`REALTIME_EMBEDDED=true`（本地开发与全部 e2e 的形态）时 `shardCount()` **强制按 1** ——
分片是扩容手段，配错不该让人起不来；同时 `config-snapshot` 会打「配了但内嵌没生效」的告警。

Compose 只预置两片（`server-realtime` + `server-realtime-1`，后者在 `profiles: ["shard-2"]`），
`OLUA_REALTIME_SHARDS` 控制 `REALTIME_SHARD_COUNT`；nginx 每片一段 `location /api/realtime/s<k>`，
`tools/audit-deploy.cjs` **逐段**校验上游服务名 / 端口 / WS upgrade / 读超时，并要求不带分片段的那段落仍然存在。

### 2.5 帧预算

| 场景 | 目标 |
|---|---|
| 同屏 20 人 + 50 怪 | 单帧 < 3KB，10Hz 下 < 30KB/s |
| 同屏 50 人 + 200 怪 | 单帧 < 8KB，10Hz 下 < 80KB/s（需要 AOI 才能达到） |
| 超预算时 | 降级顺序：怪物位置 → 其他玩家位置 → 其他玩家血量 → 自己的状态（**自己的永远不降**） |

### 2.6 位置校验与寻路（#811 已落地；#1138 起转意图校验）

三道闸，全部在**实时进程**里，客户端零决策：

| 道 | 判据 | 失败 | 出口 |
|---|---|---|---|
| ① 速度 | `dist > maxSpeed × tolerance × Δt + jitterPx`（#1138 起 `credit` 删除：突进改服务端直接落位） | `reason = "speed"` | 拒帧 + 回 `posCorrect` |
| ② 穿墙 | 扫掠 AABB（线段-矩形精确相交，Liang-Barsky） | `reason = "wall"` | 拒帧 + 回 `posCorrect` |
| ③ 寻路 | 客户端发 `pathFind`，服务端 A* 算完回 `path` | `unreachable` / `snapped` | 只回执，不拒帧 |

**`maxSpeed` 是全局尺子，不是「抄客户端的移速」**：服务端**没有**角色移速属性 ——
移速只存在于客户端刚体（`ROLE_WALK_SPEED=2` / `ROLE_RUN_SPEED=4`，按 PTM 32 折算约 64 / 128 px/s）
和怪物 `move_speed` 里。出厂 `maxSpeed = 400` 留了 3 倍余量给「网络抖动 + 客户端预测 + 未来加速道具」，
`dt` 本身再夹到 `[0, 5s]`。

**移动收权（#1138）**：客户端改发**意图帧** `moveIntent`（`kind: dir` 单位方向 / `target` 目标点 + 走跑标记）
与 `moveStop`；服务端 10Hz 步进（`slideStep` 与怪物 AI 共用同一份滑行算法），速度权威在
`runtime_params.player_move`（走 64 / 跑 128 px/s，**进客户端快照** —— 客户端拉快照覆写本地刚体，
两边同速）。意图激活期间 `pos` 帧的坐标与移动标记不再被采纳（只消费 hp）—— 兼容期
无意图的账号仍走上表的 #811 仲裁（存量客户端 / e2e 摆位），批次 4 客户端删掉本地物理后退役。
三档 `mode` 对意图语义变为**意图校验**：形状垃圾（NaN / 零向量）无论档位都不收；
`target` 落墙在 `enforce` 档拒收 + `posCorrect{wall}`，`log` 档照收；`dir` 类没有目标点，撞墙交给步进滑行。

**三档 `mode`**（`runtime_params.movement.mode`，热切，下一次判定即生效）：

| 档 | 行为 | 用途 |
|---|---|---|
| `off` | 直接放行，连判都不判 | 回滚开关。**读不到配置时的兜底也是 `off`** —— 配坏了不该全服拦人 |
| `log` | 照判、照接受，只记 60 秒一行 warn | **出厂档**。先看真实玩家会不会被误判，再升 `enforce` |
| `enforce` | 拒该帧 + 回 `posCorrect` | 生产档 |

**合法大位移只有三个出口**，都**不**靠「连发两帧」：

1. **换图** —— `join()` 重置基线（`trustedX/Y/At`，#1138 起顺带清掉旧图意图）；
2. **复活** —— `hp` 从 `≤0` 变 `>0` 那一帧一律接受。复活走存档进程 HTTP，实时进程**不会被告知**，
   判速度必然误杀；
3. **突进技能** —— #1138 起**服务端直接落位**（`teleportTo`：沿施法帧落点方向夹
   `CAST_DISPLACEMENT_MAX = 320`，撞墙 / 出图不挪；只在结算成功之后落）——
   旧的 `posCredit` 免检额度已删除（免检的本质还是「相信客户端的坐标」）。

**回拉回的是上一次被接受的坐标**（`entry.x/y`），不是「把本帧夹到上限」：
夹出来的点可能落在墙里，而且会让作弊者每帧白赚一段距离、贴着上限蹭墙。

**两端同一张网格**：服务端 `MapGeometryService.buildGrid` 与客户端 `PathGrid.stampRect` 逐行对齐
（按 `clearance` 外扩、按**格子中心**落盒判定、`originY = -height`、octile 启发、禁切角、
起点 4 圈 / 目标 6 圈吸附、`cellSize/2` 视线采样拉直）。格子口径**复用**
`runtime_params.auto_battle.cellSize / clearance`（40 / 20），不另开一套。

**客户端降级**：本地 A* 保留作**即时预判**（点了就走，不等回执），服务端 `path` 帧到达后按 `seq` 替换路点；
`seq` 对不上直接丢。`posCorrect` 到达时：< 64px 记目标做插值、≥ 64px 瞬移，两档都先 `stopRigidBody()`，
并作废当前路点（否则会继续朝着旧目标走）。

### 2.7 客户端插值（#769 已落地）

旧口径是**指数逼近**：每帧走剩余距离的一半（`factor = min(1, deltaTime/0.15 * 0.5)`）。两个硬伤 ——
数学上永远到不了（停下时靠「差量 > 1 才转向」收尾，表现为蠕动一小段）、延迟随帧率与丢帧漂
（抖一下目标点跳很远，那一段就快进；连丢两帧就站着不动）。

现在的做法是**攒快照 + 按服务端时间线性回放**：

| 项 | 规则 |
|---|---|
| 时间基准 | 帧级 `t`（服务端毫秒）+ `ServerClock`（welcome 粗校准、pong 用「发出时刻 + RTT/2」细校准）。`renderTime = ServerClock.now() - renderDelay` |
| 缓冲 | 每个远端实体一个 `SnapshotInterpolator`，留 4 条（≈400ms）。同 `t` 覆盖、比最新旧丢弃、超容量挤最旧的 |
| 采样 | `renderTime` 夹在两帧之间 → 线性插值；早于最旧 → 钳到最旧（别把刚进视野的人画在原点）；晚于最新 → 沿最后一段速度外插，**上限 100ms** |
| 朝向 / 动作 | 朝向按**这一帧的实际位移**算（位移为 0 保持不动，不再被残差转得乱转）；走 / 站取**后一条快照**的移动标记 |
| 谁在用 | 远端玩家（`OtherPlayerManager`）与怪物（`MonsterAI`）**共用同一个插值器**，不写第二份 |
| 参数 | `configs/network.realtime.interpolation`（`renderDelay` / `bufferSize` / `maxExtrapolate`）—— 手感参数，人眼调，**不进测试断言** |
| 守点 | `client/tools/test-interpolation.cjs`（插值器行为、时钟校准、两端 `t` 同形、两个生产点与裁剪保留） |

刻意不做：不改上报节拍、不预测怪物（怪物的权威在服务端）、不引入 UDP / WebTransport。

## 五、边界情况

| # | 情形 | 期望 |
|---|---|---|
| 1 | 客户端 200ms 内没发位置 | 服务端保留最后位置，不判离线（离线由 WS 心跳判） |
| 2 | 客户端发了超出移动速度的位置 / 穿墙 | 由 [#811](https://github.com/WebCoderT/olua/issues/811) 的三道校验处理（**已落地**，见 2.6）；本层只转发。被拒时服务端自己回 `posCorrect` |
| 3 | 插值缓冲空了（丢包） | 沿最后一段速度外插，**最多 100ms**（`network.realtime.interpolation.maxExtrapolate`），推到头就停住等新帧 —— 不瞬移、不倒退 |
| 4 | `offset` 突然跳变（时钟被改） | 中位数过滤 + 单次跳变 > 1s 时重置缓冲 |
| 5 | 传送后位置突变 | 服务端发 `teleport` 标记，客户端**清缓冲直接置位**（不插值） |
| 6 | 玩家进入视野 | `entityEnter` 带全量（位置/外观/血量） |
| 7 | 玩家离开视野 | `entityLeave`；客户端**立即移除**节点（不留残影） |
| 8 | 全量帧与 diff 帧乱序到达 | 用 `t` 排序；`t` 比当前缓冲最新的还旧 → 丢弃 |
| 9 | 分片切换（区服迁移） | 客户端重连（WS 地址变了），不需要无损切换 |
| 10 | 单区超过单进程上限 | 记告警；短期靠降级（减少广播频率到 5Hz），长期靠「按地图子分片」 |
| 11 | 世界频道跨图 | 按区分片后**同进程**，直接遍历所有连接即可（不跨进程） |
| 12 | 帧预算超限 | 按 2.5 的降级顺序丢字段，**不整帧丢弃** |

## 七、验收

| 用例 | 断言 |
|---|---|
| `e2e-net-rate` | 1 秒内广播帧数 = 10（±1）；静止时也是 10 |
| `e2e-net-diff` | 位置不变时帧里不含 `x,y` 字段；5 秒必出现一次 `full: true` |
| `e2e-net-aoi` | 两人相距 > 1024px → 互相收不到位置帧，但都收到对方的 `entityEnter` 再 `entityLeave` |
| `e2e-net-budget` | 50 人 200 怪场景单帧 < 8KB |
| `e2e-net-teleport` | 传送后客户端不做插值（位置立刻到位） |
| `e2e-map-movement` | ✅ **已落地（#811）**：八段 —— 配置口 · `log` 档照旧采纳 · `enforce` 单帧即拒 + 立刻回 `posCorrect` · 4Hz 25px 小步与掉帧 600ms 走 240px 都不误判 · 穿墙判 `wall` · 复活放行 · `off` 完全放行 · 改 `movement` 不清别的分组 |
| `e2e-map-path` | ✅ **已落地（#811）**：七段 —— 位置未上报 → `unreachable` · 起点取服务端坐标 · 逐段 4px 采样证明不穿墙（**刻意不复用 `segmentHitsAabb`，避免自证**）· 拉直有效 · 目标在墙里 → `snapped` · 图外 → `unreachable` · `cellSize` 改 80 立刻生效 |
| `e2e-realtime-shard` | ✅ **已落地（#770）**：七段 —— 票里带分片（两个片上取票结论一致）· 连错片 `421 / 50150 / data.shard` · 连对能进图 + 同票第二次 `401 / 40101` · 跨进程解票（0 片发的票在 1 片握手成功）· 隔离性（SIGKILL 1 片，0 片的连接不断）· 纯函数边界（区 0 / 负数 / `count=1` / 越界 index）。断言状态码与响应体用裸 `http.request` + `upgrade`（浏览器 WS 拿不到） |
| `e2e-latency` | ✅ **已落地（#1043）**：四段 —— 分位数尺子自检（空样本 / 单样本 / 插值口径 / 同序）· 位移广播（A 发 `pos` → B 收到含该坐标的 `players` 帧，30 个稳态样本 + 5 个预热 + 6 个备用点）· 出手回执（A 发 `cast` → A 收同一 `castId` 的 `settle`，20 发）· 打印两段的 p50/p95/max。**不设阈值、不断言毫秒数**：宿主机负载会让数字漂，200ms 是体验目标不是回归判据，达标与否由人看那一行 |

> **本机基线（2026-11-15，M5，loopback，连跑 3 轮）**：位移广播 p50 51.8~53.5ms / p95 94.6~100.8ms
> （10Hz 节拍本身贡献 0~100ms，**已计入**）；出手回执 p50 1.1~1.3ms / p95 3.1~16.2ms。
>
> **为什么没有「2 分片下的延迟」这一行**：分片按**区**切，同一个区的人全落在同一个实时进程里，
> 片与片之间**不代理任何帧**（见本篇「七、取舍」——「不做网关代理帧」）。所以「2 分片与单进程
> 延迟一致」是**结构同构**的结论，不是需要再测一遍的假设；分片那一侧真正会坏的只有「一个片挂了
> 带走别的片的人」，那半由 `e2e-realtime-shard` 的隔离段（SIGKILL 一片，另一片的连接不断）盯着。

## 八、暂时放置（含重开条件）

| 项 | 现在的口径 | 重开条件 |
|---|---|---|
| 按地图分片（#770 原口径） | 改按区分片（#770 已按新口径落地） | 单区超出单进程承载时，且已实现跨进程广播总线 |
| 分片数热改（不重启就改 `REALTIME_SHARD_COUNT`） | 只能重启（区→片的映射一变，所有在线连接都要重连） | 出现「必须在不掉线的前提下扩容」的运营需求 |
| 跨进程广播总线（帮会战 / 全服公告跨区） | 仍按区各自发（全服公告由存档进程逐区发） | 出现「跨区实时互动」需求（#403 帮会战若要求跨区对战） |
| 客户端预测（本地先行、服务端纠正） | 只做插值，不预测 | 插值后仍有 > 150ms 操作性延迟感时 |
| WebTransport（#771 已关） | 用 WS | HTTP/3 在目标机型普及、且 TLS（#742）就绪时 |
| 状态同步用二进制 | 用 JSON | 帧预算持续超限且 AOI 已无可裁时 |
| 给怪物做服务端 A* | 怪物仍只走 `slideMove` + `clampToMap`（直线 + 卡住重选） | 出现「怪物在复杂地形里卡住」的实测投诉，且 A* 单次耗时压到 1ms 以内 |
| NPC / 动态障碍烙进寻路网格 | 网格只烙 `map_collisions` 静态盒 | 出现「玩家能穿 NPC 走过去」的实测；现在烙了会让刷怪区与运镖路线全变（NPC 可挪，网格 5 秒 TTL 跟不上） |
| 把 `MapGeometryService` 与 `MonsterAiService.geometryOf` 合并 | 暂时各一份（AI 侧那份带缓存与告警，本份带 TTL 与网格） | 两边第二个消费方出现时再合（现在合要改 AI 的缓存语义，收益不抵） |

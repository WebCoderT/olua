# 38 · issue 标签体系

> **状态**：已落地（2026-11-10）。29 个功能域标签，476 个 issue（414 已关 + 62 开）全部覆盖。
> **口径**：标签是**检索工具，不是流程状态**。它只回答「这条 issue 属于哪个玩法」，
> 不表达优先级、不表达进度、不表达谁在做 —— 那些继续用 issue 的 open/closed 与 epic。
>
> 为什么要有这一篇：技术栈标签（`client` / `server` / `admin`）回答的是**改哪一端**，
> 而「帮会相关的全部工作有哪些」这类问题它答不了。两层正交，缺一层就查不全。

---

## 一、两层标签各管什么

| 层 | 标签 | 回答的问题 | 什么时候加 |
|---|---|---|---|
| 技术栈 | `client` `server` `admin` `devops` `docs` `epic` | 这条 issue 要动哪几个子工程 | 动手前就能判 |
| 状态 | `bug` `enhancement` `question` `wontfix` … | 这条 issue 是什么性质 | 立项时判 |
| **功能域** | `功能:帮会` … 共 **29** 个 | **这条 issue 属于哪个玩法** | 立项时必加，至少 1 个 |

一层里可以有多个，跨层互不替代：一条「帮会聊天频道串到世界频道」的 issue，
同时会有 `server` + `bug` + `功能:聊天` + `功能:帮会` —— 四个标签各答一个问题。

## 三、三条打标规则

1. **每条 issue 至少 1 个功能标签，最多别超过 3 个。**
   1 个标签 = 「只影响这个功能」；2~3 个 = 「主功能 + 被牵连的横切」（如「扣一部分就重建物品对象，绑定被洗白」
   → `功能:背包` + `功能:装备`）。超过 3 个通常说明这条 issue 该拆。

2. **`docs(memory): 归档 XXX` 跟着被归档的那条功能线打，不打「工具链」。**
   理由：搜「邮件」时应该能一起捞到「归档邮件系统那一刀」。历史归档是功能线的一部分，
   不是独立的工程工作。同理 `docs(skill)`、`chore(记忆)` 也按归档内容打。

3. **技术栈标签与功能标签正交，都要有。**
   只打 `server` 不打功能标签，等于「知道改后端但不知道改什么」；
   只打功能标签不打 `server`，等于「知道改邮件但不知道动哪端」。

## 四、最容易混的五组边界

### 1. `配置管理` vs 具体功能域

**`功能:配置管理` 只给「配置基础设施」**：快照与版本号、ETag、导入导出、单一来源与生成物、
配置下发通道、快照缺段回落策略。

**具体的某个配置页给对应功能域**：商城定价页 → `功能:商城`；装备属性页 → `功能:装备`；
掉落表页 → `功能:掉落`；称号成长列表 → `功能:成长线`。

判据一句话：**「所有配置表都受益」的改 → 配置管理；「只有这张表受益」的改 → 对应功能域。**

### 2. `掉落` vs `怪物AI`

- 掉落**表**、抽法、归属、保护期、拾取、过期、`drop_records` 流水 → `功能:掉落`
- 怪物**本身**的行为、数值、刷新、配置项、刷怪区 → `功能:怪物AI`

「怪物列表里配掉落」这种两边都沾的，给两个。

### 3. `背包` vs `装备`

- 格子、叠加、整理、绑定（作为物品属性）、入包与出包的守恒 → `功能:背包`
- 部位、属性、变体、前后缀、强化、穿脱校验 → `功能:装备`

「穿脱丢 `bound` / `from`」这类**跨越两个容器**的，给两个。

### 4. `界面交互` 是横切，不能替代功能标签

它是唯一一个「可以单独存在」的横切标签：纯客户端表现问题（飘字落在屏幕左下角、
面板被功能按钮压住、文字被行宽裁掉）可以只有 `功能:界面交互`。

但反过来不成立 —— 有 `功能:界面交互` 不代表不用打功能标签：
「成就弹窗名称被裁掉」必须同时有 `功能:成就`，否则从成就线翻历史时找不到它。

### 5. `观测审计` vs `地图`

「地图监控」这条线同时被两个标签覆盖，按**落在哪一侧**判：

- 采集频率、写入、保留策略、索引、查询页 → `功能:观测审计`
- 监控页上画的地图投影、坐标、图层 → `功能:地图`

## 六、复核命令

| 要查什么 | 命令 |
|---|---|
| 功能标签总数（应为 29） | `gh label list --limit 100 --json name --jq '[.[]\|select(.name\|startswith("功能:"))]\|length'` |
| 有没有 issue 没打功能标签（应为 0） | `gh issue list --state all --limit 1000 --json number,labels --jq '[.[]\|select([.labels[].name\|select(startswith("功能:"))]\|length==0)]\|length'` |
| 各功能标签覆盖多少条 | `gh issue list --state all --limit 1000 --json labels --jq '[.[]\|.labels[].name\|select(startswith("功能:"))]\|group_by(.)\|map({l:.[0],n:length})\|sort_by(-.n)\|.[]\|"\(.n)\t\(.l)"'` |
| 某个功能的全部 issue | `gh issue list --state all --label "功能:邮件" --limit 200` |
| 某条 issue 的标签 | `gh issue view <n> --json labels --jq '[.labels[].name]'` |

新增功能标签时：先 `gh label create`（`--force` 可幂等更新），再回到 §二 补一行，
最后跑一遍「有没有 issue 没打标签」—— 新标签不要求立刻回填历史 issue，
但**新开的那条必须带**。

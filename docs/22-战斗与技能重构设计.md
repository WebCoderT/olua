## 零、先修的那一条（不必等整篇）

判定链第 2~11 条里**没有冷却、没有法力**。证据：

```bash
grep -n "cooldown\|mp_cost\|mpCost" server/src/modules/realtime/combat-settlement.service.ts
# 无输出
```

后果：客户端把 `skills.cooldown` 改 0、`mp` 锁死，就能无限放技能。**这是现在唯一一条
「不需要任何技巧、改个包就能用」的洞**，而修它只需要两处校验 + 一张流水。

| 补什么 | 放哪 | 判据 |
|---|---|---|
| 冷却 | 判定链第 3 条（`unknown_skill` 之后、`target_dead` 之前） | `now - lastCastAt[roleId][skillId] < cooldown × 1000` → `skill_cooling`（带 `remainMs`） |
| 法力 | 判定链第 4 条 | `role.mp < mp_cost` → `not_enough_mp`（带 `need` / `have`） |
| 全局冷却 | 与冷却同处 | `now - lastCastAt[roleId][*] < globalCdMs` → `skill_cooling` |
| 流水 | 不落库，内存 `Map<roleId, Map<skillId, number>>`；角色下线清 | 重启丢冷却 = 玩家多放一次，可接受（掉落那套「重启清场」同理） |

**法力现在根本没被扣**：`roles.service.ts` 里没有扣蓝代码，`mp` 只在血蓝懒结算里回复。
所以补法力校验的**同时要补扣蓝**，否则校验永远通过。

## 一、七个结构性问题

### 1.1 状态对玩家不生效（文档 07 第五节明说「刻意宁缺毋滥」）——✅ 已修（#822）

怪物侧 `attackMultiplier` / `defenseMultiplier` 真的乘进伤害；玩家侧 `blockChance` / `blockFactor`
只在客户端表现层生效。**已定：改为全量服务端结算**（见 1.2 的连带影响）。

**已落地的部分**：`role_status` 运行时表 + `攻击倍率 / 防御倍率 / 格挡概率 / 格挡系数` 四项
进服务端出伤与受击结算，客户端 `StatusManager` 改成完全由快照驱动（`settle.statuses` 整表重建）。
**还没落地的部分**（暂时放置，重开条件见 §2.3 末尾）：控制类（晕/定身/沉默）、加速减速、
层数与周期效果 —— 它们与移动校验（#811）强耦合，见 1.2。

### 1.2 全量结算会牵动位移（新发现的耦合）

「全量」包括加速/减速类状态。而速度是移动校验（#811）的输入 —— 一旦服务端承认
`moveSpeedRate = 1.5`，就会同时承认「这 1.5 秒内他跑得比 `speed` 快 1.5 倍」。
所以这两件事必须一起定口径：

| 状态类型 | 影响什么 | 与移动校验的关系 |
|---|---|---|
| 减伤 / 增伤（`defenseMultiplier` / `attackMultiplier`） | 伤害结算 | 无关 |
| 格挡（`blockChance` / `blockFactor`） | 伤害结算 | 无关 |
| 控制（晕 / 定身 / 沉默） | 能不能出手 / 能不能移动 | **强耦合**：定身期间任何位移帧都应当被拒 |
| 加速 / 减速 | 移动速度上限 | **强耦合**：#811 的速度校验上限要乘上当前 `moveSpeedRate` |
| DoT / HoT | 周期扣血/回血 | 无关（但要走同一条「血量型写入」通道，不推 revision） |

**结论**：状态的 `kind` 必须分成 `damage` / `control` / `speed` 三类，`speed` 与 `control`
两类直接喂给移动校验。这是本次重构里**最容易漏的一处**（漏了就是「定身还能跑」）。

### 1.3 伤害只有「攻减防」，没有随机层

**已定：只加暴击**（不加命中/闪避/抗性，避免重标 685 件装备与全部怪物）。

### 1.4 没有 AOE 与目标选择 —— **已落地（#824）**

`skills.target_type` 有字段，但结算只处理单个 `targetId`。群怪场景只能一只只点。

**已修**：结算按 `target_type` + `require_target` 分流，区域/群体技能由**服务端**算命中集合
（中心 = 落点夹到 `skills.distance` 内，半径 = `skills.distance`，上限 `AOE_MAX_TARGETS = 8`，
每只独立掷骰）。回执带 `hits[]`，奖励逐只算，掉落账本按一次施放合并成一份。
细节与「暂时放置」的部分（`max_targets` 进表、群体击退、群体技能素材）见 `docs/07` §2.1。

### 1.5 技能没有学习成本

新号建号时 `owner='role'` 的技能全 1 级，`level_req` 只控制客户端的灰按钮。
服务端不校验「你学过没」以外的任何东西，也没有技能点。

### 1.6 PvP 完全没有

`cast` 只接受 `monsterKey`；`arena/duel/pvp` 全仓零命中。想做 PvP 要先有
「目标可以是角色」这条路径，而它会引出「谁先手 / 伤害减半 / 死亡惩罚」一堆规则。

### 1.7 状态没有层数与周期效果

`statuses` 只有 `duration`。没有叠层（5 层毒）、没有 DoT/HoT、没有驱散、没有免疫。

## 二、目标形态

### 2.1 判定链（新，17 条，顺序不能改）

> 顺序的依据：**越便宜、越不可能失败的先判**；所有「会改变状态」的动作（扣蓝、记冷却、扣令牌）
> 排在**最后三道**，这样前面任何一道失败都不需要回滚。A1 的「存活 → 跨图 → 距离 → 冷却 → 耗蓝 → 频率」
> 指的是这六项的**相对先后**，不是它们在表里的绝对位置（距离必须排在「目标存在」之后）。

| 序 | 判定 | `rejected` / `code` | 相比现在 |
|---|---|---|---|
| 1 | 帧字段齐全 | `bad_request` | 不变 |
| 2 | 攻击者在线有角色 | `no_role` | 不变 |
| 3 | **攻击者存活**（`hp > 0`） | `rejected: "dead"` | **新增**（现在尸体能持续输出） |
| 4 | 技能存在 | `unknown_skill` | 不变 |
| 5 | **技能已学且等级够**（`level_req` 进服务端） | `rejected: "unlearned"` | 扩 |
| 6 | **沉默 / 眩晕中不能出手** | `rejected: "stunned"` | **新增**（读 `role_status`） |
| 7 | 目标存在（怪或角色） | `unknown_target` | 扩 |
| 8 | 目标实例在世界上 | `unknown_target` | 不变 |
| 9 | **攻击者与目标同图**（比 `mapId`，不再只比 `zoneId`） | `rejected: "cross_map"` | **新增**（现在可站主城打任意图） |
| 10 | `monsterKey` 一致（怪） / 目标同区（人） | `unknown_target` | 扩 |
| 11 | 目标活着 | `target_dead` | 不变 |
| 12 | **距离够**（读 `skill.distance` + 双方坐标） | `rejected: "range"` | **挂起**（#811 位置源收口后接上，理由见 2.1.3） |
| 13 | **技能冷却未到**（`cooldown ÷ speedRate[action]`） | `rejected: "cooldown"` + `remainMs` | **新增** |
| 14 | **法力足够**（并扣） | `rejected: "mp"` + `need` / `have` | **新增**（现在 `mp` 从不被扣） |
| 15 | **令牌桶有余量**（容量 3 / 每秒补 = 1 ÷ 有效冷却） | `rejected: "rate"` | **新增**（替代原「全局冷却」，见 2.1.1） |
| 16 | 有伤害系数 | `bad_request` | 不变 |
| 17 | 目标数不超过 `maxTargets` | `bad_request` | **新增** |

> 第 17 条的落地形态（2026-11-09 / #824）：**不是报错而是截断** —— 半径内按距离排序取最近的 8 只，
> 超出的直接不打（`AOE_MAX_TARGETS` 常量）。理由：截断对玩家是「少打几只」，报错是「这一发白放了」，
> 而多目标本来就是给玩家省点击的。`max_targets` 进表等运营要按技能调上限时再说。

> **扣蓝必须在算伤害之前**：算完再扣，一旦后续判定失败就要回滚，
> 而回滚是最容易写出「扣了不退」的地方。顺序对了就没有回滚需求。
> 实现上更进一步：**所有会改状态的动作（扣蓝、记冷却、扣令牌）在六道全过之后一次性提交**，
> 这样「被拒的出手代价为零」是结构上成立的，而不是靠每条分支自己记得回滚。
>
> **落地与表的唯一偏差**：「有伤害系数」这一条在代码里排在闸**之前**（第 16 条提前了）。
> 它是配置完整性检查 —— 技能配坏了应该报 `bad_request`，而不是先给玩家一个「冷却中」。
> 六道之间的相对顺序与表完全一致。

#### 2.1.1 令牌桶与冷却的关系（已定 A2）

| 机制 | 管什么 | 参数 | 为什么需要它 |
|---|---|---|---|
| 令牌桶 | **所有出手**的总频率 | 容量 3、每秒补 **1 ÷ 有效冷却** | 挡住「连发上百次」；容量 3 用来吸收网络抖动（3 帧同时到） |
| 技能冷却 | **单个技能**的节奏 | `skills.cooldown ÷ speedRate[action]` | 挡住「同一个技能反复放」 |
| 施法硬直 | 客户端动作锁 | `cast_lock_ms` | 只做表现，服务端不校验（避免硬直算法与动画时长耦合） |

两条同时生效：**冷却管技能、令牌管总手数**。只做其中一条都会漏 ——
只做冷却，则一堆 1 秒技能轮着放能突破总频率；只做令牌，则同一技能 3 连发。

**桶状态**：进程内 `Map<accountId, {tokens, at}>`，**换图不重置**（否则「换图刷桶」又是一条洞）；
进程重启丢桶 = 最多多放 3 次，可接受。

> **补充速率为什么不是「每秒补 1」（2026-11-08 落地时改口径）**：
> 客户端出手节奏 = `skills.cooldown ÷ speedRate[action]`（`SkillManager.getEffectiveCooldown`），
> 基础剑术是 `1.0s ÷ 4 = 0.25s`，也就是 **4 刀/秒**。桶若只补 1/秒，等于把全服 DPS
> 压到 1/4 —— 那不是反外挂，是重做数值平衡。所以桶的补充速率跟攻速走，
> **容量 3 保持不变**（它才是防突发的那个数字：改包一秒钟发 100 次，仍然只过 3 发）。
> 冷却闸同理必须除以 `speedRate`，直接用 `cooldown` 会把正常出手全判成冷却中。

#### 2.1.2 失败怎么回（已定 A3）

统一走 `settle` 帧，**不新增帧类型**：

```ts
{ castId, ok: false, rejected: "cooldown", code: "cooldown", remainMs: 320 }  // 冷却：带剩余，客户端可转圈
{ castId, ok: false, rejected: "mp",       code: "mp", need: 40, have: 12 }   // 法力：带需求，客户端可飘字
{ castId, ok: false, rejected: "range",    code: "range" }                    // 距离（#811 后接上，见 2.1.3）
{ castId, ok: false, rejected: "dead" | "cross_map" | "rate", code: 同值 }     // 无附加字段
```

`code` 是一直存在的老字段（协议错、未知目标、闸拒绝都在这），`rejected` 只在**闸拒绝**时出现。
两者在闸拒绝时同值 —— 旧客户端照旧读 `code`，新客户端按 `rejected` 分支。

客户端只多一个分支：`settle.rejected` 存在 → 不播伤害数字，按 `rejected` 决定飘字/灰技能。
**成功路径的帧形状一个字不变**，旧客户端不炸。

#### 2.1.3 距离闸为什么挂起（等 #811）

距离这道判据本身很简单（`skill.distance > 0` 且超距就拒），卡的是**位置源还不是权威**：

- 玩家坐标是客户端 4Hz 自报 + 最小仲裁（`player-presence`），与客户端自己的移动预测差一两拍；
- 怪物位置是服务端 AI 模拟的，与客户端渲染也差一拍；
- 客户端判距离用**碰撞盒边缘间距**，服务端只有中心坐标。

两边各差一拍，站在攻击边缘的正常出手就会被判成超距 —— 而「打不出伤害」比「漏判一次远程出手」
严重得多。**重开条件：#811 合并**（单帧即拒 + `posCorrect` 硬拉回 + AI 只读仲裁后坐标），
那道落地后距离闸插在「跨图」与「冷却」之间即可，不需要重排。

跨**图**的远程出手不受影响：它已经被跨图闸拦住（`data.mapAt` 由服务端在 `worldJoin` 放行时写）。

### 2.2 伤害公式（暴击 + 严格等级压制 + 物法分离）

```
base   = rollRange(攻击区间) × 技能系数 × 攻击倍率(状态)
crit   = rand() < critRate ? critDamage : 1        // critDamage 默认 1.5
def    = round(rollRange(防御区间) × 防御倍率(状态))
         // 防御区间按 baseType 取：physicalAttack → physicalDefense；
         // magicAttack → magicDefense；taoistAttack → taoistDefense（映射在 game-enums）
sup    = max(0, 1 − 0.05 × max(0, targetLevel − attackerLevel))   // 严格压制
damage = max(0, round(base × crit × sup − def × blockFactor))
```

> 上面这条链**已全部落地**（#826 起 `sup` 也接了）。四处顺序见 `rollCastDamage` 的注释：
> 压制乘在扣防**之前**、基础伤害为 0 时不判暴击、暴击乘在最后、受击侧格挡再乘在它之后。
> 区域技能（`target_type = 2`）逐只算压制 —— 同一个函数、每只目标各算一次，
> 回执逐只给 `hits[i].suppressed`。

**物法分离（已定 A6 / 落地 #823）**：判据是技能系数的 **`damageCoefficients[].baseType`**
（`physicalAttack` / `magicAttack` / `taoistAttack`），不另开 `damage_type` 列 ——
三系比「物/法两档」细一档，而且这个字段本来就在、只是解析了没用（B6）。

| 端 | 读什么 | 谁读 |
|---|---|---|
| 角色 | `physicalDefense` / `magicDefense` / `taoistDefense`（等级曲线 + 装备词条） | 怪物打人时按技能的 `baseType` 取 |
| 怪物 | `physical_defense_*` / `magic_defense_*` / `taoist_defense_*` | 玩家法术打怪时按技能的 `baseType` 取 |

两张映射表（`DEFENSE_BY_ATTACK` 攻击→防御、`MONSTER_STAT_COLUMN` 属性→列前缀）都在
`common/constants/game-enums`，**两侧共用**：各写一份就会分裂成「玩家打怪按物防、怪打玩家按魔防」
那种只在数值层面才看得出来的错。

**怪物法/道攻 0 = 未配**（2026-11-08 拍板）：全服怪物只有物攻配了数，法术技能挂上去会是哑弹。
所以缓存构建时按「该项攻击上限 > 0」判断，没配就**跳过这个技能并 warn 一次**，回落到普攻 ——
而不是放出去打 0 血。法术怪由运营在管理端把数值配出来，不做「法攻 = 物攻」的自动派生。

> **为什么不做「抗性百分比」**（**暂时放置**）：抗性要做就得引入「火/冰/雷」伤害类型枚举 +
> 每件装备给抗性，那是另一层系统。重开条件：出现「同一件装备对不同元素抗性不同」的玩法需求。

**等级压制（已定：严格）**：

| 等级差（目标 − 攻击者） | `sup` | 效果 |
|---|---|---|
| ≤ 0（打低级怪） | 1.0 | **无加成**（反向不奖励） |
| +10 | 0.5 | 伤害腰斩 |
| +20 | **0** | 打不动（伤害恒 0） |

- 只算 `targetLevel − attackerLevel`，**不取绝对值** —— 打低级怪不吃惩罚也不加成；
- 与经验侧的 `maxLevelGap`（差过大给 0 经验）是**两条独立的线**，都生效；
- 等级来自服务端：怪读 `monsters.level`，人读 `roles.level`；
- 结果截到 0 之后**不再有下限保护**：`sup=0` 时这一刀就是 0 伤害，`settle` 要带
  `suppressed: true`，客户端据此显示「等级压制」而不是「伤害 0」。

> **为什么要这个**：现在 1 级号可以靠时间磨死高 50 级的怪（伤害不受等级影响，
> 只是没经验）。加了压制之后，「越级打怪」在数值上直接不成立，不需要靠封号或人工管。

| 新属性 | 来源 | 默认 |
|---|---|---|
| `critRate` | 装备词条 + 成长曲线 + 称号 + **技能行** | 0（新号无暴击） |
| `critDamage` | 同上（**技能行优先，不相乘**） | 1.5 |
| `defIgnore` | **只来自技能行**（`skills.def_ignore`） | 0（不破防） |

**为什么不把暴击做成「暴击率 × 额外伤害」的期望值**：期望值会让伤害变成一条平滑曲线，
玩家看不到「这一下爆了」的反馈；网络游戏的体感来自**离散事件**。

#### 2.2.1 本轮（#826）落地到哪一步

B9 是「技能 `description` 里写着的效果，服务端一件都没实现」。盘点下来 9 条技能受影响，
这一批**只接既有能力**（暴击 + 破防），其余逐条进「暂时放置」。

| 项 | 状态 | 口径 |
|---|---|---|
| 暴击率 | ✅ 已接（#826） | `growth_scalars.critRate` + `skills.crit_rate`，**相加**后裁到 `[0,1]` |
| 暴击倍率 | ✅ 已接（#826） | 技能 `crit_damage > 1` 用技能的，否则角色的 `growth_scalars.critDamage`，都没有才 1.5 |
| 破防 | ✅ 已接（#826） | `skills.def_ignore` 是**穿透比例**，削的是防御那一项：`防御 × (1 − def_ignore)` |
| 暴击回执 | ✅ 已接（#826） | `critical: true`（单体顶层 / 区域 `hits[i]`），**客户端只用于表现** |
| 撞飞 | ✅ 已接（#826 第二批） | `push_distance`（#670 的 `applyPush`）+ `push_chance`（0 = 从不撞，1 = 必撞）+ 等级闸（施法者等级 > 怪物等级）；回执带 `pushDistance`（只表现）。AI 侧位移按「已推游标」补齐，tick 粒度再粗总位移也恒等于配置距离 |
| 1009 群体化 | ✅ 已接（#826 第二批） | `target_type` 改区域（圆形 AOE，#824 的服务端命中集合直接复用）；desc 的「身前半圆」改为「周围范围」 |
| `desc` 里的精确数值 | ✅ 已删（#826 第二批） | 1001 / 1003 / 1005 / 1006 / 1007 / 1009 / 1011 的倍率与范围数字全部改成模糊描述，数值以表为准 |
| 等级压制 `sup` | ✅ 已接（#826 第三批） | `max(0, 1 − 0.05 × 越级数)`，乘在扣防**之前**；回执带 `suppressed`（单体顶层 / 区域 `hits[i]`）。越 20 级 `damage` 恒 0 |
| `blockFactor`（格挡） | ✅ 已有（#822 受击侧） | 格挡乘在暴击**之后**，顺序固定 |
| 灼烧 / 麻痹 / 眩晕 | ✅ 已接（#826 第三批） | `statuses.tick_ms + tick_effect` 每秒按拍结算（`StatusTickService`）；`control_flags` 在出手闸第「一·五」道与 `pos` 帧校验各判一次。**角色与怪物两侧都生效**：玩家状态落 `role_status`（跨进程 / 跨重启），怪物状态在 AI 运行时的 `Map` 里（冻结 / 重生即重建） |
| 两段连击 / 拉人 | ✅ 已接（#826 第三批） | `skills.second_hit_ratio`（第二段 = 第一段 × 系数，不单独掷区间 / 不判暴击）与 `skills.pull_distance`（与 `push_distance` **互斥、推优先**，回执给实际位移） |

> **为什么破防做成比例而不是「无视防御」开关**：开关只有 0 / 1 两态，运营没法配「削弱三成」；
> 比例制下 `1` 仍然等于完全无视，语义是超集。代价是「配了破防 ≠ 必中」——
> 防御减半之后仍可能把伤害吃到 0，测试就是靠这一点把「削防御」和「必中」两件事分开的。

> **为什么暴击倍率不相乘**：相乘会让技能倍率变成角色倍率的放大器 —— 调角色一个数，
> 所有技能的暴击一起变。相加/取大这类合成口径两端各写一份必然分裂，所以只有服务端算。

### 2.3 状态：三类 + 层数 + 周期

`statuses` 加 5 列（#826 第三批；上面这张 7 列的表里 `dispellable` 与 `move_speed_rate`
暂时放置，见 2.3.2）：

| 列 | 类型 | 含义 |
|---|---|---|
| `kind` | TEXT | `buff` / `damage` / `control` / `speed`（**只用于分组**，判据看 `tick_ms` 与 `control_flags`） |
| `max_stacks` | INT | 最大层数（1 = 不叠；同 id 再加一层 → +1 并刷新到期） |
| `tick_ms` | INT | 周期触发间隔（0 = 无周期） |
| `tick_effect` | TEXT(JSON) | 每拍做什么：`{hp:-50}` / `{mp:+20}` / `{hpPercent:-0.02}`（按最大生命比例） |
| `control_flags` | TEXT(JSON) | `{stun:1, root:1, silence:1}` |

JSON 列的唯一解析出口是 `common/config-json.ts`（`parseCombatJson` / `parseTickEffectJson` /
`parseControlFlagsJson` + 三个键清单）—— 服务端 AI、结算、DTO 三处都读它，各写一份
`JSON.parse` 必然有一处漏了脏数据兜底。

**叠层规则**（写死，不接受配置）：同 id 再加一层 → 层数 +1（不超过 `max_stacks`），
**刷新持续时间**；到期按整层消失（不按层单独计时）—— 按层计时会让客户端显示与结算对不上。
`ticked_at` 只在**第一次挂上**时初始化，重复获得不重置（否则每刷新一层就多结算一拍）。

**周期效果**：`StatusTickService` 每秒醒一次，问 `RolesService.applyStatusTicks()`
「哪些状态的这一拍该结算了」。扣血走 `updateDataKeepRevision`（血量型写入），**不推 revision** ——
每拍推一次 revision 会让客户端的 `roleUpdate` 把血量变化当成「存档被改」，属性面板一起抖。
进程卡顿 / 重启后 `ticked_at` 会落后好几拍，一次补齐、**最多补 5 拍**（挂了三天的状态不该
在登录瞬间把人打死）。

#### 2.3.1 落地到哪一步

`role_status` 现在是这样（#826 第三批补了 `ticked_at`）：

```sql
CREATE TABLE role_status (
  role_id      TEXT    NOT NULL,
  status_id    TEXT    NOT NULL,
  stacks       INTEGER NOT NULL DEFAULT 1,  -- 真层数，封顶 statuses.max_stacks
  expire_at    INTEGER NOT NULL,            -- 毫秒；服务端权威时间
  source_skill TEXT    NOT NULL DEFAULT '',
  ticked_at    INTEGER NOT NULL DEFAULT 0,  -- 上次周期结算的时刻（#826 第三批）
  PRIMARY KEY (role_id, status_id)
);
```

生命周期（已落地）：重复获得 → **叠一层 + 刷新到期**（封顶 `max_stacks`）；到期 → 读取前惰性清理
（判据绝不吃旧行）+ 5 秒一次全表清扫兜住没人读的行；死亡 / 下线 → 清空；换图 → 保留。

控制判据只有一处：`RoleStatusService.controlOf()`（`stun` 既禁移动也禁出手，`root` 只禁移动，
`silence` 只禁出手）。消费方有两条，各自独立判定：

| 路径 | 判据位置 | 拒绝形态 |
|---|---|---|
| 出手 | `cast-guard.service.ts` 第「一·五」道（存活之后、跨图之前） | `rejected: "stunned"` |
| 移动 | `player-presence.service.ts` 的 `movementLocked()` | **只更新 hp、`moving = false`，连仲裁基线都不动** |

两处各判一次是有意的：一条帧只走一条路，谁也不会替对方判。移动锁里「基线不动」这条尤其重要 ——
基线一动，解除控制后的第一帧就会被判成瞬移（人还在原地，基线却被拽到了「被控期间客户端自己
预测的位置」）。

#### 2.3.2 暂时放置（不是「不做」，是有前置）

| 暂时放置 | 现在的口径 | 重开条件 |
|---|---|---|
| `dispellable`（能否被驱散） | 没有驱散机制，配了也没人读 | 出现「净化 / 驱散」类技能或道具时 |
| `move_speed_rate`（加减速） | 只有「能不能动」，没有「动多快」。移动速度唯一的来源是装备 / 状态之外的成长值 | 出现「减速 30%」这类状态时；前置是客户端与服务端共享一份速度乘数（现在客户端算位移、服务端只校验） |
| 状态伤害致死 | 怪物侧周期伤害**夹到至少留 1 血**：掉落账本按 `castId` 记账，而 tick 里没有 settle 帧可发 —— 让它打死就只剩「地上有东西但客户端不知道 castId」的死账。角色侧可以致死（死亡有独立链路） | 出现一条不依赖 settle 帧的掉落下发通道时 |

#### 2.3.3 存量库怎么拿到这三条状态

三条状态行（2003 灼烧 / 2004 眩晕 / 2005 麻痹）与技能侧的新列取值都只写在
`config-sync.sql` 里，而快照**只在空库首启整份灌一次**（`config_meta.bootstrap_at` 有值之后
再也不灌）。所以存量库靠 `DatabaseService.seedCombatStatusesOnce()` 补一次
（取值在 `common/constants/combat-status-seed.ts`）：

| 补什么 | 写法 | 为什么不覆盖运营 |
|---|---|---|
| 三条状态行 | `INSERT OR IGNORE` | 运营自己建过同 id 的行就原样留着 |
| `skills.status_id`（1001 / 1004 / 1007 / 9001） | `UPDATE … WHERE status_id = ''` | 只在还是出厂空值时写 |
| `skills.second_hit_ratio`（1003 = 0.5）/ `pull_distance`（1004 = 300） | `UPDATE … WHERE 该列 = 0` | 同上 |

**只跑一次**，marker 是 `config_meta.combat_statuses_seeded` —— 否则运营删掉「眩晕」这行，
下次重启它又回来了。漏了这一步的症状很安静：技能照放、伤害照出，只是**不挂状态**，
而且没有任何报错（1001 的 `status_id` 指向一条不存在的状态时 `applyStatus` 直接返回 null）。

|---|---|---|

#### 2.5.1 存量库怎么拿到技能点

`config-sync.sql` 只在**空库首启**时整份灌入（`config_meta.bootstrap_at` 有值之后再也不灌），
而 `data.skillPoints` 不是配置表的一行 —— 它是**角色存档里的字段**。所以老号不会自动有点数：
一个 60 级的老号打开技能面板，每个技能都只能显示「点数不足」。

`DatabaseService.seedSkillPointsOnce()` 在 `migrate()` 末尾跑一次（marker `config_meta.skill_points_seeded`）：

| 情形 | 处理 |
|---|---|
| 存档里**已经有** `skillPoints` | 不动（那是玩家花过点之后的真实余额，按等级重算等于白送） |
| 存档里没有，JSON 解析正常 | 补成 `roles.level`（每级 1 点，与新号「1 级 1 点」同一条尺子），**不推 revision**（只动 `updated_at`，玩家没做任何操作，不该让他下次存档撞 20006） |
| 存档解析不出来（`roles.corrupted` 那批） | 跳过，交人工 —— 自动改写只会把「还能救的档」变成「救不回来的档」 |

**只跑一次**：跑过之后玩家把点花光，重启服务不会回满（否则等于无限技能点）。
验收在 `e2e-skill-upgrade` 第八段：造一个没有该字段的 7 级老号 → 重启 → 7 点；marker 在时再重启 → 不补。

### 2.6 PvP 的隔离设计（本期只留结构，玩法暂放）

`cast` 的目标类型抽象成 `targetKind: "monster" | "role"`。本期只接受 `monster`，
但**判定链与伤害计算函数都按「目标可以是角色」写**，将来开 PvP 只需放开一处白名单 +
加一张 `pvp_rules`（伤害系数、死亡惩罚、安全区）。

> 为什么现在就写：如果按「只有怪」写死，将来开 PvP 要动伤害函数与判定链两处，
> 而那两处是最容易引入回归的地方。

改 `statuses` +7 列（见 2.3）、`skills` +5 列（`max_level` / `aoe_shape` / `aoe_radius` /
`max_targets` / `cast_time_ms`）。

> **`skill_tree` 是配置表**，加它要按仓库纪律登记五处（`config-tables.cjs` 两份清单、
> `gen-api.cjs`、`audit-server-boundaries`、`audit-target.decorator`）+ 快照三处，
> 漏一处客户端单测会齐炸（见 [15 篇](./15-数据表清单.md) 第六节）。

> **`cast_log` 只留 7 天**：10 人同时打怪约 5 行/秒 → 一天 43 万行。按「事件强度」而不是
> 「重要性」设保留期，是这类表的常规做法；要长期留的证据走 `map_monitor_events`。

## 四、协议改造

| 帧 | 方向 | 改什么 |
|---|---|---|
| `cast` | C→S | 加 `targetKind` / `targetId` / `point`；`targetId` 从必填变条件必填 |
| `settle` | S→C | 加 `crit` / `critRate` / `blocked` / `statusApplied[{id,stacks,expireAt}]` / `targets[{id,damage}]` |
| `hit` | S→C | 加 `statusApplied`（怪物给玩家挂状态时要让客户端知道） |
| `statusSync` | S→C | **新增**：进图 / 重连 / 状态全量变化时下发（客户端本地数秒的兜底） |
| `world` | S→C | 加 `statuses`（自己 + 同图玩家的可见状态，只给 `kind='control'` 的，避免暴露他人 buff 细节） |

新拒绝码 4 个：`skill_cooling`（带 `remainMs`）、`not_enough_mp`（带 `need`/`have`）、
`silenced`、`too_far`（带 `distance`/`range`）。

> **#822 实际落地的协议增量**（与上表的差异，以代码为准）：
> `settle` 加的是 `statuses[{id, stacks, remainingMs}]`（**整份快照，不是增量**）+
> `statusOnly?: true` + `appliedStatus?: string`；`hit` 加的是 `blocked?: boolean`。
> 整份而不是增量的理由：客户端 `StatusManager.applyFromServer` 可以直接「快照里没有的摘掉」，
> 不需要维护「哪些是我知道过的」——增量协议一漏包图标就永久残留。
> `statusSync` 独立帧与 `world.statuses` **暂时放置**：现在每条 `settle` 都带整份，
> 进图后第一发出手就对齐了；重开条件是「出现离线/断线期间 buff 还要继续跑」的需求。

> **#826 实际落地的协议增量**：只加了 `critical?: true` 一个布尔（单体在 `settle` 顶层、
> 区域在 `hits[i]` 与 `hits[0]` 上），**不是**上表设想的 `crit` + `critRate` 两个字段。
> 不回传 `critRate` 的理由：客户端拿暴击率只能做「面板显示」，而那应该走快照里的
> `growth_scalars`（同一份数据一个来源）；每帧带一个概率值反而会诱导客户端自己掷一次。
> 另外 `critical` 只影响表现，**伤害数字服务端已经乘过倍率** —— 客户端再乘一次就是第二份公式。

## 五、分刀（六刀，前两刀不分先后）

| 刀 | 内容 | 规模 | 可独立上线 |
|---|---|---|---|
| ① | **冷却 + 法力校验与扣蓝 + `cast_log`** | 小 | ✅ 建议立刻做 |
| ② | 状态全量服务端结算（`role_status` 表 + tick + 三类 `kind` + 移动耦合） | 大 | ✅ 但与 ① 共享判定链，需串行 |

## 六、边界情况（实现时逐条对照）

| # | 情形 | 期望 |
|---|---|---|
| 1 | 两次 `cast` 同一 `castId` | 幂等命中，原样重发（**但冷却已经记了** —— 重放不再扣蓝，因为扣蓝走的是「首次通过」分支） |
| 2 | 冷却剩余 1ms 时出手 | 拒（`skill_cooling`，`remainMs` 是正整数） |
| 3 | 法力刚好等于消耗 | 通过，扣到 0 |
| 4 | 法力不足时 `settle` 里带什么 | `code=not_enough_mp` + `need` / `have`；**不返回伤害字段**（客户端据此不播伤害数字） |
| 5 | 沉默中出手普攻 | 普攻不是技能，`skillId` 为空时**不受沉默影响**（沉默只封技能） |
| 6 | 眩晕中移动 | 被 #811 的移动校验拒（`stunned`）；客户端本地也停输入（双保险） |
| 7 | 定身中放位移技能 | 拒（`rooted`），即使技能本身合法 |
| 8 | 加速状态到期那一帧 | 服务端先结算状态到期再校验位移，**到期后立刻按原始速度上限** |
| 9 | 同 id 状态第 N+1 层 | 层数封顶 `max_stacks`，但**持续时间仍刷新** |
| 10 | 两个不同来源挂同 id 状态 | 合并成一条，`source_role` 记最后一个（不记来源列表，省一列且没用途） |
| 11 | 状态到期在 tick 之间 | 到期即移除，**不再触发最后一次 DoT**（否则「刚好到期那一拍多掉一次血」） |
| 12 | DoT 把玩家扣死 | 走正常死亡路径：`hp<=0` → 客户端死亡动画 → 服务端 `forgetTarget` → 复活要调接口 |
| 13 | 角色下线时身上有状态 | 全清（离线不保留 buff，见 3） |
| 14 | 角色死亡时身上有状态 | 全清（复活后不带旧 buff，避免「死了还挂着加速」） |
| 15 | 换图时状态 | **保留**（换图不是死亡），但 `world` 帧要重发 `statuses` |
| 16 | 怪物给玩家挂状态，玩家不在视野 | 不挂（目标必须在本 room 的互见集合里） |
| 17 | AOE 的 `point` 在墙里 | 允许（不校验位置合法性）；命中判定只看距离，不看寻路可达 |
| 18 | AOE 目标数超 `max_targets` | 取**距离最近的** N 个；距离相同按 `instanceId` 字典序（保证两端结果一致） |
| 19 | 吟唱中被打断 | 本期**暂放打断**（`cast_time_ms` 只做客户端硬直），服务端不维护吟唱态 —— 加了吟唱态就要处理「吟唱中换图/下线/被晕」四种中断 |
| 20 | 技能 `damage_coefficients` 只有 3 项，角色学了 5 级 | `list[4]` 取不到 → `bad_request`（保持现有「不兜底」纪律） |
| 21 | `critDamage < 1` | 配置校验拒（管理端 40000）；服务端读到 `<=1` 按 1 处理并 warn |
| 22 | `critRate > 1` | 夹到 1（不是拒 —— 数值溢出更可能是装备叠出来的，不该让玩家打不出伤害） |
| 23 | 暴击与格挡同时发生 | 先乘暴击、再乘 `blockFactor`（顺序固定，否则两端结果会差一个乘法顺序） |
| 24 | `cast_log` 写入失败 | 只 warn，**不影响结算**（日志是旁路） |
| 25 | 反外挂：1 秒内 30 次合法 `cast` | 冷却会拦住大部分；再加一条「每秒 `cast` > 10 次」告警进 `cast_log`（不拒，只标记） |
| 26 | `sup` 算到 0（越 20 级） | `damage=0` + `suppressed: true`；**不判定暴击**（0 伤害暴击没有意义，还会让客户端播暴击特效） |
| 27 | 打比自己低 30 级的怪 | `sup=1`，无加成也无惩罚（反向不奖励；否则高等级刷小怪会变成最优解） |
| 28 | 已选分支 1，想学分支 2 | 拒（`branch_conflict`），提示「需洗点后重选」 |
| 29 | 洗点消耗 | 只消耗绑定元宝（`reset_cost_bind_gold`，默认 0），**不消耗点数**；退点后总点数 = 等级应得 + 转生额外 |
| 30 | 洗点后前置技能回 1 级 | 依赖它的技能**等级不变**（已学不回收），但**不能再升级**（前置不满足） |
| 31 | `skill_tree` 配成循环依赖（A 需 B、B 需 A） | 学的时候按深度封顶 8 层，超限按「前置不满足」拒并 warn（这是配置错，不能让服务端栈溢出） |

## 八、验收

| 用例 | 断言 |
|---|---|
| `e2e-cast-cooldown` | 连发两次同一技能 → 第二次 `skill_cooling` 且 `remainMs > 0`；`cooldown` 压 0 → 通过 |
| `e2e-cast-mp` | 把 `mp` 压到 `mp_cost-1` → `not_enough_mp`；补到刚好 → 通过且 `mp` 归 0 |
| `e2e-status-player` | ✅ **已落地**（29 条）：状态技能不掷伤害（故意带目标，血量纹丝不动 + `statusOnly` / `appliedStatus` / `damage:0`）· `role_status` 落库（`expire_at ≈ now + duration`、`source_skill`）· 重复施放刷新不新增行 · 格挡概率压 1 → 受击 `blocked: true` · 到期惰性清理 · 死亡清空。**#905**：格挡段把 2001 的 `duration` 拉到 60 秒 + 站桩期间每轮补满血（格挡是减半不是免伤，实测 ~67/刀），CI 慢时钟下不再「等格挡帧中途 buff 过期 / 角色被打死」 |
| `e2e-status` | ✅ **已落地**（55 条，`server/test/e2e-status.cjs`）：越 20 级 `damage=0 + suppressed` · 越 10 级带压制标记 · 两段连击（第二段 = 第一段 × 系数、血量差 = 两段之和；系数 0 时回执不带 `secondDamage`）· 灼烧按拍掉血 + 叠满 3 层 + **不致死（夹到 1 血）** · 玩家被眩晕（`statuses` 帧 / `rejected: "stunned"` / `pos` 帧坐标不被采纳）· 玩家被灼烧（每秒掉血 + **不推 revision**）· 怪被眩晕（不追人、不出手、坐标冻结）· 拉人（实际位移、与击退互斥） |
| `e2e-crit` | `critRate` 压 1 → 每刀都爆：`critical: true` + **暴击最小伤害 > 非暴击最大伤害** + 两段样本的**均值**满足「暴击 ÷2 ≈ 非暴击」（±20%，交错采样；不锁极值 —— 攻击是区间掷骰，两次采样的极值本来就不可比） |

| `e2e-skill-upgrade` | ✅ **已落地**（54 条，`server/test/e2e-skill-upgrade.cjs`）：建号 1 点 + 技能全 1 级 · 升级扣点 / 等级 +1 / revision +1 / 回执与存档同步 · 20035 点数不足（`details` 带 need/owned 且**一点没动**）· 20034 三种目标不合法（没学过 / 认不出 / 系数为空）· 20036 到顶 · **伤害系数真的取下一档**（把两档改成 1× / 20×，升级前后各砍一刀，15 → 400）· 客户端 PUT 存档改技能表与点数被回填 |
| `e2e-skill-tree` | 暂时放置（技能树的分支内容定下来之后再做）：前置未满足 → 拒；已选分支 1 学分支 2 → `branch_conflict`；洗点后可学 |
| `e2e-skill-reset` | 暂时放置（同上）：洗点后 `data.skills` 全 1 级、`skillPoints` 回到总数、绑定元宝扣 `reset_cost_bind_gold` |

## 十、已定参数

| 项 | 结论 |
|---|---|
| 伤害随机层 | **只加暴击**（`critRate` / `critDamage`），不加命中闪避抗性 |

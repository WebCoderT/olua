# 21 · 系统差距总表（按网络游戏口径）

> **这篇是纲**：把现有 16 个系统逐个摆到「网络游戏的常规形态」旁边，量出差距，给出
> **要不要重构 / 优先级 / 依赖谁**。后面十五篇（22~36）是它的展开，不再重复这里的判定。
>
> **一句话结论**：**服务端权威这条主线基本立住了**（伤害、存档、掉落、地图、进图门槛都是服务端算），
> 但**「玩法层」大面积缺失** —— 没有交易、没有 PvP、没有活动框架、组队只有一张壳表、
> 帮会的等级与资金是占位。另有一条**安全缺口必须先补**：服务端不校验技能冷却与法力（见 S01）。

## 零、怎么读这篇

| 你想知道的 | 看哪节 |
|---|---|
| 这系统现在到底有什么，是不是能用 | 第二节，每系统第一栏「现状（实测）」 |
| 要不要重写，还是只加功能 | 第二节最后一栏「结论」，分四档：**保持 / 扩写 / 重构 / 新建** |
| 先做哪个 | 第三节优先级矩阵 + 第四节依赖拓扑 |
| 哪些是跨系统一起改的 | 第五节「四条横切线」 |
| 哪些暂时放置 | 第六节 |

**四档结论的口径**（后面每篇都按这个标）：

| 档 | 含义 | 判断依据 |
|---|---|---|
| **保持** | 结构对，只补细节 | 权威在服务端、数据模型不缺维度 |
| **扩写** | 结构对，但缺玩法 | 加表/加接口即可，不动既有链路 |
| **重构** | 结构不对，改起来会牵动多处 | 数据模型缺关键维度（如状态对玩家无效、房间键不可扩展） |
| **新建** | 现在没有 | 表都没有 |

## 一、什么叫「网络游戏的标准形态」

不追求「和某个具体游戏一样」，只用六条通用基线来量。每条都配一个「做不到会怎样」：

| # | 基线 | 做不到会怎样 |
|---|---|---|
| B1 | **服务端权威**：客户端的每一次「我想做 X」都要被服务端校验前置条件（冷却、消耗、距离、状态、次数） | 改包即无敌 / 无限技能 / 无限资源 |
| B2 | **经济守恒**：每一枚货币、每一件道具的产生与消耗都有流水，能加总对平 | 刷金刷物查不出来，通胀失控 |
| B3 | **状态机完整**：每个玩法对象（角色、队伍、副本、订单、邮件）都有明确状态与终态 | 卡死在中途、重复领取、幽灵数据 |
| B4 | **可运营**：活动、倍率、掉落、价格都能改数据不改代码，且有生效时间窗 | 每次做活动都要发版 |
| B5 | **可观测**：关键行为有事件流，能回答「昨天为什么有人掉了 300 件」 | 只能靠玩家截图排查 |
| B6 | **可扩展**：加一张地图 / 一个等级段 / 一个频道不改核心结构 | 每加一个东西动一遍全身 |

下面每个系统都只对照这六条，不逐条罗列，只写「缺哪条」。

## 二、十六个系统逐个量

### S01 · 战斗与技能（→ [22](./22-战斗与技能重构设计.md)）

**现状（实测）**：`skills` 15 行、`monster_skills` 决定怪物放什么技能；一次出手一条 `cast` 帧，
服务端走 11 条判定（`bad_request` → `unknown_skill` → `unknown_target` ×3 → `target_dead` →
`no_role` ×2 → `skill_not_learned` → 无系数）后算伤害、扣血、结算奖励。
伤害公式 `max(0, round(攻击区间随机 × 系数 − round(怪物防御区间随机 × 状态倍率)))`。

**缺口**（按严重度）：

| 缺什么 | 后果 | 基线 |
|---|---|---|
| **服务端不校验技能冷却** | 改包可以把 `cooldown` 设 0，无限放技能。判定链里没有这一项，`roles.service.ts` 也没有扣蓝代码 | **B1 破** |
| **服务端不校验法力** | 同上，零消耗连发 | **B1 破** |
| ~~玩家侧 `statuses` 不参与结算~~ | **已修（#822）**：`role_status` 表 + 两侧结算接状态倍率/格挡。控制类另由 **#826** 收口（眩晕/麻痹/灼烧，两侧都做）；位置权威由 **#811** 收口（单帧即拒 + `posCorrect`）；**加减速仍未做**（重开条件见 [22 篇](./22-战斗与技能重构设计.md) 1.2） | B1（已消） |
| 无命中 / 闪避 / 暴击 / 抗性 | 伤害只有「攻减防」，成长维度单薄，装备词条只能堆攻防 | B6 |
| 无技能学习成本与技能树 | 新号建号即全部 1 级，`level_req` 只是客户端的灰按钮 | B4 |
| 无群体/AOE 目标选择 | `target_type` 有字段但结算只对单 `targetId` | B3 |
| 无 PvP 结算 | 全仓 `arena/duel/pvp` 零命中；`cast` 只接受 `monsterKey` | 缺玩法 |

**结论：重构**。判定链要重排（冷却/消耗进第 2~3 条），状态要双侧生效，伤害公式要加命中与暴击层。
**优先级 P0**（冷却/法力两条先单独补，不必等整篇重构）。

### S02 · 状态与 Buff/Debuff（并入 [22](./22-战斗与技能重构设计.md)）

**现状（实测）**：`statuses` 4 行，列为 `duration / source / effect / effect_hold_last / combat`，
`combat` 是 JSON：`blockChance` / `blockFactor` / `defenseMultiplier` / `attackMultiplier`。
两侧都真的生效：怪物侧 #372、玩家侧 #822（运行时表 `role_status`）。

**缺口**：~~玩家侧不生效~~（已修 #822）；无层数（叠 5 层毒）、无周期伤害（DoT/HoT）、无驱散/免疫、
无「同类互斥」规则、控制类不生效、无到期广播（客户端按 `remainingMs` 自己数秒）。
层数与周期**暂时放置**，重开条件见 [22 篇 §2.3.1](./22-战斗与技能重构设计.md)。

**结论：重构**（与战斗一起做，分开做两次会重复动同一段结算）。

### S03 · 成长与养成（→ [23](./23-成长与养成重构设计.md)）

**现状**：4×6 段等级曲线（`role_level_curves`）、`growth_scalars`、三货币、称号（`titles`）、
时装（`fashions`）、战力权重（`combat_weights`）。升级走统一链路（击杀 / 泡点 / 卷轴共用）。

**缺口**：无「等级段门槛」概念（转生/觉醒）、无熟练度、战力是纯加权和（无阈值/无评分曲线）、
称号与时装只加属性无收集度。**B4 缺**：曲线改完要重登才全生效（客户端缓存）。
（属性点分配已由 #833 补上：四维加点 + 洗点，`docs/23` §9.1。）

**结论：扩写**。

### S04 · 装备与变体（→ [24](./24-装备重构设计.md)）

**现状**：685 件装备 × 15 变体 = 10275 行；7 部位；`equipment_slots` / `equip_aligns` / `equipment_appearance`。

**缺口**：**无强化 / 精炼 / 镶嵌 / 附魔**（网络游戏装备系统的四个标准动作一个都没有）——
装备只有「掉到哪件穿哪件」，没有长线投入目标。**B2 缺**：强化消耗没有流水。
变体是「同一件装备的 15 种强度档」，与「强化等级」是两个概念，不能互相替代。

**结论：扩写**（加一层 `role_equipment` 实例表：装备从「一个 key」变成「一件有强化等级的实例」——
这一步会牵动背包与掉落，所以要排在交易之后）。

---

### S05 · 物品与背包（→ [25](./25-物品与背包重构设计.md)）

**现状**：6 类物品、7×11=77 格、五个动作（移动/拆分/并堆/使用/回收）、两条守恒、
绑定与溯源（`bound` / `from`）。客户端只报格子，数值直读表。

**缺口**：**无仓库**（网络游戏标配的「主仓 + 背包」两段空间）、**无丢弃**（18 篇暂放）、
无批量整理的服务端权威（`cocos-bag-tidy` 是客户端行为）、格子数 77 是硬编码常量。

**结论：扩写**。仓库是新表（`role_warehouse`），丢弃复用掉落的世界实体模型（等 18 篇落地后再做）。

---

### S06 · 交易与商城（→ [26](./26-交易与商城重构设计.md)）

**现状**：商城有 `mall_categories` / `mall_goods`（**3 件商品**），购买走
`POST /roles/:id/mall-purchase`（服务端权威，扣钱入包）；**玩家之间没有任何交易** ——
全仓 `trade` 零命中，`arena/shop` 零命中。

**缺口**：

| 缺什么 | 基线 |
|---|---|
| 面对面交易（两人确认、物品锁定、双向原子提交） | B2/B3 |
| 摆摊 / 拍卖行（挂单、撮合、手续费、超时下架） | B2/B3 |
| 货币流水（现在只有背包变化，没有「这 500 金从哪来」的账） | **B2 破** |
| 商城的限购 / 库存 / 上下架时间窗 | B4 |
| 赠送 / 邮件索要 | B4 |

**结论：新建**（交易）+ **扩写**（商城）。**这是当前最大的玩法空洞**：有掉落有装备有货币，
但货币只能买 3 件东西、装备不能换手。

### S07 · 世界与刷怪（→ [27](./27-世界与刷怪重构设计.md)）

**现状**：内存世界 + `world_monsters` 投影（5 秒批量）、刷怪区 64 行（`Σmax` 与实例数不等，
是 #669 的活证据）、怪物 AI（选目标/移动/出手/记恨/清场）、进图门槛（等级→战力→魂值）、
`map_monitor_*` 实时监控。地图结构本身见 [19](./19-地图流程.md) / [20](./20-地图模块重构设计.md)。

**缺口**：**只在空分域播种**（改刷怪区不回溯，#669）；无「投放密度曲线」（同一张图从早到晚一个密度）；
无 BOSS 刷新时间窗与全服公告（18 篇只做掉落公告）；无「图内事件」（攻城/守卫/世界 boss）；无人时冻结（20 篇已定）。

**结论：重构**（与 20 篇同做，20 篇是它的结构前提）。

### S08 · 实时同步（→ [28](./28-实时同步与分片设计.md)）

**现状**：单进程 WS（3101），位置上报节流、`players` 帧广播同图、`monster-ai` 帧广播怪物状态。
实测端到端延迟 **415ms**（#772 的目标是压到 200ms）。已拆四个 issue：#767 测量基线 / #768 10Hz + 帧瘦身 /
#769 快照缓冲 + 服务器时间插值 / #770 按地图分片。

**缺口**：~~无 AOI（全图广播，人一多就爆）~~（#810 服务端已落地：512px 格子 3×3 + `entityEnter/Leave`、
一格一次序列化；客户端增量消费是同一 issue 的第二刀）、无插值（靠本地缓动）、无分片、无帧预算（大图一次广播几百实体）。

**结论：重构**（#772 已有四刀，本表只补「与 20 篇 AOI 的合并口径」）。

### S09 · 社交：好友 / 组队 / 帮会（→ [29](./29-社交重构设计.md)）

**现状**：

| 子系统 | 实现程度 | 实测 |
|---|---|---|
| 好友 | 有（`role_friends` / `role_blocks` / `role_enemies` / `role_reports`） | 可用 |
| 组队 | **只有一张壳** | `parties(id, leader_role_id, created_at)` + `party_members(party_id, role_id, joined_at)`，5 队 9 人 |
| 帮会 | **只有管理** | `guilds(id, name, notice, leader_id, level, funds, …)`，**0 行**，`level`/`funds` 是占位无业务 |

**缺口**：组队没有邀请/申请/队长转让/分配方式/队伍频道（`CHAT_CHANNELS` 只有 world/guild/private，
**没有 party**）；帮会没有等级收益、资金用途、帮会技能、帮会战（#403 占位）。

**结论：重构**（组队）+ **扩写**（帮会）。

### S10 · 聊天与公告（→ [30](./30-聊天与公告设计.md)）

**现状**：`chat` 帧四频道（world/map/guild/private，#876 起），服务端限频 + 长度 + 敏感词；
`world` 已改**全服在场者广播**（进过图的在线账号，不限图），同图就近说话拆给 `map` 频道；
`announcements` 表按时间窗生效，登录页也能读（无需令牌）。

**缺口**：无队伍频道（见 S09）、无系统频道、无聊天历史（离线看不到）、无发言等级门槛/禁言
（有 `role_blocks` 但没接聊天）。

**结论：扩写**。

### S11 · 任务与活动运营（→ [31](./31-任务与活动设计.md)）

**现状**：`quests` **5 行**，`kind ∈ {main, daily}`，`objective_type ∈ {kill, collect, talk}`，
链式（`prev_quest_id`），奖励金/经验/物品。事件总线驱动进度（`monster:killed` 等）。

**缺口**：**无活动框架**（限时活动、每日重置、活动奖励倍率、活动专属任务）；无「运营配置一个活动」的入口；
无成就/任务与活动的统一调度；`daily` 只有 1 条。

**结论：扩写**（活动框架是新表，但任务引擎可复用）。

### S12 · 邮件（→ [32](./32-邮件设计.md)）

**现状**：`role_mails`（含 `attachments` / `bind_gold` / `exp` / `claimed_at` / `expires_at`）**0 行**、
`mail_queue`（外发 SMTP 投递队列）**0 行**。功能已实现（game-mail 898 行 + mail 920 行），但线上没跑过。

**缺口**：无全服邮件/按条件群发（#438 占位）、无附件过期回收策略的实证、无「邮件作为奖励唯一出口」的统一口径
（现在是经验直接入账、物品直接入包，邮件只用来发系统信）。

**结论：扩写**（群发 + 统一奖励出口）。

### S13 · 存档与账号（→ [33](./33-存档与账号设计.md)）

**现状**：`roles.data` 九类字段、`save` 十三步、乐观锁（20006/20007/4016）、血蓝懒结算、
`accounts.online_role_id` 为在线真相。每账号最多 6 个角色（实测最大 6，116 个账号）。
区服模型**已补完**（#954 / docs/39）：账号不属于区、角色带区（`roles.zone_id`）、管理端单区上下文、
状态机（open ⇄ maintenance → closed）与合区向导都已落地（#956~#961，见 [39](./39-区服模型补完设计.md) §3.9/§3.10）。
剩 P6 客户端选服交互（#962）与 P7 公告按区（#963）。

**缺口**：无封禁/解封（`role_blocks` 是拉黑不是封号）、无防沉迷/实名、
无角色删除冷静期、无存档版本号（`data` 结构升级只能靠代码兼容）。

**结论：扩写**（其中「存档版本号」建议提前做，越晚越贵）。

### S14 · 配置与热更新（→ [34](./34-配置与热更新设计.md)）

**现状**：38 张配置表 → 32 段快照 → 客户端 `configs/`；四类生效通道（库 / 快照 / 独立接口 / 客户端文件）；
`config-sync.sql` 做出厂种子；`make config-check` 守门。

**缺口**：**无版本与回滚**（改错了只能手工改回）、无灰度（全服一起变）、无变更审计到字段级
（`audit_logs` 有操作但没存前后值）、无「配置草稿 → 发布」两阶段。

**结论：扩写**（版本 + 回滚先做，灰度可以缓）。

### S15 · 管理端与运营工具（→ [35](./35-管理端与运营工具设计.md)）

**现状**：47 条路由 / 46 个页面、三级导航、`@ApiAdminDoc({permissions})`、操作审计（动作即 operationId）、
实时地图监控（#745）、在线角色、邮件群发工具。

**缺口**：无批量操作（改 100 件装备要改 100 次）、无审批流（高危操作双人确认）、
无「数据看板」（运营问「昨天新增多少号」只能查库）、审计不存前后值。

**结论：扩写**。

### S16 · 埋点数据与反外挂（→ [36](./36-埋点与反外挂设计.md)）

**现状**：`audit_logs`（管理端操作）、`map_monitor_events`（战斗/击杀事件）、`drop_records`（18 篇新增）、
**`event_logs`（#886 已落：八类玩家行为流水，管理端 `/event-logs` 可查）**。
**没有**聚合层（`event_daily` / 留存漏斗）、没有异常行为检测、处置仍靠人工。

**缺口**：B5 只剩「聚合 + 信号 + 处置」三段；B1 的检测侧（谁在异常频率出手、谁的位置跳变）没有 ——
不过证据链的**原始记录**已经有了。

**结论：新建**（流水层已完成，余下按 36 篇 §2.1.1 的「暂时放置 + 重开条件」排）。

## 三、优先级矩阵

排序依据：**安全 > 经济 > 玩法 > 体验 > 工具**。同档内按「依赖少者先做」。

| 优 | 系统 | 为什么排这里 | 预估规模 |
|---|---|---|---|
| **P0** | S01 冷却/法力校验 | 唯一一条「现在就能被改包利用」的洞，两处校验 + 一张流水，一天的量 | 小 |
| **P0** | S08 实时同步（#768 先） | 415ms 是玩家每天都能感觉到的，且 AOI 要建在它上面 | 中 |
| **P0** | S07 世界（20 篇第①刀） | #669 已经让运营配了看不见效果 | 中 |
| **P1** | S01+S02 战斗与状态重构 | 玩法深度的地基，PvP 与 BOSS 都等它 | 大 |
| **P1** | S06 交易与商城 | 经济体系缺一半，货币无处可去 | 大 |
| **P1** | S09 组队重构 | 帮会战（#403）与副本都等它 | 中 |
| **P1** | S05 仓库 | 交易上线后背包必然不够 | 小 |
| **P2** | S04 装备强化 | 长线目标，但要等「装备实例化」这一步 | 中 |
| **P2** | S11 活动框架 | 运营节奏，且能复用任务引擎 | 中 |

## 五、四条横切线（跨系统，不要按系统切）

这四件事各自会穿过五六个系统，单独做比拆进各篇更省：

| 横切线 | 穿过谁 | 为什么必须横着做 |
|---|---|---|
| **T1 服务端权威总闸** | S01 / S02 / S05 / S06 / S07 | 「客户端说干什么都要先校验」需要一张统一的「动作前置条件」清单，按系统写会写五遍且不一致 |
| **T2 货币与物品流水** | S04 / S05 / S06 / S11 / S12 | 每一处产生/消耗都要记同一种账，否则 B2 永远对不平 |
| **T3 事件总线扩展** | S07 / S11 / S16 | `monster:killed` 这类事件的消费方会越来越多，需要一次把「事件契约 + 幂等 + 重放」定好 |
| **T4 配置版本与回滚** | S03 / S04 / S11 / S14 | 所有「运营改数」共用一个版本号，按系统各做一套会互相覆盖 |

## 六、暂时放置（含重开条件）

> 这里没有「砍掉」这一档。每一条都是**现在放置、条件到了就重开**。

| 项 | 现在的口径 | 重开条件 |
|---|---|---|
| 3D / 换引擎 | 2D 瓦片够用 | 出现「2D 表现已经撑不住玩法」的具体需求（如需要真实高度差的空战） |
| 跨服战场 / 跨服交易 | 单区服模型，无全局锁 | 单区在线峰值触顶且需要「区与区之间」的对抗时；前置是 28 篇的分片先跑稳 |
| 实时 PvP 竞技场（同步对抗） | 先做异步（排行榜 / 演武） | 同步延迟稳定进 100ms 以内，或改用状态同步 + 服务端回滚重演方案 |
| 游戏内语音 | 只做文字频道 | 有素材托管与内容审核能力时（审核成本是主要门槛，不是技术） |
| 账号级拍卖行（跨角色） | 角色是存档单位，一个角色一个背包 | 26 篇的 `owner_role_id` 托管模型跑稳，且玩家明确提出「同账号转移」需求时 |

# 07 · 战斗与伤害结算

> 一次出手只发一条 `cast` 帧，回来的 `settle` 帧里带着伤害、血量、经验、掉落。
> 这一篇讲清「那一下多少血」是怎么算出来的，以及为什么客户端算不了这件事。

## 一、全景：一次普攻的完整往返

```
客户端                      实时进程（3101）                        存档进程（3100）
T 键 / 自动战斗
  └─ sendCast(skillId, targetId, monsterKey)
        { type:"cast", data:{ castId, skillId, targetId, monsterKey } }
                    │
                    ├─ ① 解析 cast（缺字段 → bad_request）
                    ├─ ② 幂等：recentSettles[castId] 命中 → 原样重发（duplicate: true）
                    ├─ ③ 技能存在？目标实例存在？key 一致？同区？还活着？
                    ├─ ④ 角色在线？等级可汇总？技能已学？有伤害系数？
                    ├─ ⑤ 算伤害 → world.applyDamage
                    ├─ ⑥ 没死：记恨 + 击退
                    └─ ⑦ 死了：经验入账 → 击杀计数 → 掉落抽取 → 掉落账本
                                 → 事件总线（任务/成就）→ 地图监控 → AI 清场 + 广播
                    │                                                        │
        { type:"settle", data:{ castId, ok, damage, hp, maxHp, killed, statuses[],
                                reward:{ exp, level, expNow, expNeed, leveledUp, revision, drops[] } } }
        { type:"picked", ... } ← 拾取                       ← HTTP 写档（revision+1）
```

**状态型技能（`category = 2`）在第 ③ 步之前就分流走了**：只给自己挂状态，回 `statusOnly: true` +
`appliedStatus` + 整份 `statuses`，不产生伤害也不碰世界状态 —— 详见第五节。

**五个「不信任客户端」的落点**：技能是谁的（服务端查 `skills`）、目标是不是真怪（服务端发的 `instanceId`）、
用哪个攻击属性（服务端读系数里的 `baseType`）、怪剩多少血（`world.applyDamage` 的结果）、
这一刀给什么奖励（服务端抽）。

## 二、判定链与拒绝码（顺序有意义）

| 序 | 判定 | `code` |
|---|---|---|
| 1 | cast 缺 `castId/skillId/targetId/monsterKey` | `bad_request` |
| 2 | 技能不在 `skills` 表 | `unknown_skill` |
| 3 | 目标怪物不在 `monsters` 表 | `unknown_target` |
| 4 | 目标实例不在世界上（伪造 / 已卸载图） | `unknown_target` |
| 5 | 实例的 `monsterKey` 与上报不符 | `unknown_target` |
| 6 | **目标不在攻击者所在区**（#295 阶段二） | `unknown_target` |
| 7 | 目标已死 | `target_dead` |
| 8 | 没有在线角色 | `no_role` |
| 9 | 等级不在成长曲线内（算不出属性） | `no_role` |
| 10 | 技能未学习 | `skill_not_learned` |
| 11 | 该等级没有伤害系数 | `bad_request` |

第 6 条值得单独记：`instanceId` 带区段但不代表不可猜测，**拿别的区的实例 id 来打必须拒绝** ——
判据是「目标区 == 攻击者账号的 `zone_id`」。

**状态型技能在判 3 之前就分流了**（#822）：技能存在（第 2 条）之后立刻看 `category = "2"`，
是状态型就转 `castStatusSkill` —— 不查目标、不掷伤害，只过 `存活 / 冷却 / 耗蓝 / 频率` 四道闸。
顺序不能反：护体神盾 / 金刚护体是**自身 buff**（`require_target = 0`），客户端送来的目标本来就是空的，
留在主链里会被第 1 条（缺 targetId）或第 4 条（实例不存在）直接拒掉，「放不出来」比「打错人」更难查。

**幂等放在最前面**：`castId` 是客户端会话内单调递增的序号。网络抖动导致的重发不会打两次血，
也不会给两份奖励。返回体 `duplicate: true` 让客户端知道这是重放。

## 三、伤害公式（两端同一口径）

```ts
damage = max(0, round(rollRange(攻击区间) × 自身状态攻击倍率 × 技能系数 − round(rollRange(怪物防御区间) × 怪物状态倍率)))
```

代码原文（`combat-settlement.service.ts`）：

```ts
// 玩家身上的状态修正（#822）：攻击倍率乘在出伤上，与受击侧的防御倍率同一个来源
const attack = rollRange(readRange(summary, coefficient.baseType)) * this.roles.statusModifiersOf(accountId).attackMultiplier;
// 怪物身上的状态修正（#372）：防御 × 状态连乘
const defense = Math.round(rollRange(readMonsterRange(stats, coefficient.baseType)) * this.monsterAi.defenseMultiplierOf(cast.targetId));
const damage = Math.max(0, Math.round(attack * coefficient.baseTypeRate - defense));
```

七个必须记住的细节：

1. **攻击区间随机**：不是取中值，也不是取上限 —— `rollRange([min, max])` 每次独立随机。
2. **用哪个属性看系数，不看客户端**：`coefficient.baseType` 是 `physicalAttack` / `magicAttack` / `taoistAttack` 之一，
   对应怪物侧的 `physical_defense` / `magic_defense` / `taoist_defense`（同名映射）。
3. **两侧状态都真的乘进去**：怪物侧 `defenseMultiplier`（#372）、玩家侧 `attackMultiplier`（#822）。
   没有这两条，「硬化皮肤」和「战意高涨」都只是客户端动画。
4. **下限 0，不设上限**：伤害不会被截断；只有**血量**会被 `applyDamage` 截到 0。
5. **`rollRange` 会交换颠倒的区间**：配置写成 `[100, 50]` 不会变成负数伤害。
6. **必须先摊平 `data`**：`roleAttributeSourceOf(role.level, role.data)` —— 直接把 `RoleDto` 传进去只会按裸等级算，
   装备与成长线全丢（这是最隐蔽的一类 bug：伤害「突然」只有等级那点）。
7. **状态型技能不走这条公式**：`category = "2"` 的技能在目标校验之前就被分流到 `castStatusSkill`，
   不掷伤害、不碰世界状态（见第五节）。

## 四、技能配置：`skills` 表的 23 列

| 列 | 用途 | 谁读 |
|---|---|---|
| `id` / `owner`（`role` / `monster`） | 技能归属 | 角色技能清单 = `owner = role` 的行 |
| `label` / `icon` / `description` | 展示 | 客户端 |
| `category` / `target_type` / `require_target` | 分类与是否需要目标 | 客户端选目标 + **服务端分流**（`category = 2` → 状态层） |
| `action` / `effect` / `effect_on_self` | 动作与特效资源 | 客户端 |
| `cooldown` / `mp_cost` / `distance` | 冷却、耗蓝、射程 | 客户端节流 + 服务端 AI 距离 |
| `level_req` | 学习等级 | 客户端 |
| **`damage_coefficients`** | **伤害系数数组（逐级一项）** | **服务端结算** |
| `status_id` | 施法后给自己挂的状态 | 怪物 AI（#372）· 角色结算（#822） |
| `cast_lock_ms` | 施法硬直 | 怪物 AI |
| `can_auto` | 自动战斗是否可用 | 客户端 |
| **`push_distance`** | 击退距离（#670） | 服务端（位移只能由服务端产生） |
| `occupation` | 职业限定 | 客户端 |

`damage_coefficients` 的形状是**逐级一项**：

```json
[{"baseType":"physicalAttack","baseTypeRate":1},   // Lv1
 {"baseType":"physicalAttack","baseTypeRate":1.1}, // Lv2
 ...]
```

读取规则：`list[skillLevel - 1]`。取不到 / `baseTypeRate` 不是数字 / `baseType` 不在三种之内 → **视为没有系数**
（`bad_request`），不会用一个默认倍率兜底 —— 静默兜底会让「配漏了一级」变成「伤害莫名低 40%」。

角色技能等级存在存档 `data.skills`（`{ skillId: level }`），新角色建号时全部 1 级（`owner = role` 的技能）。

## 五、玩家受击：怪物那一侧

怪物 AI 每 tick 走「选目标 → 移动 → 出手」，出手先试技能再普攻（#372）：

```ts
// 伤害 = 怪物「该项攻击」区间随机值 × 攻击倍率（怪物状态）
//      − 玩家「该项防御」区间随机值 × 防御倍率（玩家状态，服务端重算属性）
const modifiers = this.roles.statusModifiersOf(accountId);
const attack = rollRange(monsterAttackRange(stats, baseType)) * this.attackMultiplierOf(instanceId);
const defenseKey = DEFENSE_BY_ATTACK[baseType];          // 物理攻→物防，法攻→魔防，道攻→道防
const defense = Math.round(rollRange(summary[defenseKey]) * modifiers.defenseMultiplier);
const resolved = resolveIncomingDamage(Math.max(0, Math.round(attack * rate - defense)), modifiers, Math.random());
const applied = this.roles.applyMonsterHit(accountId, resolved.damage);
```

**物法分离（#823 / A6）**：`baseType` 来自技能系数（`damageCoefficients[].baseType`）；
普攻没有系数 → 恒按物理。`DEFENSE_BY_ATTACK` / `MONSTER_STAT_COLUMN` 两张映射表都在
`common/constants/game-enums`，**玩家打怪那侧用的是同一张**（否则会出现「法攻打物防」这种
只在数值层面看得出来的错）。怪物只有物攻配了数（全服 `magic_attack_* = 0`），所以
「法/道攻配 0 = 未配」：该技能在缓存构建时被跳过并 warn，回落到普攻 —— 不留「放了法术不掉血」的哑弹。

三层依次生效：**格挡概率 / 防御倍率 / 格挡系数**。`resolveIncomingDamage` 是纯函数
（`modules/combat/status-combat.ts`），随机数由调用方传入 —— e2e 才能钉「这一次必定格挡」，
把 `Math.random()` 藏进函数里就只能靠概率碰运气。命中格挡时 `hit` 帧带 `blocked: true`，
客户端据此播格挡动作（表现，不参与结算）。

`applyMonsterHit`（存档进程）做三件事：**先结算自然回复**（两次受击之间攒的回复不能被这一刀吃掉）→
扣血封 0 → `updateDataKeepRevision` 落库（**不推进 revision**，理由见 [04](./04-角色与存档权威.md) 第七节）。
血量归零时顺手 `clearOfRole` 清空 `role_status` —— 复活不带旧 buff。

### 状态（`statuses` 配置表 + `role_status` 运行时表）

| `statuses` 列 | 含义 |
|---|---|
| `duration` | 持续秒数，到期惰性清理 |
| `source` | 来源（`skill`） |
| `effect` / `effect_hold_last` | 特效资源 |
| **`combat`** | JSON：`blockChance` / `blockFactor` / `defenseMultiplier` / `attackMultiplier` |

**两侧状态都真的生效**（#822 起）：怪物侧 `attackMultiplier` 乘它打你的伤害、`defenseMultiplier`
乘你打它的防御；玩家侧 `attackMultiplier` 乘你的出伤、`defenseMultiplier` 乘你的防御、
`blockChance` / `blockFactor` 决定受击格挡。数值口径三处共用一份 ——
`modules/combat/status-combat.ts`（服务端）、客户端 `BattleMath.collectStatusCombatModifiers`
（规格与单测向量，自 #670 起没有生产调用方）。

叠加规则（写死，不接受配置）：格挡概率取**最大**、格挡系数取**最小**、防御 / 攻击系数**连乘**。
这样「两个减伤 buff」不会互相覆盖，也不会因为顺序不同算出不同结果。

角色状态**落库**（`role_status`）而不是像怪物那样放进程内 Map：怪物状态是「这一轮表现」，丢了无所谓；
角色状态会改结算，重启后凭空消失等于「登录即被白打工一刀」，而且死亡清在存档进程、结算读在实时进程 ——
跨进程只能靠库。换来的是「同 id 重复获得 → 刷新到期时间」这类规则要按行处理（本轮 `stacks` 恒为 1）。

`monster_skills` 决定「哪只怪放哪些技能」：`priority`（升序）、`cooldown`（覆写技能的）。
释放顺序：**状态型整体先于伤害型**（buff 先上），同类型按优先级；已在身上的状态不重复放（等它到期）；
状态型不看距离（追击路上就能上 buff），伤害型要够得着。

`monster_skills` 决定「哪只怪放哪些技能」：`priority`（升序）、`cooldown`（覆写技能的）。
释放顺序：**状态型整体先于伤害型**（buff 先上），同类型按优先级；已在身上的状态不重复放（等它到期）；
状态型不看距离（追击路上就能上 buff），伤害型要够得着。

## 六、死亡与复活

死亡不是一个「状态字段」，而是 **`hp <= 0`** 这一个事实。四件事连着发生：

| 事 | 谁做 |
|---|---|
| 客户端播死亡动画、停自动战斗 | 客户端（`hp` 由 `hit` 帧带来） |
| 服务端不再对尸体出手 | AI 的 `forgetTarget`（#670：清记恨 + 删位置缓存，缺一条都会复发「怪对着尸体连放技能」） |
| 记一次击杀 + 经验 + 掉落 | `settleKillReward` |
| 满血复活必须走接口 | `POST /roles/:id/revive`（未死亡 → 20015 拒收） |

`revive` 的口径：把血蓝补到**服务端重算的上限**、清零两个回复累加器、重置 `vitalsSettledAt`，
**不推进 revision**（血量型写入）。

客户端改包上报「我满血了」无效 —— `save` 会用 `settleVitalsAuthority` 的结算值覆盖；
而「死亡（基线 hp ≤ 0）不回复血量」这条规则保证了**死亡状态不会被离线回血自动解除**。

## 七、击杀奖励：经验、计数、事件、掉落

```ts
if (applied.killed) {
  reward = this.settleKillReward(...);      // 经验 + 掉落
  this.roles.recordKill(role.id);           // 击杀计数（排行榜原料，与经验分开记）
  this.rememberDrops(...);                  // 掉落账本（绑定 + 溯源）
  this.events.emit("monster:killed", {...});// 任务 / 成就 / 地图监控
  this.monitor.recordKill(...);             // 管理端实时地图监控
  this.monsterAi.onMonsterKilled(...);      // AI 清场 + 同图广播（带 drops）
}
```

经验公式：

```ts
gap = |角色等级 − 怪物等级|
if (gap >= maxLevelGap) return 0;
return Math.max(1, Math.round((怪物等级 + 1) × expPerLevel × (1 − gap / maxLevelGap)));
```

- 两个标量读 `growth_scalars` 表（管理端改完**下一笔结算就认**），读不到才退回生成物 seed 值。
- 两处都没有 = 0 → `maxLevelGap = 0` 会让所有击杀都不给经验。这是**显眼的坏配置**，
  比「悄悄用一个代码里的常数」好查。
- **等级差过大时经验为 0，但这一杀仍然计数**（排行榜不该因为「打小怪」而漏记）。

队友分成（#399）：同图在线队友各得 `floor(killExp(他自己等级, 怪物等级) × PARTY_EXP_MATE_SHARE)`。
不均分（击杀者不该因为带人变慢）、不加成（加成会引出多开小号），队友那份走他自己的等级差 ——
高等级带小号打高级怪时，小号基数是 0，乘任何比例还是 0，拉小号被公式本身挡住。

**失败不影响击杀**：经验入账失败（打到一半被踢）只 warn 并跳过奖励；成就写库失败只打日志。
**世界状态是权威，少记一笔进度可接受**。

## 八、泡点（#722）：唯一「不打架也涨经验」的路径

`SoakPointService` 每秒醒一次，攒够 `soakTickSeconds` 拍就给**所有在线角色**入账 `soakExpPerTick` 点经验。

| 口径 | 说明 |
|---|---|
| `soakExpPerTick = 0` | 活动关闭（出厂默认，不改变既有部署的经济节奏） |
| 每拍**现查库** | 管理端「成长参数」页改完即生效；改间隔不用重启定时器 |
| 住在实时模块 | 拆进程形态里只有实时进程装载它 → 整个游戏只发一份（放 `RolesModule` 会两进程各跑一份，经验翻倍） |
| 「在线」的真相 | `accounts.online_role_id`（心跳清算兜着），**不依赖 WS 在场表** —— 通道抖动不该影响发经验 |
| 关闭时清零计数 | 重新开启从整拍开始，不会把关闭期间的拍数补发出去 |
| 单账号失败不断批 | 发经验是尽力而为的节拍活 |

入账走 `applySoakExp`，与击杀经验**共用同一条升级链路**（等级判定 / 循环升级 / 权威属性重算），
客户端从 `roleUpdate` 帧看到变化 —— 客户端**没有任何本地加经验路径**。

## 九、自动战斗：客户端的行为，服务端的结算

`runtime_params.auto_battle` 那一组参数（`maxTargetDistance` / `repathInterval` / `stuckRetryLimit` /
`targetBanDuration` / `teleportSnapRadius` …）**全部是客户端的行动参数**，不是服务端校验规则。

分工：

| 客户端 | 服务端 |
|---|---|
| 选目标、走位、按 `can_auto` 挑技能、节流出手 | 每一次 `cast` 照常走完整判定链 |

所以「自动战斗快一点」不会变成优势：出手频率的上限由客户端动画与冷却决定，而伤害永远由服务端算。

## 十、可观测点（出问题先看这三处）

| 位置 | 内容 |
|---|---|
| `settle` 的 debug 日志 | `技能 x(LvN) → 目标 y(monsterKey) 伤害 dmg，血量 hp/maxHp，击杀/经验/掉落种数` |
| `monitor.recordDamage`（#745） | 一次伤害一行：谁、用什么、打了多少、怪还剩多少 —— **数字来自这次结算本身**，不是两次快照差分 |
| `monitor.recordKill`（#665） | 谁在哪打死了什么、掉了什么、几时刷新（管理端「实时地图监控」） |

差分为什么不够：它只能说「掉了血」，说不出是谁打的、用什么打的、这一下多少 ——
而这三件事才是排查伤害异常要的。

## 十一、排障

| 症状 | 第一嫌疑 | 查法 |
|---|---|---|
| 伤害恒为 0 | 技能缺 `damage_coefficients` 对应等级项，或用错 `baseType` | 看日志 `bad_request` 的 message |
| 伤害突然只剩等级那点 | 属性源没摊平（传了 DTO 而非 `data`） | 搜 `roleAttributeSourceOf(role.level, role.data)` 是否被改坏 |
| 「技能不存在」 | `skills` 表没有这一行 / id 拼错 | 查表 |
| 「目标实例不存在」 | 客户端拿了过期的 `world` 帧（怪已被别人打完重生） | 看是否重连后立即出手 |
| 「目标不在你所在的世界里」 | 拿了别的区的 instanceId（或账号 `zone_id` 不对） | 查 `accounts.zone_id` |
| 怪对着尸体连放技能 | `forgetTarget` 被绕过（`applyMonsterHit` 返回 null 却当「落空」） | 搜 `forgetTarget` 的调用点 |
| 重发导致双倍奖励 | 幂等账被清得太早（`resetTargets` 在错误时机调） | 查 `castId` 是否被复用 |

| 升级后蓝不满 | `applyKillExp` 的 `refillOnLevelUp` 没传 | 查调用点 |
| 泡点不生效 | `soakExpPerTick = 0` | 管理端「成长参数」 |

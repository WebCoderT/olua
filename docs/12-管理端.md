# 12 · 管理端

> React 19 + Vite + Tailwind v4 + react-router 7，46 个页面。
> 它**不持有任何数据副本** —— 所有能改的东西都在库里，所有展示的名字都按 id 现查。

## 一、结构

```
admin/src/
├── App.tsx            路由表（47 条）+ 两处全局接线
```

## 二、路由与三级导航

**路由是扁平的**（47 条 `path`：`/login`、`/register`、`*` 兜底 + 44 条页面路由，在 `App.tsx`），导航是三层（组 → 小节 → 页，`Layout.tsx` 的 `NAV_GROUPS`）：

```
概览（顶层独立项）

运营管理
├─ 账号与区服：账号管理 / 角色管理 / 区服管理
└─ 玩家与社区：帮会管理 / 邮件 / 发消息 / 玩家举报 / 公告

战斗与装备
├─ 装备：装备配置 / 前后缀管理 / 槽位与规则 / 装备边框 / 装备详情背景
├─ 对齐工作台：装备对齐 / 内观对齐
├─ 战斗配置：怪物配置 / 技能配置 / 状态配置 / 掉落配置 / 战斗力权重
└─ 世界与表现：地图管理 / NPC 配置 / 特效管理 / 音效配置
   └─ 参数与引导：运行时参数 / 新手引导

养成与玩法
├─ 角色养成：称号 / 战魂 / 军衔 / 成长参数
├─ 物品与商城：物品 / 药品 / 货币道具 / 升级卷轴 / 时装 / 商城
└─ 玩法：任务配置 / 成就配置

系统管理：管理员 / 操作日志 / 玩家行为流水 / 系统信息
```

四条实现口径：

- **每个叶子带 `permission`**，与会话里的权限点比对决定是否出现（`null` 的常显）。
- **展开态存 localStorage**，key 是各级 label 用 `/` 连接 —— 改一个分组的名字会重置那棵子树的折叠偏好（无害）。
- **换页自动展开当前路由的祖先分组**；非 `end` 项连详情页一起算「组内有高亮」。
- **整页不滚，各区域自己滚**：外层 `h-screen overflow-hidden`，侧栏与内容区各自 `overflow-y-auto`。
  `min-h-0` 是必须的 —— flex 子项默认 `min-height:auto` 会撑到内容高度，`overflow-y-auto` 永远不触发。

## 三、权限：前端只是体验层

```tsx
function RequirePermission({ permission, children }) {
  if (!hasPermission(permission)) return <EmptyState title="没有访问权限" … />;
  return children;
}
```

**真正的判定在服务端**（`PermissionGuard` 按角色反查权限点，越权返回 403 / `30006`）。
前端这层只是「直接改地址栏闯进来时给一个说明，而不是白屏」。

29 个权限点里，viewer 角色只有 7 个读权限 —— 所以「这个页面我点不进去」先看角色，不要先怀疑前端。

## 四、会话与请求层

| 件 | 位置 | 说明 |
|---|---|---|
| 令牌 + 管理员信息 | `store/session.ts` | 只做本地存读，**不发请求、不认识路由**（这样 http 层能依赖它而不成环）；localStorage 读写全包 try/catch（隐私模式不可用 → 当作未登录） |
| 请求层 | `api/http.ts` | 统一加令牌、解包、错误归一、`setReloginHandler`（401 → 清会话 + 回登录页） |
| 提示出口 | `components/ToastHost.tsx` | 全局 toast；`setErrorObserver` 由 `App.tsx` 接上 |
| 进后台先验身份 | `Layout` 的 `authApi.me()` | 令牌过期 / 被停用时请求层统一送回登录；顺带把最新角色与权限点写回会话（**被降权后刷新即生效**） |

## 五、查表：`api/gameData.ts`

管理端有大量「同步渲染」的查表（角色详情里背包那件装备叫什么、掉落条目引用哪只怪、下拉有哪几个物品）。
这些必须在 `render` 里同步拿到。

```
登录后 Layout 调一次 ensureGameData()
  → GET /admin/game-data（与客户端 GET /game-config 同一份快照）
  → 索引成几张 Map
  → 之后所有查表都是同步的
```

四条约定：

1. **代码里没有任何一份数据副本**（#655 之前是生成物，等于「代码里躺着第二份数据」）。
2. **缓存没到 / 拉取失败时回落 id 本身**（`itemText("1234")` → `"1234"`）——
   一眼能看出「名字还没加载」，而不是显示一个假装正确的空串。
3. **枚举（职业 / 性别 / 怪物定位）不在这里**：那是代码即真源，从服务端常量转发，与客户端 `types/*` 逐值一致。
4. **写操作后不自动重拉**：同步渲染的字典要求稳定，随时变会让表格里的名字跳。改完配置**刷新页面**即最新。

## 七、操作日志：动作就是 operationId

`AuditInterceptor`（全局）负责写 `audit_logs`，五条设计：

| 口径 | 说明 |
|---|---|
| **动作不另设清单** | `action` 直接取 `@ApiAdminDoc({ operationId })` 顺带写入的元数据 —— 「文档里的接口标识」与「日志里的动作」永远是同一个字符串，加接口零额外工作 |
| **只审管理端** | 玩家接口量大且属于玩家自己的数据，不在「运营操作留痕」范围内（登录 / 改密由 service 显式记） |
| **只审写方法** | `POST/PUT/PATCH/DELETE`；读接口不记，否则一页列表就把日志刷满 |
| **不碰主流程** | 记录放在 `tap` 里且 `AuditService.record` 自身吞异常 —— 审计是旁路，不该让一次正常的管理操作因为日志表出问题而失败 |
| **目标类型只有一个来源** | `AUDIT_TARGET_TYPES`（36 种）；查询层的 `@IsIn` 也从它派生（曾经两处各写一份，结果查询侧停在最早 5 种，后面加的装备 / 称号 / 帮会全筛不出来） |

`detail` 是请求体（ValidationPipe 已按白名单过滤），`AuditService` 会**打码**敏感字段
（密码 / 令牌）。目标 id 来源两种：`@AuditTarget({ source: "self" })` 取当前管理员，否则取路径里的 `:id`。

### 7.1 玩家行为流水是**另一张表、另一个页面**（#886）

| | 操作日志 `/audit-logs` | 玩家行为流水 `/event-logs` |
|---|---|---|
| 主语 | **管理员**（谁点了哪个接口、成没成） | **玩家角色**（在哪张图对谁做了什么） |
| 表 | `audit_logs` | `event_logs` |
| 写入 | 拦截器自动（`@Public()` 的注册在 service 里自己补） | 八类事件的各自埋点（总线两条 + 直接调用六条） |
| 保留 | `AUDIT_LOG_MAX_ROWS` / `AUDIT_RETENTION_DAYS`（90 天） | `EVENT_LOG_MAX_ROWS` / `EVENT_LOG_RETENTION_DAYS`（30 天） |
| 权限点 | `audit:read` | `event:read` |
| 批量操作 | 拦截器一行 + **service 按目标逐条补明细行**（#885） | — |

合表的后果是审计页被拾取流水刷没，而「查某个角色一晚干了什么」依然查不动 —— 所以刻意分开。

## 九、改配置后的生效路径（最容易问的问题）

| 改了什么 | 生效时机 |
|---|---|
| 装备 / 怪物 / 技能 / 掉落 / 称号…（绝大多数配置） | 服务端**直读库**，下一次结算即生效；**客户端**要等下一次进游戏拉快照（或重启服务端重新出快照） |
| 运行时参数（`runtime_params` 四组） | 每拍 / 每刀现查库，基本即时（掉落绑定概率、自动战斗参数、怪物 AI、帮会规则） |
| 成长标量（`roleMaxLevel` / 经验 / 泡点） | 现查库，即时 |
| 等级曲线（4 × 6 段） | 现查库（带 memo），下一笔结算即生效 |
| 装备倍率 | 必须点「**重建变体**」，否则已有装备仍是旧值 |
| 刷怪区 | **只对空分域生效**（见 [08](./08-世界与怪物.md) 第九节） |
| 外观 / 内观几何、装备边框与背景 | 客户端每次进图拉（验收动作 = 退回选角再进图） |
| 快照里其他段 | 客户端快照**进程内只拉一次** → 重启服务端 |

这条表就是「我改了怎么没生效」的标准答案。判断顺序：先问「服务端认不认」（直读库的基本即时），
再问「客户端什么时候拉」（快照 vs 每次进图）。

## 十、排障

| 症状 | 第一嫌疑 | 查法 |
|---|---|---|
| 侧栏少了几项 | 当前角色的权限点不够 | 查 `admins.role` 与 `ROLE_PERMISSIONS` |
| 改完保存报 403 | 权限点缺失（前端只是体验层） | 看接口返回的 `30006` |
| 名字全显示成 id | `gameData` 没拉到 | 看 `/admin/game-data` 请求；刷新页面重试 |
| 表格里名字不更新 | 查表缓存（设计如此） | 刷新页面 |
| 保存后客户端没变化 | 走了快照（进程内只拉一次） | 见第九节 |
| 装备属性没变 | 没点「重建变体」 | 见第九节 |
| 操作日志里没有这次操作 | 不是管理端写接口 / 方法不是写 / 没挂 `@ApiAdminDoc` | 查装饰器 |
| 日志筛不出新类型 | 用了旧的类型清单 | 加进 `AUDIT_TARGET_TYPES` |
| 构建报类型错 | `models.ts` / `endpoints.ts` 是生成物被手改 | `cd server && npm run gen:api` |

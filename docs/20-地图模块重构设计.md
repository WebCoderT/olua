## 零、一句话

现在的「地图」是**一张图 = 一份世界**（键 `zone:mapId`），所有规则都是全局的、所有广播都是全图的、所有移动都是客户端说了算。
重构目标是把它做成网络游戏的常规形态：**地图是一份配置，世界是它的若干个房间（房间可分线、可开副本），房间里的一切都按格子（AOI）裁剪、按规则（地图级参数）结算、由服务端裁决**。

```
现在                              重构后
────                              ──────
zone:mapId  → 一份世界            mapId  ──┬─→ room(zone, map, channel=0)   公共线
                                          ├─→ room(zone, map, channel=1)   二线
                                          └─→ room(zone, map, instance=i7) 副本
                                              ↑ 每个 room 独立 tick / 独立 AOI / 独立容量
```

## 一、为什么要动结构（现状 12 条缺口归纳成 6 个结构性问题）

`docs/19` 第九节逐条列了 12 个缺口。它们不是 12 个独立的小 bug，是 6 个结构性决定推出来的：

| # | 结构性问题 | 直接后果（docs/19 的条目） |
|---|---|---|
| A | **世界键 = `zone:mapId`，一个键只能有一份世界** | §9.1 无分线、无副本；§9.8 容量无上限；§9.10 玩法参数无处可放 |
| B | **广播按「整张图的观看者」发，没有空间裁剪** | §9.5 无 AOI；人一多就靠提频/瘦身硬顶（#768） |
| C | **移动与碰撞只在客户端** | §9.6 可穿墙可瞬移；§9.7 服务端无寻路 |
| D | **世界的装载/卸载是「懒 + 整份」** | §9.3 刷怪区不回溯（#669）；§9.2 无人时世界冻结 |
| E | **地图只是一行配置，没有「规则」这一层** | §9.9 传送无代价；§9.10 无倍率 / 无地图级事件 |
| F | **可观测性靠每秒投影进库** | §9.11 监控最多 1 秒前、无人不采样 |

这 6 条里有 3 条（A / D / E）必须在**数据模型**上动，2 条（B / C）在**运行时**动，1 条（F）是顺带收益。

## 二、目标模型

### 2.1 五个概念，一次分清楚

| 概念 | 是什么 | 谁持有 | 生命周期 |
|---|---|---|---|
| **Map（地图配置）** | 名称 / 类型 / 门槛 / 刷怪区 / NPC / 复活点 / 碰撞盒 / **规则参数** | 库表 + 快照 | 永久（运营改） |
| **Room（房间）** | 一份跑起来的世界：怪物实例、玩家、掉落、AOI 索引、tick | 实时进程内存 | 有人 → 建；空 → 冻结；长期空 → 卸载 |
| **Channel（分线）** | 同一张图、同一个区里的第 N 份世界（公共线 = 0） | 由 Room 隐含 | 按需创建 / 合并 |
| **Instance（副本）** | 一次独立开局的世界（个人 / 队伍），有 owner、有销毁条件 | Room + 元数据 | 通关 / 超时 / 空房销毁 |
| **Zone（区）** | 部署与数据的隔离维度（现有 `zones` 表） | 库表 | 永久 |

**Room 的唯一键**（替代现在的 `zone:mapId`）：

```ts
type RoomId = string;   // `<zoneId>:<mapId>:<slot>`
// slot = "0" | "1" | "2" …        分线（公共线固定 "0"）
// slot = "i<seq>"                 副本（进程内自增；重启不重号靠库里的 max）
```

**向后兼容**：老键 `zone:mapId` 等价于 `zone:mapId:0`。`worldKey()` 保留但只在「读旧数据 / 老日志」时用。

### 2.2 地图配置新增的一层：`map_rules`

现在一张图能配的只有「能不能进 + 刷什么怪 + 谁在哪 + 墙在哪」。网络游戏里「地图」还是**玩法规则的载体**，所以加一张表（**不是给 `maps` 加 15 个列** —— 列一多就没人敢动，而且大部分图只用默认值）：

```ts
interface MapRules {
  mapId: string;

  // ── 收益倍率（结算读它，不进快照给客户端算）──────────────
  expRate: number;          // 1.0 = 原样
  dropRate: number;         // 1.0 = 原样
  moneyRate: number;        // 1.0 = 原样

  // ── 规则开关 ────────────────────────────────────────────
  allowPk: boolean;         // 默认 false：同图玩家互相打不了
  allowAutoBattle: boolean; // 默认 true：有的图就该挂不了机
  allowRecall: boolean;     // 默认 true：能不能被拉过来 / 用回城
  allowDrop: boolean;       // 默认 true：false = 这张图不掉东西（活动图常用）

  // ── 容量与分线 ──────────────────────────────────────────
  maxPlayersPerRoom: number;// 默认 30；0 = 不限
  maxChannels: number;      // 默认 1（= 不分线）；>1 表示人满自动开新线

  // ── 传送 ────────────────────────────────────────────────
  transferCostMoney: number;// 默认 0
  transferCooldownMs: number;// 默认 0
  denyTransferInCombat: boolean; // 默认 false

  // ── 房间行为 ────────────────────────────────────────────
  respawnMsOverride: number | null; // 中间级重生时长：[27 篇](./27-世界与刷怪重构设计.md) 2.2.2 的三级继承（区 > 图 > 全局）
  simulateWhenEmpty: boolean;        // 默认 false：无人时冻结（现状）；true = 继续 tick
}
```

三条口径：

- **倍率只在服务端用**（结算时乘），**不下发给客户端算** —— 否则「客户端算出来的经验」和「服务端给的经验」迟早不一致；
- **格式给全量默认值**：一行不存在 = 全默认（新建图不用先填 15 个字段）；
- 变更**立即生效**（服务端结算现查，与 `enterRejectOf` 同一套路，不进快照）。

### 2.3 AOI：把地图切成格子

```ts
// 8192×8192 的图，512px 一格 → 16×16 = 256 格
const AOI_CELL = 512;

cellKey(x, y) = `${floor(x / AOI_CELL)}:${floor(-y / AOI_CELL)}`
// y 轴向上、范围 [-H, 0] → 行号用 -y 才对得上 Tiled 的行
```

内存索引（每个 Room 一份）：

```ts
private readonly cells = new Map<string, Set<string>>();   // cellKey → entityId（怪 + 玩家）
private readonly cellOf = new Map<string, string>();       // entityId → cellKey（反查，移动时用）
```

**广播时只发「自己所在格 + 8 邻格」里的实体**（3×3 = 一格视野半径 512，覆盖 ±512px）。这个范围与客户端的可见区（约 ±700px）大致对齐，边缘有 200px 缓冲，玩家不会看到「人凭空出现」在屏幕中央。

**为什么 512**：

| 格大小 | 256 格 / 8192 图的格数 | 一格覆盖 | 8 邻格总量 | 结论 |
|---|---|---|---|---|
| 256 | 32×32 | ±128px | ±384px | 太细，邻格数暴涨（一格平均怪少，反而更费） |
| **512** | **16×16** | **±256px** | **±768px** | **与客户端可见区匹配** |
| 1024 | 8×8 | ±512px | ±1536px | 太粗，等于半个图都发 |

### 2.4 移动：服务端从「记账」变成「裁决」

现在是「客户端说自己在哪，服务端就信」。改成三道：

```
① 速度校验（每帧上报）
   dt = now - lastReportAt
   maxDist = speed * dt * 1.35 + 24     // 1.35 容差 + 24px 抖动余量
   若 实际位移 > maxDist  →  不采纳，回 posCorrect（把权威位置发回去，客户端拉回）

② 穿墙校验（每次位移）
   对「上一位置 → 新位置」做 swept-AABB，与本地图的碰撞盒集合求交
   相交 → 取「贴着墙的最近合法点」，回 posCorrect

③ 寻路权威（点地 / 追怪）
   客户端不再自己跑 A*：发 pathFind{target}，服务端算路回 path（路点数组）
   客户端只做「沿路点走 + 平滑」，走偏了再发一次 pathFind
```

三条都要有**逃生阀**：`MOVEMENT_CHECK = off | log | enforce`（env），默认 `log` —— 先记账不改行为，跑一周看误伤率再切 `enforce`。理由：移动网络下 dt 抖动很大，直接 `enforce` 会出现「玩家被反复拉回」的地狱体验。

### 2.5 世界时钟：无人时冻结还是继续跑

现状是冻结（卸载后不 tick，回来靠 `processRespawns` 补算）。改成**每张图可选**（`map_rules.simulateWhenEmpty`）：

| 值 | 行为 | 适合 |
|---|---|---|
| `false`（默认） | 现状：空房冻结，回来补算重生 | 99% 的刷怪图（省 CPU） |
| `true` | 空房仍按低频 tick（`EMPTY_ROOM_TICK_MS = 5000`）推进重生 / 世界事件 | 世界 Boss 图、活动图 |

**不允许**「按真实时间一次性快进」：那样一晚上没人的图会在玩家进图那一帧同时刷出几百只怪，服务端与客户端都会卡住。低频 tick 是「慢，但平滑」。

### 2.6 分线与副本

**分线（channel）**：同一张图、同一个区里的第 N 份世界。

- 只在 `maxChannels > 1` 且公共线满（`maxPlayersPerRoom`）时自动创建；
- 客户端**知道自己在几线**（`world` 帧带 `channel`），小地图标题后面显示「· 2 线」；
- **换线不换图**：`changeChannel` 帧，服务端把人从旧 Room 摘掉、塞进新 Room，客户端只重建怪物与玩家（**不重进场景**，加载时间几乎为零）；
- 分线**不跨线广播**（聊天里的「世界频道」仍走存档进程那一侧，不受影响）。

**副本（instance）**：一次独立开局。

- 创建条件由调用方给（任务 / NPC / 活动入口），带 `ownerRoleIds[]`、`ttlMs`、`maxPlayers`；
- 销毁条件：所有人离开 / 超时 / 通关标记；
- 副本**不进公共线的容量统计**，也不出现在传送弹窗的图列表里（走专门的入口）；
- 副本的 `mapId` 仍是配置里的某张图（复用资源），只是 slot 不同 —— 这就是「不做第二套地图格式」的关键。

### 2.7 单图热重载（#669 的解法）

现在 `zones.epoch` 是**全局**代际，拿它做单图重载会踢掉所有图。新增一张请求表：

```sql
CREATE TABLE world_reload_requests (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  zone_id      INTEGER NOT NULL,
  map_id       TEXT    NOT NULL,
  slot         TEXT    NOT NULL DEFAULT '0',   -- 分线 / 副本也能单独重载
  mode         TEXT    NOT NULL,               -- 'respawn' = 只重播刷怪区；'reload' = 连实例带 AI 全重载
  requested_by TEXT    NOT NULL,
  requested_at INTEGER NOT NULL,
  -- 'pending' → 'done' / 'skipped'
  status       TEXT    NOT NULL DEFAULT 'pending'
);
```

流程：

```
管理端 改刷怪区 → POST /admin/maps/:id/reload-world { mode, slot? }
   → 只写一行 pending
实时进程 tick（1s）读 pending：
   若该 room 有玩家 且 mode='respawn' → 默认「排队等空窗」，最多等 N 分钟；
        超时则按 `forceAfterMs`（默认 5 分钟）执行 —— 在场玩家会看到怪整体重刷一次，并收到提示
   执行：删该 room 的 world_monsters 行 → 清空内存实例 → 按新区域播种 → 广播 world.reload
   → status='done'
```

**为什么允许「强制重刷」而不是永远等空窗**：运营配完区域要立刻验证，等 10 分钟无人是不现实的。代价是那一个房间里的人会看到怪整体刷新一次 —— 这是**可接受且有提示**的表现，比「配了看不见效果」好。

### 3.3 与「掉落系统重构」（#801）的关系

掉落物也要跟着进 Room：`world_drops` 加 `slot`，内存索引键从 `zone:mapId` 变成 `roomId`。

**顺序很重要**：#801 的掉落重构先落地（它已经把掉落搬成世界实体了），本设计的「Room 抽象」再把它挂到 room 上 —— 否则两边同时改「掉落属于谁」，一定打架。

## 四、协议改造

| 帧 | 方向 | 变化 |
|---|---|---|
| `worldJoin` | C→S | 加 `slot?`（不传 = 公共线），加 `preferChannel?`（想进几线，进不去就换） |
| `world` | S→C | 加 `roomId` / `channel` / `isInstance` / `capacity`；`monsters` 变成**AOI 裁剪后**的子集；加 `path?`（服务端算好的路点，可选） |
| `mapEnter` | C→S | 返回值加 `reason: "full" \| "level" \| ...`，`full` 时带 `suggestChannel` |
| **`entityEnter` / `entityLeave`**（新） | S→C | AOI 进出：怪物与玩家统一走这两帧（替代现在「每拍全量 players + 全量 monsterAi」） |
| **`changeChannel`**（新） | C→S | 换线（不换图），服务端回 `world` 重建 |
| **`posCorrect`**（新） | S→C | 服务端拉回位置（速度/穿墙校验失败时），带权威 `x/y` 与原因 |
| **`pathFind` / `path`**（新） | C→S / S→C | 服务端 A*：请求目标点 → 回路点数组 |
| **`world.reload`**（新） | S→C | 该房间整体重载（刷怪区改动生效 / 管理端强制重载） |
| `monsterAi` | S→C | **只发 AOI 内的怪**；帧里不再带 `maxHp` 这类不变量（首次 `entityEnter` 带全量，之后只带变化） |
| `players` | S→C | 同上，只发 AOI 内；进/出走 `entityEnter` / `entityLeave` |

**帧瘦身的收益要算**：8 人同图 + 145 只怪，现状每 200ms 一轮广播是「8 × 145」级别的对象序列化；AOI 之后每个玩家只看得到自己周围（一格视野通常 10~30 只怪），量级降到「8 × 25」。这是 #768 之外**另一个数量级**的收益来源。

## 五、服务端改造

### 5.1 模块切分

```
modules/realtime/
├── room/
│   ├── room.manager.ts      （新，~300 行）RoomId 解析、创建/查找/销毁、容量、分线选择
│   ├── room.ts              （新，~250 行）一个 Room 的内存状态（怪物/玩家/掉落/时钟）
│   ├── room-lookup.ts       （新，纯函数）  RoomId ↔ (zone, map, slot)，e2e 直接对照
│   └── room-reload.service.ts（新，~150 行）读 world_reload_requests 并执行
├── aoi/
│   ├── aoi.service.ts       （新，~200 行）格子索引、进出查询、移动时的 cell 迁移
│   └── aoi-math.ts          （新，纯函数）  cellKey / neighbors / 视野内判定
├── movement/
│   ├── movement-guard.service.ts（新，~200 行）速度校验 + swept-AABB 穿墙 + 拉回
│   └── path.service.ts      （新，~260 行）服务端 A*（把客户端 PathGrid 的算法搬过来）
├── world.service.ts         （改）删除分域 Map，改为委托 RoomManager；保留重生/落盘
├── monster-ai.service.ts    （改）runtimes 的键从 `zone:map` 改成 roomId
└── map-monitor.service.ts   （改）按 room 采样（含 slot）
```

### 5.2 `WorldService` 变成「Room 之上的操作」

保留的方法（语义不变，只是键变了）：

| 现在 | 之后 |
|---|---|
| `join(zoneId, accountId, mapId)` | `join(roomId, accountId)` |
| `leave(accountId)` | 不变（反查 roomId） |
| `snapshot(zoneId, mapId)` | `snapshot(roomId)`（**AOI 裁剪在调用方做**，World 只给全量） |
| `viewersOf(zoneId, mapId)` | `viewersOf(roomId)` |
| `applyDamage(instanceId, damage)` | 不变（instanceId 全局唯一，已带 slot） |
| `loadMap(zoneId, mapId)` | `RoomManager.ensure(roomId)` |

**关键约束：AOI 裁剪不能下沉到 WorldService**。World 是权威状态，它不该知道「谁看得到谁」；裁剪发生在**广播出口**（`realtime.service` 的 send 层），这样 e2e 可以直接断言「World 里有 145 只、某玩家只收到 25 只」。

### 5.3 移动校验放在哪一层

```
CombatChannel pos 帧
   → realtime.service 收
      → movementGuard.validate(roomId, accountId, x, y, t)
         ├─ 速度校验（用角色当前移速，含 buff）
         ├─ 穿墙校验（room 的碰撞盒 + AOI 格子范围内的盒子，避免全图扫描）
         └─ 结果：accept（更新权威位置 + AOI 迁移）/ reject（回 posCorrect，不改权威）
```

**为什么穿墙校验只查 AOI 范围内的盒子**：1538 个盒子逐帧全扫是 O(n)；按格子建 `cellKey → boxIds` 索引后只看 9 格。碰撞盒静态，索引在 Room 创建时建一次。

### 5.4 广播出口的重写（收益最大的一处）

现在的 `send()` 对**每个收件人**各 `JSON.stringify` 一次（#768 提过）。AOI 化之后要连带改成：

```
每拍：
① 收集「这一拍有变化的实体」（怪物的位置/血量、玩家的位置/动作）
② 对每个房间算「实体 → 影响的格子」
③ 对每个玩家：自己的 9 格 → 实体集合 → 生成一条帧 JSON（同一集合内的玩家**复用同一个字符串**）
④ 发送
```

**按格子聚簇复用序列化**：同一个格子的玩家看到的是同一份内容，这一条把「N 个收件人 → N 次 stringify」降到「M 个格子 → M 次」。

### 5.5 结算读 `map_rules`

`combat-settlement.service.ts` 里三处乘倍率：

```ts
const rules = this.mapRules.of(room.mapId);   // 进程内缓存 + 配置刷新时失效
exp    *= rules.expRate;
drops   = rules.allowDrop ? roll : [];
money  *= rules.moneyRate;
```

`rollDrops` 里再乘 `dropRate`（对**权重**乘还是对**结果**乘要定一个：推荐对「不掉的概率」乘，即 `P' = P × rate`，`rate > 1` 时按权重归一化 —— 否则 `rate = 3` 会算出概率 3.0）。

### 5.6 观看者名单只有一份，且换图必须退出（#821 已落地）

「谁在看这张图」（`world.viewers`）同时是四件事的依据，任何一处读到的都是同一份名单：

| 用途 | 读法 | 名单错了的表现 |
|---|---|---|
| 广播收件人 | `viewersOf(zoneId, mapId)` | 怪物/世界帧往不在图里的人身上发；世界频道串图 |
| 怪物 AI 驱动 | `viewedMaps()` | 空图 AI 一直跑（CPU + 只增不减的内存） |
| 监控采样 | `viewedMaps()` | `map_monitor_state` 一直写，管理端看到「有人在看」的假象 |
| 空闲卸载 | `emptySince` | 永远不记「无人」→ 实例永不卸载 |

**不变量：一个账号同一时刻只在一张图里。** 由 `world.join()` 自己保证 —— 登记新图之前先
`leave(accountId)`（等价 `leaveAll`：全表扫一遍所有分域的名单，把人从每一份里退掉，退空的
记下 `emptySince`）。写在 join 里而不是写成「调用方记得先 leave」，是因为调用点有三个
（进图 / 换图 / 重连），只要有一个漏了，泄漏就是静默且永久的。

断线（`socket close`）、被踢（`sweepKicked`）、换图三条路径**共用 `leave` 这一个出口**，
所以「谁在哪张图」只有一处能改。

**暂时放置：分线 / 观战「保留旧图观看」**。现在的口径是换图即移除，不支持「人在 A 图、
同时看着 B 图」这类多路观看。重开条件：出现真正的观战或分线需求（帮会战 #403 的旁观、
或 `maxChannels > 1` 的落地），届时名单要按 `(accountId, roomId)` 多值化，且
`emptySince` 的判据从「名单为空」改成「没有**主观看**（primary）」，否则观战者会让
空房永远不冻结。

**暂时放置：被顶号后新连接长期不 `worldJoin`**（玩家停在选角界面、连接还活着）时，旧图仍
留着这个账号的一条观看者记录 —— 顶号是有意的例外：旧连接的 close 清理被跳过，指望新连接
进图时自己重新登记。该记录在**新连接一断开**时就被清（close 走同一个出口），所以泄漏是
「有限且会被下一次登录治好」的，不是永久。重开条件：出现「挂机在选角界面导致某张图不冻结」
的实测案例，或选角界面改成常驻长连接时 —— 那时要在 `adopt` 里补一次与 close 同口径的清理。

## 六、客户端改造

### 6.1 AOI 进出替代全量覆盖

| 现在 | 之后 |
|---|---|
| `MonsterManager.applyWorldState(全量)` | `entityEnter` / `entityLeave` 增量；`world` 只在进图/重连时给一份 AOI 内的初始集 |
| `OtherPlayerManager` 每拍按 `players` 全量对齐 | 同样走 `entityEnter` / `entityLeave` |
| 怪物帧带 `maxHp` | 首次带全量，之后只带变化（`hp` / `x` / `y` / `state`） |

**必须处理的一类 bug**：AOI 边界上的实体反复进出（玩家站在格子边界来回走）会不停 `enter/leave`，客户端会看到怪物「闪一下」。对策：**离开有延迟**（`AOI_LEAVE_DELAY_MS = 1000`，1 秒内又进来就取消离开）。

### 6.2 寻路：客户端从「算」改成「跟」

| 项 | 现在 | 之后 |
|---|---|---|
| 点地移动 | 客户端 A*（`PathGrid`）算路点，然后自己走 | 发 `pathFind`，收 `path` 路点数组后自己走 |
| 追怪 | 同上（`AutoBattle` 直接调 PathGrid） | 同上，但目标是一只实体 id（`pathFind{targetId}`） |
| `PathGrid` | 290 行客户端 A* | **保留但降级**：只用于「预判能不能到」（点击时立刻给反馈），真路点由服务端给 |

**为什么不全删客户端寻路**：点地到路点回来有 40~80ms，这期间玩家会看到「点了没反应」。本地预判（能不能到、大概方向）负责这段体感，真路点负责正确性。

### 6.3 分线 / 副本的界面

| 位置 | 变化 |
|---|---|
| 小地图标题 | `卧龙城` → `卧龙城 · 2线`（`channel > 0` 时） |
| 传送弹窗 | 每张图按钮右侧显示 `23/30`（人数/容量）；满了显示「满」并给「换线进入」 |
| 换线 | 小地图下方加一个「换线」小按钮（`channel > 1` 时才显示）；点了不发场景切换，只发 `changeChannel` |
| 副本 | 不走传送弹窗（副本不是「想去就去」的地方），由任务/NPC 入口创建 |

### 6.4 `posCorrect` 的表现

服务端拉回时**不要瞬移**：`posCorrect` 带 `reason`，客户端按距离分两种处理 ——

- 差 < 64px：**静默插值**到权威位置（玩家察觉不到）；
- 差 ≥ 64px：瞬移 + 一次「网络波动」飘字（明显不一致时要说，否则玩家会以为游戏卡了）。

### 7.1 地图页新增「规则」页签

在现有「地图管理」详情页加一块（不新开页面 —— 规则是地图的属性，不是独立实体）：

```
地图管理 /maps
└── 选中图 → 右侧画布上方新增页签：[地图] [规则] [监控]

```

**刷怪区要能拖拽改框（本轮已定）**：现在改位置只能删了重画，调 20px 的偏移也得重建两个区。
改成：点中区域出现选中态 → 拖动整体平移、拉四角/四边改尺寸 → 松手后与新建**同一份**
`SpawnAreaForm` 确认（显示新的四至 + 尺寸 + 格数，取消则回退）；保存后照旧走 §7.2 的重载 action bar。
坐标换算与新建完全同源（`worldBoxOf` / `tiledBoxOf`），不允许拖拽走另一条换算路径 ——
否则「画出来的框」与「拖出来的框」会差半格。

> 手工验收：把 100×100 的框拖到画布别处、松手保存 → 刷新页面后框**还在拖到的位置**
> （不允许「保存后再打开就偏了」）；把它拖出地图边界 → 保存时钳到边界并提示，不是静默丢一半。

### 7.2 刷怪区保存后给「重载」动作

现在保存刷怪区只是写库（§9.3 的坑）。改成：保存成功后弹一条 action bar：

```
已保存。这张图有 3 个玩家在线。
[立即重载（他们看到的怪会整体重刷一次）]  [等无人时自动重载]  [不重载]
```

三个选项对应 `world_reload_requests` 的 `mode` + `forceAfterMs`。默认选第二项（等空窗）。

### 7.3 监控页支持分线

`MapMonitor` 加一条线选择（`slot`），表格加一列「线」。数据源 `map_monitor_state` 主键已扩成三列。

### 7.4 新增权限点

| 权限 | 用途 | 给谁 |
|---|---|---|
| `map:read` | 看地图与监控（现在复用 `GAME_CONFIG_READ`） | 全部角色 |
| `map:write` | 改规则 / 触发重载（写操作，进审计） | `SUPER` / `ADMIN` |

| ② | e2e：145 只怪的房间，某玩家只收到视野内 N 只；进出边界的延迟合并生效；序列化次数从 N 降到 M |

## 十一、暂时放置（含重开条件）

| 项 | 现在的口径 | 重开条件 |
|---|---|---|
| 地图数据进 Redis / 消息队列 | 跨进程只有共享 SQLite 一条路（既定架构），分片之间不共享状态 | 出现「两个进程必须同时看同一张图」的需求时（当前按区分片不需要） |
| 同一张图再横向拆进程 | 单图容量靠 AOI + 帧瘦身顶（#768 与本文第二节） | 单图 AOI + 帧瘦身后仍持续超帧预算（见 [28 篇](./28-实时同步与分片设计.md) 帧预算表） |
| 客户端预测怪物 | 怪物权威在服务端，预测会让「打中的判定」与「看到的」错位 | 插值已上线、且仍有人反馈「打怪手感明显滞后」时才评估（先量延迟分布） |
| 服务端跑「全图怪物 A*」 | 145 只怪每 100ms 各跑一次 A* 直接打满单核；怪走直线追击 + 卡住重选 | 单图实例数降到 ≤ 50 且 CPU 有余量时，或 [27 篇](./27-世界与刷怪重构设计.md) 的寻路改造要求时 |
| 地图格式换 protobuf | 帧瘦身 + AOI 之后 JSON 够用；过早换格式让排查变难 | 序列化占帧预算 > 30%（[28 篇](./28-实时同步与分片设计.md) 里的可测指标） |

| `allowPk` 做成真 PK | 本设计只**预留规则位**并拒绝越界攻击 | 帮会战（#403）与攻城（27 篇 2.9）落地后，PK 才是有组织的 |

## 十二、已定的 10 个点（2026-11-08 逐项拍板）

| # | 问题 | 结论 | 落在哪 |
|---|---|---|---|
| 1 | 要不要分线，还是只做副本 | **都做，但 `maxChannels` 默认 1**（出厂=不分线，要分线的图自己调）；Room 键从一开始就带 `slot` 段 | 2.1 / 2.5 |
| 2 | AOI 格子大小 | **512px**（8192² 图 → 16×16=256 格，查 9 邻格） | 2.3 |
| 3 | 移动校验默认档位 | **`log` 跑一周**再切 `enforce`；`MOVEMENT_CHECK` 三档逃生阀 | 2.4 |
| 4 | 无人时世界是否继续跑 | **默认冻结**，按图用 `simulateWhenEmpty` 单开 | 2.6 |
| 5 | 服务端寻路是否取代客户端 A* | **双轨**：客户端保留可达性预判，路点由服务端给 | 2.4 |
| 6 | 热重载时在场玩家的表现 | **等空窗，超 5 分钟强制重刷**并提示 | 2.7 |
| 7 | 地图规则先做哪几个字段 | 先接 **`expRate` / `dropRate` / `maxPlayersPerRoom` / `allowDrop`** 四个，其余建表但表单灰着 | 2.2 / 七 |
| 8 | 传送要不要代价/冷却 | 字段留好，**默认 0**（不收费不 CD），以后只改数据 | 2.2 |
| 9 | 副本的进入方式 | **走任务 / NPC 入口**，不进传送弹窗 | 2.5 |
| 10 | `map_rules` 要不要进快照 | **只进客户端要判断的三项**（`maxPlayersPerRoom` / `maxChannels` / `transferCostMoney`），倍率一律不进 | 2.2 |

**第 3 条的切换判据**（别凭感觉切 `enforce`）：`log` 跑满 7 天，看
`movement_rejects` 里按 `reason` 分组的日均笔数 —— 只有当
「`speed` 类单日 < 总移动帧的 0.5%」且「`wall` 类误判经抽样确认率为 0」时才切 `enforce`；
否则先修阈值，不要靠拉回掩盖误判。

**第 7 条的落地形状**：`map_rules` 表 15 列全建（DDL 一次到位，避免二次 ALTER），
但只有这四个进结算链；其余 11 列在管理端表单里 `disabled` 并标注「未接入」，
防止运营改了看不见效果（#747 死配置的教训）。

## 附录 B · 名词

| 词 | 这里指什么 |
|---|---|
| Room | 一份跑起来的世界实例（含怪物、玩家、掉落、AOI 索引、tick 时钟） |
| Channel | Room 的一个槽位，公共线 = 0，分线 = 1..N |
| Instance | 一次独立开局的 Room（副本），slot = `i<seq>` |
| AOI | Area of Interest，按格子裁剪「谁看得到谁」 |
| swept-AABB | 把「上一位置 → 新位置」当成一条线段，与矩形求交（防高速穿墙） |
| `map_rules` | 地图级玩法参数（倍率 / 开关 / 容量 / 传送） |

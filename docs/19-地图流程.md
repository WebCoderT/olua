## 零、一句话

玩家看到的「一张地图」是三层叠出来的，**任何一层缺失，表现都不一样**：

| 层 | 是什么 | 在哪 | 谁写 | 缺了会怎样 |
|---|---|---|---|---|
| **资源层** | `.tmx` 瓦片 + `.tsx` 图集 + 底图 + `preview.jpg` | 客户端资源包 `resources/map/<id>/` | 美术（随包发布） | 进图卡在 Loading / 黑屏 |
| **整理层** | 名称 / 类型 / 进入门槛 / 刷怪区 / NPC / 复活点 / 碰撞盒 | 服务端库表（4 张 + `maps` 7 列） | 运营（管理端「地图管理」） | 有空图、无怪、无 NPC、穿墙 |
| **世界层** | 这一张图上**此刻活着的怪物实例** | 实时进程内存（`world_monsters` 是投影） | 服务端世界服务 | 图能看见但一只怪都没有 |

一句话版本：**资源决定「长什么样」，库表决定「能不能进、有什么」，内存决定「现在场上有什么」。**

## 一、一次换图到底发生了什么

以「点开传送弹窗 → 选一张图 → 站在新图地上」为例，一共 14 步，跨两个进程。

```
客户端                                                     服务端
──────                                                     ──────
① 点按钮 → StorageManager.changeOnMap(mapId)
② 本地预检 GameHelper.getMapEnterRejectReason
   （等级 → 战力 → 战魂，不满足就提示，原地不动）
③ 同图？→ 直接跳到 ⑦
④ 通道在线？→ 发 mapEnter ───────────────────────────────▶ ⑤ MapService.enterRejectOf
   （离线则本地判据说了算，退回老行为）                        （三项顺序同上，0 = 不限制）
                                                 ◀────────── ⑥ mapEnterResult
   ↳ 被拒：按 field 提示，不切图（人还在原图）
⑦ applyMapChange：role.onMap = mapId → updateOnlineRole
   → 标记「传送到达音」→ SceneManager.loadScene("Game")
⑧ director.loadScene("Loading")（全项目唯一场景切换入口）
⑨ PreloadManager.preloadGame(mapId, role)
   ├─ await 地图 TMX（关键路径：进图第一帧就要有地）───────▶ GET /game-config（若还没拉过）
   ├─ await 光柱帧序列（进图就可能捡东西）
   └─ 不 await 边框 / 详情背景（后台预载）
⑩ director.loadScene("Game")
⑪ GameMap 构造：reset 怪物/掉落/其他玩家 + 清地图层
⑫ loadMap(mapSrcOf(id))：先锚点 (0,1) 再赋 tmxAsset
   → 逐层 _syncAnchorPoint() → enableCulling = false
⑬ MapObjectSpawner（NPC + 复活点）
   CollisionAreaSpawner（碰撞盒）
   sendWorldJoin(mapId) ────────────────────────────────────▶ ⑭ 再判一次门槛（改包也拦得住）
                                                              → world.loadMap(zone, map)
                                                                （内存 → 库 → 按刷怪区播种）
   MonsterManager.applyWorldState ◀───────────────────────── world 帧（怪物实例）
```

### 1.1 为什么要有 ② 和 ⑤ 两道

客户端那份判据（`GameHelper.getMapEnterRejectReason`，`ui/core/GameHelper.ts:76`）只做**即时反馈** —— 点了就有反应，不必等一个往返。权威在 `MapService.enterRejectOf`（`modules/map/map.service.ts:205`），两处消费：

- 实时通道的 `mapEnter`：切场景**之前**先问一句，被拒就不切 —— 否则人会先进一张空图再被踢回来；
- 实时通道的 `worldJoin`：真正落地那一刻再判一次。绕过 `mapEnter` 直发 `worldJoin` 的改包走的就是这条，**它必须拦得住**。

两条路给玩家看的必须是**同一句话**（文案 key 一套：`reject_map_level` / `reject_map_combat` / `reject_map_soul`），否则同一次拒绝会出现两种口径。

### 1.2 三条边界（动之前先读，`map.service.ts:111`）

| # | 边界 | 为什么 |
|---|---|---|
| 1 | **登录不算换图**：`worldJoin` 的目标图 == 服务端记下的位置（`data.mapAt`）时一律放行 | 否则站在图里的低等级玩家下次登录就黑屏，而且他自己没有办法出来 |
| 2 | **服务端还没有位置记录时不拦**（刚建号 / 老档第一次上线） | 那一刻玩家在哪由客户端决定，拦下来只会让「新号进新手村」被自己的配置挡住 |
| 3 | **不认识的图不拦** | 没有配置行就没有门槛，世界层照样给它建一份空图（历史行为） |

`mapAt` 是**服务端独占字段**（`role-authority.ts` 守着）：只有「被接受的 `worldJoin`」与「管理端摆位」能写它。客户端改自己的 `changeOnMap` 改不到这一列。

### 1.3 换图为什么要重进一次 Game 场景

`applyMapChange` 走的是 `SceneManager.loadScene("Game")` → `director.loadScene("Loading")` → 预加载 → 回 `Game`。原因有三：

- 地图资源是 `TiledMapAsset`，换图要换整份资源，不重建节点就会留着旧瓦片；
- `LayerManager` 的六个图层容器是静态节点、**随场景销毁**，换图必须重建（`initLayer`）；
- 怪物 / 掉落 / 其他玩家三个演出管理器在 `GameMap` 构造里各自 `reset()` —— 互见的节点不跨图。

代价是每次换图都有一次 Loading（进度条），收益是「不存在半新半旧的地图」。

## 二、坐标口径（全篇最容易错的一节）

同一条数据在四个地方有四种读法，**换算只允许发生在两个口子上**。

| 场景 | 原点 | y 正向 | 一张 8192×8192 的图占的范围 |
|---|---|---|---|
| **Tiled / TMX 原文**（美术在 Tiled 里量的数） | 左上角 | **向下** | `x∈[0,8192]` `y∈[0,8192]` |
| **世界坐标**（库表、快照、服务端、碰撞体） | 左上角 | **向上** | `x∈[0,8192]` `y∈[-8192,0]` |
| **管理端画布**（`MapCanvas` 的 SVG viewBox） | 左上角 | 向下（= Tiled 口径） | 同 Tiled |
| **客户端节点坐标** | 由 `map_layer` 决定（恒在世界原点） | 向上 | 同世界坐标 |

换算只有两条式子，且只出现在两处：

- **管理端**：读库 → 画 `y = -cy`（`tiledPointOf`）；画 → 提交 `cy = -y`（`worldPointOf`），矩形按中心反算。
- **客户端**：**不换算**。快照里给的已经是世界坐标（`MapObjectSpawner` / `CollisionAreaSpawner` 直接 `setWorldPosition`）。

### 2.1 为什么世界坐标是「左上角 + y 向上」

#566 之前，客户端把 `TiledMap` 的锚点设成 (0.5, 0.5)，坐标要「减半宽、翻半高」才能用。改成锚点 (0,1) 之后，瓦片直接铺在 `x∈[0,W]`、`y∈[-H,0]` —— **Tiled 坐标只差一次 y 取反**，不再有半图偏移。

这次改动的代价是**同一个世界位置的数值整体平移了 `(W/2, -H/2)`**（8192 的图就是 +4096 / -4096），而库里当时已经存着两批旧口径的坐标（`map_spawn_areas.cx/cy` 与 `world_monsters.x/y`）。所以 `DatabaseService.migrateMapCoordinateOrigin()`（`database/database.service.ts:1475`）做了一次性平移：

- 平移**不可重复执行**（再来一次就整体偏半张图），所以用 `world_meta.coord_origin` 打标记：只在它还是 `'center'` 时做一次，做完置 `'topleft'`；
- 地图尺寸读 `maps` 的几何列（`pixel_width/height`）；认不出的 `map_id` 只 warn、不动数据；
- 当前库的值：`coord_origin = 'topleft'`、`epoch = 0`。

> ⚠️ **改这一列就等于让搬家再跑一次**。要重跑请先把 `coord_origin` 改回 `'center'`，并且确认库里所有坐标确实还是旧口径 —— 否则会整体偏半张图。

### 2.2 越界判定的容差是 1 像素

`common/utils/spawn-area-bounds.util.ts` 只判一件事：矩形的四边有没有落在 `[0,W] × [-H,0]` 里。容差 `SPAWN_AREA_TOLERANCE = 1`：

> 导入工具从 TMX 的浮点像素算中心，而库列是整数/两位小数 —— 取整会让「刚好贴边」的区域报出 0.5~1 的越界。既然后果只是「贴边」而不是「跑到图外」，容差取 1。

同一个文件里还有点位（NPC / 复活点）的判定 —— 「一个点在不在图内」只该有一处判据。

## 三、一张图到底有哪些数据

服务端这边是 **5 个来源**：`maps` 表的玩法列 + 几何列 + `content` 列，加 3 张点位表与复活点两列。

### 3.1 `maps`（11 行，一张图一行）


**这些列谁写**：

| 列 | 写入方 | 频率 |
|---|---|---|
| `label` / `type` / 三条门槛 | 管理端 `PATCH /admin/maps/:id` | 运营改的时候 |
| 几何六列 + `content` | `tools/import-map-resources.cjs` | 换图 / 换 TMX 时 |
| `revive_cx/cy` | 管理端 `PUT /admin/maps/:id/revive-point` | 运营点放时 |

### 3.2 `maps.content`：图层结构

一列的 JSON，形状是 `{ layers: [{name,width,height}], groups: [] }`。当前 11 张图的内容**逐字节相同**：

```json
{"layers":[{"name":"ground","width":64,"height":64},{"name":"wall","width":64,"height":64}],"groups":[]}
```

- `layers`：只有**结构**（名字 + 格数），瓦片数据留在客户端资源里 —— 一层的 64×64 瓦片 data 是几百 KB，没必要进库；
- `groups`：**永远是空数组**。#676 把 TMX 里的 `monster` / `npc` / `collision` 三个对象组整组删掉了（`tools/strip-map-objects.cjs`），点位全部搬到库表。客户端要是再去读 TMX 的对象组，就会出现「后台改了点位、客户端没变」这种无法解释的现象；
- 读方：管理端地图详情页（让人能对着 Tiled 核对「资源里到底有什么」）。

> 📌 `client/assets/configs/game-config.ts:2095` 那段注释还留着「Tiled 对象组名 → 客户端消费方」的旧约定说明，末尾已改成「TMX 里一个对象组都不存在」，但标题仍是旧话术。

**播种公式**（`world.service.ts:369`）：

```
for 每个区域:
    校验 monster_key 在 monsters 表里存在，否则跳过并 warn
    校验区域在图内（越界只 warn 不拦截，见下）
    for i in 1..area.max:
        (x, y) = 区域矩形内均匀随机一个点
        新建实例 instanceId = m<mapId>_z<zoneId>_<seq>
```

**各图 `sum(max)` 与实际实例数对照**：

| 地图 | 区域数 | Σmax | 实际实例 | 是否一致 |
|---|---|---|---|---|
| 0 新手村 | 5 | **228** | **28** | ❌ 差 200（见下） |
| 1 卧龙城 | 2 | 12 | 0 | 世界未加载过 |
| 2 王城 | 2 | 20 | 0 | 同上 |
| 3 雪域高原 | 18 | 145 | **145** | ✅ |
| 4 漠北草原 | 7 | 191 | 0 | 世界未加载过 |
| 5 大漠戈壁 | 5 | 33 | **33** | ✅ |
| 6~10 | 各 5 | 35/35/33/33/25 | 0 | 世界未加载过 |

**新手村那 200 只的差额是「播种不回溯」的活证据**：`world` 里是 `m0_z1_*` 的 28 只（区域 125/126/127 = 10+10+8），而后来在管理端加的两个区域（id 187/188，各 100 只）**从来没有生效** —— 那个分域当年不是空的，`loadMap` 走了「库里已有行就沿用」那条路。这就是 §9.3 记的 #669。

**三个必须知道的细节**：

1. **`min` 是死列**：DTO 只有 `count`（映射到 `max`），播种只读 `max`。64 行里只有 2 行的 `min` 非 0（新手村 id 187/188「刷怪区 4/5」，各 `100/100`），它们**照样只按 `max` 展开**。`min` 是当年从 Tiled 对象组导入时带过来的残留，**不参与任何计算**。改它没有任何效果。
2. **越界区域只告警不拦截**（#586）：拦掉会让「改了配置忘了重跑导入工具」变成「这张图一只怪都没有」，比怪刷在图外更难查。告警文本里带「四边各越了多少」。
3. **只在空分域播种**：库里已有该分域的实例就**一概沿用**，刷怪区整份忽略 —— 不做「逐只补缺」，因为死亡未重生的实例还在库里占位，按区域补会把它顶掉。（这条的运营后果见第九节 §9.3。）

- **自动战斗也读它**：`AutoBattle` 的寻路网格把这些盒子当静态障碍（`PathGrid`）。

### 3.6 复活点（`maps.revive_cx/cy`）

一张图**最多一个**，存在 `maps` 表里而不是单独一张表。语义有两条：

- **进图定位**：`GameMap.goToRevivePoint` 把主角摆到这儿（`setReviveHandler` 注册即回调，处理「地图先加载完」的时序差）；
- **安全复活**：死亡后选「安全复活」再触发一次。

**没设复活点的图，进图不做定位**（人留在场景初始位置），并 `console.warn` 提示「在管理端地图管理 → 设复活点里点一下」。当前 11 张图全都设了。

### 3.7 `world_monsters`（206 行）：场上怪物实例

```sql
CREATE TABLE world_monsters (
  instance_id TEXT PRIMARY KEY,   -- m<mapId>_z<zoneId>_<seq>
  map_id TEXT, monster_key TEXT,
  x REAL, y REAL,                 -- 世界坐标
  hp REAL, max_hp REAL,
  alive INTEGER,                  -- 0 = 死着，等重生
  killed_at INTEGER, respawn_at INTEGER,
  zone_id INTEGER,
  updated_at INTEGER
)
```

**当前分布**：`zone 1 / map 0` 28 只、`zone 1 / map 3` 145 只、`zone 1 / map 5` 33 只，其余 8 张图 **0 只**。

样例：

| instance_id | key | (x, y) | hp / max_hp | alive |
|---|---|---|---|---|
| `m3_z1_1` | 1 | 1853.5, -1867.3 | 65 / 65 | 1 |
| `m3_z1_2` | 1 | 483.3, -1013.7 | 65 / 65 | 1 |
| `m3_z1_5` | 1 | 353.6, -848.7 | 65 / 65 | 1 |

三点：

- 实例 id 是 `m<map>_z<zone>_<seq>`，`seq` 每分域自增，**加载时从库里的最大值续起**（重启不重号）；
- 这张表是**投影不是配置**：只有实时进程写，管理端只读（详情页「场上怪物」弹窗）。进程重启后按刷怪区重新播种；
- 只有「有过玩家进过」的图才有行 —— 没人的图连实例都不存在（加载是懒的）。

### 3.8 `zones` 与 `world_meta`：区与代际

```sql
CREATE TABLE zones (id, name UNIQUE, merged_into, created_at, updated_at)
CREATE TABLE world_meta (id CHECK(id=1), epoch, coord_origin)
```

当前值：`zones` 两行（`1 一区` 正常、`2 二区 merged_into=1` —— 二区已合到一区）；`world_meta` 一行（`epoch=0`、`coord_origin='topleft'`）。

- **区（zone）是地图世界的隔离维度**：同一张图每个区各有一份独立世界（#295 阶段二），内存键是 `zone:mapId`。分区/合区改的就是这两张表；
- **`epoch` 是全局代际**：库被别的进程改写时（比如合区），实时进程在 tick 里巡检到 `epoch` 变了就整体作废内存世界、重新从库加载。它**不区分图**，所以拿它做「单图重载」会踢掉所有图（这正是 #669 的难点）。

### 3.9 客户端资源：`resources/map/<id>/`

| 文件 | 数量 | 作用 |
|---|---|---|
| `<id>.tmx` | 11 | 瓦片 + 图层（**只有这两样**，无对象组） |
| `*.tsx` | 287 | 图集定义（被 tmx 按文件名引用） |
| 底图 `.jpg` / `.png` | 若干 | 瓦片图集的切图源 |
| `preview.jpg` | 11（每图一张） | 小地图底图 + 全图预览弹窗底图 |

整目录 **68 MB**。路径规则只有一条：`map/<id>/<id>.tmx`，客户端与服务端各有一份**同样的拼法**（`mapSrcOf` / `MapService.srcOf`），**谁都不存 `src` 字段** —— 存了就会有人改它，而改它只会把客户端指到一张不存在的图上。

> `resources/map/*/` 的散图**保留不 plist 化**：它们被 `.tmx/.tsx` 按文件名引用，打包成图集会破坏地图（#577 记过这一条）。

### 3.10 客户端拿到的「地图配置」：快照第 18 段

`GET /game-config` 的 `maps` 段（`client-config.service.ts:90`，`MapService.configs()`）逐图下发：

| 字段 | 用途 | 客户端消费者 |
|---|---|---|
| `id` / `label` / `type` / `typeLabel` | 传送弹窗按钮、小地图标题、拒绝文案里的图名 | `MapTeleportDialog` / `SmallMap` / `GameHelper` |
| `level` / `combat` / `soulOfWar` | 本地预检 | `GameHelper.getMapEnterRejectReason` |
| `npcs[]` | `{npcId, x, y}` 世界坐标 | `MapObjectSpawner` |
| `revive` | `{x, y}` 或 `null` | `MapObjectSpawner` → `GameMap` |
| `spawnAreas[]` | `{monsterKey, cx, cy}` **只有中心点** | `MapPreviewDialog`（预览图上标「这区刷什么怪」） |
| `collisions[]` | `{x, y, w, h}` 中心 + 尺寸 | `CollisionAreaSpawner` |

**尺寸不进快照**：客户端自己有 TMX，从 `TiledMap.getMapSize() * getTileSize()` 算。

**快照里没有 `min`/`max`/区域名**：刷怪怎么刷由服务端算，客户端只需要知道「这一区大概在哪、刷的是什么」。

`applyMapRows`（`configs/game-config.ts:2153`）是**整表重建**：先 `clear()` 再按行填。留着旧行会让「服务端没有这张图」在客户端变成幽灵按钮，点开就是黑屏。类型分组 `mapTypeGroups` 一并替换（顺序 + 文案的唯一来源在服务端）。

## 四、客户端怎么把地图画出来

### 4.1 六个渲染层

`LayerManager`（`ui/core/LayerManager.ts`）用位掩码定义六层，容器都是静态节点、**随场景销毁**：

| 层 | 容器名 | 放什么 |
|---|---|---|
| `MAP` | `map_layer` | 地图节点（TiledMap）+ NPC + 碰撞体 |
| `DROP` | `drop_layer` | 地面掉落物 |
| `GAME` | `game_layer` | 主角 |
| `MONSTER` | `monster_layer` | 怪物 |
| `EFFECT` | `effect_layer` | 技能 / 光柱 / 飘字 |
| `UI` | `ui_layer` | HUD 与弹窗 |

只有 **`map_layer` 不跟着相机走** —— 它恒定在世界原点。整套坐标口径（「节点原点 = 地图左上角」）就建立在这条上：一旦有人移动地图层，`MapPointMath` 会整体错位，而它**不打算自我修正**（那里写着「不接收 map 参数去叠世界坐标」）。

### 4.2 挂 TiledMap 的三步，顺序不能换

`GameMap.loadMap`（`ui/components/map/GameMap.ts:48`）：

```ts
const transform = this.getComponent(UITransform) ?? this.addComponent(UITransform);
transform.setAnchorPoint(0, 1);          // ① 必须先设锚点
const tiledMap = this.addComponent(TiledMap);
tiledMap.tmxAsset = mapAsset;            // ② 再赋资源
for (const layer of tiledMap.getLayers()) {
  (layer as any)._syncAnchorPoint();     // ③ 逐层补算锚点偏移
}
tiledMap.enableCulling = false;          // ④ 关瓦片裁剪
```

四个坑，每个都对应一种「看起来像引擎 bug」的现象：

| 坑 | 现象 | 原因 |
|---|---|---|
| ① 锚点设在赋值**之后** | **地图整体偏移半张图** | 引擎在 `tmxAsset` 赋值那一刻同步 `_buildLayerAndGroup()` → `_syncAnchorPoint()`，按当时的锚点算好每个图层的 `leftDownToCenter`；之后再改锚点只改到本节点 |
| ③ 漏了逐层重算 | **整屏黑** | 图层只在 `onEnable` 里注册 `ANCHOR_CHANGED` 监听；建图时地图节点还没进场景 → 图层未启用 → 改锚点时没人接事件 → 偏移停在「按 0.5 算」的 `(W/2, H/2)` |
| ④ 不关裁剪 | **传送后一片黑、动一下才恢复** | 裁剪范围由 `updateCulling` 在「相机节点 TRANSFORM_CHANGED」时**同步**重算，用的是相机视图矩阵 —— 此刻矩阵还没跟上本帧的瞬移；引擎自己也把首次裁剪延后一帧。于是跨屏跳变会把范围算成跳变前的位置 |
| 关裁剪的代价 | 每帧全量提交瓦片 | 两层 64×64（每层 4096 格、1 个批次），实测开销远小于「传送后黑屏」 |

### 4.3 地图上的三类对象，三个生成器

| 生成器 | 生成什么 | 数据来源 | 挂到哪 |
|---|---|---|---|
| `MapObjectSpawner` | NPC 节点 + 复活点坐标 | 快照 `maps[].npcs` / `revive` | `map_layer` |
| `CollisionAreaSpawner` | 静态碰撞体（`RigidBody2D + BoxCollider2D`） | 快照 `maps[].collisions` | `map_layer` |
| `MonsterManager`（不是生成器） | 怪物节点 | `world` 帧（服务端实例） | `monster_layer` |

**NPC 生成顺序有讲究**：先 `addToMapLayer` 再 `setWorldPosition` —— 节点没有父节点时 `setWorldPosition` 写进去的其实是**本地坐标**，顺序反了就会整体偏移（将来地图层若不再位于世界原点，这个 bug 才会显形）。

**快照没到时什么都不摆**：`MapObjectSpawner` / `CollisionAreaSpawner` 都在 `maps.get(mapId)` 为空时 `warn` 并跳过 —— 挂一个猜出来的点位比没有更糟（玩家会莫名其妙撞墙，或点到一个不存在的人）。

### 4.4 小地图（右上角常驻 HUD）

`SmallMap`（370 行）结构，位置全部在 `configs/hudLayout.smallMap`：

```
地图名称条
功能入口按钮（竖排：公告 / 成就 / 世界 / 排行…）
┌─ 地图内容区（Mask 视口）────────┐
│ preview.jpg 按视野缩放后随角色平移 │   ← 角色黑点恒在内容区中心
│ 怪物红点 = (怪物世界坐标 - 角色) × 缩放 │
└──────────────────────────────┘
线路 + 排行榜 ／ 世界坐标条
```

**缩放口径**（`configs/smallMap.ts`）：

```
scale = 内容区宽度 / (2 × viewRadius)      // viewRadius 默认 600
横向覆盖的世界范围 = 2 × 600 = 1200 像素
纵向可见范围 = 2 × viewRadius × 内容区高 / 内容区宽（等比，不拉伸地图）
```

- 底图缩放与点位换算**共用同一个 `scale`** —— 换 `viewRadius` 就是整体放大/缩小，点位不会跑偏；
- 想让整张图装进小地图：把 `viewRadius` 调到 ≥ 图宽的一半（8192 的图取 4200）；
- **刷新 100ms**（`refreshInterval`）：坐标文本与红点重绘同频；怪物红点只在视野内画，不画朝向；
- 自动寻路期间额外画一条白色点状路线（与大地图、预览弹窗**同一份路点**，同一套缩放）。

### 4.5 全图预览弹窗（点小地图打开）

`MapPreviewDialog`（266 行）：

- 底图 = 当前图目录下的 `preview.jpg`，整图铺满预览区；
- 点击按「预览区 ↔ 地图像素范围」等比换算成世界坐标；
  - **左键** → `AutoBattle.requestMoveTo` 自动寻路走过去（玩家手动移动即打断）；
  - **右键** → 落点吸附到最近可站立位置后**直接传送**（`setWorldPositionByTransfer`，与复活传送同一入口）；
- 叠加层：角色黑点、**全图**怪物红点、寻路路线；另有静态标记层 —— 每个 NPC 一个白点 + 名称，每个刷怪区中心标怪物名；
- 关闭即销毁节点，可反复打开。

### 4.6 传送弹窗（按类型分组）

`MapTeleportDialog`（56 行）：

- 分组顺序与标题来自快照 `mapTypes`（4 组：安全 / 等级 / 战力 / 战魂），每张图一个按钮，按钮文案 `mapLabelOf(id)`；
- 点按钮 → `StorageManager.changeOnMap(id)`（见第一节的 14 步）；
- **快照为空时不渲染空弹窗**，直接提示「地图配置还在加载」—— 以前这里会弹一个什么都没有的框。

## 五、服务端世界里跑着什么

### 5.1 分域：`zone:mapId`

`WorldService`（`modules/world/world.service.ts`，551 行）的内存结构：

| 结构 | 键 | 内容 |
|---|---|---|
| `maps` | `zone:mapId` | 该分域的实例表 `Map<instanceId, WorldMonster>` |
| `viewers` | `zone:mapId` | 正在看这张图的账号集合（广播对象） |
| `emptySince` | `zone:mapId` | 变成「无人观看」的时刻（空闲回收计时器） |
| `instanceSeq` | `zone:mapId` | 发牌序号（加载时从库里的最大值续起） |
| `lastEpoch` | — | 上次巡检到的世界代际 |

`worldKey(zoneId, mapId)` 是纯函数，e2e 可以直接对照。

### 5.2 加载：内存 → 库 → 播种

`loadMap(zoneId, mapId)` 三层兜底：

1. **内存有** → 直接用（绝大多数情况）；
2. **库里有行** → `world_monsters.listByZoneMap` 恢复，`instanceSeq` 取 id 里 `_n` 的最大值；
3. **库里零行** → 按 `map_spawn_areas` 播种（每个区域按 `max` 展开、区域内均匀随机），怪 key 直读 `monsters` 表（改数值即时生效），不认识的跳过并 warn。

**播种只发生在空分域上** —— 这条决定了第九节 §9.3 那个运营体感问题。

### 5.3 三个定时器

| 参数（env） | 默认 | 作用 |
|---|---|---|
| `WORLD_TICK_MS` | **1000** | 世界 tick：重生补处理、脏实例批量落盘判断、空闲回收、代际巡检 |
| `WORLD_PERSIST_MS` | **5000** | 脏实例批量写库的间隔（一次事务） |
| `WORLD_RESPAWN_MS` | **30000** | 怪物死亡后多久重生 |
| `WORLD_MAP_IDLE_MS` | **600000**（10 分钟） | 无人观看多久后把分域从内存卸载（状态留在库里） |

`onApplicationShutdown` 会停 tick + **全量落盘**（连脏标记一起重置，保证幂等）。

### 5.4 图卸载与「逛一圈回来」

没人看的分域 10 分钟后从内存卸载，但**状态在库里**：回来时按第 2 步恢复（不是重新播种）。所以：

- 玩家离开 5 分钟再回来 → 打了一半血的怪**还是半血**（`hp` 在库里）；
- 死着没重生的怪 → `loadMap` 末尾 `processRespawns` 一次性把「卸载期间到期」的重生补上；
- 掉落物**不随图卸载**（#801 的设计），生命周期只由自己的过期时间决定。

### 5.5 怪物 AI 与广播

| 项 | 值 | 位置 |
|---|---|---|
| AI 逻辑 tick | 100ms | `monster-ai.service.ts` |
| 怪物帧广播 | 200ms（下限 50） | `monsterAiBroadcastMs` |
| 玩家互见广播 | 200ms | `player-presence.service.ts:561` |
| 客户端位置上报 | 250ms（4 Hz） | `CombatChannel.ts:422` |
| AI 技能配置缓存 | 1000ms（`SKILL_CACHE_TTL_MS`） | 改技能后最多 1 秒生效 |

> 这一条线正在被 #772 系列改（提频到 10Hz、快照缓冲插值、按图分片），数值会变，改动方向见那几个 issue。

### 5.6 监控：每秒把世界投影进库

实时进程的 `MapMonitorService` 干两件事：

- **每秒**把「这张图此刻的样子」（怪物 + 玩家 + `sampledAt`）写进 `map_monitor_state`（3 行）；
- 击杀 / 刷新写 `map_monitor_events`（330 行；`kind` 只有 `kill` / `respawn`，**事件明细**在 `payload` JSON 里）。

存档进程（管理端 API 跑在这儿）拿不到实时进程的内存，只能读这两张表 —— 所以 `MapService.monitor()` 是「读 + 拼」，并且必须如实返回三样东西：

| 字段 | 为什么必须有 |
|---|---|
| `staleMs` | 没人在图里时采集器不采样，快照会停住。不返回它，「停更 3 分钟」和「图里真的没人没怪」看起来一模一样 |
| `zones` | 同一张图每个区各有一份世界，监控得能切区 |
| `cursor` | 事件按 id 增量拉，页面不必每秒重画 300 行 |

保留策略：`MAP_MONITOR_EVENT_KEEP = 2000` 条 / `MAP_MONITOR_TRIM_EVERY = 100` 条攒批裁剪 —— 每杀一只就 `DELETE` 会让 WAL 白涨。

## 六、进图门槛：三条判据，两个判据来源

### 6.1 判据

`enterRejectOf(mapId, {level, combat, soulOfWar})`，顺序固定：

```
① row.level      > 0 且 > role.level      → { field: "level",  need, mapLabel }
② row.combat     > 0 且 > role.combat     → { field: "combat", need, mapLabel }
③ row.soul_of_war> 0 且 > role.soulOfWar  → { field: "soul",   need, mapLabel }
```

**返回「哪一项不够 + 差多少 + 图名」而不是一句中文** —— 客户端按 `field` 取自己的文案 key 拼提示，服务端不生产面向玩家的句子（与其余实时帧同一口径）。

`0 = 不限制`：安全地图就是 `0/0/0`。注意卧龙城/王城虽然是「安全地图」（图上不刷怪），进入等级却分别是 10 / 40。

### 6.2 两份判据，一个结论

| 位置 | 角色 | 依据 |
|---|---|---|
| `MapService.enterRejectOf`（服务端） | **权威** | `maps` 表（每次现查，改完立即生效） |
| `GameHelper.getMapEnterRejectReason`（客户端） | 即时反馈 | 快照 `maps`（下次进游戏才更新） |

客户端那份**同顺序、同判据、同文案 key**，但它只用来「点了就有反应」。改包跳过它没有任何意义：`mapEnter` 与 `worldJoin` 两道服务端判定都在。

### 6.3 现在的门槛有哪些空子

不判定的东西同样重要：

- **不判金币/道具**：换图不花任何代价；
- **不判冷却**：可以在一秒内来回跳图（每次都要重进场景，实际被 Loading 拖住）；
- **不判目标图人数**：图里已经 200 人也照样放行；
- **不判战斗状态**：残血 / 被怪追着也能传送走（除了被击退以外没有别的限制）。

## 七、怎么改：管理端入口与生效时间

### 7.1 页面结构

「地图管理」`/maps`（`admin/src/pages/MapsPage.tsx`，733 行；权限 `GAME_CONFIG_READ`）：

```
左侧：11 张图的列表（名称 / 类型 / 进入条件 / 各类对象计数）
右侧：MapCanvas（预览图 + SVG 叠加层 + 在图上改）
      顶栏：模式切换（view / spawn / npc / revive / collision）
      六个弹窗：图层 · NPC 点位 · 刷怪区 · 场上怪物 · 碰撞盒 · 数据来源
      另有：MapMonitor（实时地图监控弹窗，825 行）
```

**数据来源弹窗**（`SourcesDialog`）是这一页最该先看的东西 —— 它逐块列出「这块数据来自哪、能不能改、改完什么时候生效」，与本文第三节一一对应。

### 7.2 五种画布模式

| 模式 | 按下空白 | 按下已有对象 |
|---|---|---|
| `view` | 什么都不做 | 打开编辑弹窗 |
| `spawn` | 拖出矩形 → 新建刷怪区 | 不响应（拖拽期间误触会不停弹窗） |
| `npc` | 松手处 = 新 NPC 点位 | **拖动**，松手即保存；没拖动算点击 → 打开编辑 |
| `revive` | 松手处 = 复活点 | 拖动同理 |
| `collision` | 拖出矩形 → 新建碰撞盒 | 不响应 |

四种编辑模式共用一个「防手滑」底座：太小的框不提交（`MIN_DRAW_PX` / `MIN_COLLISION_DRAW_PX`）、`Esc` 取消、`touchAction: none`。

**碰撞盒为什么不能拖**：拖动一个「可能延伸到图外」的大矩形要处理「抓住框内哪一点」与「指针出了 viewBox 怎么算」两件事，收益只是省掉两次坐标输入 —— 表单里四个数字足够精确。

### 7.3 能改什么、改了什么时候生效

| 改什么 | 入口 | 生效时机 | 依据 |
|---|---|---|---|
| 名称 / 类型 / 进入等级 / 战力 / 战魂 | 页面右上「编辑」→ `PATCH /admin/maps/:id` | **立即**（服务端进图校验读同一张表） | 客户端下次进游戏才看到新名字 |
| 刷怪区（增 / 改 / 删） | 画布 `spawn` 模式 | **该图分域重新加载后**（10 分钟无人 / 重启 / #669 未做） | `world.service loadMap` 只在空分域播种 |
| NPC 点位（增 / 改 / 删） | 画布 `npc` 模式 | **客户端下次进游戏**（快照） | `MapObjectSpawner` 读快照 |
| 复活点（设 / 清） | 画布 `revive` 模式 | **客户端下次进游戏** | 同上 |
| 碰撞盒（增 / 改 / 删） | 画布 `collision` 模式 | **客户端下次进游戏** | `CollisionAreaSpawner` 读快照 |
| 图层 / 场上怪物 | **只能看** | — | 图层改 TMX + 跑导入工具；怪物是运行时投影 |

**为什么名字是「立即」而点位是「下次进游戏」**：前者走服务端判定（`enterRejectOf` 每次现查库），后者走配置快照（进游戏拉一次，之后不再变）。

### 7.4 加一张新图要动的地方（7 步，缺一步就出问题）

```
① 把资源放进 client/assets/resources/map/<newId>/
   ├─ <newId>.tmx（Tiled 导出，只留瓦片 + 图层，不要对象组）
   ├─ 若干 .tsx 图集
   └─ preview.jpg（小地图与预览弹窗都用它）
② node tools/import-map-resources.cjs
   → 写 maps 的几何六列 + content（图层结构）
③ 服务端启动：MAP_DEFAULTS 里没有的图会被补成「空名 / 安全 / 无门槛」
   （或管理端手动补一行）
④ 管理端「地图管理」里填名称 / 类型 / 进入条件
⑤ 画布上画刷怪区、点 NPC、点复活点、画碰撞盒
⑥ make config-export（把新表的节拼进 server/data/config-sync.sql）
⑦ 客户端重新打包（TMX 是资源，不发包就没有这张图）
```

第 ③ 步容易被忽略：`maps` 的行由 `tools/import-map-resources.cjs` 扫资源目录补出来，**行不存在就没有门槛** —— 世界层照样给它建空图（历史行为），表现是「能进、没怪、没 NPC」。

### 7.5 五个典型操作

**改进入等级**（最常见的运营动作）

```
地图管理 → 选中图 → 编辑 → 进入等级改成 60 → 保存
效果：立即。站在图里的低等级玩家不会被踢（登录不算换图），但下次换图会被拦。
```

**加一片刷怪区**

```
画布切 spawn 模式 → 拖框 → 填区域名 / 怪物 / 数量 → 保存
效果：等该图分域重新加载（10 分钟无人 / 重启实时进程）。
现在图里有人 → 看不见变化，这是 #669 记的那件事。
```

**挪一个 NPC**

```
画布切 npc 模式 → 拖 NPC → 松手即保存
效果：客户端下次进游戏。
```

**设复活点**

```
画布切 revive 模式 → 点一下 → 保存
效果：客户端下次进游戏。之前没设的图，进图不再"站在场景初始位置"。
```

**画一面墙**

```
画布切 collision 模式 → 拖框（可以画在图外）→ 保存
效果：客户端下次进游戏。服务端不校验位置，改包的人可以穿过去。
```

## 八、改完会怎样：一张效果对照表

| 你改的 | 玩家立刻看到的 | 再过一会儿 | 需要重进什么 |
|---|---|---|---|
| 图名 / 类型 | 管理端表格 | 客户端传送弹窗、小地图标题 | **重进游戏**（快照） |
| 进入门槛 | — | 换图被拦，提示「需要 60 级」 | 不用（服务端现查） |
| 加 / 改 / 删刷怪区 | 管理端计数 | 该图重新加载后怪物整体换一批 | 等分域重载 |
| 挪 NPC | 管理端画布 | 客户端 NPC 位置变了 | **重进游戏** |
| 换复活点 | 管理端画布 | 进图落点变了、安全复活落点变了 | **重进游戏** |
| 加碰撞盒 | 管理端画布 | 客户端撞得上了、自动寻路绕开了 | **重进游戏** |
| 换 TMX | — | 地面换了 | 重跑导入工具 + **重打包客户端** |
| 改怪物数值（不在本页） | — | 下次重生就是新数值 | 不用（直读 `monsters` 表） |

## 九、现状缺口（指向 `docs/20`）

这一节只列「地图模块自己缺的东西」，每条都能在代码里指出位置。

### 9.1 一张图只有一个实例，没有分线 / 副本

`ground` / `maps` 的键是 `zone:mapId`，**一个区一张图一份世界**。后果：

- 图里人多就只能挤（没有「二线」）；
- 想做副本（每人一份）没有容器概念 —— 现有的键里塞不下第二个实例；
- 世界事件（Boss 刷新）全图共享，没法按人头分成多场。

### 9.2 无人时世界会「冻住」

`WORLD_MAP_IDLE_MS = 10 分钟` 卸载分域后，那张图**没有 tick**：怪不重生、AI 不动、事件不推进。玩家回来时靠 `processRespawns` 一次性补算。对「挂机刷怪」没影响（人在就有人看），对「世界感」有影响（离线期间世界是静止的）。

### 9.3 刷怪区改完不回溯（#669）

播种只在**空分域**发生。所以「图里现在有人」时改区域 → 新区域不补怪、改过的数量不生效、删掉的区域场上怪还在。要等 10 分钟无人或重启。运营体感是「配完看不到效果」。

**库里有现成的例子**：新手村 `Σmax = 228`、`world_monsters` 只有 28 —— 后来加的两个 100 只的区域一次都没生效过（见 §3.3）。

### 9.4 `min` 是死列

`map_spawn_areas.min` 有 62/64 行是 0，剩下 2 行（新手村 187/188，`100/100`）是手工加测试数据时顺手填的。DTO 不暴露它，播种只读 `max` —— 它是当年从 Tiled 导入带过来的残留，留着会让人以为「这是个可以调的下限」。

### 9.5 没有 AOI：广播是全图的

`viewersOf(zone, mapId)` 拿的是**整张图**的观看者。8 人同图 + 145 只怪时，每 200ms 一轮广播是「8 × 视口内怪物」这个量级；图再大人再多就靠 #768 的帧瘦身与序列化缓存顶。没有九宫格/视野裁剪这层。

### 9.6 移动与碰撞只信客户端

服务端的 `world_monsters` 与位置上报只是「记账」，**不校验**玩家是否穿墙、是否瞬移。碰撞盒是客户端静态体，改包可以无视。`too_far` 那类距离校验只在掉落拾取里刚加（#802 的设计）。

### 9.7 寻路只在客户端

`PathGrid`（290 行）是客户端的 A*（八方向、对角 √2、小顶堆开放集），服务端没有寻路。后果是「怪物怎么绕过墙」由 AI 的直线追击 + 卡住重选解决，而不是真正绕路。

### 9.8 没有容量与排队

进图只看三条数值门槛，**不看图里有多少人**。也没有「图满请稍后」这种体验。

### 9.9 传送没有代价与冷却

任意图之间来回跳不花金币、不看状态、没有 CD（只有 Loading 时间）。

### 9.10 没有地图级玩法参数

一张图能配的只有「能不能进 + 刷什么怪 + NPC 在哪 + 墙在哪」。**地图级倍率**（经验 / 掉落 / 掉率加成）、地图级规则（能不能 PK、能不能挂机、能不能用回城）、地图级事件（Boss 时间表）全都没有位置可放。

### 9.11 监控精度受投影限制

`map_monitor_state` 每秒采样一次、走 SQLite 共享。管理端看到的是「最多 1 秒前」的世界，且**没人看图就不采样**（`staleMs` 会一直涨）。

### 9.12 图层结构只有「名字 + 格数」

`maps.content` 不含瓦片数据（合理），但也不含**图层属性**（是否可走、是否遮挡、是否有视差）。客户端要判断「这格能不能站」只能靠碰撞盒。

## 十、排障表

| 症状 | 先查什么 | 常见原因 |
|---|---|---|
| 进图黑屏（整屏） | `GameMap.loadMap` 的三步顺序 | 漏了逐层 `_syncAnchorPoint()` |
| 地图整体偏半张图 | 同上 | `setAnchorPoint(0,1)` 写在了 `tmxAsset` 赋值之后 |
| 传送后黑屏、动一下恢复 | `tiledMap.enableCulling` | 没关瓦片裁剪 |
| 站在图外 / 怪刷在图外 | `select coord_origin from world_meta` | 库还是旧口径；或区域越界（看实时进程 warn） |
| 图能进但一只怪都没有 | `select count(*) from world_monsters where map_id=?` | 空分域播种时 `monster_key` 在 `monsters` 表里不存在（跳过并 warn） |
| 改了刷怪区没反应 | 该图是否有人 | #669：播种只在空分域 |
| 改了图名客户端没变 | 是否重进游戏 | 快照只在进游戏拉一次 |
| NPC 不出现 | 快照 `maps[].npcs` 里有没有 | `npc_id` 在 `npcs` 表里查不到 → 客户端跳过 |
| 进图落在场景左上角 | 该图 `revive_cx/cy` 是否为空 | 没设复活点就不定位 |
| 玩家能穿墙 | — | 服务端不校验位置（§9.6），碰撞盒只在客户端 |
| 监控页显示「没有可用快照」 | `map_monitor_state` 有没有这张图的行 | 图里没人 → 采集器不采样 |
| 管理端地图页空白 | 浏览器控制台 `preview.jpg` 是否 404 | 资源目录缺预览图 |

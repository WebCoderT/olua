## 启动与构建

### 管理端怎么跑起来？接口地址在哪配？

- **启动**：`cd admin && npm install && cp .env.example .env.development && npm run dev`（默认 `5173`）
- **构建**：`npm run build` = `tsc --noEmit && vite build`，产出 `dist/`。**类型不过就构建失败**，这是刻意的 —— 接口层是生成物，签名不兼容必须在这道关卡拦下来
- **接口地址**：只由 `admin/.env.development`（或 `.env.production`）的 `VITE_API_BASE_URL` 决定，代码在 `src/api/config.ts` 里读它。生产也可以填相对路径 `/api` 走同域反向代理
- **注册**：需要在 `server/.env` 里配 `ADMIN_REGISTER_CODE`（留空 = 开放注册），注册时填同一个注册码；**第一个**注册的管理员自动成为超级管理员
- 自查：`node ../tools/audit-api-hardcode.cjs` —— 它会检查管理端有没有把地址写进代码、用到的环境变量键有没有登记进 `.env.example`

## 权限

### 按钮为什么是灰的 / 菜单为什么少了几项？

- 管理端的**每一处显隐都来自令牌里的权限点**（`store/session` 的 `hasPermission`）。导航项带 `permission` 字段（`Layout` 过滤后再渲染），写操作按钮 `disabled`，页面级用 `App.tsx` 的 `RequirePermission` 外壳
- **界面显隐只是体验，服务端才是权威**：守卫每次请求都重新判一次，改 Address 硬闯也只有 `403` + 业务码 **30006**
- 权限点的唯一来源在**服务端** `src/common/constants/permission.ts`（15 个权限点 / 3 种角色）。管理端 `src/api/types.ts` 的 `PERMISSION` 是它的镜像，两边要一一对应
- **脏会话兜底**：如果会话里 `permissions` 缺失（例如旧令牌、手改了 localStorage），`hasPermission` 按**空数组**处理 —— 结果是**最小权限**（菜单几乎全没了），而不是漏判放开
- 管理员被降权后，**刷新页面即生效**：`Layout` 进来会静默拉一次 `authApi.me()` 把最新角色与权限点写回会话

### 直接改地址栏闯进没权限的页面会怎样？

不会白屏。`RequirePermission` 外壳会就地渲染一段「没有访问权限」的提示（`EmptyState`）。但**拦不住也拦不重要** —— 真正的判定在服务端，即使前端放行，对应的数据请求也会被 `403` 挡回来。

### 为什么「我的账号」在右上角，不在左侧导航里？

因为它是**每个人的私有页面**（看自己的身份 / 登录情况 / 权限点，以及自助改密），**不需要任何权限点** —— 放右侧导航会和「需要权限才能看的功能」混在一起，语义不对。所以 `Layout` 把它做成顶部身份栏的一个按钮，路由 `/me` 直接挂在 `RequireAuth` 下、不套 `RequirePermission`。同理，`NAV_ITEMS` 里每一项都有 `permission`，唯独它没有。

## 口令管理

### 重置密码和「我的账号」改密码有什么区别？

两个入口刻意分开，因为**校验方式与后果完全相反**：

| | 重置别人 | 改自己 |
| --- | --- | --- |
| 入口 | 账号详情页 / 管理员列表行内 | 右上角「我的账号」 |
| 校验 | 不需原密码（凭权限点） | **要验原密码** |
| 口令来源 | 前端生成随机口令、**只显示一次** | 自己输入 |
| 旧令牌 | **全部作废**，对方要重新登录 | 服务端**下发新令牌**，前端覆盖会话 |

- 管理员列表里「重置密码」对**自己那一行是禁用的**（`title` 提示去「我的账号」）—— 因为走重置那条路会让自己的旧令牌当场失效、立刻被踢回登录页
- 机制的细节（`token_version` 怎么让旧令牌失效、为什么改密与版本自增要在同一条 SQL）见 [../server/FAQ.md](../server/FAQ.md#玩家忘记密码怎么办重置之后他为什么被踢出去了)
- 客户端的被踢表现（`40103` 强制重登）见 [../client/FAQ.md](../client/FAQ.md)

### 顶栏的权限点数、时间显示是怎么来的？

- 顶栏「权限点 N 项」= 会话里 `admin.permissions` 的长度，进来时由 `authApi.me()` 刷新；改完自己密码换了新令牌后靠**会话订阅机制**（`subscribeSession`）即时刷新，不用手动刷新页面
- 表格里的时间走 `src/api/types.ts` 的 `formatTime` / `formatTimeFull`（本地时间）；操作日志的时间筛选用 `<input type="datetime-local">`，由 `localInputToMs` 换算成毫秒再发给服务端 —— **服务端收的是毫秒时间戳**，界面显示的是本地时间，两边不要混

## 运营操作

### 后台「踢下线」到底做了什么？为什么玩家非得重选角色？

- **按钮什么时候可点**：账号详情页的「踢下线」需要 `account:status` 权限，且该账号**当前有在线角色**（`onlineRoleId` 非空）才可用；没有在线角色时是禁用的
- **点了之后服务端做两件事**：① 清掉账号的 `online_role_id`；② 在存档写入路径上加判 —— 推上来的角色必须仍是账号当前的在线角色，否则 `409` + 业务码 **20007**。只做①是拦不住人的，玩家本地还在跑，1.5 秒后照样把存档推上来
- **玩家那边看到什么**：飘字「你的角色已被管理员下线」→ **只清本地在线标记、不删角色** → 回选角场景。重选一次（`POST /roles/:id/select` 重新写上在线标记）即可继续
- ⚠️ 20007（被下线）与 20002（角色被删）后果完全相反，客户端是分开处理的：20002 才删本地缓存。这条有专门的守卫（`client/tools/test-client-net.cjs` 断言「这段处理里不许出现 `deleteRole`」）
- 完整的机制说明（判定为什么放在乐观锁之前、副作用是什么）见 [../server/FAQ.md](../server/FAQ.md#后台踢下线到底做了什么为什么玩家非得重选角色)；联动时序见 [../FAQ.md](../FAQ.md#后台改了角色玩家那边什么时候生效)

## 接口层

### 接口文件能手改吗？加一个后台接口要动哪些文件？

**不能。** `src/api/{routes,models,endpoints}.ts` 是生成物，头一行写着 `@generated by tools/gen-api.cjs`。手改的话下一轮 `npm run gen:api` 就被回滚，而且 `node ../tools/audit-api-generated.cjs` 会逐字节比对判 FAIL。

加一个后台接口的标准动作：

1. **服务端**写控制器方法 + DTO，并在 `@ApiAdminDoc({ operationId, permissions: [Permission.X] })` 里给 `operationId` 与权限点（**漏了权限点就是真放行**）
2. `cd server && npm run gen:api` —— 重新产出 `openapi.json` 与两端接口文件（管理端的 `endpoints.ts` 里会多出对应方法）
3. 管理端**在 `src/api/types.ts` 补权限点常量**（生成物不含权限点字典），页面里 `adminApi.xxx()` 调用新方法
4. `npm run build` —— 签名对不上会直接报

**手写的那几个文件**（改动都落在这里）：`config.ts`（地址）、`http.ts`（请求层）、`types.ts`（业务码 / 权限点 / 中文字典 / 时间工具）、`index.ts`（统一出口）。页面只从 `index.ts` import。

### 构建报错 / 类型不过，通常是什么原因？

按频率排：

1. **改了服务端接口但忘了 `npm run gen:api`** —— 管理端 `models.ts` / `endpoints.ts` 停在旧契约上，调用点签名对不上（这是设计意图：宁可编译报错，也不要线上出现 `undefined`）
2. **`types.ts` 里漏登记新权限点 / 新业务码** —— 页面里引用了不存在的常量
3. **未使用的导入** —— `tsconfig` 开了 `noUnusedLocals`，删掉即可
4. **JSX 里写了 markdown** —— `**加粗**` 在 JSX 文本里会原样显示星号，界面文案要写 `<strong>…</strong>`
